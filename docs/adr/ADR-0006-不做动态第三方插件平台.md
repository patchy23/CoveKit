# ADR-0006 · 不做动态第三方插件平台

- 状态：已采纳
- 日期：2026-09-14
- 批次：arch-202609-001

## 处境

「支持第三方插件」的诉求随时会出现：用户想自己加工具，或团队想把内部小工具挂进来。一旦允许动态下载与加载第三方插件，签名校验、沙箱、权限模型、依赖升级、崩溃归因、数据边界这六件事都要另建一套，而本项目是内置受信工具集合，插件之间靠公开契约协作、共享同一份用户数据。

## 决定

不做动态第三方插件平台：插件随应用整体发布，不提供插件市场、动态下载或运行时热加载。扩展能力通过新增内置模块实现，走既有的 owner 分界与装配规则。

## 代价与边界

用户与团队不能自行扩展，只能等我们内置；新增能力要跟着应用发版节奏走。重新审视的条件是出现两个以上真实外部扩展需求，且能同时给出签名、沙箱与数据边界的解法；在此之前，任何「先加个加载器、权限以后再说」的方案都不接受。
