# ADR-0002 · 存储四分区与按 owner 的数据库路径规则

- 状态：已采纳
- 日期：2026-09-14
- 批次：arch-202609-001

## 处境

插件各自决定落盘位置，会让迁移、备份、清理、权限收紧与诊断各自为政：换存储位置要写 N 套逻辑，删数据分不清哪些是用户数据、哪些是可重建缓存。

## 决定

所有持久化经 `framework::paths`，统一为 `<storageRoot>/{data,vault,logs,cache}` 四分区；模块数据固定 `<storageRoot>/data/<owner>.db`，缓存只能进 `cache/`。禁止绕过 `paths` 直接取根写盘（架构守卫会让绕过者失败）。

## 代价与边界

新增 owner 必须登记路径规则，不能随手在业务目录写文件；历史存储名允许显式映射，不因此改写或丢弃旧数据。空间（space）维度落地时，路径规则在其上扩展，不推翻本节。
