# ADR-0007 · 验收按变更分档，证据等级不得越级声明

- 状态：已采纳
- 日期：2026-09-14
- 批次：arch-202609-001

## 处境

验收出现过两种相反的病：

1. **越级声明**：拿单元测试当「已验收」，把平台、协议、交互类结论写成通过。本项目已多次付出代价——剪贴板权限提示、诊断报告复制的缺陷都是真机走查才发现的，静态与单测当时全是绿的。
2. **过度验证**：改一个小缺陷也要跑完全量前后端测试、静态检查与冷启动，单次几分钟到半小时不等，改个小问题变成一小时；成本高到让人干脆跳过验证，反而更糟。

两种病同源：**没有按变更定档，只有「全跑」和「不跑」两个极端。**

## 决定

1. **先定档，再选验证**。档位沿用工作流的 S1 / S2 / S3-S4；每档要求跑什么、明确不要求跑什么，唯一来源是 `standards/20-验证矩阵.md`。
2. **未列入本档的验证不要求执行**，禁止用「全都跑一遍」兜底；改一个小点跑一小时的全量验证，与漏测同样按缺陷对待。
3. **证据等级如实声明**：静态核对 / 单元或行为测试 / 真实链路 / 真机，做到哪级写哪级，未做的写「未验证」，不得用「理论上支持」或其他档位的结果替代。
4. **越档只在两种情形发生**：改动实际触及更高档的内容（如文档改动顺带改了脚本），或本档验证失败需要更大范围复现。事后发现漏跑，补跑并记录，不靠全量预防。

## 代价与边界

定档判断有主观性，可能低估影响面而漏跑。代价按「补跑 + 记录」处理，不用全量兜底。本 ADR 不放松任何硬要求：持久化、密钥、迁移、装配权限与发布仍然必须全量门禁、夹具与故障注入、冷启动与平台登记——这几档的门槛不变，变的是其余档位不再被它们连带。
