# ADR-0009 · 路径字符串规范化下沉后端

- 状态：已采纳
- 日期：2026-09-14
- 批次：ssh-202609-002

## 处境

Windows 路径的等价写法极多：`C:\` 与 `C:/`、大小写、UNC 前缀、`.` 与 `..`、长路径、驱动器根与空串。前端做字符串拼接与比较必然漏判，且一处漏判的表现是「找不到文件」「落到错误目录」这类难复现的故障。更棘手的是「此电脑」根本不是文件系统路径，而是 Shell 命名空间式的虚拟层。

## 决定

路径规范化、驱动器与根列表判定、等价性比较一律在 Rust 后端实现（参照 WinSCP / FileZilla 的做法）；前端只负责把用户输入原样传给后端、把后端结果原样展示，**不做路径字符串手术**。

## 代价与边界

每新增一种路径交互都要有对应的后端接口，前端不能就地判断；后端接口因此承担更多语义。收益是规范化只有一处实现、且性能更好（避免在前端反复拼串与正则）。若出现只能在前端完成的展示型格式化（例如仅折叠显示的长度省略），允许做纯展示处理，但不得参与判定与比较。
