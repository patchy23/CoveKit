# patchyBox 项目分析报告

> 分析日期：2026-09-06（临时文档，随迭代会过时，不作为规范依据）
> 分析范围：全仓快照（267 个提交，main 领先 origin 24 个提交）；方法为代码实读 + 探索代理分区域调查，结论均附文件级证据。

## 总体结论

这是一个工程纪律罕见严格的项目——"文档-代码-检查脚本三位一体"落到实处（运行期 panic 清零、MutexGuard 跨 await 清零、全仓零 TODO、提交规范 100% 遵循），架构上"自注册 + 前缀分派"的插件化设计经受住了第二批复杂工具（数据库工作台、SSH）的实测。

主要风险集中在四处：

1. **CI 不跑 Rust 测试**——86 个内联单测全靠本地自觉；
2. **双凭据体系并存**——框架 Vault 与 ssh/database 插件私有 AES 加密割裂；
3. **i18n 只做了壳层**——8 个插件全部硬编码中文；
4. **文档宣称与实现脱节**——README/CHANGELOG 夸大了工具与 Vault 集成范围。

## 一、框架及架构

### 1.1 实际形态

技术栈：Tauri 2.11（Rust）+ Vue 3.5 + TS（strict）+ Tailwind 4 + Pinia。规模：前端 115 个 Vue 组件 + 70 个 TS 文件（约 2.2 万行），Rust 侧 58 个文件约 1.36 万行。

```
前端                                    Rust
src/core/     框架层                    src-tauri/src/framework/   框架层
  ├─ ipc/       invokeCommand + 契约     ├─ ipc_registry.rs  命令入库/唯一性校验
  ├─ registry/  工具自注册               ├─ store.rs         PluginDb 骨架 + 迁移
  └─ ui/        41 个 Ui* 组件           └─ vault/           凭据库（keyring+AES-GCM）
src/plugins/  8 个插件（互不 import）    src-tauri/src/plugins/     7 个插件目录
src/features/ workspace/settings/vault  （mod.rs 门面 + 前缀分派 handler）
```

### 1.2 优点（有证据支撑）

**① 扩展协议兑现了"框架零改动"。** 新增前端工具 = 建目录 + `registerTool` 一行（`src/core/registry/toolRegistry.ts:10`，重复注册仅告警）；新增 Rust 插件 = 建目录 + mod.rs/lib.rs 各一行链式装配（`src-tauri/src/lib.rs:62-71`，9 个插件各一行）。抽查全 plugins 目录，插件间互相 import 为零——隔离不是写在纸上的。

**② IPC 类型安全设计干净。** `invokeCommand` 统一归一化错误为 `IpcError`（`src/core/ipc/ipc.ts:18-28`），框架命令走 `Payloads/Results` 双映射的强类型 `call`，插件命令在各自 `contracts.ts` 单点定义、`ipc.ts` 封装。配合 `strict: true + noUnusedLocals + vue-tsc` 进 CI，类型防线完整。

**③ 前缀分派解决了 Tauri 的真实痛点。** `Builder::invoke_handler` 只能设置一次，多插件各自注册会互相覆盖；项目用 `is_command()` 按前缀（`http_`/`dbc_`/`ssh_`…）路由到插件私有 `generate_handler`（`src-tauri/src/plugins/mod.rs:26-39`），并用 `ipc_registry` 在启动期校验全局唯一（重复即 panic，fail-fast）。零宏魔法，问题解得直白。

**④ 安全架构是认真设计过的。** hosts 用临时 ps1 + UAC 一步提权，应用本体不常驻管理员；SSH 主机密钥 TOFU + 私有 known_hosts，密钥不一致拒绝连接；Vault 的威胁模型在文件头明示（防"密文文件被拷走即泄密"，不防同账户恶意进程）——诚实的安全边界声明。

**⑤ 架构选型与产品形态匹配度高。** Tauri 对比 Electron：安装包 ~5MB（LTO+strip）、内存占用低；多页签工作区用 `compCache + v-show` 保持会话不销毁（`ToolWorkspace.vue:24-31`），SSH 连接、数据库页签切走再回来状态完好——正是"长连接复杂工具"最需要的载体决策。

### 1.3 缺点与风险

**① 前缀分派与 IPC 入库是两套脱节的机制（最大的架构隐患）。** `ipc_registry` 只做登记不参与路由；命令真正能不能到达插件，取决于 `is_command()` 里有没有手写对应前缀。新增插件忘了加前缀 → 命令静默落到 framework handler → 编译期不报错、启动期不报错、运行期前端收到莫名的"命令不存在"。目前 7 个前缀靠人工同步，register 时自动推导前缀即可消除。

**② "Adapter/Provider trait 是第二批骨架"的宣称与实现不符。** 实际数据库插件没有 per-driver trait，靠枚举 `DbSession`（Mysql/Postgres/Sqlite/Redis/Agent 五变体）match 分派，唯一的 trait 是 `DbDialect`（SQL 方言语义纯函数）。5 个驱动规模下枚举分派反而更直白——实现本身合理，但 AGENTS.md 描述失实，且新增驱动要改 connect/test/disconnect/cancel 四处 match，规模再涨就该 trait 化。

**③ 双凭据体系并存是长期债。** 框架 Vault（keyring 主密钥 + AES-256-GCM）之外，ssh 插件手工凭证走私有 `ssh-master.key`、database 走插件私有 AES 文件（`database/secrets.rs`）——三套密钥管理。文档说数据库"已接入可选引用"，实际 `ConnectionDialog.vue` 只有手工密码框，未接 Vault。

**④ 其他结构性问题**：`modal` 展示载体是死代码（零使用）；`ConnectionProfile` 预留类型还写着"存 stronghold"（已弃用的技术）；异步路径里 86 处同步 `std::fs`、Argon2id 在 async 命令中同步计算（未 `spawn_blocking`）；迁移 `ALTER TABLE ADD COLUMN` 无幂等保护，中断后重放会报错。

### 1.4 适配程度评价

对这个产品（个人维护的桌面开发者工具箱）和团队形态（单人 + AI 辅助开发）：

- **高度适配**：自注册/懒加载/声明式 settingsSchema 都是"加东西不动框架"的正向设计；重流程纪律（注释密度检查、棘轮脚本、check-list）恰好是 AI 协作开发最需要的护栏。
- **阶段性适配**：第一批"只增不改"铁律基本守住（载体从 modal 改 workspace 是唯一推翻，且留了类型退路）；但第二批已出现"用第三套私有方案绕过框架抽象"的迹象（凭据），框架抽象的引力在衰减。
- **规模边界**：前缀路由、枚举分派、`useDatabase.ts` 1416 行，都还能跑，但都站在"再涨就该重构"的临界点上。

## 二、代码质量

### 2.1 强项（数据说话）

| 指标 | 实测值 |
| --- | --- |
| 运行期 panic 风险 | **0**（117 处 unwrap 全在测试代码，棘轮基线清零） |
| unsafe / Box::leak / transmute | 0（零容忍，脚本实测通过） |
| TODO/FIXME/HACK 注释 | 全仓 **0** 处 |
| 注释掉的大块代码 | 0 |
| 孤儿组件 | 0（41 个 Ui* 逐一验证有引用） |
| 提交规范遵循度 | 近 30 条 **100%** conventional commits，中文描述具体到行为 |
| MutexGuard 跨 await | 0（3 个启发式扫描候选逐一核实均为误报，代码有大量纪律注释自证） |

- **CI 五道门禁**：ESLint `--max-warnings 0` → prettier → vue-tsc 构建 → `cargo clippy -D warnings` → 自研 `check_docs.py` 注释密度检查。
- **Rust 规范的执行是全项目最亮眼的部分**：`docs/05-rust-code-standard.md`（v1.1）+ `check_rust_rules.py` 棘轮脚本 + 白名单显式登记（仅 3 条 expect 例外），文档引用的写法（`dialect_or_err`、锁内最小提取）都能在代码里找到对应实现与注释。文档、代码、脚本三者一致。
- **测试有真实质量**：前端 17 文件 141 用例，纯函数抽取得当（SQL 切分/格式化、树过滤、hosts 往返），甚至有架构守护测试（"业务组件不得绕过公共表格契约"）；Rust 86 个内联单测，Vault 模块连"Windows 凭据管理器静默丢写后降级"这种平台级坑都有回归测试。

### 2.2 弱项（按风险排序）

1. **CI 不执行 Rust 测试**——`cargo test` 不在任何 workflow 里，86 个单测全靠本地自觉；`check_rust_rules.py` 棘轮也只手动跑。两大质量支柱都没有机器守护，与项目纪律水平最不匹配。
2. **"组件 < 300 行"红线已被自家违反**：4 个文件超标且全在 ssh 插件（`ServerList.vue` 334、`FileManagerTab.vue` 317、`ServerForm.vue` 316、`TerminalTab.vue` 305）；`useDatabase.ts` 1416 行、`ssh/contracts.ts` 481 行，虽然按规则字面（hook/契约文件不限制）合规，但单文件复杂度已失衡。
3. **依赖卫生债**：`sqlx` 声明但源码零使用（纯死编译）；reqwest 未关 default features 导致 native-tls + rustls 双 TLS 栈并存（与"统一 ring"的明确决策矛盾）；chrono 与 time 双时间库；jsdom 与 happy-dom 双 DOM 测试库。版本滞后集中在工具链（vite 6→8、TS 5.6→7、eslint 9→10）和个别 crate（tokio-tungstenite 0.24→0.30、rusqlite、redis、keyring）。
4. **小规模重复与漂移**：`formatBytes` 双实现且行为已漂移（http-ws 三档 vs ssh 四档带 GB）；http-ws 删除接口无确认（见 3.3）。
5. **文档失实清单**：CHANGELOG 宣称的二维码/密码哈希/文本对比等工具不存在；README 宣称数据库可引用 Vault 但未实现；AGENTS.md 全文未提 tts 插件；docs/README 还叫旧项目名"ToolKit"；两个 `04-` 编号文件冲突。
6. **工作区状态**（快照时点）：7 个 modified 文件里 4 个是 CRLF 幻影改动（autocrlf 与 prettier `endOfLine: crlf` 打架），1 个是进行中的 ServerList 拖拽重写（HTML5 DnD 与 Tauri OLE 拖放冲突，换 pointer 事件自实现——方向正确，未提交）。

## 三、功能设计

### 3.1 功能全景

8 个已注册工具，全部走 workspace 载体：格式转换（JSON/XML/时间戳/Base64）、HTTP/WS 调试、数据库工作台（MySQL/PG/SQLite/Redis + agent 侧车支持 Oracle/Kingbase 等）、hosts 编辑、DNS（查询 + 阿里/腾讯/CF）、SSH 远程管理（终端/SFTP/监控/进程/systemd/Docker）、TTS、component-lab。深度上 database（~5600 行前端）和 ssh（~3400 行）是两个旗舰，其余是轻工具。

### 3.2 设计亮点

1. **Vault 可选引用 + 手工输入双路径**是全项目最聪明的设计：值留空=不用凭证，选中即优先、清空即回退——存量用户零迁移成本，新用户有安全路径。配套三层失效防线（选择器即时提示 → 表单提示 → 后端连接时最终校验类型），删除凭证前汇总 DNS/SSH 引用计数并区分文案。
2. **踩过坑的细节**：数据库连接"取消即断开防幽灵会话"；SSH SFTP 长驻复用（注释写明逐操作新建是卡顿与内存飙升根因）；空闲自动断开排除后台传输/终端活动防误杀；终端右键粘贴后归还 xterm 焦点。
3. **hosts 提权模型正确**：先备份后覆盖一步 UAC，保存后回读确认，前端语法校验拦截——对"改 hosts"这个本质危险操作做了完整防护。
4. **交互模式有意识复用**：两段式删除（15 处）、`UiPagination`、`UiSearchInput`、自研右键菜单（带视口边界 clamp）跨插件一致；无障碍做到"够用"水准（reka-ui 弹窗焦点陷阱、UiTree 完整 aria 树角色）。

### 3.3 设计隐患

1. **http-ws 删除接口无任何确认**，直接删库——与全站两段式删除模式冲突，交互一致性上最明显的破绽。
2. **SSH 手工凭证与框架 Vault 是两套加密体系**，用户视角会出现"凭证库里有的连接用不了、连接表单里的密码不在凭证库"的认知割裂。
3. **查询结果分页语义不统一**：查询结果前端切片分页、数据页签后端分页，UI 无区分提示，用户可能误解数据完整性。
4. **settingsSchema 机制成型但只有 2/8 工具接入**，`secret` 字段类型无消费者——框架能力供给超前于实际需求。
5. **多页签工作区无键盘快捷键**（无 Ctrl+W/Ctrl+Tab），对以页签为核心交互的界面是可用性短板。

### 3.4 深度不足

- **Redis 仅只读键查看**（无 TTL 修改/删除/编辑），离"可用"有距离；数据库数据页签只读无行内编辑。
- **http-ws 缺请求历史、环境变量、认证助手**，WS 不支持二进制消息——作为日常调试工具竞争力有限。
- **i18n 只有壳层**：仅 4 个框架文件用 `useI18n`，8 个插件的全部文案硬编码中文，切到英文后工具内部体验断裂（且 fallbackLocale 是 zh-CN）。

## 四、综合评价

| 维度 | 评级 | 一句话 |
| --- | --- | --- |
| 架构设计 | 良好偏优 | 协议兑现、边界真实；扣分在前缀分派手工同步风险与凭据体系分裂 |
| 代码质量 | 优秀（流程）/ 良好（局部） | 纪律执行力罕见，但两大检查未进 CI、红线已破、依赖有死重 |
| 功能设计 | 良好 | 双路径 Vault 和踩坑细节体现成熟度；深度与一致性参差 |

**如果只做五件事**（按投入产出排序）：

1. CI 加 `cargo test` + 棘轮脚本（半小时补上最大的守护缺口）；
2. `register()` 时自动推导命令前缀并校验 `is_command` 一致性（消除静默失败）；
3. 删 `sqlx` 死依赖 + reqwest 统一 rustls；
4. 把 database/ssh 私有 AES 迁到框架 Vault，收敛为单一密钥体系；
5. http-ws 删除补确认 + 修正 CHANGELOG/README 与实现的一致性。
