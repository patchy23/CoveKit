## 0. 用户验收标准（三条，逐条可量化）

用户原话：「高性能、低占用、该有的功能都有」。翻译成可验收标准：

| 要求 | 可验收标准 | 实测方法 |
| ---- | ---------- | -------- |
| 高性能 | 打开 1 万行文本首次渲染 < 100ms；连续输入无可感延迟；切换页签即时恢复 | dev 实测（Performance 面板 + 手工输入体感） |
| 低占用 | 前端打包增量 ≤ 500KB（gzip，含常用语言包）；空编辑器单实例内存 < 10MB；用不到的语言不加载 | `pnpm build` 前后对比 `dist/` 体积；WebView2 进程内存对比 |
| 该有的功能都有 | §4 的 22 项功能全部可用（按 §5 清单勾选） | component-lab showcase + 迁移后的真实工具 |

**业界锚点（供判断是否正常）**：代码编辑器前端增量 300–500KB 属于正常偏轻；VS Code 的编辑器 + 语言服务是几十 MB 级；同类桌面应用（Obsidian、Replit、Joplin）均选用 CodeMirror 6。没有引入 Monaco 不是省事，而是**它的三条要求都反向违反**（见 §1）。

## 1. 选型结论：CodeMirror 6 为唯一基座

实拉数据（GitHub API + npm registry，2026-09-11）：

| 项目 | star | 最近提交 | npm 解包体积 | 周下载 | 结论 |
| ---- | ---- | -------- | ------------ | ------ | ---- |
| **CodeMirror 6**（`@codemirror/*` 多包） | 7.8k（dev 聚合仓库） | 各包活跃 | `view` 1.2MB + `state` 0.4MB + 扩展按需 | `view` 1062 万 | ✅ 基座 |
| Monaco Editor | 46.7k | 2026-09-10 | **93.4 MB** | 627 万 | ❌ |
| Ace | 27.1k | 2026-08-13 | **52.5 MB** | 99 万 | ❌ |
| TipTap / Lexical / Slate / ProseMirror / Quill | 38k / 24k / 32k / 8.7k / 47k | 活跃 | 2.8–3.4MB | 千万级 | 富文本，非本需求 |
| Milkdown / Vditor | 11.9k / 11.3k | 活跃 | 0.2MB / **22.5MB** | 25 万 / 3.6 万 | Markdown 专用，非本需求 |

**排除 Monaco 的四条硬理由**

1. 解包 93.4MB，而本项目打包偏好是单 exe 便携交付（前端资源内嵌），体积直接反映到交付物；
2. 依赖 web worker（语言服务），Tauri 下需 `vite-plugin-monaco-editor` 或手写 worker 入口，官方讨论区 #9595 有实际卡壳案例；
3. worker 还需放宽 CSP（`blob:`），与 Tauri 默认收紧的 CSP 冲突；
4. 主题是自定义 token 规则表，无法贴合 `DESIGN.md` tokens；CodeMirror 的高亮样式直接吃 CSS 变量（现有 `CodeViewer`/`EditorDialog` 已是此写法）。

**反方向证据**：Azure LogicAppsUX 官方设计文档《Monaco to CodeMirror Migration Design》（2025-01-14，Status: Approved）把 Monaco 整体迁到 CodeMirror 6，理由为性能与体积。

**CodeMirror 的已知弱项与对策**：LSP/IntelliSense 生态弱（官方 `@codemirror/lsp-client` 仓库已于 2026-04-15 归档，周下载仅 1.2 万）。本项目场景只需要 schema/词法级补全（SQL 表名列名已由 `@codemirror/lang-sql` 的 `schemaCompletionSource` 实现），不构成阻塞；**本轮不做语言服务**（§4 不做项）。

## 3. 架构设计

### 3.1 档位化对外（避免「哪里都塞重编辑器」）

| 档位 | 组件 | 场景 |
| ---- | ---- | ---- |
| L0 | `UiInput` / `UiTextarea` / `UiSearchInput`（保留不动） | 短文本、表格内联编辑、单行输入 |
| L1 | `UiCodeEditor mode="minimal"` | 取代现有 7 处「行号文本域」：JSON/XML/Base64 面板、hosts、HTTP Body、展示页 |
| L2 | `UiCodeEditor`（`mode="full"`，默认） | SQL 编辑器、SSH 远程文件编辑、任意配置文件编辑 |
| L3 | `UiCodeDiff` | 乐观锁冲突、格式化前后对比 |

`readonly` 模式即「查看器」，用于取代 `CodeViewer.vue`。

### 3.2 目录结构

```
src/core/ui/
├── UiCodeEditor.vue            # 唯一对外可编辑组件（含 readonly 查看器模式）
├── UiCodeDiff.vue              # diff 视图（基于 @codemirror/merge）
├── index.ts                    # 追加导出（UiCodeEditor / UiCodeDiff）
└── editor/
    ├── useCodeEditor.ts        # 生命周期 + Compartment 热重配置 + 命令式 API
    ├── extensions.ts           # 基础能力集组装
    ├── keymap.ts               # 快捷键（与全局 Ctrl+W / Ctrl+Tab 协调）
    ├── languages.ts            # 扩展名 / 文件名 / 首行特征 → 语言 id + 懒加载
    ├── theme.ts                # 唯一主题源（HighlightStyle + --cm-* 变量）
    ├── searchPanel.ts          # 中文查找替换面板（自绘 UI + CM6 搜索命令）
    ├── format.ts               # JSON / XML 复用现有纯函数，SQL 走 sql-formatter
    ├── lint.ts                 # JSON / XML 校验（复用现有解析器）
    ├── completion.ts           # 补全源注入接口 + 词法兜底
    ├── status.ts               # 状态栏数据（行列 / 选中 / 语言 / 缩进 / 长度）
    └── *.test.ts               # 纯函数单测（语言识别 / 格式化 / 状态文本 / 大文件判定）
```

**红线**：`UiCodeEditor.vue` ≤ 250 行，逻辑一律外置到 `editor/`；每个 `editor/*.ts` ≤ 300 行。

### 3.3 组件契约（冻结，开发时以此为准）

```ts
// props

language?: EditorLanguageId | 'auto'   // 默认 'auto'（按 filename 推断）

readonly?: boolean                     // 默认 false
placeholder?: string

foldGutter?: boolean                   // 默认 full 下 true

tabSize?: number                       // 默认 2
height?: string                        // 默认 'auto'（撑满父容器）；数字字符串则固定高度
autoGrow?: boolean                     // 默认 false；true 时随内容增高，上限 maxHeight
maxHeight?: string

// expose（命令式 API）
```

### 3.4 语言识别（`languages.ts`）

- 映射表：扩展名（`.json/.jsonc/.xml/.html/.svg/.yaml/.yml/.toml/.ini/.conf/.sh/.bash/.py/.js/.ts/.css/.md/.sql/.properties`）+ 特例文件名（`Dockerfile`、`Makefile`、`.env`、`hosts`、`nginx.conf`、`.gitignore`、`*.service`、`authorized_keys`）。
- 懒加载走 `@codemirror/language-data`（100+ 语言，含经 `@codemirror/legacy-modes` 提供的 shell / nginx / toml / ini / dockerfile）；`await lang.load()` 后经 `Compartment` 重配置。
- 未知类型 → 纯文本（不高亮、不报错），绝不抛异常。
- 加载期间先渲染纯文本，加载完成再重配置（不阻塞输入，不重建 EditorView）。

### 3.5 主题（`theme.ts`，唯一源）

- 一份 `HighlightStyle.define`，色值全部引用 `main.css` 已有变量 `--cm-keyword/--cm-property/--cm-string/--cm-number/--cm-tag/--cm-punct/--cm-comment`；**补齐缺口 token**：`typeName/variableName/function(definition)/className/link/heading/strong/emphasis/strikethrough/invalid/meta`。
- 明暗跟随：高亮与容器色走 CSS 变量（`.dark` 切换无需重配置）；仅编辑器基础颜色用 `Compartment` 重配置。
- 迁移后**删除** `CodeViewer.vue` 与 `EditorDialog.vue` 各自的 `HighlightStyle`，以及 `sqlEditorThemes.ts` 中的重复部分（SQL 专属增量保留为 `plugins/database/sqlTheme.ts`，仅覆盖 SQL 需要的差异）。
- 新增/调整 CSS 变量必须同步 `DESIGN.md`（tokens 单一事实源），禁止在组件内新造色值。

### 3.6 基础扩展集（`extensions.ts`）

`lineNumbers`、`highlightActiveLine` + `highlightActiveLineGutter`、`highlightSelectionMatches`、`history` + `historyKeymap`、`defaultKeymap`、`indentWithTab`、`indentOnInput`、`bracketMatching`、`closeBrackets` + `closeBracketsKeymap`、`foldGutter` + `foldKeymap`、`drawSelection`、`dropCursor`、`rectangularSelection` + `crosshairCursor`、`EditorState.allowMultipleSelections`、`EditorView.lineWrapping`（按 prop）、`EditorState.tabSize`（按 prop，用 Compartment）、`highlightSpecialChars`、`scrollPastEnd`（full 模式）、`syntaxHighlighting(theme)`、`search`。

`mode="minimal"` 时：只保留 行号 / 历史 / 基础 keymap / 缩进 / 高亮（不装折叠、补全、搜索面板、状态栏、括号自动闭合可留）。

### 3.7 快捷键（`keymap.ts`）与全局冲突

| 键 | 行为 |
| -- | ---- |
| `Ctrl+F` | 打开中文查找面板（编辑器内实现；**必须 `preventDefault` 并拦截**，否则走 WebView2 自身查找） |
| `Ctrl+H` | 打开替换 |
| `Ctrl+S` | `emit('save')` + `preventDefault`（否则 WebView2 会触发页面保存） |
| `Ctrl+/` | 注释切换（`toggleComment`） |
| `Alt+↑/↓` | 上/下移动行；`Shift+Alt+↑/↓` 复制行（`@codemirror/commands`） |
| `Ctrl+D` | 选中下一个相同词（多光标）；优先用 `@codemirror/search` 的 `selectNextOccurrence`，**开发时对着 `node_modules/@codemirror/search/dist/index.d.ts` 核实导出名**，若无则自实现 |
| `Tab` / `Shift+Tab` | 缩进 / 反缩进（`indentWithTab`）；`Esc` 关闭查找面板并归还焦点 |

**全局快捷键已占用**：`Ctrl+W`（关页签）、`Ctrl(Shift)+Tab`（切页签），均在 `ToolWorkspace.vue`；编辑器聚焦时不得抢占，也不得被它们吞掉编辑器自身的 `Ctrl+F`。

### 3.8 查找替换 / 格式化 / 校验 / 补全

- **查找替换**（`searchPanel.ts`）：自绘中文面板（与项目 UI 一致），底层用 `@codemirror/search` 的 `SearchQuery` / `setSearchQuery` / `findNext` / `findPrevious` / `replaceNext` / `replaceAll` / `openSearchPanel` / `closeSearchPanel` / `searchPanelOpen`（开发时核对导出名）。元素：输入框（150ms 防抖）、计数 `n/total`、上一个/下一个、Aa（大小写）、`.*`（正则）、替换输入框、「替换」「全部替换」、关闭。配色取 DESIGN tokens。
- **格式化**（`format.ts`）：JSON / XML **复用现有纯函数**（来自 `plugins/format-tools/JsonPanel.vue`、`XmlPanel.vue` 的解析与宽松回退逻辑，需下沉到 `core/ui/editor/format.ts` 或 `core/format/`，两处共用）；SQL 用 `sql-formatter`（**动态 import**，仅点击格式化时加载）。格式化失败 → `emit('error')`，由上层 toast，禁止静默。
- **校验**（`lint.ts`）：JSON 用 `@codemirror/lang-json` 的 `jsonParseLinter()`（开发时核实导出名）；XML 复用现有 DOMParser 校验；SQL 只做括号配对与未闭合引号检查（不引 SQL 语法解析器）。错误行波浪线 + hover 中文提示。
- **补全**（`completion.ts`）：暴露注入接口 `CompletionSource = (ctx: CompletionContext) => CompletionResult | null`；SQL 场景由 `plugins/database/sqlEditorExtensions.ts` 现有 `schemaCompletionSource` + `keywordCompletionSource` + snippet 注入；通用兜底为当前文档词法补全。

### 3.9 diff（`UiCodeDiff.vue`，基于 `@codemirror/merge`）

- 只读双栏 / 内联两种展示（`mergeView` / `unifiedMergeView` / `acceptChunk` 视需求取舍，开发时核对 API）。
- 使用场景：SSH 远程文件保存时的乐观锁冲突对比、格式化前后对比。
- 组件不参与编辑保存，纯展示 + 折叠块统计（新增/删除行数）。

### 3.10 状态栏（`status.ts`）

展示：`行:列`、选中字符数、语言名（中文映射）、缩进（`空格: 2` / `Tab`）、总行数、字符数、编码（固定 UTF-8）。`readonly` 时隐藏选中项。样式用小号 caption，颜色取 muted token。

### 3.11 性能与「低占用」硬措施

| 措施 | 规则 |
| ---- | ---- |
| 语言懒加载 | 未打开的语言不进内存；`language-data` 的动态 `load()` 保证 Vite 按语言 code-split |
| 隐藏页签不渲染 | 页签容器用 `v-show` 保活时，编辑器在重新变为可见时调 `view.requestMeasure()`；条件允许时优先 `v-if`（不保活编辑器实例） |
| 大文件降级 | `doc.length > 524288`（512KB）→ 关闭语法高亮 / 折叠 / 补全 / 选区匹配，保留纯编辑；`> 5242880`（5MB）→ 强制只读 + `emit('error')` 提示 |
| 不重建 EditorView | 明暗、语言、只读、tabSize、换行切换一律用 `Compartment.reconfigure` |
| 无 worker / 无 eval | 不引入任何 worker，符合 Tauri 默认 CSP |
| 单实例复用 | 同一时刻只创建可见页签的编辑器；切换页签不销毁也不新建（保活由容器决定） |

### 3.12 其他实现要点

- **v-model 回写循环**：`EditorView.updateListener` 中仅当 `view.state.doc.toString() !== props.modelValue` 才 `emit('update:modelValue')`；`setValue()` 带标志位避免把程序性变更当用户编辑。
- **中文输入法**：不得在 `input`/`change` 回调里做值归一化或重建内容（会打断 IME 组合）。
- **右键菜单**：不调用原生菜单（Windows 端已由 `lib.rs` 的 `SetAreDefaultContextMenusEnabled(false)` 封禁）；`domEventHandlers.contextmenu` 抛 `emit('contextmenu')`，由调用方挂项目 `ContextMenu`（复制/粘贴/全选/格式化/跳转行）。
- **i18n**：面板与提示文案中文，走现有 i18n 基建（`zh-CN` 默认）。
- **未保存提示**：`dirty` 由上层用 `change` 对比基线判断（组件只提供 `isDirty()`）。

### 3.13 测试策略

- **纯函数全测**（happy-dom 可跑）：语言识别（扩展名/特例文件名/未知回退）、格式化（JSON/XML 合法与非法输入）、大文件判定阈值、状态文本拼装、diff 统计。
- **组件级**：CM6 依赖真实 DOM 测量，happy-dom 下不测交互；做「挂载不报错 + props 变化不崩 + 只读生效」的最小冒烟。
- **视觉与交互验收**：`plugins/component-lab/` 新增 showcase 页（替换现有 `DatabaseWorkbenchShowcase` 里的旧编辑器展示），做一次全功能走查。
- **性能实测**：dev 下用 1 万行 / 10 万行 / 5MB 文本各测一次，记录渲染耗时与内存（`pnpm build` 前后对比 `dist` 体积）。

## 7. 风险与坑（开发时逐条验）

| 风险 | 对策 |
| ---- | ---- |
| v-model 回写死循环 / 光标跳动 | 值比对 + 标志位（§3.12） |
| 明暗或语言切换丢历史与滚动位置 | 一律 `Compartment.reconfigure`，禁止重建 EditorView |
| 隐藏页签恢复后测量为 0、编辑器塌陷 | 恢复可见时 `view.requestMeasure()` |
| `Ctrl+F` 被 WebView2 自身查找抢走 | 编辑器 keymap 里 `preventDefault` 并返回 `true`（拦截） |
| `Ctrl+S` 触发 WebView2 页面保存 | 同上，必须 `preventDefault` |
| IME 中文输入被打断 | 不在编辑回调中改写内容 |
| 超大文件卡死 WebView2 | 512KB / 5MB 两级降级 |
| 语言包按需加载后样式错乱 | 加载完成后重配置高亮 Compartment（不重建 view） |
| 主题变量与 `DESIGN.md` 脱节 | 新增/修改 `--cm-*` 必须同步 `DESIGN.md` |
| `sql-formatter` 体积超预期 | 动态 import + 实测；超标则改自研缩进式格式化 |
| 迁移破坏现有工具行为 | 批 3 每迁一处立即跑该工具的 dev 手测（JSON/XML/Base64、hosts、HTTP、SQL、SSH 编辑） |

### 批 1 实测记录（2026-09-11，真实 Chromium + vite dev）

测量方式：临时页挂载 `UiCodeEditor` 渲染 N 行 JSON，`performance.now()` 计同步创建与首帧可见（双 rAF）；`performance.memory` 仅作量级参考（GC 波动大，不写入结论）。

| 场景 | 同步创建 | 首帧可见 | DOM 行数 |
| --- | --- | --- | --- |
| 1 万行 · full · 冷启动（含模块解析，dev 未压缩） | 65.1ms | 123.2ms | 36 |
| 1 万行 · full · 热态 | 11.8ms | **15.4ms** | 36 |
| 1 万行 · minimal · 热态 | 5.2ms | **9.3ms** | 36 |
| 10 万行 · full · 热态 | 32.7ms | **38.1ms** | 36 |

**结论**：性能目标达成（热态 1 万行 15.4ms，目标 < 100ms）。1 万行与 10 万行都只挂 36 个 `.cm-line` 节点——CM6 只渲染视口，DOM 与内存不随行数线性增长。冷启动首帧 123ms 主因是 dev 未压缩的模块解析，生产构建更快；若要让首次交互更短，可在打开编辑器前预热 `@codemirror/view`。

**打包体积（批 1 收口）**：
- 修正前 `vendor-editor` 1,650.76KB（gzip **572.36KB**）：`vite.config.ts` 的 `manualChunks` 把 `@codemirror/**` 全量并入，语言包被迫随身携带；
- 修正后 `vendor-editor` 415.02KB（gzip **134.84KB**），语言包各自成 chunk（如 `erlang-*.js` 8.10KB）按需加载；
- 手段：`manualChunks` 白名单化（只有 state / view / commands / language / search / autocomplete + lezer 基础包进 vendor-editor），并把 `@codemirror/language-data` 也改成动态 import。
