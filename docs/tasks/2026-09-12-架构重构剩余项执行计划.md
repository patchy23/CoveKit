## 3. 每项的执行纪律

1. 一次只做一项；做完立刻跑该风险层门禁并单独提交，只 `git add` 本项文件，不 `git add -A`。
2. 动 Rust → `cargo fmt` + 相关测试 + `clippy --all-targets -- -D warnings`；动前端 → `pnpm test/lint/build/format:check` + `check:deps`；动持久化/凭证/注册 → 加旧数据夹具与故障恢复用例。
3. 改 `tauri.conf.json`、插件注册、`Cargo.toml`、能力权限 → 提交前冷启动冒烟（本轮实测方式：直接跑 `src-tauri/target/debug/patchybox.exe`，存活 12 秒且无 panic 输出）。
4. 每项完成即在 `TODO.md` 勾掉对应条目，并在本文件该项标注完成提交。
5. 不新增功能；行为不确定的地方先把现状固化成特征测试再动。
