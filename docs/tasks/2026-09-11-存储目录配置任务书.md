## 1. 背景与现状

当前所有运行时数据都写死在 `app_data_dir()` 下（Windows：`%APPDATA%\com.patchy23.patchybox\`），无任何配置项、无 UI、无迁移能力。用户无法把数据放到别的盘（例如把 C 盘占用挪到 D 盘），也无法统一管理日志与缓存。

已核实的落盘点（8 处，均在 Rust 侧直接调用 `app.path().app_data_dir()`）：

| # | 位置 | 产物 |
| - | ---- | ---- |
| 1 | `framework/store.rs:45-52` | `<plugin>.db`（所有插件的 SQLite 库：ssh.db、database.db、dns.db、hosts.db…） |
| 2 | `framework/vault/store.rs:49` | `vault.dat`（凭证密文）+ `vault-master.key`（keyring 不可用时的降级 key） |
| 3 | `framework/credentials.rs:48,69` | `credentials-master.key` + `credentials/<namespace>.enc` |
| 4 | `plugins/ssh/host_keys.rs:17` | `ssh-known-hosts` |
| 5 | `plugins/database/agent/manager.rs:31` | `agents/drivers/<key>/`（JDBC agent 与 jar） |
| 6 | `plugins/database/secrets.rs:36` | 数据库插件凭证文件 |
| 7 | `plugins/tts/mod.rs:28` | `tts/<ts>.mp3`（语音缓存） |
| 8 | 各插件临时文件（`std::env::temp_dir()`） | hosts 写入脚本、SSH 上传下载临时文件等 |

> 第 8 类走系统临时目录，**不在本次范围**（易失数据，系统清理无副作用）。

另：全局设置存 `tauri-plugin-store` 的 `settings.json`（`framework/settings.rs`，key `app`），**不在 app_data_dir 内** —— 这一点是方案能成立的前提，见 §3.1。

## 2. 目标与非目标

### 目标

1. 一个全局配置项：数据根目录（默认 `app_data_dir`，可改成任意可写目录）。
2. 目录内按用途分区：数据 / 日志 / 缓存 / 凭证，便于用户理解与备份。
3. 迁移能力：把现有内容搬到新根目录，**校验通过才切换**，失败不破坏现有数据。
4. 设置页可视化：当前路径、修改、迁移、恢复默认。
5. SSH 会话日志等新功能直接消费该配置（见 `docs/plugins/ssh/2026-09-11-扩展任务书.md` §5）。

### 非目标（本轮不做）

- 云端同步、多设备共享目录、多根目录并存。
- 自动按容量/时间清理缓存（另开）。
- 混合盘符的跨卷符号链接方案（迁移即物理复制）。

## 3. 设计

### 3.1 配置存放位置（自举安全）

配置**不能存在被迁移的目录里**（否则第一句就是鸡生蛋）。`tauri-plugin-store` 的 `settings.json` 落在 `app_config_dir`（与 `app_data_dir` 不同目录），因此：

- 新增设置项 `app.storageRoot`（字符串，空 = 用默认 `app_data_dir`）。
- **实现前必须验证的第一件事**：确认 `settings.json` 的实际路径不在 `app_data_dir` 下（`framework/settings.rs` 用的是 `app.store("settings.json")`，需实测确认落点），若在，则改用 `app_config_dir()/storage.json` 承载该配置。

### 3.2 目录布局

```
<storageRoot>/                 （默认 %APPDATA%\com.patchy23.patchybox）
├── data/                      # 插件 SQLite：<plugin>.db、ssh-known-hosts、credentials/、secrets
├── vault/                     # vault.dat、vault-master.key（降级 key）
├── logs/                      # logs/ssh/（会话日志）、logs/app/（应用日志，若后续加）
├── cache/                     # cache/agents/（JDBC agent）、cache/tts/（语音缓存）
```

- **默认根目录的现状结构保持不变**（`<plugin>.db` 直接在根下），避免升级时老用户数据"搬家"：新布局只对**自定义根目录**生效？→ 不采用，会导致两套布局逻辑。**采用统一布局 + 一次性内部迁移**：首次启动新版本时，若检测到旧布局（根下直接有 `*.db`），自动搬到 `data/` 子目录（同盘 rename，失败则复制+校验），记录 `layoutVersion` 防止重复搬。
- 迁移后旧路径保留不删（除自动布局迁移的 rename 外），由用户在设置页显式清理。

### 3.3 统一路径入口

新建 `src-tauri/src/framework/paths.rs`，所有落盘路径必须经此模块（禁止任何插件手拼路径，与 `plugin_db_path` 现有约定一致）：

```rust
pub fn storage_root(app: &AppHandle) -> Result<PathBuf, String>   // 读配置，空则 app_data_dir
pub fn data_dir(app: &AppHandle) -> Result<PathBuf, String>       // <root>/data
pub fn logs_dir(app: &AppHandle) -> Result<PathBuf, String>       // <root>/logs
pub fn logs_dir_for(app: &AppHandle, scope: &str) -> Result<PathBuf, String>  // <root>/logs/<scope>
pub fn cache_dir(app: &AppHandle, scope: &str) -> Result<PathBuf, String>     // <root>/cache/<scope>
pub fn vault_dir(app: &AppHandle) -> Result<PathBuf, String>      // <root>/vault
```

改造 §1 表格中除第 8 类以外的全部调用点（`plugin_db_path` 改走 `data_dir`）。

### 3.4 迁移流程

设置页引导式四步，任一步失败即中止且**不写配置**：

1. **预检**：目标目录存在性/可写性（写探针文件后删除）、剩余空间 ≥ 当前数据体积 × 1.2、目标目录非空时提示「将合并/覆盖」并要求确认。
2. **前置约束**：要求**断开所有 SSH 连接、关闭其他工具页签**（避免迁移中仍有写操作）；建议在迁移前提示重启应用以确保无残留句柄。
3. **复制 + 校验**：
   - 按 §3.2 结构逐文件复制（保留相对路径）。
   - 校验：文件数量与总字节数一致、每个 `.db` 跑 `PRAGMA quick_check`、`vault.dat` 能用现有主密钥解密自检（`framework/vault/store.rs` 已有解密路径可复用）。
   - 校验失败 → 删除本次复制产物 + 报错原因。
4. **切换**：写 `app.storageRoot` → 提示「已切换，需重启生效」→ 提供重启按钮（Tauri `app.restart()`）。

### 3.5 生效策略

**重启生效**（不做热切换）：避免所有已打开的 SQLite 连接、Vault 句柄、终端日志句柄在运行中被换路径。设置页文案明确写「重启后生效」，并给一键重启按钮。

### 3.6 UI（设置页）

新增「存储位置」卡片（`src/features/settings/`，与现有卡片同风格）：

| 元素 | 说明 |
| ---- | ---- |
| 当前路径 | 只读显示 `storage_root`；默认时标注「默认位置」 |
| 修改 | `dialog.open({ directory: true })` 选目录 → 弹迁移确认（显示体积、目标路径、风险说明） |
| 恢复默认 | 切回 `app_data_dir`，同样走 §3.4 迁移流程 |
| 打开目录 | `opener.revealItemInDir` |
| 状态区 | 迁移进度（复制字节数）、错误行、重启按钮 |

## 4. 风险与对策

| 风险 | 对策 |
| ---- | ---- |
| 迁移中仍有进程写数据 | 迁移前强制断开连接 + 提示重启后迁移；复制阶段对每个文件做大小/哈希复核 |
| Vault 主密钥在 keyring、密文在新目录 | 一起迁移即可（keyring 存的只是 key，路径无关）；迁移后解密自检作为校验项 |
| 目标目录不可写（Windows 权限/只读盘） | 预检写探针；错误信息含完整路径与人话原因 |
| 用户把根目录设到网络盘/U 盘，拔出后应用报错 | 路径解析失败时**降级回默认目录并 toast 提示**，不崩溃（`storage_root` 需检查可用性） |
| 老用户升级后布局变化导致数据"消失" | 自动布局迁移（同盘 rename 优先）+ 首次启动提示「数据已迁移到 data 子目录」 |
| 配置丢失（settings.json 损坏） | 回落默认目录；不静默删除任何数据 |

## 5. 验收

1. 默认状态下行为与现状完全一致（路径、文件、数据无损）。
2. 迁移到新目录后重启：服务器列表、凭证（Vault）、目录书签、数据库连接、TTS 缓存、known_hosts 全部可用。
3. 迁移中途失败（可用只读目录模拟）：配置不变、原数据完好、有明确错误提示。
4. 把根目录指向不可用路径（如拔掉的 U 盘）：应用正常启动并降级到默认目录 + 提示。
5. `pnpm test` / `cargo test` 覆盖路径解析与迁移校验的纯函数；`pnpm tauri dev` 冷启动无 panic。
6. 文档更新：`docs/02-architecture.md` 补「存储布局」一节，`docs/03-plugin-development.md` 补「禁止手拼路径，统一走 `framework::paths`」。
