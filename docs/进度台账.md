## 三、开工前必做（用户 2026-09-13 定）

**大任务必须先出两份文档并获用户确认，才允许动代码**：

1. **任务书** —— 做什么：范围、产出清单、验收标准、明确不做什么、约束与红线
2. **实现方案** —— 怎么做：技术路线与取舍、改动面（逐文件／逐模块）、实施步骤与批次划分、风险与回退

**小任务直接改**（读代码 → 改 → 跑门禁 → 提交）。

档位及已有授权的处理只见[工作流](standards/10-AI开发工作流.md)，不按文件数量自动升级。

**落盘位置**：批次目录 `docs/batches/<批次号>/`，文件名 `任务书.md` / `实现方案.md`（或 `执行计划.md`）。

## 四、维护规则

- **开工前**：读TODO裁决，再搜索本表当前批次及前置，按工作流定档。
- **收尾时**：先提交实现，再用独立记录提交更新台账与证据，不要求同一提交自填hash：
  1. 更新对应行的「状态」与「证据」列，只引用已存在的实现提交；有完整证据才标✅
  2. 状态从 ⬜ → 🔶／✅ 时，「未完成」列写清剩什么
  3. 新增批次 / 新任务书 → 在台账加行
- **禁止**：把没做的事写成 ✅；把「结构完成」与「行为验收完成」混为一谈；用「基本完成」这类无判据措辞
- **自动校验**：check_progress检查批次文件覆盖、严格状态、已完成提交证据存在；子项表证据可由父批次及说明承载。语义与验收真实性需人工复核，链接和预算由独立文档检查处理，命令见20验证矩阵。
