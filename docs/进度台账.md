## 三、开工前必做（用户 2026-09-13 定）

**大任务必须先出两份文档并获用户确认，才允许动代码**：

1. **任务书** —— 做什么：范围、产出清单、验收标准、明确不做什么、约束与红线
2. **实现方案** —— 怎么做：技术路线与取舍、改动面（逐文件／逐模块）、实施步骤与批次划分、风险与回退

**小任务直接改**（读代码 → 改 → 跑门禁 → 提交）。

档位判据见 [`docs/standards/10-AI开发工作流.md`](standards/10-AI开发工作流.md)：**S3 框架级 / S4 新工具 → 必须先任务书 + 实现方案**；S1 小改直接改；S2 大修复先出根因分析，若改动跨模块或多文件则升级为任务书。

**落盘位置**：批次目录 `docs/batches/<批次号>/`，文件名 `任务书.md` / `实现方案.md`（或 `执行计划.md`）。

## 四、维护规则

- **开工前**：读本文 → 认领批次（新建或并入）→ 按上节定档决定是否先出文档
- **收尾时**（提交同一批次的代码时一并提交本文）：
  1. 更新对应行的「状态」与「证据」列，提交号必须是**本次真实的提交号**
  2. 状态从 ⬜ → 🔶／✅ 时，「未完成」列写清剩什么
  3. 新增批次 / 新任务书 → 在台账加行
- **禁止**：把没做的事写成 ✅；把「结构完成」与「行为验收完成」混为一谈；用「基本完成」这类无判据措辞
- **自动校验**：`python scripts/check_progress.py` —— 扫描 `docs/batches/` 下全部任务书／方案类文档，任何一份没进台账就报错（防漂移）
