## 1. 文档约定

### 1.1 状态标记

| 标记 | 含义 |
|---|---|
| `已实现` | 当前代码中已经存在主要闭环，后续仅做修复或体验完善 |
| `需完善` | 已有界面或后端能力，但存在明显缺口，不能视为最终形态 |
| `规划` | 建议新增，尚未在当前代码中实现 |
| `冻结` | 保留现有能力，但不继续扩大功能边界 |
| `不做` | 明确排除，防止项目重新变成无法维护的工具堆积 |

### 1.2 优先级

| 优先级 | 定义 |
|---|---|
| P0 | 安全、数据完整性、现有核心能力可靠性；未完成前不建议公开发布 |
| P1 | 能建立 patchyBox 差异化价值的核心能力，应作为下一主版本重点 |
| P2 | 明显改善日常使用效率，但不阻塞核心版本发布 |
| P3 | 锦上添花、生态或长期探索项，有真实需求后再实施 |

### 1.3 需求编号

- `CORE-*`：应用框架与通用体验。
- `VAULT-*`：凭证和敏感数据。
- `SSH-*`：SSH 远程管理。
- `NET-*`：网络诊断。
- `HTTP-*`：HTTP/WebSocket 调试。
- `DNS-*`：DNS 查询与云解析。
- `HOSTS-*`：Hosts 管理。
- `DATA-*`：格式、编码与文本数据工具。
- `TTS-*`：文字转语音。
- `DB-*`：数据库工作台。
- `SETTINGS-*`：应用设置。
- `SYS-*`：本机系统工具。
- `REL-*`：发布、性能、安全与可维护性。

## 2. 产品定位

### 2.1 一句话定位

**patchyBox 是一款本地优先、低资源占用，面向开发者和个人服务器维护者的桌面工作台，用一个 Tauri 应用覆盖高频的远程运维、网络排障、接口调试和数据处理操作。**

这里的关键词不是“工具数量最多”，而是：

1. 高频能力随开随用，不必同时启动多个 Java/Electron 工具。
2. SSH 是旗舰入口，围绕一台服务器完成终端、文件、监控、服务、进程、Docker 和网络排障。
3. 数据本地优先，不登录也能完整使用；后期用户可选择通过云账户同步配置、凭证和使用习惯，本期不上传数据。
4. 工具彼此独立，但可以通过受控的“发送到……”意图进行联动。
5. 每项能力只覆盖个人日常最常用的 80%，不复制完整的 Postman、DataGrip、FinalShell 或运维平台。

### 2.2 目标用户

第一目标用户是作者本人，兼顾后续开源用户：

- 日常需要连接若干 Linux 服务器的开发者。
- 需要临时查询 DNS、修改 Hosts、验证 HTTP 接口的后端或全栈开发者。
- 希望减少常驻应用数量和内存占用的个人开发者。
- 有自己的服务器和域名，但不需要企业级堡垒机、CMDB、团队权限系统的个人站长。

### 2.3 核心使用场景

1. 按全局快捷键唤起 patchyBox，连接服务器并进入终端。
2. 在同一个服务器连接内检查负载、文件、systemd 服务、进程和 Docker 容器。
3. 输入域名或 URL，一次完成 DNS、TCP、TLS、HTTP 链路定位。
4. 修改云 DNS 记录后立即在多个公共 DNS 上验证传播结果。
5. 从 HTTP 响应把 JSON 发送到格式转换，从网络诊断结果把主机发送到 SSH。
6. 临时进行 JSON/XML/YAML、时间戳、编码、JWT、哈希等确定性转换。

### 2.4 明确不做

以下方向在没有新的强需求前不进入路线图：

- 不做 Agent，不在 patchyBox 中实现依赖 LLM 语义理解的大批量文件生成或转换中心。
- 本期不做云端账号与实际云同步，但它们属于后期个人多地同步规划；现在先做本地导入导出及同步数据接口预留。团队协作和权限审批仍不做。
- 不做完整数据库 IDE，不继续追逐更多数据库方言和 DBA 管理功能。
- 不做完整 API 协作平台，不实现团队工作区、云 Mock、在线文档和云测试执行器。
- 不与 patchyDoc 强耦合；未来若出现“打开文档”等需求，只走公开 URL 或独立插件。
- 不为了填满分类而添加低价值小工具；图片分类在没有真实工具时应隐藏。
- 不允许插件直接 import 其他业务插件，也不允许通过共享数据库形成隐式耦合。

## 3. 当前代码基线

### 3.1 已有应用框架

当前项目已经具备一套成熟骨架，不应重写：

- Tauri 2 + Vue 3 + TypeScript + Rust。
- 自定义标题栏、最小化、最大化、关闭到托盘和单实例唤起。
- 200px 分类侧栏、66px 顶栏、工具库首页和多工具页签。
- 工具页签使用 `v-show` 保持状态，过多页签自动收纳进溢出菜单。
- 工具注册表、分类、模糊搜索、收藏、最近使用。
- 浅色、深色和跟随系统主题。
- 全局快捷键、开机自启、默认下载目录、工具级设置 schema。
- 前后端同名插件边界、IPC 命令注册表和插件独立 SQLite 迁移骨架。
- Vault 凭证库、系统 keyring 主密钥、AES-256-GCM、本地加密导入导出。

### 3.2 当前工具盘点

| 工具 | 当前主要能力 | 结论 |
|---|---|---|
| SSH 远程管理 | 多连接页签、xterm 终端、远程文件、监控、systemd、进程、Docker | `需完善`，应作为旗舰模块继续投入 |
| HTTP/WS 调试 | 请求构建、响应预览、WS 会话、接口保存 | `需完善`，保留轻量定位，不复制 Postman |
| 数据库 | 9 类连接声明、SQL、元数据、表数据、Redis、历史、收藏、部分管理操作 | `冻结`，规模已经过大，只做收尾 |
| DNS | 多服务器查询、阿里云和 DNSPod 解析管理 | `需完善`，重点补凭证安全、变更历史和联动 |
| Hosts | 列表/源文件编辑、语法校验、UAC 保存、自动备份 | `需完善`，增加方案和恢复能力 |
| 格式转换 | JSON、XML、时间戳、Base64 | `需完善`，可扩充高频确定性数据工具 |
| 文字转语音 | Edge TTS、音色、语速、音调、播放、MP3 下载 | `需完善`，低优先级完善隐私和长文本体验 |
| 组件实验室 | 公共组件交互验收 | `内部工具`，正式构建不应展示给普通用户 |

### 3.3 当前最重要的技术债

1. Vault 已存在，但没有真正成为各插件的统一敏感数据入口。
2. SSH 仍通过 `ssh_credential_get` 把明文凭证返回前端，再由前端传给 `ssh_connect`。
3. DNS 的 AccessKey/SecretId/SecretKey 当前明文存入 `dns.db`。
4. 数据库有独立秘密存储，没有统一使用 Vault。
5. Vault 的引用计数目前恒为 0，删除凭证不能准确提示受影响连接。
6. 工具页签只保留当前进程生命周期，应用重启后没有可控的工作区恢复策略。
7. 文件传输、TTS、数据库导出等长任务没有统一任务中心。
8. 插件之间没有正式的联动协议，未来若直接互相 import 会破坏现有插件边界。
9. 部分文档中的阶段状态已经落后于代码，后续以本需求文档和实际代码为准。

### 4.3 首页

#### CORE-001 首页卡片排序（P0）

- 默认排序：手动置顶顺序 > 收藏 > 最近使用 > 工具名称。
- 首次安装的推荐顺序：SSH、网络诊断、HTTP/WS、DNS、Hosts、格式转换、TTS、数据库。
- 数据库卡片增加“维护模式”或“实验性”弱标签，不用“热门”标签。

- 没有任何工具的分类不在侧栏显示，避免长期存在空的“图片工具”。

卡片保留现有名称、描述、标签和收藏按钮，并增加：

- 最近使用时间，如“10 分钟前使用”。
- 有未完成任务时显示进度点，如“2 个传输中”。
- 有活动连接时显示状态，如“SSH：2 个连接”。

#### CORE-002 首页快速继续（P1）

首页顶部“最近使用”下方增加“继续工作”横条，只展示可恢复的上下文：

- 最近 SSH 服务器：点击后先选中配置，不默认自动连接；用户再次点击“连接”才产生外部连接。
- 最近 HTTP 请求：恢复草稿，但不自动发送。
- 最近 DNS 查询：恢复域名和记录类型，但不自动查询。
- 不恢复密码明文、SSH 终端内容、WebSocket 会话和数据库在线连接。

### 4.4 工具页签

#### CORE-003 页签行为（P0）

- 新页签追加在当前页签右侧，不再固定插到首页后的第二位。
- 页签右键菜单包含：关闭、关闭其他、关闭右侧、固定页签。
- 有未保存内容时展示灰色状态点，关闭前弹确认。
- 有活动连接时展示绿色状态点；连接异常展示红点；后台任务展示旋转状态。
- `Ctrl+W` 关闭当前工具页签，`Ctrl+Tab` / `Ctrl+Shift+Tab` 切换。
- 应用重启只恢复“打开了哪些工具”和安全草稿，不自动恢复网络连接或重新执行操作。

#### CORE-004 工具生命周期（P0）

每个插件 manifest 增加可选生命周期：

```ts
interface ToolLifecycle {
  canClose?: () => boolean | Promise<boolean>
  serializeDraft?: () => unknown
  restoreDraft?: (draft: unknown) => void
  dispose?: () => void | Promise<void>
}
```

- 关闭 SSH 页签时释放全部 SSH、SFTP、日志和监控任务。
- 关闭 HTTP 页签时关闭全部 WS 会话。
- 关闭数据库页签时取消查询并断开连接。
- 应用退出前统一执行 `dispose`，超时 3 秒后强制退出并记录诊断日志。

### 4.7 跨工具联动

#### CORE-007 Tool Intent（P1）

插件仍然彼此隔离，通过框架级意图总线通信：

```ts
interface ToolIntent<T = unknown> {
  id: string
  sourceToolId: string
  targetToolId: string
  action: string
  payload: T
  createdAt: number
}
```

框架提供 `openToolWithIntent(targetToolId, intent)`：打开目标页签并把一次性意图投递给目标插件。目标插件不活动时保留；消费后删除；不写入跨插件数据库。

首批联动：

| 来源 | 操作 | 目标与效果 |
|---|---|---|
| DNS 查询结果 | “用此主机连接 SSH” | 打开 SSH 添加配置，预填 host，不预填凭证 |
| DNS 查询结果 | “添加到 Hosts” | 打开 Hosts，预填 IP + 域名草稿，仍需用户保存和 UAC |
| DNS 云记录 | “验证传播” | 切回 DNS 查询并选中多个公共服务器 |
| HTTP URL | “诊断此地址” | 打开网络诊断，预填 URL |
| HTTP 响应 | “格式化响应” | 打开格式转换 JSON/XML 面板并填入内容 |
| SSH 服务器 | “网络诊断” | 打开网络诊断，预填 host 和 SSH 端口 |
| SSH 服务/容器端口 | “用 HTTP 测试” | 打开 HTTP，预填 `http://host:port`，不自动发送 |
| Hosts 条目 | “查询真实 DNS” | 打开 DNS 查询，预填域名 |

所有联动都遵循“预填但不自动执行”，避免一次点击触发连接、修改或外部请求。

## 5. 凭证与敏感数据

### 5.1 目标

Vault 已经实现加密存储和备份机制。下一阶段不是再造存储引擎，而是让所有连接型插件真正只保存 `credentialId`，并让秘密默认不经过前端。

### 5.2 VAULT-001 插件统一接入（P0）

#### 数据边界

- SSH profile 保存 host、port、名称、标签、`credentialId`，不保存密码和私钥。
- DNS provider profile 保存平台、名称、`credentialId`，不保存 AK/SK。
- Database connection 保存地址、库名、选项、`credentialId`，不保存密码。
- HTTP Auth 保存认证方式和 `credentialId`，请求执行时由 Rust 解析并注入 Header。
- `vault_reveal` 只允许在凭证管理页用户主动点击“显示”或“复制”时调用。
- 日志、错误、任务快照和导出文件不得出现密码、私钥、Token、Authorization 和 Cookie 明文。

#### SSH 契约调整

当前流程：前端读取秘密 → 前端传入 `ssh_connect`。

目标流程：前端只传 `profileId` → Rust 读取 profile → Rust 调用 Vault → 建立连接。

建议命令：

- `ssh_profile_list()`。
- `ssh_profile_save({ profile })`。
- `ssh_profile_delete(profileId)`。
- `ssh_connect({ profileId, oneTimeOverrides? })`。
- `ssh_test_connection({ profileDraft, credentialId })`。

退役：`ssh_credential_save/get/delete`。

#### DNS 契约调整

- `dns_provider_list()` 返回平台配置摘要，不返回秘密。
- `dns_provider_save({ id?, name, platform, credentialId })`。
- `dns_provider_test(providerProfileId)`。
- `dns_domains/records/...` 改传 `providerProfileId`。
- 退役会回显秘密的 `dns_config_get/set`。

#### Database 契约调整

- `dbc_connection_save` 的 `password` 改为 `credentialId`。
- `dbc_test` 只传配置和 `credentialId`。
- agent 侧车的启动参数、环境变量和日志都不得携带可恢复秘密。

### 5.3 VAULT-002 存量迁移（P0）

首次升级后按顺序执行：

1. 检测旧 SSH 凭证文件、DNS 明文配置、数据库秘密存储。
2. 先读取并校验旧数据，不立即删除。
3. 写入 Vault 并回读验证。
4. 把对应 profile 更新为 `credentialId`。
5. 整体迁移成功后把旧文件改名为带时间戳的 `.migrated.bak`。
6. 下一次正常启动且用户确认连接可用后，设置页提供“清理旧凭证备份”按钮。
7. 任一步失败则回滚 profile，不允许出现“配置更新了但凭证没写入”的半迁移状态。

迁移完成后显示一次报告：迁移多少条、跳过多少条、失败条目和备份位置。报告不得展示秘密。

### 5.4 VAULT-003 凭证引用与删除（P0）

`reference_count` 不再恒为 0。返回引用明细，而不只是计数：

```ts
interface CredentialReference {
  toolId: 'ssh' | 'dns' | 'database' | 'http-ws'
  profileId: string
  profileName: string
}
```

删除交互：

- 无引用：普通二次确认后删除。
- 有引用：弹窗列出引用方，默认禁用“删除”。
- 用户必须先选择“解除引用并删除”或逐个更换凭证。
- 解除引用后，相关 profile 保留但标记“缺少凭证”，不能连接。

### 5.5 VAULT-004 凭证选择器（P0）

连接表单统一使用 `CredentialPicker`：

- 下拉只显示允许的 credential kind。
- 每项展示名称、类型和掩码摘要。
- 有“新建凭证”按钮，弹窗创建成功后自动选中。
- 有“管理”按钮，跳转到凭证管理并在关闭后刷新列表。
- 选中凭证后不允许在连接表单中显示秘密。
- 提供“一次性凭证”选项：仅在内存中使用，不保存；窗口关闭或连接结束后清除。

### 5.6 VAULT-005 安全说明（P0）

设置页应明确展示：

- 可以防止应用数据目录被直接复制后读取凭证明文。
- 默认不防护已经登录当前系统账号且有同等权限的恶意进程。
- 本期 Vault 不上传云端；导出文件由用户设置的密码加密。后期云凭证同步为独立选择项，预留账户内容密钥与设备 keyring 分离的端到端加密边界，具体协议另行设计。
- 剪贴板复制秘密后，可选在 30 秒后仅当剪贴板仍是该值时清除。

## 6. SSH 远程管理（旗舰模块）

### 6.1 产品目标

SSH 不只是一块终端，而是一台服务器的本地工作区。它要替代作者日常最常打开的 SSH/SFTP/基础运维工具，但不变成堡垒机或自动化运维平台。

### 6.2 主页面布局

#### SSH-001 工作区结构（P0/P1）

```text
┌─服务器列表 220px──┬──────────────────────────────────────────────────────┐
│ 搜索          ＋  │ 生产服务器 ● | 测试机 ● | …                         │
│ [导入 SSH Config] ├──────────────────────────────────────────────────────┤
│ ▾ 生产环境 (3)    │ 终端 | 文件 | 监控 | 服务 | 进程 | Docker | 隧道    │
│   ● 主站          ├──────────────────────────────────────────────────────┤
│   ○ 数据节点      │ 当前功能区                                           │
│ ▾ 测试环境 (2)    │                                                       │
│ ☆ 未分组          │                                                       │
│                   ├──────────────────────────────────────────────────────┤
│ + 添加服务器      │ host · user · 延迟 · 连接时长 · 最近活动             │
└───────────────────┴──────────────────────────────────────────────────────┘
```

调整点：

- 左栏从当前 180px 调整到默认 220px，并允许在 180–360px 间拖拽。
- 顶部为搜索框；`+` 打开新增菜单：添加服务器、导入 OpenSSH Config、从剪贴板识别 SSH 命令。
- 服务器按用户定义分组折叠，未分组置底。
- 列表项显示收藏、名称、`user@host:port`、状态点、最近延迟。
- 单击选中；双击连接；Enter 连接；右键菜单含连接、新窗口连接、编辑、复制 SSH 命令、网络诊断、删除。
- 同一 profile 可建立多个独立连接，沿用当前“名称、名称 2”的页签策略。
- 底部状态栏显示连接目标、握手延迟、连接时长、当前网络状态。

### 6.3 服务器配置

#### SSH-002 新建/编辑服务器（P0）

表单分为三个折叠区：

**基本信息**

- 名称，必填，默认从 host 推断。
- 分组，可新建分组。
- 标签，多选自由输入，如“生产”“国内”“个人”。
- 主机，支持 IPv4、IPv6、域名。
- 端口，默认 22，限制 1–65535。
- 备注。

**认证**

- 凭证选择器，支持密码或 SSH 私钥。
- “新建凭证”在 Vault 中创建，不把秘密保存到 SSH profile。
- “一次性认证”不落盘。
- 用户名以凭证中的用户名为主；若允许 profile 覆盖，界面必须明确显示覆盖关系。

**高级选项**

- 连接超时：3/5/10/30 秒。
- ServerAliveInterval：默认 30 秒；0 表示关闭。
- ServerAliveCountMax：默认 3。
- TCP keepalive：默认开启。
- 压缩：默认关闭。
- 首次进入目录：默认用户 home。
- 终端字符集：UTF-8；其他编码作为 P3。
- 跳板机：选择另一个 SSH profile，P2 实现。
- 代理：不设置 / SOCKS5，P2 实现。

底部按钮：

- `取消`：有修改时确认放弃。
- `测试连接`：执行握手和认证，返回 DNS、TCP、握手、认证各阶段耗时，不创建持久会话。
- `保存`：只保存配置，不自动连接。
- `保存并连接`：保存成功后连接；编辑已有在线 profile 时不影响现有会话，只影响新会话。

### 6.4 主机身份校验

#### SSH-003 known_hosts 与指纹（P0）

首次连接未知主机时必须弹窗：

- 主机和端口。
- 密钥算法。
- SHA256 指纹，可复制。
- `仅本次信任`、`保存并连接`、`取消`三个按钮。

已保存指纹发生变化时：

- 红色阻断弹窗，说明可能是服务器重装，也可能是中间人攻击。
- 显示旧指纹和新指纹。
- 默认按钮为“取消连接”。
- “替换指纹并连接”放在危险操作区，要求再次确认，不允许静默接受。

设置页增加“已知主机”管理：搜索、主机、算法、指纹、首次/最后连接时间、删除记录。

建议后端：

- `ssh_known_host_check(host, port, key)`。
- `ssh_known_host_trust({ host, port, algorithm, fingerprint })`。
- `ssh_known_host_list/delete`。

### 6.5 连接状态与错误

#### SSH-004 分阶段连接（P0）

连接状态必须区分：

`解析主机 → 建立 TCP → SSH 握手 → 校验主机指纹 → 认证 → 打开会话 → 已连接`。

错误使用稳定错误码：

- `DNS_RESOLVE_FAILED`。
- `TCP_TIMEOUT` / `CONNECTION_REFUSED`。
- `HOST_KEY_UNKNOWN` / `HOST_KEY_MISMATCH`。
- `AUTH_FAILED` / `KEY_PASSPHRASE_INVALID`。
- `SSH_PROTOCOL_ERROR`。
- `SESSION_CLOSED`。

错误面板提供：重试、编辑配置、网络诊断、复制详情。详情自动脱敏。

断线策略：

- 意外断线可自动重连，1/2/5/10/30 秒指数退避，最多 5 次。
- 用户主动断开不重连。
- 自动重连成功后新建 PTY；旧终端输出保留并插入“已于 xx:xx 重连”分隔线。
- 有文件传输或远程编辑保存时，不执行空闲自动断开。

### 6.6 终端

#### SSH-005 多终端与工具栏（P1）

连接级“终端”页内增加第二层终端页签：

```text
┌─────────────────────────────────────────────────────────┐
│ Shell 1 × | Shell 2 × | ＋     分屏  搜索  命令  重连  │
├─────────────────────────────────────────────────────────┤
│                                                         │

│                                                         │
├─────────────────────────────────────────────────────────┤

└─────────────────────────────────────────────────────────┘
```

- `+` 新建 PTY；下拉可选普通 Shell、`sudo -i` 提示方式、已保存启动命令。
- 终端页签可重命名、关闭、关闭其他。
- 分屏支持水平/垂直两块，P2；第一版最多 4 个 pane。
- 搜索支持上一项、下一项、区分大小写、正则开关。
- 工具栏保留清空、重连，并增加复制全部、导出当前可见日志。

建议后端继续复用：`ssh_terminal_open/write/resize/close/list` 和事件 `ssh://terminal-data`，新增：

- `ssh_terminal_signal(terminalId, signal)`，用于发送 SIGINT 等明确动作。
- `ssh_terminal_snapshot(terminalId)` 只导出当前缓冲区，不在后端永久记录终端内容。

#### SSH-006 命令片段（P1）

这不是 Agent，也不是复杂编排，只解决重复输入命令。

- 终端右侧可打开 280px“命令片段”抽屉。
- 片段字段：名称、命令、分类、说明、危险级别、变量。

- 危险级别：普通、需要确认、高危；高危命令必须完整预览并再次确认。
- 按钮：插入终端、执行、编辑、复制、收藏。
- “插入终端”只写入但不回车；默认推荐该方式。
- 片段数据保存在 SSH 插件本地库，可导入导出 JSON；不得保存密码变量。

两侧工具栏：

#### SSH-008 远程编辑（P1）

- 状态栏显示编码、换行符、文件大小和是否已修改。
- 支持 UTF-8；检测非 UTF-8 时以只读方式打开并说明原因，其他编码 P3。

- `ssh_file_mkdir`。
- `ssh_file_stat`。
- `ssh_file_chmod`（P2，明确确认）。

### 6.8 监控

#### SSH-009 真实采样与短期曲线（P1）

页面分三部分：

1. 顶部 CPU、内存、根分区、负载四张摘要卡。
2. 中部 CPU/内存、网络上下载速率两张最近 10 分钟折线图。
3. 底部磁盘分区表、网络接口表和系统信息。

要求：

- 当前网络累计值必须改成连续采样差值，输出真实 B/s。
- 采样间隔默认 2 秒，可选 1/2/5/10 秒。
- 只有页面可见且连接在线时采样；切走后停止定时器。
- 前端只保留最近 300 点，不落盘，不做长期监控平台。
- 单次获取失败不清空图表；连续 3 次失败显示“采样中断”和重试按钮。
- 显示 Linux 发行版、内核、运行时长、CPU 核数、主机名。

建议后端由 `ssh_monitor_get` 扩展为 `ssh_monitor_snapshot`，返回前后采样可计算字段；或由后端按 connection 维护上一采样值并直接给出速率。

#### SSH-010 systemd 服务（P1）

- 保留全部/运行中/已停止/失败筛选，增加名称搜索。
- 表头显示服务名、描述、状态、自启、最近状态变化、操作。

- 日志支持暂停滚动、清空显示、搜索、复制、下载；关闭弹窗立即停止后台任务。

#### SSH-011 进程（P1）

- 保留搜索和 CPU/内存/PID 排序，增加自动刷新开关和刷新间隔。
- 点击行打开详情抽屉：完整命令、父 PID、启动时间、工作目录（能获取时）、打开端口（P2）。

#### SSH-012 Docker（P1）

- 保留列表、筛选、启停重启、删除、日志和容器终端。
- 增加容器健康状态、CPU/内存快照、重启策略和完整端口映射。

- 日志与 systemd 共用统一增量日志查看器。
- 容器终端先探测 `/bin/bash`，失败回退 `/bin/sh`，并允许用户选择。

### 6.10 SSH 隧道

#### SSH-013 隧道管理（P1，旗舰新增）

这是比继续扩数据库更有价值的新能力。

页面：连接内新增“隧道”页签。

| 列 | 内容 |
|---|---|
| 名称 | 用户自定义名称 |
| 类型 | 本地转发 / 远程转发 / SOCKS5 |
| 监听 | 本地或远端监听地址和端口 |
| 目标 | 目标 host:port；SOCKS 无固定目标 |
| 状态 | 已停止、启动中、运行中、异常 |
| 流量 | 当前连接数、上传、下载 |
| 操作 | 启动/停止、编辑、复制地址、删除 |

顶部按钮：`+ 新建隧道`、`全部启动`、`全部停止`、`仅看运行中`。

新建表单：

- 名称。
- 类型：Local `-L`、Remote `-R`、Dynamic `-D`。
- 监听地址，默认本地 `127.0.0.1`，不默认暴露 `0.0.0.0`。
- 监听端口，保存前检测端口占用。
- 目标主机和端口。
- 建立 SSH 连接后自动启动开关，默认关闭。
- 断线恢复后自动重建开关，默认开启。

安全要求：

- 监听 `0.0.0.0` 或 `::` 时显示橙色警告和额外确认。
- 远程转发明确说明是否依赖服务端 `GatewayPorts`。
- 隧道失败展示监听端冲突、远端拒绝、SSH 断开等具体原因。

建议命令和事件：

- `ssh_tunnel_list(connectionId)`。
- `ssh_tunnel_start({ connectionId, config })`。
- `ssh_tunnel_stop(tunnelId)`。
- `ssh_tunnel_delete(tunnelId)`。
- `ssh://tunnel-status`、`ssh://tunnel-traffic`。

### 6.11 OpenSSH 配置导入

#### SSH-014 导入与导出（P1）

- 支持选择 `~/.ssh/config` 或用户指定文件。
- 预览 Host、HostName、Port、User、IdentityFile、ProxyJump。
- `Host *` 只作为默认值合并，不创建服务器条目。
- 通配符 Host 默认不导入，显示原因。
- IdentityFile 只在用户确认后读取并保存到 Vault；不把路径内容悄悄复制。
- 已存在的 host/port/user 组合提示覆盖、跳过或另存。
- 导出时只导出非秘密 profile；私钥不写入普通 JSON。
- 支持复制标准 `ssh user@host -p port` 命令。

## 7. 网络诊断（建议新增）

### 7.1 定位

网络诊断是 SSH、DNS 和 HTTP 之间缺失的一环。它是确定性程序能力，不需要 Agent，且能让现有三个工具形成一条完整排障链。

### 7.2 页面布局

#### NET-001 一键链路诊断（P1）

```text
┌──────────────────────────────────────────────────────────────────┐
│ 目标 [https://example.com:8443/path________] [开始诊断] [停止] │
│ 预设：URL / 主机+端口 / SSH 服务器                 [导出报告] │
├─────────────────┬────────────────────────────────────────────────┤
│ 最近目标        │ ① DNS       12 ms   1.2.3.4                   │
│ example.com     │ ② TCP       28 ms   已连接                    │
│ api.example.com │ ③ TLS       41 ms   有效至 2026-12-01         │
│ 192.168.1.10:22 │ ④ HTTP      89 ms   200 OK                    │
│                 │ ⑤ 路由追踪   可选                              │
├─────────────────┴────────────────────────────────────────────────┤
│ 详情：阶段日志 / 解析记录 / 证书链 / 响应头 / 路由节点          │
└──────────────────────────────────────────────────────────────────┘
```

目标输入规则：

- URL：自动提取协议、host、port 和 path。
- `host:port`：执行 DNS（如需要）和 TCP。
- 纯 host/IP：默认执行 DNS/Ping；可选择端口。
- SSH 联动传入 profile 时展示 profile 名称，但不读取 SSH 凭证。

开始后按阶段显示：等待、进行中、成功、警告、失败、跳过。某阶段失败不一定阻止后续可独立执行的阶段。

### 7.3 诊断能力

#### NET-002 DNS 阶段（P1）

- 系统 DNS 解析 A/AAAA。
- 展示 CNAME 链、最终地址和耗时。
- “在 DNS 工具中详细比较”按钮投递 Tool Intent。

#### NET-003 连通性阶段（P1）

- ICMP Ping：次数 4，展示丢包、最小/平均/最大延迟；权限不允许时说明并继续 TCP。
- TCP connect：目标端口、超时、建立耗时和错误码。
- 可并行检查一组常用端口，但上限 20 个，不做网段扫描器。
- “本机端口被占用”时联动本机端口查看器。

#### NET-004 TLS 证书（P1）

- SNI、TLS 版本、cipher suite。
- 证书主题、SAN、签发者、序列号、SHA256 指纹。
- 生效/过期时间和剩余天数。
- 证书链是否完整、主机名是否匹配、系统是否信任。
- 剩余小于 30 天显示警告，已过期显示失败。
- 支持复制 PEM 和导出证书信息，不保存私钥。

#### NET-005 HTTP 阶段（P1）

- 默认 HEAD；服务不支持时提示可改 GET，不自动下载大响应体。
- 展示状态、重定向链、最终 URL、响应头、首字节和总耗时。
- “在 HTTP 调试中打开”按钮预填请求，不自动发送。

#### NET-006 路由追踪（P2）

- Windows 使用系统兼容实现或后端原生探测，macOS/Linux 使用对应能力。
- 逐跳显示序号、IP、反向域名、三次延迟和超时。
- 支持取消；最长 30 跳；不会阻塞整个 Tauri 命令线程。

### 7.4 后端交互

长诊断使用任务 + 事件，不使用一个超长阻塞 invoke：

- `net_diagnosis_start({ target, options }) -> { taskId }`。
- `net_diagnosis_cancel(taskId)`。
- `net_tcp_probe({ host, ports, timeoutMs })`。
- `net_tls_inspect({ host, port, serverName })`。
- `net_trace_start({ host, maxHops })`。
- `net://diagnosis-stage` 推送阶段结果。
- `net://trace-hop` 推送每一跳。

诊断报告导出为 Markdown 或 JSON，默认隐藏本机用户名、内网接口和代理认证信息。

## 8. HTTP / WebSocket 调试

### 8.1 边界

目标是覆盖“临时调接口和保存个人常用请求”，不是完整 Postman。第一版不做团队同步、Mock Server、复杂测试集合和云 Runner。

### 8.2 页面布局

#### HTTP-001 请求工作区（P1）

```text
┌─集合 260px────────┬──────────────────────────────────────────────────┐
│ 环境 [本地 ▼]     │ [GET ▼] [https://api..._______________] [发送] │
│ + 新建            │ [保存] [另存] [导入 cURL] [更多…]              │
│ ▾ 我的接口        ├──────────────────────────────────────────────────┤
│   ▾ 用户          │ Params | Auth | Headers | Body | Settings        │
│     获取用户      ├──────────────────────────────────────────────────┤
│ 历史记录          │ 请求编辑区                                       │
│                   ├──────────────────────────────────────────────────┤
│                   │ Body | Preview | Headers | Cookies | Timing      │
│                   │ 响应区                                           │
└───────────────────┴──────────────────────────────────────────────────┘
```

左栏：

- 顶部环境选择器和管理按钮。
- `+ 新建`菜单：请求、WebSocket、集合、文件夹。
- 树支持拖动排序、重命名、复制、删除；删除必须确认。
- “历史记录”按日期分组，默认保留 200 条，可在设置调整或关闭。
- 当前接口有未保存修改时显示灰点。

请求行：

- 方法、URL、发送/取消、保存、另存、导入 cURL。
- `Ctrl+Enter` 发送，发送中按钮变为“取消”。
- URL 支持环境变量 `{{baseUrl}}`，未解析变量在发送前阻止并列出。
- 下拉历史显示最近输入 URL。

### 8.3 请求构建

#### HTTP-002 Params 与 Headers（P1）

- 键值行包含启用框、key、value、说明和删除按钮。
- 最后一行输入后自动增加空行。
- 支持批量编辑模式：粘贴 query string 或 header 文本并解析。
- 重复 Header 被保留，不转成 map 丢失顺序。
- 变量值在 UI 中显示解析预览；秘密变量只显示掩码。

#### HTTP-003 Auth 与 Vault（P0/P1）

认证类型：None、Basic、Bearer、API Key。

- Basic 选择 `password` 凭证。
- Bearer 选择 `api-token` 凭证。
- API Key 配置注入 Header 或 Query，并选择自定义凭证字段。
- 前端保存 `credentialId`，Rust 发送请求前解析并注入；Authorization 不回传前端日志。
- 请求导出为 cURL 时，默认使用 `${TOKEN}` 占位；用户主动选择“包含秘密”时再次确认，且只复制到剪贴板，不落盘。

#### HTTP-004 Body（P1）

模式：None、JSON、Text、XML、Form URL Encoded、Multipart Form Data、Binary File。

- JSON/XML 提供格式化和语法错误行列提示。
- Form 表格与 Params 一致。
- Multipart 支持 Text/File 行，文件仅保存路径引用；文件不存在时阻止发送。
- Binary File 展示路径、大小、MIME 和清除按钮。
- 超过 10 MiB 的请求体由 Rust 流式读取，前端不把整个文件转字符串过 IPC。

#### HTTP-005 请求设置（P1）

- 超时：默认 30 秒。
- 自动跟随重定向，默认开启，最多 10 次。
- TLS 证书校验，默认开启；关闭时显示持续警告，不全局记住到生产环境。
- 系统代理 / 不使用代理 / 自定义代理。
- 响应体上限，默认 20 MiB；超过后只保存到临时文件并提示下载。

### 8.4 响应区

#### HTTP-006 响应查看（P1）

页签：Body、Preview、Headers、Cookies、Timing。

- Body：Pretty/Raw，JSON 折叠树、搜索、复制、保存到文件、发送到格式转换。
- Preview：图片、HTML 沙箱预览、音频；不在主 WebView 直接执行返回 HTML 脚本。
- Headers：按响应跳转阶段分组，重复 header 不丢失。
- Cookies：名称、域、Path、Expires、Secure、HttpOnly、SameSite。
- Timing：DNS、TCP、TLS、请求发送、TTFB、下载、总耗时；后端无法细分的阶段显示“不可用”，不伪造。
- 元信息固定显示状态码、总耗时、响应大小和完成时间。
- 二进制响应不强制 UTF-8 解码，提供十六进制摘要和保存按钮。

#### HTTP-007 cURL 导入导出（P1）

- 支持常用 `curl -X/-H/-d/--data-raw/--form/-u`。
- 导入先展示解析预览；无法识别的参数列为警告，不静默丢弃。
- 导出默认进行 shell 安全转义。
- Windows 可选择 PowerShell 或 Bash 格式。

### 8.5 WebSocket

#### HTTP-008 WS 体验（P1）

- 使用与 HTTP 一致的 URL、环境变量、Headers 和 Auth。
- 状态：未连接、连接中、已连接、正在关闭、已断开、错误。
- 消息区支持文本、JSON、Binary 摘要；JSON 自动 Pretty。
- 发送模式：Text、JSON、Binary File。
- 消息可收藏为模板、重新发送、复制、保存。
- 可配置自动 Ping 间隔和重连策略，默认均关闭。
- 消息数量上限可配置，默认 500；超限丢弃最早消息并展示提示。
- 后端从当前 300ms `ws_recv` 轮询升级为 `ws://message` 事件推送；页面关闭立即释放会话。

建议后端命令：

- 保留 `http_request`，扩展为可取消 task，或增加 `http_request_start/cancel`。
- `http_download_response(responseId, path)`。
- `ws_connect/send/close/sessions`。
- 退役轮询型 `ws_recv`，改用事件推送。


- 服务商 profile、域名、动作。
- 操作前完整记录和操作后目标值。
- 时间、结果、平台请求 ID、脱敏错误。

“变更历史”从解析管理右上角打开抽屉：

- 按域名、动作、成功/失败筛选。
- 修改和删除成功后提供“恢复为操作前状态”。
- 恢复仍然是一次新的变更，需确认，不篡改历史。
- 无法原样恢复的平台字段明确提示并打开编辑表单。

#### DNS-005 传播验证（P1）

- 新增/修改成功后 toast 提供“立即验证”按钮。
- 跳转到 DNS 查询，预填域名、类型和多个公共服务器。
- 展示目标值与各服务器当前值是否一致。
- 可手动刷新；不在后台无限轮询。

## 11. 格式与数据工具

### 11.1 边界

这里适合做确定、可复现、可离线的转换。不会接入 LLM 猜测文件含义，也不做复杂批量文档生产。

### 11.2 页面结构

#### DATA-001 数据工作台（P1/P2）

将当前“格式转换”扩展为以下子页签，并继续用 `v-show` 保留各页输入：

1. JSON。
2. XML。
3. YAML/TOML（P2）。
4. 时间戳。
5. 编码（Base64、URL、Hex）。
6. JWT。
7. 哈希/校验和。
8. 文本对比（P2）。
9. 正则测试（P2）。

顶部通用按钮：从剪贴板粘贴、打开文件、交换左右、复制结果、保存结果、清空。打开文件默认限制 20 MiB，超限提示改用专用工具。

### 11.3 JSON

#### DATA-002 JSON（P1）

- 左输入、右输出，保留行号。
- 按钮：格式化、压缩、校验、转义、反转义、复制、保存。
- 缩进使用现有全局工具设置 2 空格/4 空格/Tab。
- 错误显示行、列、附近片段，并能点击定位。
- 可选排序对象 key；默认关闭，避免无意改变字段顺序。
- JSONPath 查询作为 P2：底部输入表达式，高亮并输出匹配结果。
- 不做“智能修复后直接覆盖”；可提供修复建议，但必须展示差异并由用户确认。

### 11.4 XML / YAML / TOML

#### DATA-003 结构化格式（P2）

- XML：格式化、压缩、校验、XML ↔ JSON。
- YAML：格式化、校验、YAML ↔ JSON。
- TOML：格式化、校验、TOML ↔ JSON。
- 转换前说明可能丢失注释、锚点、属性顺序或类型信息。
- 默认不在错误输入上强行转换。

### 11.5 编码与时间

#### DATA-004 编码（P1）

- Base64 文本编码/解码，支持标准和 URL-safe。
- URL encode/decode，可选择整体或 Query Component。
- UTF-8 文本 ↔ Hex。
- 自动识别只用于推荐操作，不自动修改输入。
- 解码失败显示明确原因和非法位置。

#### DATA-005 时间戳（P1）

- 秒/毫秒/微秒时间戳和日期时间互转。
- 当前时间实时刷新，可暂停和复制。
- 时区选择：本地、UTC、固定 UTC offset；IANA 时区 P2。
- 支持 ISO 8601、RFC 3339 和自定义常用格式。
- 展示相对时间，如“3 小时前”，但复制仍使用精确值。

### 11.6 JWT 与哈希

#### DATA-006 JWT 查看器（P1）

- 三段输入自动拆分 Header/Payload/Signature。
- Header 和 Payload 只做 Base64URL 解码与 JSON 展示。
- 展示 `exp/nbf/iat` 的本地时间和是否过期。
- 明确警告：“解码不等于验签”。
- P2 支持使用用户临时输入的 HMAC secret 或公钥验签；秘密不默认保存。
- 不提供伪造生产 Token 的一键功能。

#### DATA-007 哈希/校验和（P1）

- 文本或文件输入。
- 算法：MD5（兼容用途并标记不安全）、SHA-1（标记不安全）、SHA-256、SHA-512、BLAKE3。
- 文件使用 Rust 流式读取并通过任务事件显示进度，避免大文件进入前端内存。
- 支持输入期望 hash 后比较，成功/失败明显展示。
- 按钮：计算、停止、复制、保存 checksum 文件。

### 11.7 文本对比与正则

#### DATA-008 文本对比（P2）

- 左右双栏输入，下方或中央展示行级 diff。
- 忽略空白、忽略大小写、只显示差异开关。
- 支持复制 unified diff、保存 `.patch`。
- 仅处理文本，不承担目录同步或 Git 客户端职责。

#### DATA-009 正则测试（P2）

- 正则、flags、测试文本、替换模板四区。
- 实时高亮匹配，展示捕获组和匹配数量。
- 防止灾难性回溯卡死：放入 Worker 或后端带超时执行。
- 明确当前使用的正则引擎及与 JavaScript/Rust 的差异。

## 13. 数据库工作台：冻结范围

### 13.1 决策

数据库当前已经包含 MySQL/PolarDB、PostgreSQL、SQLite、Redis 原生驱动和 Oracle/Vastbase/Kingbase agent 路径，且前后端代码规模很大。该模块不应再作为 patchyBox 的竞争主线。

原则：**保留已实现能力，完成安全和可靠性收尾，然后进入维护模式。**

### 13.2 保留范围

- 保存、测试、连接、断开连接。
- 对象树和表结构查看。
- SQL 编辑、执行、取消、结果表格和 CSV 导出。
- 查询历史和收藏。
- 表数据分页只读查看。
- Redis key 浏览和查看。
- 已存在的建库、DDL、索引、表管理能力只修 bug，不继续扩展。

### 13.3 DB-001 发布前收尾（P0）

- 全部连接凭证迁移 Vault。
- Dameng 后端未实现前从可选连接类型中隐藏，避免创建必然失败的配置。
- agent 驱动不可用时在选择数据库类型时立即显示依赖状态和安装说明。
- 连接列表明确显示开发/测试/生产环境标签。
- 生产连接默认只读；关闭只读必须在表单中主动选择。
- 每次执行前由后端识别是否为潜在写操作；只读连接直接阻止。
- `DROP/TRUNCATE/DELETE without WHERE/ALTER` 等高危 SQL 显示确认摘要；不能仅靠字符串前缀判断，允许保守误报但不能静默放过明显高危操作。
- 查询取消必须真实中断或明确说明“仅停止等待，服务端仍可能执行”，不得假装取消成功。
- 结果截断时展示上限和“已截断”，导出不能只导出当前已截断结果而不提示。
- 连接、查询、导出失败都使用稳定错误码和可复制详情。

### 13.4 DB-002 维护模式 UI（P1）

- 工具卡显示“维护模式”。
- 设置中允许隐藏数据库工具；隐藏不删除配置。
- 首次打开提示支持范围，并声明不是 DataGrip/Navicat 的替代品。
- 右侧摘要默认可折叠，记住宽度和开关状态。
- 后台不可见时不轮询连接和对象树。

### 13.5 明确不新增

- 不新增更多数据库类型。
- 不做 ER 图、数据建模、数据库迁移、结构同步。
- 不做完整数据编辑器、批量数据修复和 DBA 监控。
- 不做 SSH 隧道内置于数据库模块；需要时选择 SSH 模块创建的本地隧道，再连接本地端口。
- 不做团队共享连接；个人云凭证同步属于后期账户规划，当前只预留数据与密钥接口。

## 16. 插件框架增量设计

### 16.1 Manifest 扩展

建议在现有 `ToolManifest` 上增加可选字段：

```ts
interface ToolManifest {
  // 现有字段省略
  visibility?: 'public' | 'developer' | 'experimental'
  order?: number
  capabilities?: string[]
  acceptedIntents?: string[]
  providedCommands?: ToolCommand[]
  lifecycle?: ToolLifecycle
}
```

- `visibility` 控制组件实验室、数据库实验标签等。
- `order` 用于默认排序，不在首页组件写死。
- `providedCommands` 自动进入 `Ctrl+K`。
- `acceptedIntents` 由框架校验，不接受的 intent 不投递。

### 16.2 IPC 规范

- 命令名继续使用插件前缀。
- 所有长操作必须可取消，并用事件或任务快照报告进度。
- 统一错误结构：`code`、`message`、`detail?`、`retryable`、`source`。
- 前端显示 `message`，详情抽屉展示已脱敏 `detail`。
- 不再混用“抛异常”和 `{ ok: false }` 两套业务失败语义；新命令统一 Rust `Result<T, IpcError>`。
- 密钥、Authorization、Cookie、私钥不得作为普通返回值。
- 事件订阅必须返回取消函数，组件卸载时释放。
- Rust 端会话和任务都必须带所有者 tool instance id，防止同一工具多实例误清理。

### 16.3 插件数据

- 每个插件只访问自己的 SQLite 文件。
- profile 数据从 localStorage 逐步迁移到插件数据库；localStorage 仅保留轻 UI 偏好。
- 所有 schema 通过 `PRAGMA user_version` 顺序迁移。
- 跨插件关联只存稳定 ID 或通过框架意图即时传递，不直接查询其他插件数据库。
- 用户删除 profile 时，先关闭关联会话和任务，再删除数据；失败则不删除一半。

### 16.4 统一日志

- 默认日志级别 Info；发布构建不打印秘密或完整请求体。
- 每条日志包含时间、插件、操作、会话/任务 ID、错误码。
- 日志按大小滚动，默认最多 5 × 5 MiB。
- Authorization、Cookie、password、token、secret、private key 和自定义秘密字段统一脱敏。
- UI toast 只用于简短结果；可恢复失败同时进入通知/任务详情。

## 17. 非功能需求

### 17.1 性能

- Windows 冷启动到首页可交互目标：2 秒内；热启动目标：1 秒内。
- 首页静置 30 秒后 CPU 目标低于 1%。
- 首页无活动连接时内存目标低于 150 MiB；开启多个 xterm 后按实际测量建立回归基线。
- 隐藏工具页签停止无必要轮询；保留连接不等于持续刷新所有子页面。
- 大文件、文件哈希、下载和导出必须流式处理，不能完整复制进 JS 内存。
- SQLite 写入放在短事务中，不能持锁跨网络 await。

### 17.2 安全

- 默认 CSP 保持最小范围；新增网络能力通过 Rust 发起，不随意扩大 WebView `connect-src`。
- 禁止引入通用 shell 插件；系统命令由固定参数的 Rust 适配器执行。
- Hosts 提权继续使用最小范围一次性助手，应用本体不常驻管理员。
- 所有删除、强杀、停止服务、覆盖文件、修改 DNS 等危险操作使用统一确认等级。
- 首次连接 SSH 必须校验 host key。
- TLS 校验默认开启；忽略证书只对当前请求生效。
- 导出配置默认排除秘密；包含秘密必须使用 Vault 加密格式。

### 17.3 稳定性

- 网络命令都有超时和取消。
- 应用关闭、工具页签关闭、连接页签关闭都验证后端资源释放。
- SQLite 迁移失败不得继续用不完整 schema 运行。
- 文件覆盖使用临时文件 + 原子替换；能保留备份的场景必须保留。
- 断网、休眠恢复、服务器主动断开和 WebView 重载都应有测试。

### 17.4 可访问性与交互

- 所有图标按钮有可见 tooltip 和 `aria-label`。
- 键盘可以完成页签、列表、菜单、弹窗和主要表单操作。
- 焦点不会被 Teleport 弹窗丢失；关闭后回到触发按钮。
- 不只用颜色表达在线/错误状态，同时有文字或图标。
- 破坏性按钮使用统一 danger 样式；默认焦点不放在危险确认按钮。

### 17.5 国际化

- 当前只正式支持简体中文。
- 英文语言包未完成前设置项禁用并标注“开发中”。
- 新文案禁止直接散落在 Rust 错误字符串中作为唯一用户文案；Rust 返回稳定错误码，前端翻译。

| 图片小工具填充分类 | 不明确 | 低 | 中 | 暂不做 |
| 云账户/同步 | 多地登录同步个人配置、凭证、使用习惯 | 高 | 高 | 后期规划；本期做本地导入导出与接口预留 |

## 20. 测试与验收矩阵

### 20.1 通用

- 工具反复打开/关闭 50 次，无后端会话、监听器和定时器持续增长。
- 应用最小化到托盘 30 分钟，无无意义轮询和明显 CPU 占用。
- 深浅主题、900×620 最小窗口和 125%/150% 系统缩放可用。
- 所有弹窗可用 Esc 关闭；危险操作需要明确确认。
- IPC 错误可复制，用户提示不暴露秘密。

### 20.2 Vault

- 同明文多次保存密文不同，均能解密。
- keyring 不可用时降级路径有告警，已有 Vault 不会被静默重置。
- SSH/DNS/Database 存量迁移成功、部分失败、写入中断和回滚均有测试。
- 有引用凭证不能无提示删除。
- 全仓库与运行日志扫描不出现测试密码、私钥片段和 Token。

### 20.3 SSH

- 密码、无密码私钥、有 passphrase 私钥。
- 未知 host key、匹配、变化三种情况。
- IPv4、IPv6、域名、自定义端口。
- 网络断开/恢复、服务端断开、系统休眠恢复。
- 多连接、多终端、快速切换、关闭顺序。
- 大文件、空文件、中文名、深目录、权限失败、传输取消和同名冲突。
- systemd 不存在、Docker 不存在、无权限、命令输出异常。
- 隧道端口占用、断线重建、监听公网地址警告。

### 20.4 HTTP/DNS/Hosts

- HTTP 重定向、超时、无效证书、大响应、二进制、重复 Header、取消。
- WS 文本/JSON/Binary、服务端断开、消息上限、关闭资源。
- DNS 各记录类型、部分服务器超时、平台限流、权限不足、传播不一致。
- Hosts 外部修改冲突、UAC 取消、保存失败、备份恢复、换行符保留。

### 20.5 质量门槛

每个版本至少执行：

- `pnpm run test`。
- `pnpm run lint`。
- `pnpm run build`。
- `cargo test`。
- `cargo fmt --check`。
- `cargo clippy -- -D warnings`。
- `python scripts/check_docs.py`（若脚本仍是项目文档校验入口）。

## 21. 开放决策

以下问题不阻塞 R0，但进入对应版本前需要确认：

1. 侧栏是否新增“远程运维”分类，还是继续把 SSH 放在“网络工具”。
2. SSH 文件管理是否采用完整本地/远端双栏，还是保留远端单栏 + 系统选择器。
3. SSH 终端分屏是 R1 必须项还是延后 P2。
4. 数据库工具是否默认显示，还是新安装默认隐藏为实验工具。
5. 网络诊断是否第一版包含路由追踪，还是先做 DNS/TCP/TLS/HTTP。
6. 格式工具下一批优先 JWT + 文件哈希，还是 YAML/TOML + 文本 diff。
7. 是否正式支持 macOS；当前 bundle 已声明 dmg，但 Hosts、系统进程、端口等能力需要真实设备验收。
8. 开源前是否保留“关闭到托盘”为默认，还是首次启动让用户选择。

## 22. 推荐的下一步

不要同时开始所有规划项。建议立即进入 R0，并把第一个可见功能版本定为“SSH 旗舰版”：

1. 先完成 Vault 接入和 SSH known_hosts，解决公开发布前的安全底线。
2. 再实现全局任务中心，把现有 SFTP 传输接进去。
3. 完成 SSH 双栏文件、真实监控曲线和隧道页。
4. 做网络诊断与 Tool Intent，让 SSH、DNS、HTTP、Hosts 串成排障闭环。
5. 数据库仅穿插安全修复，不再开新功能线。

这样得到的 patchyBox 不会只是“很多小工具放在一个壳里”，而会形成一个清晰特点：**启动轻、数据在本机、以 SSH 为中心，能把个人开发和服务器排障的高频动作留在同一个工作区内完成。**

## 附录 A：当前 IPC 基线与演进方向

此表来自 2026-09-01 代码，实施新需求时用于判断“扩展现有命令”还是“新增命令”。命令的 TypeScript 契约仍应保留在各插件自己的 `contracts.ts` 中。

| 范围 | 当前命令 | 演进要求 |
|---|---|---|
| 框架设置/窗口 | `settings_get`、`settings_set`、`window_toggle`、`window_hide`、`open_external`、`framework_commands` | 保留；设置增加分区不会改变基础读写模式 |
| Vault | `vault_list`、`vault_save`、`vault_delete`、`vault_reveal`、`vault_export`、`vault_import` | 保留；增加真实引用明细；普通插件执行时不得调用 reveal 把秘密送到前端 |
| HTTP | `http_request` | 扩展可取消请求、流式文件和 timing；兼容期保留旧命令 |
| API 保存 | `api_save`、`api_list`、`api_delete` | 升级为集合/文件夹/环境/历史模型后做数据库迁移，不直接破坏旧记录 |
| WebSocket | `ws_connect`、`ws_send`、`ws_recv`、`ws_close`、`ws_sessions` | 保留连接/发送/关闭；`ws_recv` 轮询退役为事件推送 |
| DNS | `dns_query`、`dns_domains`、`dns_records`、`dns_add_record`、`dns_update_record`、`dns_delete_record` | 保留业务动作；参数从平台名切换为 provider profile id |
| DNS 配置 | `dns_config_get`、`dns_config_set` | 完成 Vault 迁移后退役，避免回传明文密钥 |
| Hosts | `hosts_read`、`hosts_save` | 保留；save 增加 expected hash；新增备份列表、恢复和刷新 DNS 缓存 |
| SSH 连接 | `ssh_connect`、`ssh_disconnect`、`ssh_reconnect`、`ssh_connections` | connect/reconnect 改为只传 profile id，由 Rust 解析 Vault |
| SSH 终端 | `ssh_terminal_open/write/resize/close/list` | 保留；增加关闭原因、信号和多终端管理 |
| SSH 文件 | `ssh_file_list/upload/download/delete/rename`、`ssh_edit_open/save` | 保留；接入统一任务，增加 mkdir、stat、取消、冲突检查 |
| SSH 凭证 | `ssh_credential_save/get/delete` | Vault 迁移后全部退役 |
| SSH 运维 | `ssh_monitor_get`、`ssh_service_list/action/logs`、`ssh_process_list/kill`、`ssh_docker_list/action/logs/exec` | 保留；监控改真实采样，日志改增量事件，补充详情能力 |
| Database 连接 | `dbc_connection_save/delete`、`dbc_connections`、`dbc_connect/disconnect/test`、`dbc_driver_status` | 保留；密码参数改 credential id；不再增加方言 |
| Database 查询 | `dbc_execute/cancel`、`dbc_databases/schemas/objects/columns/table_data/export_csv` | 保留并修可靠性、安全提示和真实取消 |
| Database 记录 | `dbc_history/list/add/clear`、`dbc_saved/list/add/update/delete` | 保留；增加数量上限和清理设置即可 |
| Database 管理 | `dbc_charset_options/users/create_database/drop_database/table_admin/table_ddl/table_indexes` | 冻结，只修 bug 和危险操作确认 |
| Redis | `dbc_redis_keys`、`dbc_redis_key_info` | 冻结，只修 bug |
| TTS | `tts_voices`、`tts_synthesize` | 保留单次合成兼容；长文本改为统一任务命令 |

新增插件必须继续在 Rust 的插件总路由中按唯一前缀分派。建议前缀：网络诊断使用 `net_`，统一任务使用框架命令 `task_`，本机端口工具使用 `port_`。新增命令必须进入 IPC 注册表并提供中文说明。
