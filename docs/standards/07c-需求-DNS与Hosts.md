# 07c · DNS 与 Hosts

本文记录现有工具范围，不把多账户管理、变更回滚或跨工具联动等设想作为已实现能力。公共边界见[产品范围](07-产品需求.md#当前有效范围裁决)。

## DNS 查询

支持域名、记录类型与多个 DNS 服务器的查询对比。预设包含系统、阿里 DNS、DNSPod、114、Cloudflare 和 Google；可输入自定义服务器地址。支持的记录类型以 `src/plugins/dns/useDns.ts` 与后端解析器共同维护。

结果展示服务器、耗时、记录与 TTL；失败按服务器分别反馈，不把超时或解析失败显示为空记录成功。复制结果保留记录语义，查询和云记录写入是不同动作。

## 云解析管理

- 已接入阿里云、腾讯云 DNSPod、Cloudflare，支持域名与记录查看、添加、修改和删除。
- 三个平台均支持凭证库引用与手工配置。凭证引用由后端解析，删除引用前通过框架检查使用者。
- 手工 DNS 配置按普通配置处理，可按所选数据集参与传输；需要凭证保护时使用凭证库。具体导出边界见[数据空间](07e-数据空间与导入导出.md)。
- 记录表单校验名称、类型、值与平台所需字段；TTL、线路及代理等能力以服务商契约为准，不能假定各平台一致。
- 删除前确认对象，保存成功后刷新相关记录；平台拒绝、权限不足、网络错误和限流须可感知，不伪造成功。

当前不承诺多服务商账户档案、完整变更审计回滚、传播验证流程或自动联动 Hosts/SSH。新增这些能力需要独立需求。

## Hosts 编辑

提供系统 Hosts 的列表和源文件编辑、语法校验与保存前备份。写系统文件时按需申请平台权限，应用本身不常驻管理员。

保存和重新读取的失败必须保留用户可恢复的输入并说明原因，取消提权不等于写入成功。平台路径与写入方式分别适配，不通过引入 shell 插件绕过边界。

多配置方案、备份历史管理、三方合并和 DNS 缓存刷新不作为现有能力宣传。Windows/macOS 的真实验证范围见[平台能力矩阵](09-平台能力矩阵.md)。
