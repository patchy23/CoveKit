## 9. DNS 查询与云解析

### 9.1 页面结构

保留当前三个一级页签，但把“密钥设置”改为“服务商”：

- DNS 查询。
- 解析管理。
- 服务商。

### 9.2 DNS 查询

#### DNS-001 查询对比（P0/P1）

- 输入域名、记录类型、服务器集合。
- 记录类型：A、AAAA、CNAME、MX、TXT、NS、SRV、CAA、SOA、PTR。
- 服务器预设保留系统、阿里、DNSPod、114、Cloudflare、Google；支持自定义 IP/DoH 作为 P2。
- 点击查询后并行执行；每张结果卡显示服务器、耗时、状态、记录和 TTL。
- 相同答案用相同颜色标识，答案不一致时显示“结果存在差异”。
- CNAME 自动展示链路，但保留原始每一跳。
- 支持复制单条、复制全部为 dig 风格文本、导出 Markdown。
- 最近查询保留 50 条，可关闭记录。

按钮与联动：

- `查询` / `停止`。
- `清空`。
- `添加到 Hosts`：只对 A/AAAA 结果可用。
- `连接 SSH`：预填选中的 IP 或原始域名。
- `网络诊断`。

### 9.3 云解析管理

#### DNS-002 服务商配置（P0）

- 页面展示多个“服务商配置”，而不是全局各一套密钥。
- 字段：显示名称、平台、凭证、备注、最近测试时间、状态。
- 按钮：新增、编辑、测试、设为默认、删除。
- 阿里云与腾讯云继续实现；Cloudflare 只保留 adapter 扩展点，不在没有需求时承诺开发。
- 凭证必须使用 Vault，旧明文配置完成迁移后不再回显。
- 测试按钮只调用最小只读接口，不修改 DNS。

#### DNS-003 域名与记录页（P1）

```text
┌─域名 240px────────┬────────────────────────────────────────────────┐
│ 服务商 [个人阿里] │ example.com              [刷新] [+ 添加记录] │
│ 搜索域名          ├────────────────────────────────────────────────┤
│ example.com       │ 搜索  类型筛选  线路筛选  [验证传播]          │
│ example.net       ├────────────────────────────────────────────────┤
│                   │ RR  类型  线路  值  TTL  状态  更新时间  操作 │
└───────────────────┴────────────────────────────────────────────────┘
```

- 域名分页或增量加载，显示记录数和最后刷新时间。
- 记录支持关键字、类型、线路筛选。
- 添加/编辑表单根据类型校验：
  - A/AAAA 校验 IP。
  - CNAME/NS/MX 校验域名；MX 额外优先级。
  - TXT 保留空格和引号语义。
  - SRV 拆分优先级、权重、端口、目标。
- TTL 使用预设和自定义；保存前显示平台允许范围。
- 删除保留当前二段式确认，并在弹窗展示完整 `RR TYPE VALUE`。
- 若平台支持，增加启用/暂停记录；不支持的平台隐藏按钮而不是报错。

#### DNS-004 变更历史与回滚（P1）

每次新增、修改、删除前，先在本地 `dns.db` 记录：

- 服务商 profile、域名、动作。
- 操作前完整记录和操作后目标值。
- 时间、结果、平台请求 ID、脱敏错误。

“变更历史”从解析管理右上角打开抽屉：

- 按域名、动作、成功/失败筛选。
- 修改和删除成功后提供“恢复为操作前状态”。
- 恢复仍然是一次新的变更，需确认，不篡改历史。
- 无法原样恢复的平台字段明确提示并打开编辑表单。

#### DNS-005 传播验证（P1）

- 新增/修改成功后 toast 提供“立即验证”按钮。
- 跳转到 DNS 查询，预填域名、类型和多个公共服务器。
- 展示目标值与各服务器当前值是否一致。
- 可手动刷新；不在后台无限轮询。

## 10. Hosts 管理

### 10.1 页面布局

#### HOSTS-001 配置方案（P1）

```text
┌─方案 220px────────┬──────────────────────────────────────────────┐
│ 当前系统 Hosts ●  │ [列表方式] [源文件] [差异]                 │
│ 开发环境          ├──────────────────────────────────────────────┤
│ 游戏测试          │ 搜索  + 添加  批量启用  批量禁用            │
│ + 新建方案        │ IP | 主机名 | 注释 | 启用 | 状态 | 操作    │
│                   ├──────────────────────────────────────────────┤
│                   │ [重新读取] [验证] [应用方案（需授权）]      │
└───────────────────┴──────────────────────────────────────────────┘
```

“方案”是本地草稿集合，不直接修改系统：

- 当前系统 Hosts：只读基线，重新读取时刷新。
- 用户方案：可复制当前系统内容后编辑。
- 应用方案时显示与当前系统文件的差异，然后 UAC 保存。
- 方案只存 hosts 内容和说明，不存凭证。

### 10.2 列表与源文件

#### HOSTS-002 列表能力（P1）

- 搜索 IP、域名、注释。
- 新增单条；一个 IP 可对应多个 hostnames。
- 启用/禁用：禁用时保留为带 patchyBox 标记的注释，重新启用可恢复。
- 多选后批量启用、禁用、删除。
- 重复域名、无效 IP、同域名冲突和非法字符实时提示。
- 列表改动同步回源文件；源文件中的普通注释和空行尽量保留。

#### HOSTS-003 保存与恢复（P0/P1）

保存流程：

1. 重新读取系统文件，检测外部修改。
2. 若基线变化，展示三方选择：重新加载、查看差异后合并、取消。
3. 语法校验通过。
4. 创建带时间戳备份。
5. 按需 UAC 覆盖。
6. 回读并验证内容。
7. 可选执行系统 DNS 缓存刷新。

增加“备份历史”抽屉：时间、来源、大小、查看差异、恢复、在资源管理器中显示。默认只保留最近 20 份，清理前不删除当前可恢复的最后一份。

按钮：

- `重新读取`。
- `验证`：只校验，不申请管理员权限。
- `应用方案`。
- `刷新 DNS 缓存`：单独按钮，明确展示即将执行的系统动作。
- `导入` / `导出`。

#### HOSTS-004 验证联动（P1）

每条记录操作菜单：

- 查询真实 DNS。
- TCP 连接测试。
- 用 HTTP 打开（80/443）。
- 复制 `IP hostname`。

联动只预填，不自动产生请求。

建议后端：

- 保留 `hosts_read/hosts_save`。
- 增加 `hosts_backup_list/read/restore`。
- `hosts_flush_dns()`。
- `hosts_save` 增加 `expectedHash` 防止覆盖外部修改。
