# 17 · 文档组织与批次

> 何时读：新增、迁移文档或处理规则冲突。目标是有效知识可发现，不是每次工作都留档。

## 仓库自有与工具中立

长期项目约束、有效决策和必要接续信息在仓库维护。助手配置只放入口与环境适配，不复制独立生效的规则。常规工具失败和临时环境状态不自动升级为规范。

## 权威与分工

用户当前明确指示和适用裁决优先于旧需求。现行规范负责执行方式；活动方案负责范围、重要取舍与接续状态；独立任务书仅在复杂工程确有需要时维护。历史材料中的旧命令、角色要求、默认动作不产生当前执行义务。

| 内容 | 维护位置 |
| --- | --- |
| 不可遗漏边界、请求分流 | AGENTS.md，细节链接对应专题 |
| 活动任务与待办入口 | TODO.md，短摘要和链接，不复制测试与提交串 |
| 任务范围、验收、任务内裁决 | 默认同一份方案；复杂工程拆分时用任务书 |
| 技术方案、下一步、阻塞、重要偏离 | 对应实现方案 |
| 当前架构、产品、模块契约 | standards 与 plugins 对应专题 |
| 长期重要决策理由 | adr，普通选择无需 ADR |
| 人工或真机待验证项 | 待人工验证清单，其他文件引用 |
| 验证命令 | 20-验证矩阵，模板与任务书只补场景 |
| 历史证据 | 已完成批次及 Git；原进度台账冻结为历史索引 |

## 文档身份与落位

现行说明与代码保持一致；活动方案不能冒充现状；历史记录只说明对应时点。批次路径保持稳定，用入口或文首标明身份即可，不为归档机械搬目录。

需要接续或记录重要取舍时默认保留一份方案，复杂工程按需拆分范围与技术设计，见[工作流](10-AI开发工作流.md)。一个目标沿用一个入口，不按会话、消息或提交重复建批次。批次结束后冻结，后续缺陷进入当前修复，不重开旧验收。

## 入库门槛

入库：当前知识、重要决策、有长期价值的方案与必要接续状态、可复现测试及必要夹具、关键发布或安全验收摘要。

默认不入库：原始会话、临时推理、一次性计划、完整命令输出、临时截图、PID/端口/本机进程状态、可直接由 Git 或 CI 得到的重复统计。临时文件放被忽略的 .work/，同时排除出 lint、格式和测试发现；有效裁决不能只留在此处。测试源码、夹具与生成报告的边界见[15](15-测试与走查.md)。记录用环境代号和脱敏路径，不保留秘密。

原始输出优先本地或 CI artifact；需长期保留的关键证据必须有稳定存储或入库摘要，不能依赖即将过期的链接。旧材料先核对有效内容与引用，再提炼或移除，不批量删除决策依据。

## 阅读、更新与迁移

默认入口只有 AGENTS，之后按任务导航。普通文档大小仅提示职责审查，不机械拆分；入口预算是阅读成本保护，不代表语义质量。

只在行为说明失真、有效范围变化、重要决策、阶段完成或交接时更新必要文档。相关说明可以与实现同提交，不要求自填 hash、独立回填提交或收尾报告。

迁移须核对来源、去向与引用，保留有效裁决的日期和适用范围。历史路径可保留，历史正文不必重新套用现行格式。
