# 17 · 文档组织与批次

> **何时读**：新增、迁移文档或处理规则冲突。进度不在本文维护。

## 仓库自有与工具中立

- **手册在仓库，不写进工具侧配置**：项目流程、规范、已知坑与验证方法的权威正文必须保存在本仓库并受版本管理。助手侧skill、全局提示词或工具配置只可保存入口指针及必要的环境适配，不复制或新增独立生效的项目规则；新经验先更新仓库对应文档。换助手、换机器后仍能从AGENTS找到完整规则。
- **工具中立**：常青规则描述任务目标、能力、输入输出、边界和验收，不依赖特定助手的API名称、模型配置、调用上限或上下文继承机制。必要的工具专用操作应标为可选适配示例，注明适用环境，并提供通用做法或不可用时的处理方式；仓库实际使用的构建、测试命令仍保留准确名称。

## 权威与分工

用户当前明确指示及已确认裁决按适用范围优先于旧需求；未解决的实质冲突给出证据再裁决，不按“哪个文件刚读到”决定。

| 信息 | 唯一维护位置 | 其他文件做什么 |
| --- | --- | --- |
| 当前批次状态、下一步、阻塞项 | docs/进度台账.md | 只链接相关批次；批次内可保留带日期的执行证据 |
| 当前范围限制、明确不做和用户裁决 | TODO.md，详细裁决链接批次决策书 | 需求分册顶部提醒先查TODO，不复制一份裁决 |
| 框架/模块事实与契约 | standards对应专题、源码契约 | AGENTS摘要；与源码不符先核对，不能把未实现方案当现状 |
| 流程定档与授权 | 10-AI开发工作流 | 其他手册链接，不重复门禁 |
| 验证命令 | 20-验证矩阵 | 各任务书补场景，不复制过期命令表 |
| 导航 | docs/README.md | 不复制状态列 |
| 跨批次决策理由 | adr/ | 已采纳正文保留，变更由新ADR取代；状态元数据可更新 |

台账的完成状态必须有证据，脚本只能验证结构/路径/提交存在，不能证明实现正确。历史数量、进度只作为带日期快照，不覆盖现行台账。

## 落位

- `docs/standards/`：常青规范，中文标题+两位序号；a/b分册用于按需查阅，templates放任务模板。
- `docs/plugins/<id>/`：当前工具需求、设计和机制说明。
- `docs/batches/<领域>-<YYYYMM>-<三位编号>-<中文简述>/`：任务书、实现方案、决策及验收证据。简述原则上10字内，已有批次保持稳定。
- `docs/adr/`：跨批次重要决策；`docs/releases/`：发布验证。
- 批次子编号AR/T/L/P不改名。小改不强行建批次；大任务两份文档要求见工作流。
- 批次完成后不搬路径、不维护重复当前状态。历史删除须确保裁决依据与恢复入口可追溯，不能因“已完成”自动删除全部证据。

## 渐进披露

入口给“何时读、管什么、下一跳”，复杂专题保留标题定位。允许先列目录、搜索引用、读调用图；限制的是无目的整库正文加载。字符预算仅是跨模型可比代理，不是token估计或语义质量证明。

默认读AGENTS、TODO、工作流、地图；台账按当前批次查询，UI/API细节只读相关章节。新增必读依赖必须计入任务路径成本。详见20的文档命令与四条路径验收。

## 迁移与回填

迁移前列来源/去向/消费方；同步本地链接、锚点和模板路径。历史路径必要时给新入口，不用字符总量相等替代语义核对。
先提交实现，再以独立记录提交引用实现hash；历史裁决记录日期、来源与适用项，不能强求同一提交自填hash。
