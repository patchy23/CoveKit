# 17 · 文档组织与本地任务记录

> 2026-09-18 用户裁决：任务过程只在本地维护，仓库保存长期有效的项目知识。本节取代旧的批次入库规则。

## 仓库自有与工具中立

现行项目规则、架构与契约在仓库维护，不依赖某个助手的配置、会话或本地任务书。助手配置只放入口与环境适配。新克隆仅凭仓库规范和源码就能开展开发；本地记录缺失不要求恢复，也不阻塞任务。

## 权威与分工

用户当前明确指示优先；现行规范约束实现，本地方案辅助接续，历史记录只说明当时情况。不要把方案当作已经实现的事实，也不要把旧任务自动当成执行义务。

| 内容 | 位置与是否跟踪 |
| --- | --- |
| 开发入口、现行产品要求、架构、模块与 IPC 契约、设计规范 | AGENTS、DESIGN、docs/standards 与 docs/plugins，入库 |
| 长期重要决策及必要理由 | docs/adr，入库；普通选择不另建 ADR |
| 使用说明、关键发布或安全结论 | README、CHANGELOG、必要发布摘要，入库 |
| 可复用测试源码、检查器及最小脱敏夹具 | 源码或 scripts，入库 |
| 任务书、实施方案、批次进度、交接与验收待办 | 默认 .work/tasks/，仅本地 |
| 当前任务索引 | 可选的本地 TODO.md，不入库 |
| 历史批次与原人工验证清单 | 原 docs/batches/、docs/待人工验证清单.md 保留本地并忽略 |
| 会话记录、临时分析、输出、截图及生成报告 | .work/ 或忽略的输出目录、CI artifact，不入库 |
| 早期交互原型、想法便笺、一次性竞品调研与本机试作脚本 | 本地草稿或原路径忽略，不入库；采纳的要求提炼到现行规范 |
| 产品实际使用的资源、依赖锁文件、通用开发配置 | 入库；不能仅因可生成或位于隐藏目录就移除 |

`docs/standards/templates/` 是可选的通用模板，模板本身可以入库；由其生成的任务材料必须留在本地。不按会话、消息或提交新建批次，也不强制批次编号。

## 更新与引用

只在规则、接口、用户行为或长期决策发生变化时更新对应现行说明，与实现同提交即可。普通修复的验证结果写提交正文或最终回复，不回填历史任务书，不另交收尾报告。

长期裁决不得只藏在本地计划里：按主题提炼必要条款、日期与适用边界到现行文档，删去过程、阶段编号和逐次验证流水。现行文档不链接仅本地存在的文件；需要说明本地记录位置时使用行内代码并明确其可选。

验证命令只维护在[20](20-验证矩阵.md)，测试取舍见[15](15-测试与走查.md)。链接检查以 Git 跟踪集合判断仓库内引用，不能因为本地仍有被忽略的文件就判为有效。

## 迁移与保留

取消跟踪前先核对有效约束和引用；使用 `git rm --cached -- <明确路径>` 保留工作树文件，再加入忽略规则。不得用普通删除、强制清理或重写历史代替取消跟踪。

删除记录随普通提交进入 Git，推送后才从远程当前版本消失；旧提交仍可追溯，不为过程文档清理改写历史。本地过程记录不由 Git 备份，需要时由用户备份工作目录。
