## 1. 文档约定

### 1.1 状态标记

| 标记 | 含义 |
|---|---|
| `已实现` | 当前代码中已经存在主要闭环，后续仅做修复或体验完善 |
| `需完善` | 已有界面或后端能力，但存在明显缺口，不能视为最终形态 |
| `规划` | 建议新增，尚未在当前代码中实现 |
| `冻结` | 保留现有能力，但不继续扩大功能边界 |
| `不做` | 明确排除，防止项目重新变成无法维护的工具堆积 |

### 1.2 优先级

| 优先级 | 定义 |
|---|---|
| P0 | 安全、数据完整性、现有核心能力可靠性；未完成前不建议公开发布 |
| P1 | 能建立 CoveKit 差异化价值的核心能力，应作为下一主版本重点 |
| P2 | 明显改善日常使用效率，但不阻塞核心版本发布 |
| P3 | 锦上添花、生态或长期探索项，有真实需求后再实施 |

### 1.3 需求编号

- `CORE-*`：应用框架与通用体验。
- `VAULT-*`：凭证和敏感数据。
- `SSH-*`：SSH 远程管理。
- `NET-*`：网络诊断。
- `HTTP-*`：HTTP/WebSocket 调试。
- `DNS-*`：DNS 查询与云解析。
- `HOSTS-*`：Hosts 管理。
- `DATA-*`：格式、编码与文本数据工具。
- `TTS-*`：文字转语音。
- `DB-*`：数据库工作台。
- `SETTINGS-*`：应用设置。
- `SYS-*`：本机系统工具。
- `REL-*`：发布、性能、安全与可维护性。

## 2. 产品定位

### 2.1 一句话定位

**CoveKit 是一款本地优先、低资源占用，面向开发者和个人服务器维护者的桌面工作台，用一个 Tauri 应用覆盖高频的远程运维、网络排障、接口调试和数据处理操作。**

这里的关键词不是“工具数量最多”，而是：

1. 高频能力随开随用，不必同时启动多个 Java/Electron 工具。
2. SSH 是旗舰入口，围绕一台服务器完成终端、文件、监控、服务、进程、Docker 和网络排障。
3. 数据本地优先，不登录也能完整使用；后期用户可选择通过云账户同步配置、凭证和使用习惯，本期不上传数据。
4. 工具彼此独立，但可以通过受控的“发送到……”意图进行联动。
5. 每项能力只覆盖个人日常最常用的 80%，不复制完整的 Postman、DataGrip、FinalShell 或运维平台。

### 2.2 目标用户

第一目标用户是作者本人，兼顾后续开源用户：

- 日常需要连接若干 Linux 服务器的开发者。
- 需要临时查询 DNS、修改 Hosts、验证 HTTP 接口的后端或全栈开发者。
- 希望减少常驻应用数量和内存占用的个人开发者。
- 有自己的服务器和域名，但不需要企业级堡垒机、CMDB、团队权限系统的个人站长。

### 2.3 核心使用场景

1. 启动 CoveKit，连接服务器并进入终端。
2. 在同一个服务器连接内检查负载、文件、systemd 服务、进程和 Docker 容器。
3. 输入域名或 URL，一次完成 DNS、TCP、TLS、HTTP 链路定位。
4. 修改云 DNS 记录后立即在多个公共 DNS 上验证传播结果。
5. 从 HTTP 响应把 JSON 发送到格式转换，从网络诊断结果把主机发送到 SSH。
6. 临时进行 JSON/XML/YAML、时间戳、编码、JWT、哈希等确定性转换。

### 2.4 明确不做

以下方向在没有新的强需求前不进入路线图：

- 不做 Agent，不在 CoveKit 中实现依赖 LLM 语义理解的大批量文件生成或转换中心。
- 本期不做云端账号与实际云同步，但它们属于后期个人多地同步规划；现在先做本地导入导出及同步数据接口预留。团队协作和权限审批仍不做。
- 不做完整数据库 IDE，不继续追逐更多数据库方言和 DBA 管理功能。
- 不做完整 API 协作平台，不实现团队工作区、云 Mock、在线文档和云测试执行器。
- 不与 patchyDoc 强耦合；未来若出现“打开文档”等需求，只走公开 URL 或独立插件。
- 不为了填满分类而添加低价值小工具；图片分类在没有真实工具时应隐藏。
- 不允许插件直接 import 其他业务插件，也不允许通过共享数据库形成隐式耦合。

## 3. 当前代码基线

### 3.1 已有应用框架

当前项目已经具备一套成熟骨架，不应重写：

- Tauri 2 + Vue 3 + TypeScript + Rust。
- 自定义标题栏、最小化、最大化、关闭到托盘和单实例唤起。
- 200px 分类侧栏、66px 顶栏、工具库首页和多工具页签。
- 工具页签使用 `v-show` 保持状态，过多页签自动收纳进溢出菜单。
- 工具注册表、分类、模糊搜索、收藏、最近使用。
- 浅色、深色和跟随系统主题。
- 开机自启、默认下载目录、工具级设置 schema。
- 前后端同名插件边界、IPC 命令注册表和插件独立 SQLite 迁移骨架。
- Vault 凭证库、系统 keyring 主密钥、AES-256-GCM、本地加密导入导出。

### 3.2 当前工具盘点

| 工具 | 当前主要能力 | 结论 |
|---|---|---|
| SSH 远程管理 | 多连接页签、xterm 终端、远程文件、监控、systemd、进程、Docker | `需完善`，应作为旗舰模块继续投入 |
| HTTP/WS 调试 | 请求构建、响应预览、WS 会话、接口保存 | `需完善`，保留轻量定位，不复制 Postman |
| 数据库 | 连接、SQL 会话、类型化结果、表编辑、CSV、Redis、文档与历史 | 按开发测试范围完善，详见数据工具第 13 节 |
| DNS | 多服务器查询、阿里云和 DNSPod 解析管理 | `需完善`，重点补凭证安全、变更历史和联动 |
| Hosts | 列表/源文件编辑、语法校验、UAC 保存、自动备份 | `需完善`，增加方案和恢复能力 |
| 格式转换 | JSON、XML、时间戳、Base64 | `需完善`，可扩充高频确定性数据工具 |
| 文字转语音 | Edge TTS、音色、语速、音调、播放、MP3 下载 | `需完善`，低优先级完善隐私和长文本体验 |
| 组件实验室 | 公共组件交互验收 | `内部工具`，正式构建不应展示给普通用户 |

### 3.3 当前最重要的技术债

1. Vault 已存在，但没有真正成为各插件的统一敏感数据入口。
2. SSH 仍通过 `ssh_credential_get` 把明文凭证返回前端，再由前端传给 `ssh_connect`。
3. DNS 的 AccessKey/SecretId/SecretKey 当前明文存入 `dns.db`。
4. 数据库有独立秘密存储，没有统一使用 Vault。
5. Vault 的引用计数目前恒为 0，删除凭证不能准确提示受影响连接。
6. 工具页签只保留当前进程生命周期，应用重启后没有可控的工作区恢复策略。
7. 文件传输、TTS、数据库导出等长任务没有统一任务中心。
8. 插件之间没有正式的联动协议，未来若直接互相 import 会破坏现有插件边界。
9. 部分文档中的阶段状态已经落后于代码，后续以本需求文档和实际代码为准。

### 4.3 首页

#### CORE-001 首页卡片排序（P0）

- 默认排序：手动置顶顺序 > 收藏 > 最近使用 > 工具名称。
- 首次安装的推荐顺序：SSH、网络诊断、HTTP/WS、DNS、Hosts、格式转换、TTS、数据库。
- 数据库卡片增加“维护模式”或“实验性”弱标签，不用“热门”标签。
- 组件实验室只在开发构建或“开发者模式”开启时注册。
- 没有任何工具的分类不在侧栏显示，避免长期存在空的“图片工具”。

卡片保留现有名称、描述、标签和收藏按钮，并增加：

- 最近使用时间，如“10 分钟前使用”。
- 有未完成任务时显示进度点，如“2 个传输中”。
- 有活动连接时显示状态，如“SSH：2 个连接”。

#### CORE-002 首页快速继续（P1）

首页顶部“最近使用”下方增加“继续工作”横条，只展示可恢复的上下文：

- 最近 SSH 服务器：点击后先选中配置，不默认自动连接；用户再次点击“连接”才产生外部连接。
- 最近 HTTP 请求：恢复草稿，但不自动发送。
- 最近 DNS 查询：恢复域名和记录类型，但不自动查询。
- 不恢复密码明文、SSH 终端内容、WebSocket 会话和数据库在线连接。

### 4.4 工具页签

#### CORE-003 页签行为（P0）

- 新页签追加在当前页签右侧，不再固定插到首页后的第二位。
- 页签右键菜单包含：关闭、关闭其他、关闭右侧、固定页签。
- 工具页签不显示未保存、连接、异常或后台任务的状态点与旋转标记；状态由工具内容区呈现。
- 未保存内容和运行任务仍参与关闭确认与资源清理，不因取消页签标记而跳过。
- `Ctrl+W` 关闭当前工具页签，`Ctrl+Tab` / `Ctrl+Shift+Tab` 切换。
- 应用重启只恢复“打开了哪些工具”和安全草稿，不自动恢复网络连接或重新执行操作。

#### CORE-004 工具生命周期（P0）

每个插件 manifest 增加可选生命周期：

```ts
interface ToolLifecycle {
  canClose?: () => boolean | Promise<boolean>
  serializeDraft?: () => unknown
  restoreDraft?: (draft: unknown) => void
  dispose?: () => void | Promise<void>
}
```

- 关闭 SSH 页签时释放全部 SSH、SFTP、日志和监控任务。
- 关闭 HTTP 页签时关闭全部 WS 会话。
- 关闭数据库页签时取消查询并断开连接。
- 应用退出前统一执行 `dispose`，超时 3 秒后强制退出并记录诊断日志。

### 4.6 全局任务中心

#### CORE-006 统一任务中心（P1）

适用任务：SSH 上传/下载、递归目录传输、HTTP 大文件下载、TTS 批次合成、数据库导出、诊断报告导出。

入口：标题栏增加“任务”图标和活动任务数量；点击后从右侧打开 360px 抽屉。

每条任务显示：

- 来源工具图标、任务名和目标。

- 已完成/总量、速度、预计剩余时间。
- `暂停/继续`（后端支持时）、`取消`、`重试`、`打开所在目录`、`清除记录`按钮。

建议框架命令：

- `task_list()`。
- `task_cancel(taskId)`。
- `task_retry(taskId)`。
- `task_clear_finished()`。
- 后端推送 `core://task-updated`，前端不轮询。

### 4.7 跨工具联动

#### CORE-007 Tool Intent（P1）

插件仍然彼此隔离，通过框架级意图总线通信：

```ts
interface ToolIntent<T = unknown> {
  id: string
  sourceToolId: string
  targetToolId: string
  action: string
  payload: T
  createdAt: number
}
```

框架提供 `openToolWithIntent(targetToolId, intent)`：打开目标页签并把一次性意图投递给目标插件。目标插件不活动时保留；消费后删除；不写入跨插件数据库。

首批联动：

| 来源 | 操作 | 目标与效果 |
|---|---|---|
| DNS 查询结果 | “用此主机连接 SSH” | 打开 SSH 添加配置，预填 host，不预填凭证 |
| DNS 查询结果 | “添加到 Hosts” | 打开 Hosts，预填 IP + 域名草稿，仍需用户保存和 UAC |
| DNS 云记录 | “验证传播” | 切回 DNS 查询并选中多个公共服务器 |
| HTTP URL | “诊断此地址” | 打开网络诊断，预填 URL |
| HTTP 响应 | “格式化响应” | 打开格式转换 JSON/XML 面板并填入内容 |
| SSH 服务器 | “网络诊断” | 打开网络诊断，预填 host 和 SSH 端口 |
| SSH 服务/容器端口 | “用 HTTP 测试” | 打开 HTTP，预填 `http://host:port`，不自动发送 |
| Hosts 条目 | “查询真实 DNS” | 打开 DNS 查询，预填域名 |

所有联动都遵循“预填但不自动执行”，避免一次点击触发连接、修改或外部请求。

## 5. 凭证与敏感数据

### 5.1 目标

Vault 已经实现加密存储和备份机制。下一阶段不是再造存储引擎，而是让所有连接型插件真正只保存 `credentialId`，并让秘密默认不经过前端。

### 5.2 VAULT-001 插件统一接入（P0）

#### 数据边界

- SSH profile 保存 host、port、名称、标签、`credentialId`，不保存密码和私钥。
- DNS provider profile 保存平台、名称、`credentialId`，不保存 AK/SK。
- Database connection 保存地址、库名、选项、`credentialId`，不保存密码。
- HTTP Auth 保存认证方式和 `credentialId`，请求执行时由 Rust 解析并注入 Header。
- `vault_reveal` 只允许在凭证管理页用户主动点击“显示”或“复制”时调用。
- 日志、错误、任务快照和导出文件不得出现密码、私钥、Token、Authorization 和 Cookie 明文。

#### SSH 契约调整

当前流程：前端读取秘密 → 前端传入 `ssh_connect`。

目标流程：前端只传 `profileId` → Rust 读取 profile → Rust 调用 Vault → 建立连接。

建议命令：

- `ssh_profile_list()`。
- `ssh_profile_save({ profile })`。
- `ssh_profile_delete(profileId)`。
- `ssh_connect({ profileId, oneTimeOverrides? })`。
- `ssh_test_connection({ profileDraft, credentialId })`。

退役：`ssh_credential_save/get/delete`。

#### DNS 契约调整

- `dns_provider_list()` 返回平台配置摘要，不返回秘密。
- `dns_provider_save({ id?, name, platform, credentialId })`。
- `dns_provider_test(providerProfileId)`。
- `dns_domains/records/...` 改传 `providerProfileId`。
- 退役会回显秘密的 `dns_config_get/set`。

#### Database 契约调整

- `dbc_connection_save` 的 `password` 改为 `credentialId`。
- `dbc_test` 只传配置和 `credentialId`。
- agent 侧车的启动参数、环境变量和日志都不得携带可恢复秘密。

### 5.3 VAULT-002 存量迁移（P0）

首次升级后按顺序执行：

1. 检测旧 SSH 凭证文件、DNS 明文配置、数据库秘密存储。
2. 先读取并校验旧数据，不立即删除。
3. 写入 Vault 并回读验证。
4. 把对应 profile 更新为 `credentialId`。
5. 整体迁移成功后把旧文件改名为带时间戳的 `.migrated.bak`。
6. 下一次正常启动且用户确认连接可用后，设置页提供“清理旧凭证备份”按钮。
7. 任一步失败则回滚 profile，不允许出现“配置更新了但凭证没写入”的半迁移状态。

迁移完成后显示一次报告：迁移多少条、跳过多少条、失败条目和备份位置。报告不得展示秘密。

### 5.4 VAULT-003 凭证引用与删除（P0）

`reference_count` 不再恒为 0。返回引用明细，而不只是计数：

```ts
interface CredentialReference {
  toolId: 'ssh' | 'dns' | 'database' | 'http-ws'
  profileId: string
  profileName: string
}
```

删除交互：

- 无引用：普通二次确认后删除。
- 有引用：弹窗列出引用方，默认禁用“删除”。
- 用户必须先选择“解除引用并删除”或逐个更换凭证。
- 解除引用后，相关 profile 保留但标记“缺少凭证”，不能连接。

### 5.5 VAULT-004 凭证选择器（P0）

连接表单统一使用 `CredentialPicker`：

- 下拉只显示允许的 credential kind。
- 每项展示名称、类型和掩码摘要。
- 有“新建凭证”按钮，弹窗创建成功后自动选中。
- 有“管理”按钮，跳转到凭证管理并在关闭后刷新列表。
- 选中凭证后不允许在连接表单中显示秘密。
- 提供“一次性凭证”选项：仅在内存中使用，不保存；窗口关闭或连接结束后清除。

### 5.6 VAULT-005 安全说明（P0）

设置页应明确展示：

- 可以防止应用数据目录被直接复制后读取凭证明文。
- 默认不防护已经登录当前系统账号且有同等权限的恶意进程。
- 本期 Vault 不上传云端；导出文件由用户设置的密码加密。后期云凭证同步为独立选择项，预留账户内容密钥与设备 keyring 分离的端到端加密边界，具体协议另行设计。
- 剪贴板复制秘密后，可选在 30 秒后仅当剪贴板仍是该值时清除。

## 16. 插件框架增量设计

### 16.1 Manifest 扩展

建议在现有 `ToolManifest` 上增加可选字段：

```ts
interface ToolManifest {
  // 现有字段省略
  visibility?: 'public' | 'developer' | 'experimental'
  order?: number
  capabilities?: string[]
  acceptedIntents?: string[]
  providedCommands?: ToolCommand[]
  lifecycle?: ToolLifecycle
}
```

- `visibility` 控制组件实验室、数据库实验标签等。
- `order` 用于默认排序，不在首页组件写死。
- `providedCommands` 自动进入 `Ctrl+K`。
- `acceptedIntents` 由框架校验，不接受的 intent 不投递。

### 16.2 IPC 规范

- 命令名继续使用插件前缀。
- 所有长操作必须可取消，并用事件或任务快照报告进度。
- 统一错误结构：`code`、`message`、`detail?`、`retryable`、`source`。
- 前端显示 `message`，详情抽屉展示已脱敏 `detail`。
- 不再混用“抛异常”和 `{ ok: false }` 两套业务失败语义；新命令统一 Rust `Result<T, IpcError>`。
- 密钥、Authorization、Cookie、私钥不得作为普通返回值。
- 事件订阅必须返回取消函数，组件卸载时释放。
- Rust 端会话和任务都必须带所有者 tool instance id，防止同一工具多实例误清理。

### 16.3 插件数据

- 每个插件只访问自己的 SQLite 文件。
- profile 数据从 localStorage 逐步迁移到插件数据库；localStorage 仅保留轻 UI 偏好。
- 所有 schema 通过 `PRAGMA user_version` 顺序迁移。
- 跨插件关联只存稳定 ID 或通过框架意图即时传递，不直接查询其他插件数据库。
- 用户删除 profile 时，先关闭关联会话和任务，再删除数据；失败则不删除一半。

### 16.4 统一日志

- 使用 Rust `log` 与官方 `tauri-plugin-log`，直接调用库接口，不自建 logger、writer 或日志协议。接入、级别、打印范围及敏感信息规则以 [Rust 日志约定](05-Rust代码规范.md#7-日志约定)为准。
- 默认 Info；普通文本包含时间、级别、模块与操作结果，会话/任务 ID、错误码和耗时仅在适用时附带，不要求统一事件 DTO。
- 应用日志保存在固定的系统应用日志目录，不随业务存储根迁移或空间切换；SSH 录制等业务日志保留原空间归属。按大小滚动，包含当前文件在内最多 5 个，每个 5 MiB。
- 所有级别均不记录秘密或业务正文；调用点负责选择安全摘要，不能依赖日志库自动脱敏。
- UI toast 只用于简短结果；可恢复失败同时进入通知/任务详情。

## 17. 非功能需求

### 17.1 性能

- Windows 冷启动到首页可交互目标：2 秒内；热启动目标：1 秒内。
- 首页静置 30 秒后 CPU 目标低于 1%。
- 首页无活动连接时内存目标低于 150 MiB；开启多个 xterm 后按实际测量建立回归基线。
- 隐藏工具页签停止无必要轮询；保留连接不等于持续刷新所有子页面。
- 大文件、文件哈希、下载和导出必须流式处理，不能完整复制进 JS 内存。
- SQLite 写入放在短事务中，不能持锁跨网络 await。

### 17.2 安全

- 默认 CSP 保持最小范围；新增网络能力通过 Rust 发起，不随意扩大 WebView `connect-src`。
- 禁止引入通用 shell 插件；系统命令由固定参数的 Rust 适配器执行。
- Hosts 提权继续使用最小范围一次性助手，应用本体不常驻管理员。
- 所有删除、强杀、停止服务、覆盖文件、修改 DNS 等危险操作使用统一确认等级。
- 首次连接 SSH 必须校验 host key。
- TLS 校验默认开启；忽略证书只对当前请求生效。
- 导出配置默认排除秘密；包含秘密必须使用 Vault 加密格式。

### 17.3 稳定性

- 网络命令都有超时和取消。
- 应用关闭、工具页签关闭、连接页签关闭都验证后端资源释放。
- SQLite 迁移失败不得继续用不完整 schema 运行。
- 文件覆盖使用临时文件 + 原子替换；能保留备份的场景必须保留。
- 断网、休眠恢复、服务器主动断开和 WebView 重载都应有测试。

### 17.4 可访问性与交互

- 所有图标按钮有可见 tooltip 和 `aria-label`。
- 键盘可以完成页签、列表、菜单、弹窗和主要表单操作。
- 焦点不会被 Teleport 弹窗丢失；关闭后回到触发按钮。
- 不只用颜色表达在线/错误状态，同时有文字或图标。
- 破坏性按钮使用统一 danger 样式；默认焦点不放在危险确认按钮。

### 17.5 国际化

- 当前只正式支持简体中文。
- 英文语言包未完成前设置项禁用并标注“开发中”。
- 新文案禁止直接散落在 Rust 错误字符串中作为唯一用户文案；Rust 返回稳定错误码，前端翻译。

## 20. 测试与验收矩阵

### 20.1 通用

- 工具反复打开/关闭 50 次，无后端会话、监听器和定时器持续增长。
- 应用最小化到托盘 30 分钟，无无意义轮询和明显 CPU 占用。
- 深浅主题、900×620 最小窗口和 125%/150% 系统缩放可用。
- 所有弹窗可用 Esc 关闭；危险操作需要明确确认。
- IPC 错误可复制，用户提示不暴露秘密。

### 20.2 Vault

- 同明文多次保存密文不同，均能解密。
- keyring 不可用时降级路径有告警，已有 Vault 不会被静默重置。
- SSH/DNS/Database 存量迁移成功、部分失败、写入中断和回滚均有测试。
- 有引用凭证不能无提示删除。
- 全仓库与运行日志扫描不出现测试密码、私钥片段和 Token。

### 20.3 SSH

- 密码、无密码私钥、有 passphrase 私钥。
- 未知 host key、匹配、变化三种情况。
- IPv4、IPv6、域名、自定义端口。
- 网络断开/恢复、服务端断开、系统休眠恢复。
- 多连接、多终端、快速切换、关闭顺序。
- 大文件、空文件、中文名、深目录、权限失败、传输取消和同名冲突。
- systemd 不存在、Docker 不存在、无权限、命令输出异常。
- 隧道端口占用、断线重建、监听公网地址警告。

### 20.4 HTTP/DNS/Hosts

- HTTP 重定向、超时、无效证书、大响应、二进制、重复 Header、取消。
- WS 文本/JSON/Binary、服务端断开、消息上限、关闭资源。
- DNS 各记录类型、部分服务器超时、平台限流、权限不足、传播不一致。
- Hosts 外部修改冲突、UAC 取消、保存失败、备份恢复、换行符保留。

### 20.5 质量门槛

发布前验证对应能力、平台与回归场景；日常修改按影响选择检查。命令、CI 与本地执行边界统一见[20-验证矩阵](20-验证矩阵.md)，不在需求文档维护第二份门禁清单。

## 21. 开放决策

以下问题不阻塞 R0，但进入对应版本前需要确认：

1. 侧栏是否新增“远程运维”分类，还是继续把 SSH 放在“网络工具”。
2. SSH 文件管理是否采用完整本地/远端双栏，还是保留远端单栏 + 系统选择器。
3. SSH 终端分屏是 R1 必须项还是延后 P2。
4. 数据库工具是否默认显示，还是新安装默认隐藏为实验工具。
5. 网络诊断是否第一版包含路由追踪，还是先做 DNS/TCP/TLS/HTTP。
6. 格式工具下一批优先 JWT + 文件哈希，还是 YAML/TOML + 文本 diff。
7. 是否正式支持 macOS；当前 bundle 已声明 dmg，但 Hosts、系统进程、端口等能力需要真实设备验收。
8. 开源前是否保留“关闭到托盘”为默认，还是首次启动让用户选择。

## 22. 推荐的下一步

不要同时开始所有规划项。建议立即进入 R0，并把第一个可见功能版本定为“SSH 旗舰版”：

1. 先完成 Vault 接入和 SSH known_hosts，解决公开发布前的安全底线。
2. 再实现全局任务中心，把现有 SFTP 传输接进去。
3. 完成 SSH 双栏文件、真实监控曲线和隧道页。
4. 做网络诊断与 Tool Intent，让 SSH、DNS、HTTP、Hosts 串成排障闭环。
5. 数据库仅穿插安全修复，不再开新功能线。

这样得到的 CoveKit 不会只是“很多小工具放在一个壳里”，而会形成一个清晰特点：**启动轻、数据在本机、以 SSH 为中心，能把个人开发和服务器排障的高频动作留在同一个工作区内完成。**

## Codex 重置消息

- 单栏展示 SaveMeTibo 整理的 Codex 重置消息，使用固定的 `status.json` 与 `timeline.json` 公共源；保留原文、来源链接、本地时间和消息状态，按事件 ID 合并。

## 当前有效范围裁决

- 端口占用查询为独立 Windows 系统工具，与文件占用查询共用框架进程能力。当前实现 TCP/UDP、IPv4/IPv6 的本地端口与进程查询、分页、手动及可选自动刷新、复制、定位程序和确认后关闭进程；macOS 明确不支持，不自动提权。以[端口查询范围](07b-需求-网络与调试.md#15-本机端口占用查询)替代旧 P2 联动规划。

- 文件占用查询为 Windows 专属工具：输入、选择或拖入单个文件，展示使用它的进程 PID、应用与服务名称、可读取的程序路径，支持刷新、复制信息和打开程序所在目录。允许用户确认后强制关闭选定进程，提示未保存内容可能丢失；后端重新核对文件使用关系及 PID 与启动时间，拒绝关闭 CoveKit 自身、系统保留进程和关键进程，不自动提权，关闭成功后刷新。不支持目录、批量查询或直接关闭文件句柄；查询结果不等同于阻止删除的判定，空列表不保证没有占用。macOS 显式显示不支持。

- 接口调试保持轻量，协议为 HTTP、SSE 和原始 WebSocket；按 SSH 页面风格采用紧凑接口侧栏与独立请求页签，协议在新建时绑定，不设置顶层协议切换。当前功能与明确排除项以[网络与调试第 8 节](07b-需求-网络与调试.md#8-接口调试)为准，替代此前完整 API 工作台规划。

2026-09-19 SSH 认证裁决：保留凭证库认证；手工密码/私钥支持“本地保存”“不保存”“保存到凭证库”。新建手工认证默认本地保存，直接写入本机 SSH 数据库，不依赖 Vault 或系统密钥。已有凭证引用不自动迁移。编辑留空保留匹配连接参数的本地认证，填写则覆盖；改变主机、端口、用户名或认证类型需重新输入，删除服务器同时清理本地认证。普通逻辑配置导出不包含本地认证，完整数据目录副本包含该数据库。此裁决覆盖旧的 SSH 秘密只能写入 Vault 的要求，日志和 IPC 元数据仍不得泄露秘密。
