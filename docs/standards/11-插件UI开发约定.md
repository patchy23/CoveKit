# patchyBox 插件 UI 开发约定

## 配套 references

- `references/reka-ui-pitfalls.md` — Reka UI 原语坑：`SelectItem`/`ComboboxItem` 空串 value 会让弹层渲染即崩（表现为「下拉点不开」）、模态 `pointer-events`、浮层 z 序与 portal、排查配方。
- `references/form-layout-conventions.md` — 配置类表单排版：「更多配置」折叠、分节卡片、必填与提示范式、公共组件加档位优于新建。

两条硬规则（细节见上）：

- 传给 `UiSelect` / `UiCombobox` 的**每一项 value 必须非空**。「不选 / 跟随默认 / 不使用」一律用非空哨兵值，并在选中回调里反映射回 `''`；命中空串时弹层渲染直接 `throw`，而触发器看着完全正常（文案、箭头都在），极易误判成「交互没接上」。
- **配置类表单默认只露能直接跑起来的字段**，进阶字段收进默认收起的「更多配置」（用 `v-show` 保已填值）。用户原话：「快速配出能用的，其他无关紧要的配置统一放在一个收起的『更多配置』中」。

## When to Use

- 在 patchyBox（G:\workspace\patchyBox）新建/改造插件页面（`src/plugins/<id>/`）时
- 使用 UiTree / ContextMenu / UiTable / UiDataGrid 等公共组件拼装复杂工具页时
- `components.test.ts` 契约测试报「原生控件」违规时
- 并行会话下需要精确暂存共享文件（plugins/index.ts 等）时

针对 patchyBox（Tauri 2 + Vue 3 工具箱）插件页面的布局风格红线与公共组件契约。

## 复杂工具页布局风格（2026-08-15 用户纠偏，红线）

**禁止套"超级应用"外壳**。database-v2 第一稿模仿 database v1（`rounded-xl border shadow` 卡片壳 + UiStatusBar 状态栏 + UiSplitPane + 工具内嵌 UiWorkbenchTabs）被用户推翻：「不要参考第一版，按照我们其他工具的风格来做」。

正确范式 = http-ws / ssh 风格：

- 根 `flex h-full min-h-0` 朴素多栏，`border-r/border-l` 分区——**无卡片壳、无阴影、无全局状态栏、无全局顶部工具栏**
- 每栏自治局部 header（如 ApiSidebar「接口列表（N）+ 新建」、ServerList 搜索框 + 添加按钮）
- 中栏 UiTabs 管理子页签（连接/文档维度）
- 右栏摘要收起后**必须留恢复入口**：收起态渲染 28px 细轨道条（`v-else-if` + `border-l` + 双 chevron 展开按钮 + `[writing-mode:vertical-rl]` 竖排栏名），不依赖页签类型随时可展开；面板头收起按钮用双 chevron（收起方向）不用 X（关闭语义）。X 掉且无恢复入口被用户否（2026-08-15）
- 上下分栏（编辑器/结果区）用 `style="flex: 0 0 38%"` 固定比例即可，不必上 UiSplitPane
- 图标一律内嵌 SVG，不用 Unicode 符号。**但勿照搬参考项目的图标选型**：树节点先换 dbx 同款的 Unicode 字形被嫌丑，准备照抄 dbx 的 lucide 图标映射时又被用户否——「这也别照着换了，有抄袭了，我们自己设计一下吧」（2026-08-15）。参考项目可借资产/数据结构/机制（logo svg、能力集合），视觉设计（图标形状、配色映射）要自己画

## 公共组件契约（components.test.ts 强制，违反即红）

`src/plugins/**/*.vue` 出现 `<button|<input|<select|<textarea|<table` 即测试失败（**原生 `<input type="checkbox">` 也在禁令内**，建库授权勾选/建表列编辑踩过）：

- 表格一律 **UiTable + UiTableCell**（UiTableCell 仅 `as/content/align` 三个 prop——**无 muted**，database v1 里传的 `muted` 是无效透传；数据列 `content="technical"`，键徽标列可放 UiBadge；**可编辑网格也可套 UiTable**——单元格里放 UiInput/UiSelect/UiCheckbox，加序号列 `content="numeric"`、操作列 `content="action"`）
- 复选框一律 **UiCheckbox**（v-model boolean，size xs/sm/md/lg）
- 表单一律 UiInput / UiSelect / UiButton
- 可点击列表行/条目用 `<div class="cursor-pointer" @click>`（ApiSidebar 惯例），不用原生 button
- **紧凑行内小按钮**（书签行尾 ×、传输项「取消」等）：`UiButton variant="ghost" size="xs" class="!h-auto !px-[4px] !py-[1px]"`（2026-09-09 契约测试实拦截后定稿）
- **勾选矩阵等布局网格用 `div.grid`**（如 chmod 3×3 权限矩阵 `grid-cols-[auto_repeat(3,1fr)]`）——`<table>` 只留给数据表（UiTable）；**需要完全自定义内部布局的按钮**（如本体即进度条的传输按钮）用 `div role="button" tabindex="0" @click @keydown.enter`（2026-09-09 实测过契约）
- 类型选择网格用 `UiButton size="xs" block :variant="active ? 'primary' : 'secondary'"`
- **契约测试失败先 `git show HEAD:<file>` 对照确认违规归属**——并行会话可能新加规则撞上别的插件存量违规（如 ssh/TerminalTab.vue），别替别人修文件
- **基础控件不得依赖应用服务（2026-09-12 起）**：`core/ui` 只放无业务依赖的基础控件与编辑器——不得 import `@/stores/*`、`@/core/vault` 或业务 IPC（现存 `useClipboard` 依赖 ui store 等例外按 AR03 迁移）；凭证复合组件（CredentialPicker / CredentialForm）统一从 `@/core/vault` 使用，平台操作走 `core/platform`、应用级提示走 `core/feedback`。新写控件按此分层，不要再往 `core/ui` 里塞带 store / 业务 IPC 的文件

## 弹窗与下拉层级（2026-08-16 用户纠偏，全局已定稿）

- **UiModal 默认不响应遮罩点击关闭**（`closeOnBackdrop` 默认 `false`）：用户实测「点弹窗外直接关闭，填了一半的信息没了」——误点丢表单是红线。关闭只走 Esc/取消/关闭按钮；个别确需点外关闭的弹窗显式传 `close-on-backdrop`。**UiModal 已全局内置右上角 ✕ 关闭按钮**（禁用遮罩关闭后每个弹窗都必须有可见出口），业务弹窗无需自画关闭按钮。
- **UiSelect 下拉层 z-[220]，必须高于 UiModal 遮罩 z-[180]**：弹窗内下拉"没东西"不是数据问题，是下拉被遮罩盖住（曾致凭证类型下拉看似为空）。新做的浮层组件（菜单/气泡/工具提示）一律 ≥ z-[220]，勿用 z-50。
- **reka 模态弹窗会把 body 置 `pointer-events:none`——Teleport 到 body 的组件（ContextMenu 等）在弹窗内整体点不动**：症状是菜单正常渲染、位置正确，但所有项点击无反应（凭证管理右键三功能失效实测）。修复：Teleport 浮层根元素必须带 `pointer-events-auto`（ContextMenu 已内置，勿移除）；新做 Teleport 浮层组件时把这条列入自检。
- **框架级功能不进工具体系；设置页定稿为整页模式（2026-08-16 两轮纠偏后终稿）**：第一版凭证管理注册 hidden 工具开 workspace 页签被否（「框架功能，不要和工具混在一起」）；第二版设置从弹窗改成 workspace 框架页签（ToolWorkspace FRAMEWORK_PAGES 特判）又被否（「不是用页签，直接铺满右侧整个页面，设置本身是独立的框架级功能」）。**终稿**：框架级整页 = ui store `settingsOpen` 开关 + `openSettings()/closeSettings()/toggleSettings()`，App.vue 右侧 SettingsPage 与 ToolWorkspace 用 `v-show` 整体互切（覆盖页签条区域，TopBar 同步 `v-show` 隐藏；工具页签在后台保留状态）；侧栏「设置」入口是**开关式**（`ui.toggleSettings()`，打开态再点即退出，用户明确要这个而非只能点页面 ✕）并带激活高亮，页面右上角返回按钮仅作备选；`openTool()` 与切分类会自动 `closeSettings()`（否则工作区被盖着点了没反应）。框架功能的二级内容（凭证管理）在设置页内用 xl UiModal 承载，管理面板做成纯内容组件（CredentialManagerPage，无自有页头）复用。hidden 工具机制（ToolManifest.hidden）与 FRAMEWORK_PAGES 均已回滚删除，勿再造。

## UiTree 使用三坑

1. **展开状态必须独立持久化**：`treeItems` 若是 computed，每次重算重建全新对象数组，`toggleTree(item){ item.expanded = !item.expanded }` 改的展开状态在下次依赖变化时丢失。正解：`expandedIds: ref<Set<string>>`，build 时 `expanded: expandedIds.has(id)`，toggle 操作 Set 后整体替换（触发响应式）。
2. **折叠过滤用严格 `<`**：`visibleTreeItems` 里 `if (item.depth <= hiddenDepth) hiddenDepth = ∞` 的 `<=` 会让 depth 恰等于 hiddenDepth 的子节点误触发重置（折叠连接的子树全部漏出）——必须 `item.depth < hiddenDepth` 才重置。
3. **折叠箭头已定稿 SVG chevron**（Unicode ⌄/› 被用户嫌丑，「参考 dbx」）：lucide path `m9 18 6-6-6-6`（chevron-right），展开态 `rotate-90` + `transition-transform duration-150`；箭头区 16×16 圆角 + `hover:bg-border`；loading 用旋转圆弧 path `M21 12a9 9 0 1 1-6.219-8.56`（对齐 dbx 的 ChevronRight/ChevronDown/Loader2）。

## 组件真实 API 备忘

- **ContextMenu 是声明式**：`:x :y :items` + item 内联 `onClick` 回调 + `@close`，父组件 `v-if="menu"` 控制显隐——**不是** `ref.open(mouse)` 命令式；分隔线项 `{ label: '', separator: true }`。**有 `size` 档位（2026-08-15 新增）**：`md`（默认，w-150/text-body/py-7，SSH 文件等）与 `sm`（紧凑，w-124/text-body-sm/py-5，树/列表内嵌场景）；坐标收拢随档位（md `innerWidth-158`、sm `innerWidth-132`）。需要更小菜单时加档位，勿新建组件。**收拢用的固定 N 与面板最小宽度绑定，改宽度时两处一起复核。**
- **菜单面板宽度取「最小宽度 + 按内容自适应」，不要写死宽度；菜单项一律 `whitespace-nowrap`**（现役值 sm `min-w-[140px] w-max max-w-[320px]`、md `min-w-[168px] w-max max-w-[340px]`）：菜单文案长短差异大，「在资源管理器中显示」这类偏长的项会被写死宽度挤成两行——该行行高比相邻项高出一截（实测 58px vs 36px），整块菜单看起来像坏了。**同规则适用于任何自绘浮层（下拉/气泡/提示条）**：固定宽度 + 缺 `nowrap` 是长文案换行的高发配置。
- **UiInput/UiSelect 的 `update:modelValue` 是 `string | number`**：写入 string 型 state 必须 `String(v)` 转换，否则 vue-tsc TS2322/TS2769。
- **UiTree 树节点交互语义（2026-08-16 用户定稿，取代旧「表点击开数据页签」）**：**单击任何节点仅选中**（同步活动连接，不开页签）；**双击**：连接节点（depth 0）= 离线即连接（`onTreeOpen` 必须显式处理连接节点，只处理叶子会出现「双击不连接、右键才能连」）；可展开节点折叠/展开，不可展开叶子触发 `open` 事件（UiTree 新增 emit：表/视图→结构页签，Redis 键→键详情）；打开数据页签只在右键菜单「查看数据」。右键按层级出菜单。tab id 带连接前缀（`data-<connId>-<table>` / `structure-<connId>-<table>`）防跨连接同名表冲突。
- **UiIcon 与 AppIcon 是两套独立图标表**：UiIcon（`core/ui`，@lucide/vue 封装）是小工具图标固定集合（search/grid/copy/play/chevrons/x/refresh/eye/eye-off/dots(横向三点，更多/溢出) 等，TS 字面量枚举，用错名字直接 TS2322，新增图标 = 注册表加一行）；AppIcon（`features/ui`）是工具大图标表（lock/db/gear/sliders 等）。用图标前先 grep 对应表确认名字存在，勿跨表引用。**注册新图标前先确认 lucide 真有这个导出**：`ls node_modules/@lucide/vue/dist/esm/icons/ | grep '^<kebab-name>'`（文件名即 kebab 名，`arrow-left-to-line.mjs` → 导出 `ArrowLeftToLine`），确认后再在注册表加一行并补中文用途注释。
- **UiIconButton 无 disabled prop 但可透传**：UiButton 读 `$attrs.disabled === true`，直接 `:disabled` 即可；尺寸 xs=24/sm=28/md=36 正方形。
- **密码框定稿（2026-08-16 三轮纠偏后）**：一律 `UiInput type="password"`——组件自带输入框内眼睛切换明文，**禁止在 label 行/输入框右上角另加眼睛按钮**（会与自带眼睛重复）；**禁止加 `font-mono`**（掩码圆点要与普通输入框视觉一致，font-mono 只给明文数据如 AKID/私钥全文）；WebView2 原生 reveal 眼睛由 main.css `.field-input::-ms-reveal { display: none }` 全局隐藏（否则与组件眼睛重合）。私钥等多行秘密不脱敏，UiTextarea 明文可编辑。UiIcon 的 eye/eye-off 注册保留给非输入框场景（如「显示密钥」列表切换）。
- **UiSearchInput 不得加回 `type="search"`**：WebView2 原生清除按钮 × 会与组件自带清空按钮重复（双 X 实测被用户报 bug）；同理新输入类组件不要依赖浏览器原生控件装饰（搜索清除/密码眼睛都走组件自绘）。
- **Tauri 窗口内 HTML5 拖拽不可用（2026-09-05 SSH 分组拖拽实测）**：`dragDropEnabled` 默认 true 把窗口注册成 OLE 拖放目标（OS 文件拖入走 `getCurrentWebview().onDragDropEvent`，SSH 文件上传靠它），副作用是吞掉应用内 HTML5 DnD——合成 DragEvent 正常、真实鼠标拖拽无效。内部拖拽（如列表行拖到分组）用 **pointer 事件自实现**（`useGroupDrag` 模式：pointerdown + 6px 阈值 + window pointermove/pointerup + elementFromPoint 命中 `[data-group-drop]` + Esc 取消 + 跟随指针的浮动标签）；不能为了内部拖拽关掉 dragDropEnabled（会弄丢 OS 文件拖入的路径）。**pointerup 必须做无中间帧兜底**：down 与 up 之间若丢了全部 pointermove（合成输入、极快甩拖），active 永不置位 → 整次拖拽静默丢弃且无任何报错；onPointerUp 先按 up 相对 down 位移 ≥ 阈值补激活，再走投放判定（2026-09-10 双栏文件拖拽实测，背景注入一次 move 都没有）。**pointer 拖拽激活后必须锁浏览器文本选择**：pointer 自实现拖拽不拦默认行为时，拖过路径上的文字会被选中（用户报「拖拽上传下载时会选中拖动区域的文本内容」）——越过阈值激活那一刻 `document.body.style.userSelect='none'` 并 `getSelection().removeAllRanges()` 清掉已开始的选区，拖拽结束（pointerup/Esc/取消）恢复原值；只锁真拖拽期间，单击/双击选词、行内复制不受影响。
- **WebView2 原生右键菜单必须运行期屏蔽（2026-09-09 用户报「原生菜单干扰程序内右键菜单」）**：浏览器默认菜单（复制/粘贴/刷新/检查元素）会与自绘 ContextMenu 叠加。**JS `contextmenu` preventDefault 无效**——WebView2 默认菜单是 COM 层 UI（页面事件取消不影响，只有 `AreDefaultContextMenusEnabled` 能关）。Tauri 2.11 零依赖可达：`WebviewWindow.with_webview(|wv| ...)` 拿到 `PlatformWebview`（Windows 专属 `controller()` 方法），`controller.CoreWebView2()?.Settings()?.SetAreDefaultContextMenusEnabled(false)`——方法都是 webview2-com 类型的固有方法（该 crate 已被 tauri-runtime-wry 引入且全局开启 windows 相关 feature），**无需新增 Cargo 依赖也无需 import 路径**；`#[cfg(windows)]` 包住、setup 里遍历 `app.webview_windows()`。副作用：输入框原生剪切/粘贴菜单一并消失（Ctrl+C/V 不受影响）。排查思路：窗口级浮层问题先翻 wry/tauri 源码的 `PlatformSpecificWebViewAttributes` 与 `PlatformWebview` 方法表，别自己造轮子。
- **自定义滚动条必须连 corner 一起覆盖（2026-09-10 用户报「横向滚动条右侧白方块」）**：`::-webkit-scrollbar` 只自定义 thumb/track 时，横向+纵向滚动条交汇的右下角仍是浏览器默认纯白方块（scrollbar-corner）——浅色主题下格外刺眼；补 `::-webkit-scrollbar-corner { background: transparent }`（main.css unlayered 全局区，深浅色通吃，所有表格/列表一次受益）。排查引导：任何「滚动条旁莫名色块/残留 UI」先查 ::-webkit-scrollbar 系列伪元素是否覆盖全。
- **SFC scoped 样式暗色覆盖两连坑（2026-09-05 UiTable 斑马纹暗色白黑相间实测）**：① 组件 `<style scoped>` 里 `:global([data-theme='dark']) .x :deep(...)` 混写选择器会被 Vue SFC 编译**静默丢弃**——规则根本不进样式表，且无任何报错；② 暗色覆盖若写进 main.css 的 `@layer components`，按 CSS 层叠规则**整层输给**组件 scoped（unlayered）样式，同优先级还输在文档顺序。正解：暗色覆盖写 main.css **unlayered 全局区** + `html[data-theme='dark']` 前缀提优先级（参 542 行 tree-line 区段与 UiTable 覆盖段注释）；验证手法 = 浏览器查 styleSheets 里规则是否存在 + 切暗色后 getComputedStyle 实测。SSH 表格没事是因为它用 Tailwind `dark:` 类（@custom-variant 生成，不走 scoped）。
- **页签条三件套（2026-08-16 用户定稿：页签永不换行 + 溢出收纳公共化）**：① CSS 红线：`.ui-tab` 带 `whitespace-nowrap`/`shrink-0`，文字套 `.ui-tab-label`（max-w-160 truncate），`.ui-tabs` 是 `overflow-hidden` 不再 `overflow-x-auto`——「页签名字无论何时只能一行」。② 溢出用公共 **UiTabsOverflow**（`@/core/ui`）：触发器是**横向三点 dots 图标**（Ellipsis，UiIcon 注册名 `dots`；初版 chevron+数量徽标被用户否——「常规是三个点图标」），下拉样式对齐 UiSelect，逐行悬停 X 关闭，点外收起，emits `select/close`。③ composable **useTabsOverflow**（容器 ref + items + active + reserved + widthOpts{extra,maxLabel} → visible/hidden）：按**每个页签文字实际宽度**估算（CJK 14px/其余 8px + extra 固定宽，文字 capped）动态决定可见个数——固定单宽估算（如一律 190px）窄窗口只剩 3 个被用户否。两个硬约束：**容器必须 `overflow-hidden`**（否则 scrollWidth 不可测）；**估算必须配实测反馈**——纯估算偏小会出现「没显示完但没出三点」被裁掉，watchPostEffect 渲染后测 scrollWidth>clientWidth 即 trim+1 逐步多收直至收敛（宽度/页签数变化重置 trim）。**第三个硬约束（2026-09-05 实测）：UiTabsOverflow 下拉面板必须 Teleport 到 body 用 fixed 定位**——面板若绝对定位在页签条内，会被容器的 overflow-hidden 整体裁掉，症状是「点三点没反应」（其实开了但看不见）；触发器右缘对齐面板右缘。数据库工作台与 ToolWorkspace 都已接入同一套；ToolWorkspace 旧的自写「···」下拉已删，勿再造私有溢出菜单。
- **components.test.ts 的原生控件/表格禁令只扫描 `src/plugins/**/*.vue`**：`src/features/**`、`src/core/**` 下的框架级页面（SettingsPage、凭证管理面板等）不被契约测试强制，但仍须自觉走 Ui* 组件与语义字体 token。
- **UiCombobox（2026-09-05 新增，`@/core/ui`）**：可输入搜索的下拉选择（reka Combobox 封装）——触发框输入即过滤（匹配 label + keywords，大小写不敏感）、↑↓ 高亮、Enter 选中；样式对齐 UiSelect（`ui-control-*` 档位 + z-[220] 浮层）。props：`modelValue / options{value,label,keywords} / placeholder / searchPlaceholder / emptyText / size`；选项末尾可放「+ 新建」哨兵项由调用方拦截（ServerForm 的 `__create__` 模式）。选项多（>8 个）或需要搜索时用它，不要用 UiSelect 硬撑。

- **含反斜杠的字符串 prop 禁止走 HTML 属性直传**（2026-09-08 本地面包屑不分层实测）：`separator="\\"` 传入的是两个字符的反斜杠，与 JS 里单 `'\\'` 不相等且**编译无警告**——必须 `:separator="'\\'"` 绑定表达式。排查信号：组件行为像「没收到 prop」但模板里明明写了。

## 数据库管理功能模式（2026-08-16 dbx 对齐批定稿）

- **管理类 SQL（建库/授权/DDL/索引/重命名/清空/删除）一律后端方言层构造**，前端只传选项参数：dialect trait 加管理方法（默认 `None` 不支持，mysql 主力实现、pg/sqlite 按需覆盖），标识符走 `quote_ident`、字符串字面量走 `quote_literal`（单引号转义）、权限入参白名单校验（readonly/readwrite/all → 固定 GRANT 文本），禁止前端拼 SQL 发 dbc_execute。
- **scope 入参约定**：`dbc_columns`/`dbc_table_data` 等的 `schema` 参数 mysql/polardb 传**库名**、PG 系传 schema、sqlite 忽略。页签 TabContext 的 database/schema 必须来自**树节点 id 的 scope 段**（`conn::scope::kind:name` 解析），不能取连接配置默认库——否则非默认库对象查看数据/结构全失效（本批修的 bug）。
- **DDL 预览用纯函数 + vitest 实测**（`createTableSql.ts` 模式：buildXxxSql 纯函数生成、单测覆盖标识符转义/非法输入丢弃）；默认值渲染自动判别（数字/NULL/TRUE/FALSE/CURRENT_* 原样，其余按字符串加引号），不给用户加「是否字面量」开关。
- **mysql_async 行转换会 panic 而非报错**（2026-08-16 实测拖垮 tokio worker）：预编译语句（exec/exec_first 带参）下 information_schema 的 BIGINT 列（如 TABLE_ROWS）到达时是 `Int`，`exec_first::<String>`/`query::<String>` 触发 FromRow panic（"Couldn't convert Row{...} to String"），NULL 同理。**标量/统计值一律 `exec_first::<Option<mysql_async::Value>, _>` 取值后用 `mysql_value_str` 转字符串再 parse**；行集用 `Vec<Row>` + `row.get::<Option<String>>` 逐列取。`.ok().flatten()` 兜不住 panic——类型选错在 from_row 阶段就崩。
- **危险操作三件套**：ConfirmDialog 确认（文案写明不可恢复）→ 执行成功 `useUiStore().toast`（成功反馈不再借道 showError/errorHint，那是错误通道）→ 刷新该 scope 对象缓存 + 关闭受影响页签（drop/rename 后关掉旧表的 data/structure 页签）。
- **编辑器区域是多类型页签容器**（不只是 SQL 编辑器）：V2TabKind 已含 query/data/structure/redis/create-table，新页签类型 = 加 kind + DatabaseWorkbench 模板分支 + tabContexts 上下文。

## core 层「同名文件 + 目录」会让 alias 悄悄解析到单文件（2026-09-11 实测）

新建 `src/core/format/` 目录时仓库已有 `src/core/format.ts` 单文件 → `@/core/format` 解析到**单文件**，只拿到它的导出；`@/core/format/json`、`@/core/format/index` 正常。症状极具误导性：导入不报错，运行时 `xxx is not a function`（本次表现为 `formatJson is not a function`，`Object.keys(barrel)` 只剩 `['formatBytes']`）。

### 编辑器细节组件的既有做法（2026-09-12）

- **缩进参考线按行绘制，不要用整行宽度的 `repeating-gradient`**：gradient 铺满整行会让缩进浅的行也出现满屏竖线（观感变栅格），且从行左边缘起算、与文字起始位置错开一个 padding。正确做法（对齐 VS Code indent guides 与 Replit `@replit/codemirror-indentation-markers`）：每行按自身层级拼多层 `linear-gradient(...) 0 1px, transparent 1px / 1px 100% no-repeat` 写到行 decoration 的 `--cm-indent-bg`，用伪元素 + `z-index:-1` 绘制（不盖住当前行高亮/选区）；光标所在层级换激活色（VS Code 是 `editorIndentGuide.activeBackground1`）。
- **折叠箭头用 `foldGutter({ markerDOM })` 自绘 SVG，不要用默认 `⌄` / `›`**：默认是文本字符，笔画位置在 12px 字号下不可控。`markerDOM(open)` 的语义与官方 `openText`/`closedText` 一致：`open=true` = 可折叠且未折叠（箭头朝下），`false` = 已折叠（朝右）。
- **数 gutter 元素时跳过隐藏占位**：`foldGutter` 的 `initialSpacer()` 会用一个 `markerDOM(false)` 生成 `visibility:hidden`、高 0 的 spacer 并排在 `.cm-foldGutter .cm-gutterElement` 列表首位 —— 用 `querySelector` 取第一个箭头判断状态会误判（实际拿的是 spacer，会得出“方向映射反了”的错误结论）。要从第二个元素起取，或按可见性过滤。

**编辑器统一契约测试（2026-09-12）**：`src/core/ui/editor/editorUnification.test.ts` 扫全仓库源码，禁止编辑器实现之外实例化编辑器、引入其它基座、工具层 import `@/core/ui/editor/*`、残留 `LineNumberTextarea`/`CodeViewer`。插件给共享编辑器**注入扩展**（SQL 补全、语句运行 gutter）是允许的。

坑：`import.meta.glob` 的 key 是**相对当前测试文件**的路径（如 `../UiCodeDiff.vue`），用 `includes('/core/ui/...')` 判定会静默失效、误报一片；要项目内绝对路径就用 `/src/**/*.{ts,vue}` 开头的 glob。

- **改 CodeMirror 内置部件外观时，选择器要写得跟它一样深（2026-09-12 实测）**：`EditorView.theme` 的规则会自动带主题 class 前缀（多 1 个特异性），所以大多数情况下能压过 `EditorView.baseTheme`；但**插件内置的聚焦态复合选择器很深**，浅写会被静默压过。典型：`drawSelection` 的选区层是 `&light.cm-focused > .cm-scroller > .cm-selectionLayer .cm-selectionBackground`（5 个 class），只写 `&.cm-focused .cm-selectionBackground`（3 个）改不动它 —— 症状是「聚焦框选时看不到自己的颜色，光标移开（走原生 `::selection`）反而正常」。改法：在 theme 里写全同一条链条。动手前先到 `node_modules/@codemirror/*/dist/index.js` 搜对应类名，确认有没有更深的对手规则。
- **编辑区内的原生 `::selection` 不要给颜色**：`drawSelection` 用 `hideNativeSelection`（`Prec.highest` + `!important`）把 `.cm-line ::selection` 强制透明，编辑区选区**只由自绘层一条路径决定**——给原生 `::selection` 上色不会生效，反而会在 CM 判定「内容区获得焦点」时切到系统 `Highlight`（不透明）叠在自绘层上，症状是聚焦框选比失焦更深一档。在 `theme.ts` 落一句注释锁住这个意图，防后人误加颜色。
- **同一元素在浅深两套主题里按对比度配平，不按「看着差不多」**：用户说暗色「还行」而浅色「几乎看不见」，实为两档差一个量级（实测暗色 `#264f78`/`#161b21` 2.04:1、浅色 `#add6ff`/白 1.52:1）。把用户认可的那一档当基准，用 `(L1+0.05)/(L2+0.05)` 算另一档再取值，一次到位；旋钮只留一个（如 `--cm-selection`），别同时改多处让用户测不出差异。

## 常用操作的大图标按钮范式（运行/停止，2026-08-15 用户定稿）

常用操作（运行/停止）**不要文字大按钮，也不要和普通工具图标同尺寸**——「应该是一个大三角和大方块」：

## 浏览器驱动验证 Vue UI 的坑（本会话实测）

- **实测前先确认 dev 进程与窗口活着**：`ps -W | grep -i patchybox`（空 = 进程没了）+ `curl -s -o /dev/null -w '%{http_code}' http://localhost:1420/`（`000` = vite 已死）。dev 退出后所有 capture/click 都是空转，还会拿着过期界面状态判断「改动没生效」。后台重启 `pnpm tauri dev`，等输出出现 `Running `target\debug\patchybox.exe`` 再操作（vite ready 只代表前端就绪，窗口还没起）

## 并行会话精确暂存共享文件

`git add -p` 在非交互后台 shell 会被 SIGINT（exit 130）。共享文件（如 `plugins/index.ts`，他人会话也加了行）用手写 unified diff + `git apply --cached` 只暂存自己的行：从 `git diff` 输出抄上下文，删掉别人的 `+` 行、保留自己的，heredoc 传入。验证 `git diff --cached` 确认只含自己的改动后再提交。

- **他人已暂存的改动会被我的 commit 卷走（2026-09-08 实测）**：`git add <我的文件>` 只加自己的文件，但对方会话预先 `git add` 暂存的内容（如目录重构的 rename）会随我的 commit 一起提交。提交前必须 `git status --short` 看左侧暂存列；误卷后恢复 = `git reset --soft HEAD~1`（回到暂存态）+ `git commit -m ... -- <只我的文件>`（pathspec 提交不动他人暂存区）。
- **审查他人改动时工作区可能是活体（同日实测）**：审查中途对方提交，diff 目标从「未提交」变「某 commit」；甚至文件停在未闭合字符串的中间编辑态（eslint/vue-tsc 报语法错但马上又消失）。审查前先 `git log -3 --format='%h %ad %s' --date=format:'%H:%M'` 确认最近提交时间，几分钟内有新提交就先停手问用户归属。

## SSH 文件模块·本地路径与元数据展示坑（2026-09-08 实测）

- **Windows 路径规范化必须下沉后端，前端禁做字符串手术**（用户纠偏「不要自己研究，先看开源实现」）：`ssh_local_list` 入参为空/`/`/`\` 时返回驱动器列表——「此电脑」是 Shell 命名空间式虚拟层（WinSCP/FileZilla 本地侧同款），由文件系统抽象自身处理。前端逐层打补丁曾连环踩坑：① `C:` 裸盘符是「该盘当前目录」而非根，必须补成 `C:\`；② `read_dir('/')` 在 Windows 静默解析到当前盘根（表现为「切不了盘」）；③ 驱动器视图哨兵 `''` 是假值，`:disabled="!parentPath"` 和 `if (parentPath)` 都误判禁用——合法上级用 `!== null` 精确比较。规范化纯函数 `normalize_local_path` + 单测在 sftp/browse.rs。
- **SFTP 元数据展示**：权限位转 rwx 字符串（`drwxr-xr-x`，`format_permissions` 纯函数带单测，在 sftp/util.rs）——八进制 `40755` 用户看不懂；owner/group 两级回退 `user(名字) → uid/gid(数字) → "-"`——russh-sftp 的 `FileAttributes.user` 是 longname 解析名（多数服务器不给），`uid` 才是线协议标配。
- **UiTable 长文本截断：auto 布局 + 弹性列 `max-w-0` + 内容 `block truncate`**（完整值挂 title）；**勿用 table-fixed**——它按列声明宽度分配，无固定宽度的名称列在窄容器里会被分到 0 宽整列消失（2026-09-08 FileBrowser 实测：table-fixed 下默认窗口文件名全没，回退 auto + max-w-0 后正常截断）。大小/时间等数据列补 `whitespace-nowrap` 防换行。
- **错误信息带操作对象上下文**：`读取目录失败: {e}` → `读取目录失败 [{path}]: {e}`——os error 123（尾点/尾空格目录名触发 legacy API 拒绝）这类只有看到具体路径才能定位。

## 文件管理器型页面架构模式（2026-09-09 SFTP 双栏增强定稿）

## UI 元素设计取舍：先调研同类产品，再改代码（2026-09-10 用户要求）

用户对某个 UI 元素说「不合适 / 再想想 / 是不是用处不大了」时，**不要凭直觉反复换图标或直接删**（本次连换两版图标都被否，调研后才定案）：

1. **先调研，不动代码**（用户原话「先不改代码，先看看方案」）。证据优先级：产品**官方文档** → **官方界面截图**（用 `vision_analyze` 看实物：`browser_exec` 打开官网/文档页，`js` 取 `document.images` 的 URL 再逐张分析；官网截图页常靠 JS 加载，`web_extract` 拿不到图）→ **产品论坛的一手讨论**（用户抱怨 + 维护者回应最能说明取舍理由）
2. **产出对比表 + 2-4 个候选方案 + 明确推荐**：表格列「产品 / 布局 / 中缝有无按钮 / 符号与位置 / 依据」；每个候选写清业界依据与被否风险，别只给一个方案
3. **候选方案做成可点选的 HTML widget**（写 HTML → `::preview{file=...}`，每个卡片挂 `data-hermes-send`）：用户点选即回话，省一轮来回
4. 用户点头后才改代码；换符号后 `search_files` 复查旧图标名是否还有引用，没人用的就从 UiIcon 注册表删掉（不留死注册项）

**删除入口（工具栏按钮/图标）比换符号风险更高，按三步走**：

1. **可达性核对**：删前把每个按钮的替代入口列出来，并检查替代入口在**所有状态**下是否可达——列表铺满时列表空白处的右键菜单点不到（用户自己报过的痛点），「上传文件/上传目录」这类只挂在空白菜单上的项会因此彻底失去入口；导航类（后退/上级）几乎没有替代（面包屑只能跳层级，回不到「上一个目录」），工具栏里一律保留
2. **删除范围交用户拍板**：删除属破坏性改动，用一次 clarify 给 2-3 档范围（推荐档排第一）让用户选，别自己认定「都删」等于删哪几个；**用户的取舍常比你的推荐更彻底**，默认他会选最精简的一档
3. **清事件转发链**：删按钮后 emit 声明 → 中间层转发 → 页面监听三处要一起清（逐文件 `search_files` 搜 `emit[(]|defineEmits|event: '` 确认无残留），否则留下死绑定；**但共享 handler 一个都别删**——同一批 handler 通常被右键菜单复用（页面里那个 actions 对象仍在引用），删 handler 前先 grep 该对象确认引用

### 「打开目录 / 在文件管理器中显示」类入口放哪一层（2026-09-12 用户否掉固定目录版）

**固定不变的目录**（插件自己的数据目录，如 `…\data\frp\profiles`）上挂「显示路径 + 打开目录」是低价值元素：路径值永远一样、长了还要截断，而界面里本来就有该目录的内容列表——为看配置文件去开资源管理器是绕路。用户会直接说「没啥用」，此时的正确处理不是辩解也不是照单全删：

- **默认形态 = 能力下移到条目**：删掉固定目录那一行，改在**条目右键菜单**加「在资源管理器中显示」，定位到那一个文件（`revealItemInDir(<dir>/<fileName>)`，来自 `@tauri-apps/plugin-opener`）——「这个条目在磁盘哪里」才是从列表点进去时真正想知道的。菜单里用分隔线独立成区（重命名/复制/备注 ─ **显示** ─ 删除），危险项仍排最后。
- **例外：路径由用户配置且会变的目录保留入口**（如设置页的「存储根目录」）——那里「打开目录」表达的是「去看我配的位置」，与固定目录不是同一件事，别顺手一起删。
- **入参必须是绝对路径**：列表项通常只带文件名，用列表提供的 dir 拼上；目录未解析或调用失败一律 toast，不要静默（否则又变成「点了没反应」）。
- **验证判据**：`computer_use list_windows` 出现新的 `explorer.exe` 窗口（标题 = 目标目录名）即成功，比截图取证更快更确定。

### 「有点丑 / 不够精致」类观感诉求：读参考实现的配方，别猜颜色

用户说某处「丑」时不要直接调色（本类诉求凭直觉改的第一版几乎必被否），按四步走：

1. **先判定参考对象是不是「某个公开包的配方」**：主题化组件（编辑器 / 终端 / 表格）的观感基本都能追到一个 npm 包。GitHub 网页编辑器（github.dev）底层就是 VS Code 引擎，其观感 = `@fsegurai/codemirror-theme-github-light` 与 `...-theme-vscode-light` 两个 MIT 包的配色 + 结构声明。用 `web_extract` 抓 `https://unpkg.com/<包名>/dist/index.js` 直接读源码拿精确色值与结构项 —— **只读配方不引包**（「编辑器类只引官方包」的约束不因调研而放宽）
2. **把差距量化成表**：字号 / 行高 / gutter 底色与行号字重 / 当前行底色 / 高亮 token 档数 / 关键字色 / 与本设计体系的契合度。「丑」不能停在形容词，必须落到「缺哪几条声明」
3. **候选按改动幅度分档，而不是随机配几套色**：① 色板一个不动、只补结构（最低风险）② 参考对象原味（说清它与本设计体系可能打架的地方）③ 贴本项目 token（**推荐档放最后并标推荐**，理由写足：不新造色相 / 暗色同步成本 / 与交互色同源）。放推荐档的论据要能被检验，不要只写「更好看」
4. **交付前数值自检**：逐方案读 `getComputedStyle`（fontSize / lineHeight / gutter 底色与字重 / 当前行底色 / 各 token 色）加 `scrollWidth > clientWidth` 溢出判定，断言等于设计值 —— 数值探测比看图精确，顺带排掉错位与横向溢出

对照件的具体配方（伪编辑器 DOM 结构、变量块写法、样本代码要覆盖的 token 类型、点选按钮）见 `references/editor-theme-polish.md`。

#### 排版/布局嫌丑（与配色/主题嫌丑分开走）

「重新排版 XX 页面，现在比较丑」这类**整页排版**诉求，参照物换成本仓库自己的同类页面，不要先去翻 npm 主题包——一致性优先（用户红线「按照我们其他工具的风格来做」）。步骤：

1. **先读两份原文**：目标表单组件 + 它的子卡片（拿字段清单、字段数量、已有 label/placeholder/hint 的分布），以及本仓库既有的同类表单（如 `ssh/ServerForm.vue`）当范式基线——它决定分组方式（`UiField` 带 label + `space-y-[10px]`/`grid grid-cols-2`）、`font-mono` 用在哪、端口类字段走 `type="number"`。
2. **到真机把该形态切出来看实物**（`capture(mode='vision')`，先点进对应子页签，如「表单/源码」切换），别只凭模板代码判断观感。
3. **把「丑」拆成能指到代码行的缺陷清单**，高发四种：① **无分组容器**——只有小号加粗 `<h4>` 分节标题、字段直接平铺，标题与字段 label 视觉重量同级，分节形同虚设（正确形态 = 每节一个 `rounded-md border` 卡片 + 标题行 + 节内 `space-y`）；② **分栏错位**——短数值字段（端口）与长字段各占半列、开关独占半列留大片空白、末尾字段孤立半列；③ **子表单字段只有 placeholder 没有 label**——填完值就分不清哪个是哪个（数值类字段如 localIP/remotePort 尤其致命）；④ **同义控件重复**——同一卡片头尾各一个删除入口、同一句 hint 在每张卡片与页脚各说一遍。
4. **给 2-3 个 wireframe 候选让用户点选**：写 HTML → `::preview{file=...}`，每个候选一个「选 X」按钮挂 `data-hermes-send`；用真实控件尺寸画 minimock（36px 高、1px border、6px 圆角、`var(--card)/var(--border)/var(--muted-foreground)`），候选按改动幅度分档并给明确推荐，推荐理由要能被检验（与既有范式同源 / 改动面小 / 不新增交互）。
5. 顺手把第 3 步 ④ 类冗余一并清掉，不必等用户单独特地提。

同类产品对照与符号选型规则见 `references/dual-pane-transfer-ui.md`。

## 终端（xterm）内文案与断线提示（2026-09-10 用户定稿）

- **终端缓冲里的系统消息一律英文 OpenSSH 措辞，中文只留给应用 chrome**（用户原话「终端断开应该使用 ssh 断开的那种样式，显示中文显得不太专业」）：断开写 `Connection to <host> closed.` + `Press Enter to reconnect.`，重连打 `--- reconnected to <host> at HH:MM:SS ---`；不要装饰性破折号横幅，也不要黄色告警色（`\x1b[33m` 是告警语义）。状态栏、按钮、toast 仍写中文，两边不混
- **终端内文字颜色一律真彩色显式声明，禁 16 色槽位里的暗色档（尤其 `\x1b[90m`）**（2026-09-11 用户报「断开连接的这个颜色调一调」后纠偏，取代此前「系统消息统一暗灰 `\x1b[90m`」的写法）：客户端自己 `write()` 的系统消息，颜色由我们定，必须按背景算对比度——`\x1b[90m` 落在 xterm 内置 Tango 的 bright-black `#555753`，在 `#0d1117` 上只有 **2.59:1**，等同糊在背景里，「暗灰次要信息」这个意图在深底上它实现不了。定稿：关键行（`Connection to <host> closed.`）用品牌橙 `\x1b[38;2;240;86;44m`（`#f0562c`，5.47:1，与窗口 tertiary 同值），次要提示行与重连分隔线用中灰 `\x1b[38;2;139;148;158m`（6.15:1），每段结尾 `\x1b[0m` 复位；**准入线 ≥4.5:1，达不到就换真彩色值，别换槽位**
- **提示文案抽纯函数 + 单测锁定**（`useTerminalBanner.ts` 模式）：断言「不含 CJK 字符」「不出现 `\x1b[33m` 告警色」「不出现 `\x1b[90m`」与两个真彩色常量，措辞或配色被改回去立刻红；顺带测 host 缺失回退 `remote host` 与 24 小时制时间格式（`toLocaleTimeString('en-GB')`）。**已写入 buffer 的旧文本不会随配色改动重绘**——改完只能在下次触发该事件时肉眼确认，别把屏幕上的旧颜色当成改动没生效
- **断开事件会把 host 清空**（后端断开态 `ServerConnection.host = None`），而断线提示恰恰要写出对端地址 → 组件里缓存最近一次已知 host，别直接读 `props.connection?.host` 得到空
- **终端配色目前只覆盖 3 个值**（`background` / `foreground` / `cursor`），16 个 ANSI 槽位全部走 xterm 内置 Tango 调色板——`ls --color` 的目录蓝、报错红在 `#0d1117` 上对比度不足 4.5:1；用户说「终端颜色/符号不好看」时先查这里。补 16 色暗色主题、以及「提示符 / 关键字高亮」（远端 PS1 vs 客户端规则）的路线对比、实测对比度与 xterm API 事实见 `references/terminal-palette-and-highlight.md`
- **调色板主题化 + 远端 PS1 上色均已由用户搁置（2026-09-10）**：给出对比度实测与 One Dark 前后对比后，用户答复「那感觉不需要 现在颜色挺好的」（他能看到 `ll` 的颜色，只是接受现状）——保持 xterm 内置 Tango 槽位、不碰远端配置。**别再主动重提**这两条方案，只在用户自己说「某个输出看不清」时再翻 references 的路线对比；另注意终端承诺「先看方案」不等于会采纳，本会话四个方案的推荐档两次被实机观感否决
- 连接生命周期侧的兜底（会话句柄被回收后怎么重连、终端如何保留缓冲）见 `russh-ssh-development` 的「会话保活与空闲断开设计」

## 改 .vue / .css 的手法坑

- **每次 patch 之后立刻 `npx prettier --write <改动文件>`，再做 vue-tsc/eslint 校验**：patch 工具的模糊匹配会把替换块按错缩进写回（函数体整体多缩进 4 空格、注释被并进上一行、模板属性搬家），当次不报错、汇总门禁时才炸；prettier 一步清掉，别等最后统一跑
- **`patch` 的 new_string 会把转义序列当真实控制字符写进文件**（终端横幅写 `\r\n\x1b[90m…` 时实测）：参数里写 `\r\n`，落到文件里就是真实换行 + ESC，代码结构当场烂掉（diff 里能看到参数被折行、字符串跨界），而且 vue-tsc/eslint 之前不会提醒。规则：**转义密集的内容在参数里写双反斜杠**（`\\r\\n`、`\\x1b`、`\\t`）才拿到字面量；已成形的整块（如两个完整函数）改用 Python 脚本 `re.subn` 替换——`open(path, newline='')` 保留 CRLF、替换文本先 `.replace('\n', '\r\n')`，一次到位。改完 `read_file` 复核那一段
- **长脚本（改文件 + 跑门禁 + 提交一条龙）被中断后，先确认落盘到哪一步再动手**：`execute_code` 被 kill 时，它**已经执行过的写文件保留在工作区**（本次 `main.css` 已写成新值、只是没提交），误判成「改动没生效」就会重改一遍甚至重复提交。中断后的固定动作：`git status --short` + 直接读目标文件那一段，判定是「已写未提交」还是「未写」，只补缺的那步。

- **组件 emit 与监听必须成对，漏接是「点了没反应」的高发根因，且全部门禁都拦不住（2026-09-12 实测）**：用户报「左下角『打开目录』点了没反应」——`ProfileSidebar` 的 `emit('openDir')` 正常发出，父组件 `FrpWorkbench` 挂载它时**漏写了 `@open-dir`**，事件抛给空气。这类缺陷 vue-tsc / eslint / vitest / 契约测试全绿：事件名只是一段字符串，没有类型把它和监听方绑起来。排查路径：**从用户报的按钮文案反查组件里的 `emit(`，再确认父组件模板有对应监听**（注意 kebab-case——`emit('openDir')` 对应 `@open-dir`，`@openDir` 才是不生效的写法）；拿到根因后用 `search_files` 全仓库扫 `emit[(]` 与 `@<kebab>` 做同类普查（本轮扫描确认全仓库仅此一处；注意首版扫描器把 props 当 emits 会误报一片，只扫插件组件）。改组件 emit 契约（新增 / 改名 / 删除）时必须同步查监听方。
