# 01 · 技术选型

本文记录当前采用的技术与边界。具体版本以 `package.json`、`src-tauri/Cargo.toml` 及锁文件为准，不维护平行版本表。

## 桌面与平台

CoveKit 使用 Tauri 2 和 Rust，前端由系统 WebView 渲染，桌面发布目标为 Windows 与 macOS。Windows 使用 WebView2，macOS 使用系统 WebKit；不提供 Linux 安装包或功能支持承诺。

Tauri 提供窗口、托盘、单实例、对话框、剪贴板、存储与更新能力。平台原生适配按目标条件编译；不支持的能力必须明确反馈，验证状态见[平台能力矩阵](09-平台能力矩阵.md)。禁止引入 `tauri-plugin-shell`，系统操作按[系统能力边界](../adr/ADR-0001-禁用shell插件与系统能力实现边界.md)实现。

## 前端与公共 UI

| 技术 | 职责 |
| --- | --- |
| Vue 3、TypeScript、Vite | 界面、类型检查与前端开发构建 |
| Pinia | 应用级状态，工具内部状态按 owner 管理 |
| Tailwind CSS 4 | 使用 DESIGN tokens，公共样式集中维护 |
| Reka UI、shadcn-vue 源码模式 | 无障碍交互原语与公共控件组合，组件源码归 `src/core/ui/` |
| CodeMirror 6 | 公共代码编辑、只读查看与差异比较 |
| xterm.js | SSH 交互式终端 |
| vue-i18n、Fuse.js | 国际化与工具搜索 |

`components.json` 记录按需生成公共组件的目录配置。生成组件须适配现有 Ui API 和设计 tokens；业务工具不能直接复制公共控件或建立第二套编辑器。界面规范见[DESIGN](../../DESIGN.md)和[公共 UI 规则](11-插件UI开发约定.md)。

## 后端与数据

| 能力 | 技术与约束 |
| --- | --- |
| 异步任务 | Tokio；同步锁不得跨 await |
| 本地数据 | rusqlite 与统一 PluginDb，迁移追加并以事务执行 |
| 凭证 | 系统 keyring、AES-256-GCM；备份派生密钥使用 Argon2id |
| HTTP / SSE / WebSocket | reqwest、tokio-tungstenite；TLS 使用 rustls/ring |
| SSH / SFTP | russh、russh-sftp；认证策略见产品范围 |
| 数据库 | mysql_async、tokio-postgres、redis、rusqlite；部分类型使用外部 agent 协议 |
| DNS | hickory-resolver 与云服务商 API 适配 |
| 日志 | Rust log 与 tauri-plugin-log，在应用入口统一配置 |

路径和数据上下文归框架所有，工具不得独立推导数据根或跨 owner 访问内部表。数据库支持边界见[数据库设计](../plugins/database/设计.md)，凭证例外和导出范围见[产品需求](07-产品需求.md#当前有效范围裁决)。

## 工程与分发

pnpm 管理前端依赖，Cargo 管理 Rust 依赖，两份锁文件均入库。ESLint、Prettier、Vitest、rustfmt、clippy 和 Rust 测试承担相应验证职责；命令与执行边界统一见[验证矩阵](20-验证矩阵.md)。

CI 在 Windows 检查 Rust，并分别构建 Windows NSIS、macOS DMG。文档和前端检查可运行在 Ubuntu 执行器上，这不代表应用支持 Linux。发布使用 Tauri updater 签名产物与 GitHub Releases，更新签名和操作系统代码签名分别配置，见[发布与更新](06-发布与更新.md)。
