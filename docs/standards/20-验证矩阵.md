# 20 · 验证矩阵

> 何时读：实施前选择验证，提交前核对实际结果。档位只由[工作流](10-AI开发工作流.md)定义；任务书补场景，不复制命令。咨询没有开发门禁。

## 按变更选择

默认只验证受影响对象，不因文件数量、报告更新或角色交接全量重跑。失败需要更大复现范围或实际风险扩大时才增加检查。

| 变更 | 本地检查 | CI 或用户执行的行为验证 |
| --- | --- | --- |
| Markdown | 显式修改文件的链接检查、git diff --check；入口改变再查预算 | 文档链接与入口预算 |
| 文档检查器 | 隔离行为测试、相关文档检查 | 同一检查器回归 |
| CI | 变更分类负例、工作流语法与依赖/失败传播审查 | 实际工作流运行；本地审查不等于远端通过 |
| 前端逻辑或 UI | pnpm run check；局部格式化只限定本次文件 | 相关行为测试、交互与视觉检查；CI 完整 lint/test/build 与依赖守卫 |
| Rust 逻辑 | check_docs.py、check_rust_rules.py | fmt、相关测试、clippy；CI lib 与 source_rules |
| 持久化、密钥、上下文 | 相应语言静态检查与契约核对 | 旧数据夹具、并发、故障、重启恢复与相关平台场景 |
| 装配、权限、依赖 | 静态检查与消费方核对 | 构建、冷启动及平台差异验证 |
| 发布、跨层最终集成 | 发布配置与相关静态检查 | 前后端完整检查、平台冒烟及必要真实链路 |

## 文档命令（仓库根，无Cargo）

```bash
python scripts/check_markdown.py AGENTS.md docs/README.md
python scripts/check_doc_budget.py
python -m unittest discover -s scripts -p test_doc_checks.py
python -m unittest discover -s scripts -p test_ci_changes.py
python -m unittest discover -s scripts -p test_check_commit_msg.py
git diff --check
```

按上表选择，不是每次全部运行。check_markdown 不带参数时只查 Git 已跟踪的 Markdown；带参数可查本次新增文件。只检查显式本地链接与标题锚点，不验证外网、代码示例或实现语义。删除目标或改标题时扩大到引用方，必要时全量链接扫描。

入口预算保护 AGENTS 和文档地图声明的默认读取集合；普通文档超限只提示职责审查。台账已冻结，不再检查登记格式、状态 emoji 或实现 hash。检查器修改时才运行对应负例测试。

## 提交前门禁（本地）

[.githooks/commit-msg](../../.githooks/commit-msg) 在提交落盘前校验标题，规则与例外见[21-Git提交规范](21-Git提交规范.md)；[.githooks/pre-commit](../../.githooks/pre-commit) 按暂存文件类型跑本表第一列的检查：`.md` 走 check_markdown 与 check_doc_budget，`.rs` 走 rustfmt 与 check_rust_rules，前端与配置文件走 prettier。改文档的提交不触发 cargo，全部命中的最坏情况约 8 秒。

门禁不替代 eslint、类型检查、测试与构建。文档与前端检查按暂存清单选文件；rustfmt 与规范扫描作用于工作树当前的整个 crate，未暂存的 Rust 改动也会被一起检查，未跟踪文件不在范围内。工具不在 PATH 时打印跳过原因、不拦截提交，`git commit --no-verify` 是明确的跳过方式。新克隆需要执行一次 `git config --local core.hooksPath .githooks`。

## Rust命令（CI或用户手动）

```bash
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo clippy --manifest-path src-tauri/Cargo.toml --locked --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml --locked --no-default-features --lib
cargo test --manifest-path src-tauri/Cargo.toml --locked --no-default-features --test source_rules -- --nocapture
```

check_docs.py 是 Rust 注释扫描，check_rust_rules.py 是 Rust 规则扫描，均不检查 Markdown；source_rules 已覆盖两者，避免重复扫描。无默认 features 不表示关闭依赖默认 features。

## 本地与CI的分工

保留 2026-09-15 用户裁决：助手本地不执行 Cargo；产品编译和行为测试交 CI 或用户手动。本地按变更选择 pnpm run check 或 Rust 两个静态扫描，不因纯文档修改运行产品检查。检查器自身的轻量隔离测试属于本次工程工具验证，可在本地执行。

CI 将纯文档与文档工具变更分流；汇总任务“CI 结果”校验必要任务的成功/跳过状态，可作为分支保护入口，仓库远端设置不由本次自动变更。产品代码、依赖、构建配置、工作流与未知工程路径执行产品检查。标签发布仍独立执行完整发布门禁；纯文档分流不证明对应产品已重新测试。正式发布按发布流程执行，不以跳过测试宣称通过。

check_release_config.py 只在发布环境执行；缺发布密钥/公钥配置时不伪装成功。本地静态通过不代表编译或行为通过；远端未执行须说明。

## 证据与人工验证

证据明确提交、环境和等级：静态、单元/行为、真实链路、真机。历史结果不会因后续文档提交失效；是否适用于当前版本要核对相关代码、配置与环境变化。

2026-09-14/16 用户裁决继续有效：macOS 照常实现但无环境不做平台实测，差异见[09](09-平台能力矩阵.md)；人工与真机项目见[集中清单](../待人工验证清单.md)，不阻塞任务书收口，仍须声明未验证。用户已裁决不补的项目不重新强迫执行。

## 入口行为验收

规则调整后核对：咨询零写入；小修无需管理文档；大任务先确认范围与方案；接手可找到下一步；实质偏离先确认。检查通过不能替代这些行为判断。
