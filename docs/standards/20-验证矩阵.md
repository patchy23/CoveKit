# 20 · 验证矩阵

> **何时读**：实施前选择验证、提交前执行。此处是现行命令要求唯一来源，任务书补具体场景。

## 先定档，再选行

**档位与[工作流](10-AI开发工作流.md)同一套口径**：S1 小改直接做，S2 大修复先出根因分析，S3 框架级 / S4 新工具先出任务书与实现方案。

| 档 | 典型改动 | 必需验证 | 明确不要求 |
| --- | --- | --- | --- |
| S1 | 单文件小改、文案、注释、纯文档 | 下表对应行的「相关 / 定向」项，加本次文件格式检查 | 全量测试、build、冷启动 |
| S2 | 跨文件或跨模块、有契约或接口变化 | 下表对应行，加该语言全量测试与 build | 冷启动（除触碰启动路径） |
| S3 / S4 | 框架级、持久化/密钥/迁移、装配权限与运行依赖、发布 | 下表对应行全部，加夹具与故障注入、冷启动、平台登记 | — |

**默认只跑本档要求的行；未列出的验证不要求执行，禁止用「全都跑一遍」兜底。** 改一个小点却跑半小时到一小时的全量验证，与漏测同属缺陷。

越档只有两种正当情形：本次改动实际触及了更高档的东西（例如文档改动顺带改了脚本），或本档验证失败、需要更大范围复现。事后发现漏跑，补跑并在验收记录写明即可，不靠全量预防。

声称的证据等级不得高于实际执行：静态核对 / 单元或行为测试 / 真实链路 / 真机，各自写明；未做的写「未验证」，不得用「理论上支持」或别的档位的结果替代。

## 按变更选择

| 变更 | 必需验证 |
| --- | --- |
| Markdown/导航/裁决/台账 | check_markdown、check_progress、check_doc_budget；本次文件格式与git diff --check，不编译Rust |
| 文档检查器/CI | 上述检查+test_doc_checks负例；审CI环境、完整历史和失败传播 |
| 前端逻辑 | 相关行为测试、pnpm lint、pnpm build；批次收尾pnpm test和pnpm check:deps |
| UI | 前端项+相关组件/交互/视觉检查，基础Ui按需无业务服务挂载 |
| Rust逻辑 | cargo fmt只读检查、相关测试、clippy all-targets；批次收尾lib与source_rules测试 |
| 持久化/密钥/上下文 | 旧数据夹具、并发/故障/重启恢复；相关平台实测 |
| Tauri装配/权限/运行依赖 | 相关构建与pnpm tauri dev冷启动，Windows/macOS分别登记 |
| 发布/跨层最终集成 | 前后端全量lint/test/build、格式/依赖守卫、文档检查、平台冒烟 |

用户明确豁免的平台/场景记“已裁决不补，未验证”，不能写通过。外部服务缺项不阻塞独立自动化，但不得由mock结果冒充真实协议通过。

## 文档命令（仓库根，无Cargo）

```bash
python -m unittest discover -s scripts -p 'test_doc_checks.py'
python scripts/check_markdown.py
python scripts/check_progress.py
python scripts/check_doc_budget.py
git diff --check
```

check_markdown检查Markdown本地显式链接（含标题锚点）；代码围栏、模板占位符与外网链接不验证目标。反引号中的普通路径不当链接，现行模板路径另由回归测试核对。check_progress只证明登记结构和提交存在，不证明提交实现了该任务。

CI文档任务使用完整Git历史。文档格式化只写本次文件，CI用pnpm format:check；不要为过门禁停止用户应用。

## Rust命令（仓库根）

```bash
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo clippy --manifest-path src-tauri/Cargo.toml --locked --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml --locked --no-default-features --lib
cargo test --manifest-path src-tauri/Cargo.toml --locked --no-default-features --test source_rules -- --nocapture
```

`scripts/check_docs.py`仍是Rust注释扫描兼容入口，`check_rust_rules.py`仍是Rust规则入口；二者不检查Markdown。source_rules已同时覆盖二者，不重复执行同一扫描。当前无本包默认features，no-default-features不意味着关闭依赖默认feature。

`scripts/check_release_config.py`只在发布流水线（`release.yml`）执行，校验更新公钥、下载地址与签名产物开关；本机无 `TAURI_UPDATER_PUBLIC_KEY` 时按设计失败，登记为“发布环境项，本机跳过”，不写成通过。

## 本地与CI的分工

**本地只做静态与格式，编译与测试进CI**。助手在本机执行 `pnpm run check`（eslint与prettier的只读合并入口）、`python scripts/check_docs.py`、`python scripts/check_rust_rules.py`；上述Rust命令段与本矩阵其余条目由CI执行，用户可在需要时手动跑。理由：本机全量编译占用时间远超单次改动所需，且与CI结论重复。

由此产生的证据缺口必须如实声明：本地通过只代表静态层与格式层通过，**不代表能编译、不代表用例通过**；写法、交付说明与验收记录都不得把本地绿灯表述成“已验证”。收口、发布、以及任何声明“可交付”的结论，以CI结论为准。

```bash
pnpm run check                     # eslint + prettier，本地唯一格式与lint入口
python scripts/check_docs.py       # Rust注释与文档规则
python scripts/check_rust_rules.py # 棘轮规则（候选数与基线比较）
```

## 四条读取路径验收

每次调整入口或分册，用以下任务核对：能找到裁决、规则、契约、验证与下一步；计数按实际读取章节去重，不要求一次读整个专题。

| 路径 | 追加读取 | 必须发现 |
| --- | --- | --- |
| 改按钮文案 | 11必读摘要、实际组件 | S1可直接做，语义token与可访问性保持 |
| 修IPC参数 | 02/03相关节、实际contracts/ipc/handler、19对应检查 | 权威契约、消费方、错误/事件映射，是否需要升S3 |
| 新增SSH能力 | 07a相关需求、TODO裁决、当前SSH批次 | ssh/config导入等本轮不做项不能被旧需求覆盖 |
| 接手批次 | 台账对应行与前置、批次方案/最近证据 | 实现与验收区分，用户已豁免不再追问 |

预算：默认集合≤15,000字符；单文档≤30,000字符/500行；历史例外有明确上限且不得增长。字符不是token。复杂任务新增读取面在验收记录列出，不以单文件达标替代整条路径检查。
