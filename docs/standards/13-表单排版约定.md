# CoveKit 配置类表单的排版约定

用户偏好 + 仓库范式，做配置/档案表单时直接套用。

## 一屏配完，其余收进「更多配置」

用户原话：「我们的目的是快速配出能用的，其他无关紧要的配置统一放在一个收起的『更多配置』中，使用默认值即可，大多数的时候不会去修改」。

- 表单**默认只露能直接跑起来的字段**；进阶/罕见字段收进默认**收起**的「更多配置」分节。
- 折叠内容用 **`v-show` 而不是 `v-if`**：收起再展开时已填值和滚动位置都还在。
- `core/ui` 里**没有**现成的折叠组件。仓库惯例是**给现有组件加档位，而不是新建组件**——`UiPanel` 就是靠新增 `collapsible` 档（chevron 指示 + 标题整行可点 + `Enter` 切换）承载折叠的。
  加档位时把新分支**包在开关里**：只有开启档位时才走 wrapper，关闭时走原渲染路径，否则会影响其余全部调用方（改 `UiPanel` 时仓内有 10 处调用）。
- 折叠边界要经得起「用户想不起来还有这一项」：收进去的应是**靠默认值就能跑通**的项，而不是偶尔要改的项。分组划完主动把边界报给用户确认，别自己拍板了事。

## 分节卡片排版

- 每个分节 = 一张带边框卡片 + 标题左侧橙色竖条（`bg-tertiary`）。
- **相关字段同行**，数值字段走窄列；开关与它的标签同行；不要让某个字段孤立占半列留白。
- 间距节奏：组内 8px / 组间 20px / 卡片间 20–24px。子卡片靠更浅底色 + 更紧凑内边距形成二级，别做出「卡片套卡片」的糊感。
- 条目型字段（数组元素）的子卡片里**每个字段都要有 label**。
- 删除入口**每个条目只留一处**；同类说明文案**只在页脚出现一次**，不要每张卡片重复一遍。

## 必填与提示

- 必填用 `*` 标注；**placeholder 只放示例值**，不要用 placeholder 写「可留空」这类说明。
- 可选说明文案放**字段下方**。同一表单里这两种范式必须统一——混用会被一眼看出来。

## 公共组件的一刀修复优先

同类缺陷往往同时存在于多个调用点：改 `core/ui` 一次全局受益，改完主动核对其它调用方是否仍走原路径。
