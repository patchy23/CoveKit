# 15 · 测试与走查

> 测试的目的：以合理成本发现会影响用户或后续修改的错误。命令和执行环境只见[20](20-验证矩阵.md)。不按每文件、每函数或覆盖率配额补测试。

## 哪些测试值得长期保留

- 业务规则与边界：解析、排序、路径规范化、SQL 生成、权限计算等，以具体输入和外部可观察输出断言。
- 故障与状态：保存失败不伪装成功，乱序响应不覆盖新状态，取消、重试、重复执行、卸载和资源释放；优先给已修复缺陷补能复现它的回归。
- 数据与跨层契约：事务、版本迁移、损坏恢复、隔离、密钥失败、真实 IPC 命令名及 wire args、注册与路由。跨语言边界的载荷测试有独立价值，即使 wrapper 很薄。
- 公共组件行为：受控更新、焦点、键盘、关闭、事件透传及元素引用。布局、拖动、颜色和滚动条效果需真实浏览器或 WebView，DOM 模拟器不能替代。
- 架构守卫：长期且明确的边界由一个权威检查器维护；同时有合法和违规夹具、扫描非空检查及可定位错误。已有 AST 检查器覆盖的规则不再复制正则版本。

## 不应机械增加的测试

- `1 + 1 = 2`、只确认对象存在、逐字段复写实现返回值的初始化占位用例。
- 仅验证内部函数调用顺序、类名或样式字符串，却宣称验证实际行为或视觉效果。
- 同一输入、相同失败原因在多层重复断言；多个 owner 虽用相似框架但有不同关闭策略时不属于重复。
- 只为一次搬移保留旧文件名黑名单、快照全部 DOM、固定文件数或规则数。迁移期对照可放 `.work/`；长期守卫应约束仍有效的能力边界。
- 对无独立逻辑的内部透传层逐函数建文件；已有消费方行为覆盖即可。删除前必须指出替代覆盖或说明该用例没有独立保障，不能因为慢或难修就删。

## 仓库与本地的边界

| 内容 | 位置 |
| --- | --- |
| 可重复的回归测试、检查器负例、最小确定性夹具 | 源码附近或 scripts，随实现提交 |
| 可复用的真实服务集成测试 | 仓库；默认隔离或显式 opt-in，用环境配置，写明环境与副作用 |
| 一次性排查/迁移对照脚本、试验代码、原始截图和命令输出 | 被忽略的 .work/ |
| 覆盖率、浏览器报告、trace、安装包等生成产物 | 被忽略的输出目录或 CI artifact |
| 环境地址和真实凭证、用户数据副本 | 本地配置或临时目录；凭证不得入库 |
| 必须长期保存的缺陷复现数据或关键验收结论 | 最小脱敏夹具或简短摘要，说明来源与适用范围 |

“只在本地运行”不等于“不提交测试代码”。能帮助以后复现缺陷的测试应入库；只为本次排查服务的草稿不应入库。

## 编写与排查

1. 从用户行为和已确认契约定义预期，mock 外部边界，不 mock 掉被测逻辑。断言应能在相关行为错误时失败。
2. 每例隔离状态；清理 mount、监听、计时器、mock 和临时文件。进程全局状态优先隔离，无法隔离才用同一锁串行保护。
3. 异步优先等待明确状态、nextTick 或受控 Promise；不靠任意延时和重试掩盖竞态。
4. Portal 内容挂载到 body 后按 role、可访问名称或用户文案查找；不要 stub 掉实际待验证的浮层行为。断言元素不存在应显式失败，不用可选调用悄悄跳过操作。
5. 基线失败与本次回归分别说明。必要时隔离复现；不能清掉用户改动、篡改预期或降低门禁来制造通过。
6. 测试源码也受项目类型和运行环境约束；通过单测不等于通过构建、真实链路或平台验证。

## 真实交互与证据

浏览器和桌面验证按[11b](11b-浏览器驱动验证UI.md)选择可用工具。一次验证记录必要的提交/代码范围、环境和结论；静态、模拟行为、真实链路和平台实测分开表述。无需每次创建计划、矩阵和测试报告。

确需读取内部资源计数时，可以沿 2026-09-16 用户裁决提供 `import.meta.env.DEV` 门控的只读计数入口；只暴露本次有用信息，正式构建不包含、不改变业务行为，计数口径用回归验证。不要为方便测试新增生产后门。
