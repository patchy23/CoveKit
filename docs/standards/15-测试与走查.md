# 15 · 测试与走查（spec-driven plugin QA）

> 何时读：制定测试与走查场景。命令只见[20验证矩阵](20-验证矩阵.md)，定档只见10；本文示例工具名称按当前可用能力替换。

按需求与已确认契约制定预期，阅读实现定位风险。独立评审默认报告问题；已授权修复的执行者应完成修复与回归，不因测试角色停在报告。

## 按需测试

1. 阅读相关需求、当前方案、契约与调用链，不全量加载所有模块文档。
2. 选择隔离测试数据与环境，真实远端操作须已有授权；缺少环境如实说明。
3. 自动测试放源码附近，真实交互检查补充 mock 无法覆盖的路径。
4. 验证按[20](20-验证矩阵.md)选择；小修结果在会话与提交中，大任务阶段结果写已有方案。

## 坑（实测踩过）
- **执行中断**：需跨会话接续的核心用例与必要状态及时保存，接手先核对文件与提交状态，不假定某个助手固定调用次数或无上下文记忆。
- **覆盖矩阵汇总数必重数**：写完汇总表后按模块逐行重数状态数与优先级数（本会话曾把 44/24/82 错写成 40/27/81）。出错点：把部分"通过+备注缺陷"的行计错、把 X 边界用例漏计。
- **pnpm 路径**（Windows git-bash）：先 `export PATH="/c/Users/patchy/AppData/Roaming/npm:$PATH"`。
- **基线失败排查**：先核对失败路径与已知提交；必要时在隔离worktree复现，不在共享工作区stash/checkout他人改动。基线失败和本次回归分别报告，不能声称整仓全绿。
- **reka 弹窗/下拉内容在传送门里，组件测试必须挂到 body（2026-09-13 实测）**：`UiModal`（reka Dialog）内容渲染进 `document.body`，`mount()` 不挂 DOM 时 `wrapper.html()` 只有 `<!--v-if-->`，断言全落空；更坑的是 `stubs: { teleport: true }`——它会替换 reka 自己那个名为 `Teleport` 的组件，把整棵内容吞掉，看起来像「组件挂载不出东西」（曾据此怀疑组件缺陷）。正确姿势：`mount(Comp, { props, attachTo: document.body })` → `await nextTick()` → 用 `document.body.querySelector(...)` 取内容与按钮，输入框用原生 `value` + `dispatchEvent(new Event('input'))` 驱动 v-model。
- **测试代码禁用 `Array.prototype.at()`（2026-09-13 实测）**：vitest 跑得动，但 `pnpm build`（vue-tsc 按项目 lib 目标）报 `TS2550 Property 'at' does not exist on type ...`，整条前端门禁红。取末元素写 `arr[arr.length - 1]`。
- **write_file 语法检查误报**：可能因 MSYS 路径转换报 TS6053 file not found——文件其实已写入，以实际 `pnpm test` / `pnpm lint` 结果为准。
- **dev server 端口占用**：1420 被占时先 `curl -s -o /dev/null -w "%{http_code}" http://localhost:1420/`——若已有 dev server 在跑就直接复用（浏览器访问 + HMR 反映最新代码），不要盲目再起一个。
- **读到的疑似密钥字面量已被脱敏，不可照抄（2026-09-14 实测）**：read_file 与终端输出会把疑似密钥/口令的字面量改写成占位符，照抄进新文件会让夹具字符串走样、断言失败（本轮搬迁 `vault/store.rs` 时 `mask_secret` 用例即因此报错）。搬迁含样例密钥的代码时改为运行期拼装（如 `format!("AKIA{}PLE", "X".repeat(10))`），或换自己的假值并同步期望。
- **进程级全局状态的用例必须串行（2026-09-14 实测）**：任务登记表这类全局静态在并行执行时会互相清空或占满上限，表现为单跑全过、全量跑随机挂两条。每个用例在同一把 `Mutex` 上取守卫并在用例结束前持有，不允许只靠 `reset()`。
- **改文件的行尾锚点（2026-09-14 实测）**：仓库工作区的 `.rs` / `.md` 为 CRLF，用脚本按行锚点改文件时锚点要按目标文件实际行尾构造，否则命中 0 次而静默不改；补丁报「找不到匹配」时先查行尾，不要接着换措辞重试。另注意 `docs/batches/<批次>/` 下的证据文档在 git 索引里是非文本条目，git 不做行尾归一化：工作区被改成 LF 或整篇重写，`git diff` 都会把整份文件算成改动。改这类文件用 `newline=''` 保留原行尾，并先 `git ls-files --eol <路径>` 看 `i/` 与 `w/` 两侧状态。
- **桌面容器里 `navigator.clipboard` 会弹 WebView2 权限提示（2026-09-14 真机走查实测）**：打包版点「复制诊断信息」后弹出「http://tauri.localhost 想要 查看复制到剪贴板的文本和图像 / 阻止 / 允许」，未点「允许」前剪贴板内容不变（前后读一次即可证明）、该提示还会占据页面文本；提示不出现在窗口截图里，只在应用窗口为前台时才看得见。结论：桌面路径统一走 `@tauri-apps/plugin-clipboard-manager`（数据库/SSH 早就是这么用的），`navigator.clipboard` 只留浏览器预览回退。
- **跨语言传递的值不能直接字面比较（2026-09-14 真机走查实测）**：框架规范化后回写的值与界面保存/显示的值常常只是写法不同（该缺陷出现在已移除的全局快捷键上：框架写 `shift+control+Space`，界面持有 `Ctrl+Shift+Space`），`===` 必然不等，于是每台机器都误报「未生效」，而启动日志里并没有失败记录。比较前先规范化（大小写、修饰符别名与顺序）。夹具必须用框架的真实形态，写成人类形式会把缺陷一起掩盖。

## 浏览器实走查技巧（Vue 应用，accessibility 树信息不足时）
- `browser_navigate` 进应用 → 点工具卡片进工作区
- 用 `browser_console` 执行 JS 查 DOM：按文本找元素 `[...document.querySelectorAll('button')].find(b => b.textContent.trim() === 'X')`，点击后 `new Promise(r => setTimeout(r, 200))` 等渲染再断言
- 右键菜单：`el.dispatchEvent(new MouseEvent('contextmenu', {bubbles:true, cancelable:true, clientX, clientY, button:2}))`，再查叶子文本（连接/编辑/删除…）
- **UiTree 展开走 dblclick 且元素引用会失效（2026-08-15 实测）**：`el.dispatchEvent(new MouseEvent('dblclick',{bubbles:true}))` 触发展开；Vue 状态更新是异步的，展开后整树按钮重建，**必须先重新 querySelectorAll 再点下一个**，拿旧引用点击静默无效；断言前 `await new Promise(r=>setTimeout(r,50))` 等渲染。树节点 textContent 带图标字形前缀（◈库/◇schema/▸分组/▦表），精确匹配要用带前缀全文（如 `'◈patchybox'`）或 startsWith，同名节点（两个连接的 patchybox）按数组下标区分
- **失效按钮验证**：点击前后对比 DOM 指标（如终端区 `textContent.length` 253→253）证明按钮无事件绑定——这是高价值缺陷证据
- 空表单提交、toast 出现、表格行数、tab 切换、连接状态流转（未连接→连接中→已连接）均可用 JS 断言；深色模式等纯视觉项单独列"待人工目测"
- **要读正式版看不到的计数，就留 `import.meta.env.DEV` 门控的开发期取数钩子（规范，2026-09-16 用户裁决）**：订阅数、定时器数、生命周期活体数这类页内计数在正式版没有可观测面，走查要读它就在核心模块暴露只读计数导出，并在 `import.meta.env.DEV` 下挂到 `window.__pbXxx`。钩子必须只在开发构建存在、正式构建被摇除、只读且不改变业务行为，证据文档里写明钩子名与读数口径，计数口径写进单测钉住（口径错了走查结论会一起错）。

## 阶段 B：契约与端到端数据流审计
契约核对不能停在 `contracts.ts` 与 Rust struct 的字段名比对。建立完整矩阵：**命令常量 / Payload+Result / 前端 IPC wire args / IPC registry / `generate_handler!` / Rust command / 前端调用点**，报告每层差集、重复项和无调用命令。

事件另建矩阵：事件名 → Rust emit 点 → 实际 payload → TS listener 泛型 → 组件订阅/取消订阅 → UI 完成与错误反馈。重点检查异步命令是否只返回“已启动”，而完成事件无人消费。

专项必查：
- `{ payload: ... }` 等顶层包裹与业务 Payload 是否混为一型；不要把 `Record<string, unknown>` 称为类型安全。
- camelCase、missing/null/`Option<T>`、枚举实际值、`u16/u32/u64` 对 JS `number` 的范围/截断/精度。
- `Result::Err` 与 `ok=false+error` 是否统一；成功结果是否错误地携带 `error`；远程命令 exit status 是否丢失。
- 契约字段虽类型一致，后端是否长期返回 `0/false` 占位，或返回展示文本而前端按规范化枚举比较。
- Tauri 2 `Builder::invoke_handler` 是覆盖式 setter；多个插件各自注册时必须审查装配顺序，registry 清单不能证明命令真实可调用。
- “只审查、不修改”任务结束前用 scoped `git diff --exit-code` + `git status --short` 自证零改动。

每个发现固定给：严重级、`文件:行`、最小复现、修复建议；同时报告命令总数、各层覆盖数、死命令和验证命令结果。详细方法见 `docs/standards/19-Tauri契约审计.md`。
