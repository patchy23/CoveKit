# 设计任务书模板

> 复制到 `docs/batches/<批次号>/设计任务书.md`。本阶段做分析与设计，不写实现代码。
> 必读AGENTS、TODO、[模块规则](../03-模块开发规则.md)、[UI摘要](../11-插件UI开发约定.md#必读摘要)。

## 输入

项目、批次、用户原话、已确认范围与不做项、已有能力：<填写>。
必要时查DESIGN和实际core/ui组件；编辑器使用UiCodeEditor/UiCodeDiff，不参考已删除基座。

## 工作

1. 调研与当前问题直接相关的产品/机制，记录真实来源和适用条件，不以星数或数量充当方案质量。
2. 明确需求边界与取舍、关键状态和错误/取消流程、平台条件。
3. 设计UI与IPC（包括事件、错误、取消、资源所有权和数据兼容），核对现有框架消费方。
4. 给出任务书与实现方案，连同验收场景供确认；内部常规选择不反复上交用户。

## 产出

- 当前工具定义：`docs/plugins/<id>/需求.md`、`界面设计.md`，按需竞品分析。
- 本批任务：任务书、实现方案、契约草案、验收场景和必要待决策项。
- 草案若包含代码在隔离环境验证语法，禁止临时修改共享装配后整体checkout撤销。
- 报告选择理由、兼容风险与未定问题。未确认设计不得描述为当前实现事实。
