## 项目背景
- patchyBox：Tauri 2 + Vue 3 + TypeScript + Tailwind CSS 4 的桌面工具箱（uTools 风格），插件化架构
- 项目路径：<G:\workspace\patchyBox>（git-bash 环境）
- **开工前必读**（按顺序）：
  1. `AGENTS.md` —— 项目简报与架构规则（插件模式、契约规则、工程红线）
  2. `docs/standards/03-模块开发规则.md` —— 插件开发规则 v1（目录结构、IPC 契约、数据库规则、质量门槛）
  3. `DESIGN.md` —— 设计 tokens（色彩/字号/组件规范，单一事实源）
  4. `src/core/ui/` —— 可复用公共组件（CodeViewer / LineNumberTextarea / Select / Toast 等）
  5. `src/plugins/http-ws/` 与 `src-tauri/src/plugins/http_ws/` —— 现有最复杂插件样板（契约/封装/UI/会话模型）
- 设计约束：明净浅色·内容优先；交互驱动色 tertiary #F0562C；深色模式用 `-dark` token 变体；字号一律语义 token，禁止 arbitrary px；UI 自研，不引入重型组件库

## 产出物（全部落盘，6 个文件）
1. `docs/plugins/<id>/竞品分析.md` —— 功能矩阵 + 借鉴清单（含 star 数与仓库地址）
2. `docs/plugins/<id>/需求.md` —— 功能按 **P0（必须）/P1（建议）/P2（可延后）** 分级；含"边界：不做什么"；含契约分批建议
3. `docs/plugins/<id>/界面设计.md` —— 布局 ASCII 线框图 + 各模块交互设计 + 状态机 + 复用 core/ui 组件清单 + 需新增公共组件清单
4. `src/plugins/<id>/contracts.ts` —— 完整 IPC 契约草案（命令名 + 入参/出参 TS 类型；字段 camelCase；错误统一 `{ ok:false, error?:string }`；中文注释）
5. `src-tauri/src/plugins/<id>/models.rs` —— 对应 serde 结构草案（字段 `pub(crate)`，`#[serde(rename_all = "camelCase")]`；与 contracts.ts 逐字段对应）
6. `docs/plugins/<id>/待决策清单.md` —— 无法确定/需用户拍板的项；**每个问题给 2-3 候选方案 + 推荐**（必含关键安全/选型决策）

## 设计约束与规范
- 命令命名 snake_case 按功能分组；每条命令附中文说明（ipc_registry 入库格式）
- 会话型工具参考 http-ws 的 State 模式：`id → 会话句柄 + 后台任务`；敏感数据（密码/密钥）禁止明文落盘
- 全部文档与注释中文；代码标识符英文

## 验收标准（全部满足才提交）
- 6 个产出文件齐全、路径正确；竞品分析 ≥5 真实项目带 star
- 需求.md 含 P0/P1/P2 + 边界 + 分批建议；界面设计.md 含线框图 + 模块交互 + 状态机

- 命令清单 ≥15 条且全部带中文说明；待决策清单 ≥3 个问题
- **只新增** `docs/plugins/<id>/`、`src/plugins/<id>/contracts.ts`、`src-tauri/src/plugins/<id>/models.rs`，**不修改任何现有文件**
