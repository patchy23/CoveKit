# 测试任务书模板

> 复制到 `docs/batches/<批次号>/测试任务书.md`；按需求与已确认契约制定预期，阅读实现定位风险。
> 必读AGENTS、TODO、[模块规则](../03-模块开发规则.md)、[测试方法](../15-测试与走查.md)、[验证矩阵](../20-验证矩阵.md)。

## 输入

项目/批次/提交范围：<填写>；需求与设计：<链接>；契约：<contracts/ipc/Rust模型/事件>。
用户已裁决不补项：<来源、日期和范围>。没有条件不代表测试通过。

## 测试计划

- 需求→场景→用例→证据矩阵，覆盖正常、空态、错误、取消、并发、卸载。
- 阶段A：纯函数、composable及组件测试，mock外部IPC/事件边界，不能mock待测状态所有者。
- 阶段B：实际协议、平台与端到端交互；临时数据/隔离服务优先，远端需已授权。
- 静态契约检查验证命令与事件实际消费方，不能用注册表证明真实可调用。
- 所需环境、清理责任、实际命令、预期及失败证据：<填写>。

## 产出

批次目录的测试计划、覆盖矩阵、报告；源码旁的可运行测试。
区分实现缺陷和环境缺项，独立QA角色只报告问题；负责修复的执行者按授权单列修复。
报告命令/退出码/提交基线与局限，不用总数代替场景覆盖；当前进度只回填台账。
