# 任务书模板 · 测试

> 本文原为 AI 助手侧技能库中的项目知识，2026-09-13 迁入仓库，作为项目自有开发手册的一部分。正文未改写（仅同步文档路径与目录规范）。

> 使用：复制到 `docs/batches/<批次号>/测试任务书.md`，替换 `<占位符>` 后交给 delegate 的测试 agent（或独立会话）。
> 要点：**按需求文档和 UI 设计测，不是按实现测**；两阶段（后端完成前先测前端+写用例，后端完成后核对契约一致性）；不修改实现代码，问题写清单。

## 角色
你是资深 QA 工程师，按**需求文档和 UI 设计**（不是按实现）测试 <项目名> 的 <插件名> 插件。

## 项目背景
- 项目路径：<绝对路径>（<shell 环境说明>）
- **开工前必读**（按顺序）：
  1. `<docs/plugins/<id>/需求.md>` —— **测试依据①**（功能清单 P0/P1/P2 + 边界）
  2. `<docs/plugins/<id>/界面设计.md>` —— **测试依据②**（布局/交互/状态机/组件）
  3. `<src/plugins/<id>/contracts.ts>` —— 契约（含事件通道）
  4. `<docs/03-plugin-development.md>` §质量门槛
  5. 前端代码 `<src/plugins/<id>/>`（当前 mock 数据模式，UI 可测）
- 后端开发并行进行中（feature/<id>-backend 分支），**后端完成前先测前端与写用例**

## 任务目标
产出可执行测试 + 需求覆盖矩阵 + 测试报告，验证插件符合需求与 UI 设计。

## 测试依据（按此组织，不是按代码）
- 需求.md 的 P0/P1/P2 各功能
- 界面设计.md 的状态机（未连接/连接中/已连接/断开/重连等）、各模块交互、组件复用
- 边界清单（明确不做什么——不测边界外功能）

## 工作安排（两阶段）
### 阶段 A（后端完成前，先做）
1. **测试计划**：`docs/plugins/<id>/测试计划.md` —— 范围、环境（真实服务可用性评估）、用例分级（P0 必测/P1 应测/P2 可选）
2. **需求覆盖矩阵**：`docs/plugins/<id>/覆盖矩阵.md` —— 每条需求 → 用例编号 → 状态（待执行/通过/失败）
3. **前端纯函数单测**：为 `use<Xxx>.ts` 纯函数写 vitest 用例（放插件目录，用现有测试基建跑 `pnpm test`）
4. **UI 走查清单**：`docs/plugins/<id>/UI走查清单.md` —— 按 界面设计.md 逐项核对（布局/交互/空态/深色模式/反馈），mock 模式下记录"待后端接入项"
### 阶段 B（后端完成后）
5. **后端命令测试**：读 feature 分支代码，验证命令与契约一致（字段名 camelCase、事件名、错误结构）；能本地跑的 Rust 单测补充
6. **联调验收清单**：`docs/plugins/<id>/联调验收清单.md` —— 有真实环境时的手工用例（各功能一组）

## 输出物
- `docs/plugins/<id>/测试计划.md`、`覆盖矩阵.md`、`UI走查清单.md`、`联调验收清单.md`
- `<src/plugins/<id>/use<Xxx>.test.ts>`（可跑、通过）
- 阶段 B 后：`docs/plugins/<id>/测试报告.md`（覆盖矩阵结果 + 问题列表：编号/严重级/描述/复现步骤/证据）

## 约束
- **不修改实现代码**（除新增自己的测试文件）；发现问题写进问题列表，不自行修复
- 只新增以上文件；分支 `feature/<id>-qa`（基于 main，不合并）
- 测试文件也要过 lint + 全绿才能提交
- 提交信息 conventional commits 带 `<id>` 作用域；禁止 git add -A

## 最后一步
阶段 A 完成时输出总结：测试计划要点、覆盖矩阵规模、前端单测结果、UI 走查发现的问题清单（编号列表）。
