# 修复：一句话标题

> S2 大修复的根因分析模板。小体量修复可不落盘，直接把本模板内容写进给用户的确认消息。
> 存放路径：`docs/batches/<批次号>/fix-<slug>.md`（框架级修复放 `docs/fix-<slug>.md`）

## 现象与复现

- 现象：用户视角的异常表现（什么操作、什么结果、什么反馈缺失）
- 复现步骤：最小步骤，能稳定触发
- 影响范围：哪些功能/插件受影响，从什么版本或哪次改动开始（能查到就写）

## 根因

- 根因一句话：为什么会出现这个现象
- 定位依据：`文件:行` + 关键代码/日志证据
- 触发链条：从用户操作到出错的完整路径

## 修复方案

- 改动点：修哪里、怎么修（到函数/组件粒度）
- 同类排查：还有哪些调用路径有同样缺陷，是否一并修（必须回答，不能省略）
- 不改什么：明确排除的相邻代码（防止范围蔓延）

## 回归验证计划

- 全量门禁：`pnpm test` / `lint` / `build`；动 Rust 加 `cargo fmt` + `cargo clippy -- -D warnings` + `python scripts/check_docs.py`
- 功能回归：该功能的正常路径 + 出问题的路径各走一遍
- 受影响面：同类排查中改到的其他路径如何验证

## 结果记录（修完后回填）

- 验证结果：每条命令真实执行结果（通过/失败/受阻）
- 返修轮数：N/3（超过 1 轮要简述每轮失败原因）
- 遗留问题：未修的同类项、受阻项及解除条件
