# 16 · 多角色协作与交接

> **何时读**：任务明确需要委派、并行或跨会话交接时；普通任务不用读。
> 定档见[10](10-AI开发工作流.md)，验证见[20](20-验证矩阵.md)，进度只见台账。

## 何时委派

优先保持独立、边界明确的任务；只有任务或当前环境授权时才委派。没有可用多agent能力则串行完成，不假定助手工具名称、模型配置、调用次数或上下文继承。

角色可分为设计、开发、验收、集成；开发必须自测，独立验收补充需求视角。设计先冻结必要契约再拆任务；不因角色划分跳过测试或人为延后接线。

## 文件与集成责任

- 并行写入使用各自分支/worktree；工作区隔离不能消除语义冲突。
- 装配、公共契约、CI、台账等共享文件明确一个集成负责人。跨域契约变化先协调消费方，不各自加兼容壳。
- 同一工作区不得同时修改同一文件；他人的未提交/已暂存内容不能被自己的commit卷走。
- 提交前看整个暂存区和明确路径diff；只暂存自己的文件。误提交先记录HEAD和归属再制定恢复方案，不盲目reset，禁止清掉他人工作。
- 验证草案时用隔离目录或临时测试入口；不在共享装配文件临时加模块后用checkout整体撤销。

## 交接包

范围、起始HEAD、必要规则链接、当前契约、文件所有权、验收场景、已知问题、实际验证命令和输出位置。任务书用[templates](templates/)；按需摘必要规则，不复制全部规范。IPC包括事件、取消、错误和资源生命周期，不能仅列字段名。

接收方复核固定commit范围和实际消费方；返回key相等或重命名完成不能证明行为等价。具体方法见[18](18-重构与搬移验证.md)和[19](19-Tauri契约审计.md)。

## 进度与接手

只在台账维护当前状态；批次执行计划/报告记录带日期证据，TODO只记当前范围与裁决。接手先核对台账、Git与任务实际运行状态。文件20分钟没变化不能证明agent已停，编译或等待也可能没有源文件写入；用可用的任务状态或与原执行者协调。

用户已裁决“不补/自己测”时记录日期、适用范围和原文入口，不能改成验证通过。待确认项只暂停依赖该答案的工作，其他独立事项继续。

历史经验若需追查见Git历史；不将某个助手的调用上限、进程命令或模型限制写成项目长期规则。
