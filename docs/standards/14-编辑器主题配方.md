# 编辑器观感升级：基线、参考配方与对照件配方

用途：用户嫌 `UiCodeEditor` 观感丑 / 不够精致，或要把编辑器主题与参考产品对比时，直接用本文件的数据与手法，不要再从头调研。

## 现状基线（改动前先核对这些是否已变）

- `core/ui/editor/theme.ts` 的 `EditorView.theme`：字号 13px、行高 1.5、`.cm-content` padding 10px 0、`.cm-line` padding 0 12px
- gutter：`background: transparent` + `borderRight: 1px solid var(--color-border)`、行号 12px 常规字重
- `.cm-activeLine` 与 `.cm-activeLineGutter` 均为 `transparent`（**当前行没有任何高亮**）
- 语法高亮只有 7 个变量（`main.css` 的 `--cm-keyword/-property/-string/-number/-tag/-punct/-comment`），`--cm-punct` 与正文同为近黑 `#24292f` —— 标点、变量名、属性名、函数名全挤在同一档，整屏显得只有 4 档层次
- 括号匹配 = `outline: 1px solid`（生硬），tooltip 无圆角/阴影，滚动条未自定义

## 「精致度」来自哪些具体声明（缺哪条补哪条）

1. gutter 有底色、行号有 500 字重、行号列与内容区有明确分隔线
2. 当前行有底色且**行号格一起强调**（只有行底色会显得悬浮）
3. 字号 14px / 行高 1.6 起步（13px + 1.5 在浅色底上明显偏紧）
4. 匹配括号 = 底色 + 细边 + 圆角，不用裸 outline
5. 折叠箭头有 hover 变色；tooltip 有圆角与阴影；滚动条自定义（含 `-corner`）
6. 高亮档数 ≥ 7（标点/变量/属性名不能与正文同色）——**这是「偏黑白」的根因，改这一条收益最大**

## 对照件配方（可点选的 HTML widget）

- **一套 DOM + 每方案一个 CSS 变量块**：伪编辑器结构照抄 CodeMirror 类名（`.line` / `.ln` / `.lc` / `.line.active` / `.match`），token 用语义类（`.tok-kw/-op/-str/-num/-prop/-fn/-type/-cmt/-punct/-var`），每方案只写一个 `.t-x { --kw: …; --fs: …; }` 块 —— 样本代码只写一遍，方案改动与真实 `--cm-*` 改动 1:1 对应
- 样本代码要**覆盖多个 token 类型**（注释 / 关键字 / 字符串 / 数字 / 函数 / 标点），并标出一条当前行（含缩进，顺带展示缩进参考线）与一对匹配括号 —— 配色差异与结构差异一次看清；字号写真实 px，别为塞进卡片缩水（缩了就比不出 13 vs 14）
- 每张卡配「改动清单」+**采纳按钮 `data-hermes-send`**（消息内容写全方案要点，点一下就完成一轮回复）；推荐档卡片加高亮边框并标「推荐」
- 卡片容器用 widget 注入的主题变量（`var(--card)` / `var(--border)` / `var(--accent)`），**只有伪编辑器内部写方案自己的硬色值**（它模拟的就是应用面板）
- 交付前逐方案跑数值探针：`getComputedStyle` 取 fontSize / lineHeight / gutter 底色与字重 / 当前行底色 / 各 token 色，外加 `scrollWidth > clientWidth` 溢出判定；同时确认卡片数与关键行文本，别只看高度

## 选区：只有一条路径，浅深两档按对比度配平

- 编辑区选区**只由 CodeMirror 自绘层决定**（`drawSelection` 用 `hideNativeSelection` 把原生 `::selection` 强制透明），旋钮就是 `main.css` 的 `--cm-selection`；给原生 `::selection` 上色不会生效，反而在聚焦时叠出双层、比失焦更深
- `drawSelection` 的两条内置色（非聚焦 `#d9d9d9` / 聚焦 `#d7d4f0`）都需覆盖，且必须**聚焦与失焦分别实测**——只测一种会得出错误结论（失焦态曾被误判为「我们的颜色生效了」）
- 定稿值：浅色 `#79b8ff`（对白底约 2.0:1）、暗色 `#264f78`（对 `#161b21` 2.04:1）；选中词标记 `.cm-selectionMatch` 取同色更淡一档
- 配平依据：用户认可暗色 2.04:1、否掉浅色 1.52:1 → 同一元素跨浅深两主题时按**对比度比值**对齐，不靠肉眼「看着差不多」。浅色可在这些档位里挑：`#add6ff` ≈1.5、`#79b8ff` ≈2.0、`#5aa9ff` ≈2.5、`#3d8bfd` ≈3.0（比值以脚本现算为准，别背数）

## 落地注意

- 方案定了才动 `core/ui/editor/theme.ts` + `main.css` 的 `--cm-*` 区块；扩展 `--cm-*`（如加类型色 / 函数色 / 运算符色）要同步登记 `DESIGN.md`
- 暗色一份同步改，且必须写在 `main.css` 的全局 unlayered 区（`html[data-theme='dark']` 前缀），不要写进 SFC scoped 样式
- 只改主题不动组件结构、不改编辑器性能与分包：改完仍要过 `pnpm lint` / `test` / `build`，并确认 `vendor-editor` gzip 体积没有明显上涨
