# 双栏传输 UI：同类产品对照与符号选型

用于双栏文件管理页（SSH 文件页为首个实例）的中列按钮、上传/下载符号、工具栏按钮取舍决策。

**结论先行**：方向类符号一律**箭头指向目标栏**；中缝放不放按钮两种范式都成立。**本项目定稿 = 中缝两个最简裸箭头**（`arrow-left` / `arrow-right`，无文字标签、无配色，完整语义写悬停 `title`）——下表与选型规则里的「配文字标签」是业界（WinSCP）做法，本项目实机复看后判为过重，见规则 2/3。

## 对照表

| 产品 | 布局 | 中缝有传输按钮 | 上传/下载符号 | 位置 |
|---|---|---|---|---|
| WinSCP（Commander 双栏） | 本地左 / 远程右 | 无 | 箭头指向目标栏（Upload = 箭头指远程、Download = 箭头指本地）+ 文字标签，无颜色区分 | 各自面板工具栏 |
| WinSCP 旧版（论坛用户怀念的那版） | 同上 | 有，两栏中间并排 | 蓝箭头→ = 上传、绿箭头← = 下载，带文字 | 中缝 |
| FileZilla | 本地左 / 远程右 | 无 | 工具栏图标 + 右键 Upload/Download + 拖拽 + 双击 | 顶部工具栏 |
| Xftp | 本地左 / 远程右 | 无 | 拖拽 + 右键 + 命令菜单 | — |
| ForkLift（macOS） | 双栏 | 无（偏好里可开） | 工具栏「文档 + 外指箭头」= Copy To / Move To | 工具栏 |
| Total / Double Commander | 双栏 | 无 | F5 功能键 + 工具栏按钮 | 工具栏 / 功能键 |

## 一手依据（可复查）

- WinSCP 论坛帖「Upload and Download buttons placement」：用户回忆旧版「箭头指向文件将要被传去的那个窗口，非常直观，不用按上下箭头去想」，并指出旧箭头能并排放在两栏中间；维护者回复会考虑该诉求。
- WinSCP 论坛帖「Lets Talk About Those Upload & Download Buttons」：用户嫌箭头太细、要更粗并可移动位置；**维护者的反驳是本条最重要的设计依据** —— 上传/下载按钮靠它们的文字说明（caption）才显眼，其它按钮都没有。
- WinSCP 官方 Commander 界面截图：Upload 在本地栏工具栏、图标指向右（远程）；Download 在远程栏工具栏、图标指向左（本地）——**方向是「指向目标栏」，不是固定上/下箭头**。
- FileZilla wiki 教程的窗口布局图例只有 Toolbar / Local pane / Remote pane / Transfer queue，没有中缝按钮。

## 选型规则

1. 箭头指向目标栏（几何即语义）；不要用固定 up/down 箭头表达左右两栏之间的传输。
2. **裸箭头是本站定稿**：16px 下「◀ ▶」确实可能被读成翻页 / 上一步下一步，业界解法是配文字标签（WinSCP 靠 caption 让这两个按钮显眼）；本项目试过「标签 + 上传侧配色 + 抵线箭头」的加强版，**用户看实机后要求回到最简裸箭头**——补救走悬停 `title` 写全（「上传到远端：把本地选中的文件/目录传到左侧远端当前目录」），不加可见标签与配色。
3. **备选加强形态**（用户明确要求「更醒目」时才用）：图标换 lucide 抵线箭头 `ArrowLeftToLine` / `ArrowRightToLine`（语义「推到对侧那一栏」，回应论坛那条「箭头太细」的抱怨），配「上传 / 下载」文字标签 + 上传侧 `text-tertiary-strong dark:text-tertiary-dark`，中列需加宽到 `w-[58px]`；从加强版撤回最简版时，同步删掉 UiIcon 里只服务于它的注册项。
4. 中缝按钮的多选语义要显式处理：单项走单选链路、多选走批量链路（否则多选时报「请先选择文件」）。
5. 工具栏按钮与右键菜单重复时（下载 / 重命名 / 删除这类选中项操作），默认保留右键入口、精简工具栏；危险操作（删除）不进工具栏，与「危险操作走右键 + 二次确认」的既有偏好一致。**删到多彻底由用户拍板**：本项目的定稿是远程栏工具栏只剩「后退 / 上级 + 面包屑」，上传/下载/重命名/删除全部交给右键菜单 + 双栏拖拽 + 中缝按钮（同类产品普遍在工具栏保留上传/下载按钮，这是本项目刻意偏离业界的一点，别照业界把按钮加回来）。
6. **精简工具栏前先做入口可达性核对**：文件列表铺满时「空白处右键菜单」点不到，只挂在空白菜单上的项（上传文件 / 上传目录 / 新建）会因此失去入口——所以删这些按钮前必须确认中缝按钮、系统拖拽文件进窗口等替代路径仍然可用，并把这个取舍明确讲给用户。
7. **导航按钮不参与精简**：后退在所有同类产品的双栏工具栏里都存在，面包屑替代不了「返回上一个目录」；上级可被面包屑部分替代但仍保留（高频）。
