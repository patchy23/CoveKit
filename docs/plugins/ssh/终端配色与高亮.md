# 终端 ANSI 调色板与输出高亮

用于回答「终端颜色不好看 / 能不能给提示符上色 / 能不能像 Xshell 那样高亮关键字」这类需求，以及动手改 `TerminalTab` 的 xterm `theme` 之前。

## 现状事实（先查这里，别猜）

- `TerminalTab.vue` 的 `new Terminal({ theme: { background, foreground, cursor } })` **只覆盖了 3 个值**，16 个 ANSI 槽位继续走 xterm 内置调色板。
- xterm 内置值 = **Tango 调色板**（GNOME 桌面那套），定义在 `node_modules/xterm/src/browser/services/ThemeService.ts` 的 `DEFAULT_ANSI_COLORS`：
  dark `#2e3436 #cc0000 #4e9a06 #c4a000 #3465a4 #75507b #06989a #d3d7cf`，bright `#555753 #ef2929 #8ae234 #fce94f #729fcf #ad7fa8 #34e2e2 #eeeeec`。
- 远端程序输出的一切颜色都取自这 16 个槽位；服务端 PS1 若自己带 `\e[32m` 之类，用的也是这些槽位——**换主题时两者一起变**。

### 对比度实测（背景 `#0d1117`，WCAG 相对亮度比）

| 槽位 | 现状（Tango） | 现代暗色主题（One Dark 一类） |
|---|---|---|
| blue（`ls --color` 目录名） | `#3465a4` **3.19:1 偏暗** | `#61afef` 8.01:1 |
| red（报错 / grep 命中） | `#cc0000` **3.21:1 偏暗** | `#e06c75` 5.92:1 |
| green（root PS1 / systemctl active） | `#4e9a06` 5.36:1 偏土黄绿 | `#98c379` 9.39:1 |
| magenta | `#75507b` **2.87:1 几乎不可读** | `#c678dd` 6.43:1 |
| black（次要信息） | `#2e3436` **1.50:1 等同背景** | `#3f4451` 1.94:1 |
| brightGreen | `#8ae234` 11.72:1 **荧光刺眼** | `#98c379` 9.39:1 |

结论：Tango 在深色 GitHub-Dark 系背景上「暗的看不清、亮的刺眼」，与 `#f0562c` 主色不同族。

## 让终端「有颜色」的三条路线

| 路线 | 机制 | 代表产品 | 代价 |
|---|---|---|---|
| A 远端 PS1 配色 | 往 `~/.bashrc` / `~/.zshrc` 写 `PS1='\[\e[1;32m\][\u@\h \W]\[\e[0m\]$ '` | OpenSSH 生态；Xshell/FinalShell 用户手工配 | 要改远端（需授权）；readline 重绘 / Ctrl+R / 多行续行 / tmux 全对；多机各写一次；非 bash/zsh 另做模板 |
| B 客户端规则高亮 | 正则匹配输出 → 客户端渲染层着色，不碰远端 | Xshell / SecureCRT / MobaXterm / WindTerm / Royal TSX 的「突出显示集」；iTerm2 的 Triggers | 不碰远端、用户可配、能兼顾 error/warn/ok 关键字；要处理跨 chunk 断行、行内列偏移、buffer 滚出、刷屏限流 |
| C ANSI 调色板主题 | 补 16 色 + `selectionBackground` 的暗色主题 | 所有终端都有 | 半天量、零行为风险；**只在程序真的输出颜色时可见收益** |

**当前状态：A 与 C 均已由用户明确搁置（「那感觉不需要，现在颜色挺好的」）——别主动重提，只在用户自己说某段输出看不清时才翻本表。** 组合建议：C 先做（零风险，服务端 PS1 本来带颜色的机器直接受益）；A 用于自己的机器（一次配好终身正确）；B 只在「有很多不许改配置的生产机」时才必需。

## xterm 5.3 API 事实（做 B 之前必读）

- **没有官方的「正则 → 前景色」addon**。官方 search addon 只高亮搜索结果（background/border），`registerLinkProvider` 只能加下划线 + 可点击态。
- **`IDecorationOptions` 支持 `foregroundColor`**（还有 `backgroundColor` / `width` / `height` / `layer` / `overviewRulerOptions`，`#RRGGBB`）。所以 B 可以走官方 API：定位到行 marker + 列区间（`registerMarker` + `registerDecoration`）改前景色，**不必篡改输出流**。
- 点 `registerDecoration` 的代价：marker 绑 buffer 行，行滚出 / 被清屏后装饰失效；列区间要自己算（宽字符占 2 列）。
- 另一条路是「在 `term.write` 前注入 SGR 转义」，实现最短但 readline 重绘会丢色 / 重复（终端 buffer 是屏幕状态，不是日志流）。
- 别忽略内置选项 **`minimumContrastRatio`（默认 1 = 不调整）**：设 4.5 会自动提亮低对比前景，能救「偏暗」救不了「荧光刺眼」，且会让颜色不统一——与主题方案二选一。

## 边界（先说清，避免承诺做不到的事）

- **客户端做不到「命令一个色、输出一个色」**：客户端无法区分命令回显与程序输出，那是远端 shell 能力（fish 自带、zsh-syntax-highlighting 插件）。
- 机器输出本来就不带颜色时（默认 PS1 + `ls` 未带 `--color`），C 看不到任何差别——提 C 的收益时必须讲这个条件。
- 硬编码「识别 prompt 并上色」不是业界做法：Xshell 系走用户规则、iTerm2 走 Triggers，都是规则驱动。

## 客户端自己写的系统消息：着色必须走真彩色（实测定稿）

终端横幅、断线提示这类由客户端 `term.write()` 写进去的文本，颜色是我们自由决定的，所以必须按背景算对比度，不能沿用「服务端输出什么就用什么」的思路：

- **`\x1b[90m`（bright black）在本项目不可用**：它落在 Tango 的 `#555753`，在 `#0d1117` 上只有 **2.59:1**，用户看到的反馈是「断开连接的这个颜色调一调」。16 色槽位里的暗色档在深底上一律读不出来，别拿它们表达「次要信息」。
- **定稿值（真彩色，跨调色板稳定）**：关键行 `\x1b[38;2;240;86;44m`（品牌橙 `#f0562c`，5.47:1，与窗口 tertiary 同值）；次要提示行 / 重连分隔线 `\x1b[38;2;139;148;158m`（6.15:1）；每段结尾 `\x1b[0m` 复位。
- **自检**：任何新增的终端内文案，先算「前景 vs `#0d1117`」对比度，准入 ≥4.5:1；达不到就换真彩色值，而不是换槽位（槽位取值取决于用哪套内置调色板，随时会变）。
- **改配色后旧内容不会重绘**：已经写进 buffer 的文本保持原色，改动只能在下次触发该事件时肉眼确认——别把屏幕上的旧灰色当成改动没生效。
