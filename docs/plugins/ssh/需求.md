# patchyBox SSH 工具 · 需求文档

> 版本：v1.0（2026-08-08）  
> 来源：用户原话 8 项 + 竞品分析结论  
> 优先级定义：P0 = 必须（MVP 核心体验）；P1 = 建议（完整体验）；P2 = 可延后（锦上添花）

---

## 1. P0 必须（MVP 核心，契约第 1 批）

| # | 功能 | 一句话说明 |
|---|------|-----------|
| 1 | 服务器连接管理 | 侧栏列表展示已保存服务器，支持添加/编辑/删除/连接/断开 |
| 2 | SSH 终端 | 基于 xterm.js 的交互式终端，支持窗口 resize、Ctrl+C 等控制字符、滚动缓冲 |
| 3 | 文件管理（查看/上传/下载） | 远程目录列表 + 路径导航 + 文件上传（Tauri 对话框）+ 文件下载 |
| 4 | 凭证管理（密码/密钥） | 服务器配置含认证方式（密码 / 私钥 / 私钥+passphrase），**禁止明文落盘** |

## 2. P1 建议（完整体验，契约第 2 批）

| # | 功能 | 一句话说明 |
|---|------|-----------|
| 5 | 远程编辑文件 | 双击远程文件 → 下载到临时目录 → 本地编辑（CodeMirror）→ 保存自动上传 |
| 6 | 资源监控 | CPU / 内存 / 磁盘 / 网络 四卡片仪表盘，轮询刷新（默认 3s） |
| 7 | 服务管理 | systemd 服务列表 + 状态筛选 + 启动/停止/重启/查看状态 |
| 8 | 进程管理 | 进程列表（PID/用户/CPU%/MEM%/命令）+ 排序/搜索 + 结束进程确认 |

## 3. P2 可延后（契约第 3 批或后续迭代）

| # | 功能 | 一句话说明 |
|---|------|-----------|
| 9 | Docker 容器管理 | 容器列表 + 启停 + 查看日志 + `docker exec` 进入终端 |
| 10 | 终端分屏 | 单页签内左右/上下分屏，同时操作多台服务器 |
| 11 | 快速命令 | 预定义常用命令（如 `tail -f /var/log/nginx/access.log`），一键发送 |
| 12 | 终端主题自定义 | 字体/字号/配色方案选择 |

## 4. 边界：明确不做什么

| 不做项 | 理由 |
|--------|------|
| SFTP 拖拽可视化（本地↔远程双栏拖拽） | 桌面端 Tauri 文件对话框已够用，双栏拖拽交互复杂且与 patchyBox 轻量定位不符 |
| 网站/数据库/计划任务/防火墙管理 | 1Panel 领域，超出 SSH 工具边界，patchyBox 有独立 DB 插件 |
| 多语言 i18n | 第一批仅中文，i18n 框架预留但不实现 |
| 服务器分组树 | 第一批平铺列表 + 搜索，分组树 P2 再议 |
| 终端录制/回放 | 安全与隐私风险高，且非核心需求 |
| SSH 隧道/端口转发 | 高级功能，第一批不做，契约预留扩展字段 |

## 5. 契约分批建议

| 批次 | 范围 | 命令数 | 说明 |
|------|------|--------|------|
| **第 1 批** | 连接 + 终端 + 文件管理 | ~14 条 | P0 全部：连接生命周期、终端数据流、文件列表/上传/下载 |
| **第 2 批** | 凭证 + 远程编辑 | ~6 条 | 凭证 CRUD（加密存储）、远程文件打开/保存 |
| **第 3 批** | 监控 + 服务 + 进程 + docker | ~10 条 | P1 + P2：监控轮询、systemd 服务、进程列表、docker 容器 |

> 第 1 批契约冻结后，agent2 可先开发终端与文件管理；第 2/3 批契约并行设计，不阻塞开发。

---

## 6. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 终端输入延迟 < 50ms（本地回显），文件上传进度可见 |
| 安全 | 凭证加密存储（stronghold / 系统钥匙串），终端数据不落盘，断开自动清理会话 |
| 稳定性 | 断线自动检测 + 重连提示，会话异常退出有 toast 反馈 |
| 可维护性 | 契约与 serde 逐字段对应，Rust 注释覆盖率 100%（结构体/函数/属性） |
