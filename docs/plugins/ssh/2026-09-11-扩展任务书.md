## 0. 总则（每批都适用）

- 语言：文档与代码注释中文；代码标识符英文。
- 前端只用语义 token（`text-caption`/`text-body`/`text-card-title` 等），禁止 arbitrary `text-[*px]`；字体族 `--font-mono` 只用于明文数据（终端内容、路径、命令文本），UI 文案一律 sans。
- 公共组件只从 `@/core/ui` 取：按钮 `UiButton`/`UiIconButton`、输入 `UiInput`、面板 `UiPanel`、进度 `UiProgress`、空态 `UiEmptyState`、右键菜单 `ContextMenu`。契约测试（`nativeControls`）会拒绝原生 `<button>`/`<table>`。
- 所有用户操作必须有可见反馈（toast 或错误行），禁止静默 catch。
- 组件 300 行红线：**`TerminalTab.vue` 当前已 349 行（超红线）**，本批新增逻辑一律外置到独立组件/composable，不得再加重该文件；头部工具条是否另行拆分由用户决定，不在本任务书范围。
- Rust 规范 v1.1：运行期禁 `unwrap`/`expect`/`panic`；async 中禁 `std::fs` 阻塞（用 `tokio::fs`）；错误信息脱敏；新增依赖需过「四问评审」。
- 提交：Conventional Commits + 中文，标题自包含（读标题即知改了什么行为），只 `git add` 本批文件。

## 2. 批 2 · 右键「复制当前行」

### 2.1 现状

- `src/plugins/ssh/terminal/useTerminalContextMenu.ts`（74 行）已有 全选 / 复制 / 粘贴 三项；`openContextMenu(event)` 已经拿到 `MouseEvent`（现有代码只用了 `clientX/clientY`）。

### 2.2 语义（用户已确认）

**复制鼠标右击的那一行**，不是光标所在行。

### 2.3 实现

新增 `src/plugins/ssh/useTerminalLineCopy.ts`（纯逻辑 + 单测 `useTerminalLineCopy.test.ts`）：

```ts
/** 由右击坐标换算绝对行号（screen 高度恒等于 rows × cellHeight） */
rowFromMouse(term, event) → number | null
/** 取整行文本：沿 isWrapped 向上合并折行，行尾 trim */
lineTextAt(term, absRow) → string
```

关键点：

- 单元格高度 = `screen.clientHeight / term.rows`（`.xterm-screen` 元素），相对行 = `floor((event.clientY - screenRect.top) / cellHeight)`，绝对行 = `term.buffer.active.viewportY + 相对行`；越界返回 `null`。
- `line.isWrapped === true` 表示该行是上一行的续行，需向上一直合并到 `isWrapped === false` 的那一行；合并后 `translateToString(true)`（trimRight）。
- 合并折行的部分抽成纯函数（注入 `{ getLine }` 形态的 mock buffer），单测覆盖：单行、两行折行、三行折行、空行、缓冲区首行。

### 2.4 菜单与反馈

- `useTerminalContextMenu.ts` 的 `menuItems` 在「复制」下方插入「复制当前行」；`MenuState` 增加 `row: number | null`（打开时算好）。
- 复制成功 → `ui.toast('已复制当前行')`；该行为空/纯空白 → `ui.toast('该行为空')`，不写剪贴板。
- 写剪贴板失败 → `ui.toast('复制失败：<原因>')`（沿用现有 `copySelection` 的错误处理风格）。
- 动作完成后 `term.focus()` 归还焦点。

### 2.5 验收

- 执行一条超长命令（自动折行）后右击其中某行，复制结果拼接完整、无换行残留、行尾无多余空格。
- 右击不同行得到各自内容；右击空白行有「该行为空」提示。
- 复制后焦点回到终端，可直接继续输入。

### 3.2 Rust 侧

**新建 `src-tauri/src/plugins/ssh/system_info.rs`**（不塞进 monitor.rs：该文件加新解析函数会逼近 400 行红线）。

注册 `ssh_system_info_get(connectionId)` → `{ info: SshSystemInfo, disks: SshDiskEntry[] }`。

一次 exec 采集（用连接层现有的 `exec_collect`）：

```
LC_ALL=C hostname; echo ---; cat /etc/os-release; echo ---; uname -srm; echo ---; uptime; echo ---; nproc; echo ---; df -hlPT
```

要点：

- `LC_ALL=C` 避免不同 locale 下表头/单位变化。
- 磁盘用 `df -hlPT`：`-h` 人类可读、`-l` 只本地文件系统、`-P` 强制 POSIX 一行一条（**这是与裸 `df -h` 的关键差别：设备名过长时 `df -h` 会折行，把解析搞坏**）、`-T` 带文件系统类型列（列序：Filesystem Type Size Used Avail Use% Mounted on）。
- 解析函数写成纯函数并单测：`parse_system_info(&str)`、`parse_disks(&str)`。
- 缺失字段容错：无 `/etc/os-release`、无 `nproc`、`uptime` 格式异常时字段留空，不报错（返回部分数据好过整条失败）。

契约（`src/plugins/ssh/contracts/monitor.ts` 或新建 `contracts/system.ts`，与 `models/` 逐字段对应，注释中文）：

```ts
interface SshSystemInfo {
  hostname: string
  osName: string       // /etc/os-release → PRETTY_NAME
  kernel: string       // uname -srm
  uptimeText: string   // 运行时长（从 uptime 输出提取）
  loadAvg: [number, number, number]
  cpuCores: number
}
interface SshDiskEntry {
  filesystem: string   // /dev/sda1、overlay、tmpfs
  fsType: string       // ext4、xfs、tmpfs、overlay
  sizeText: string     // 人类可读（df -h 原文）
  usedText: string
  availText: string
  usePercent: number   // 0-100（去 % 后转数字）

}
```

### 4.1 现状与落点

### 4.2 Rust 侧

新建 `src-tauri/src/plugins/ssh/log.rs`：

```rust
/// 日志写入器（按终端绑定）
struct LogSink { file: tokio::fs::File, path: PathBuf, bytes: u64 }

/// TerminalHandle 新增字段（Arc 共享给后台任务）
log: Arc<tokio::sync::Mutex<Option<LogSink>>>
```

- `ssh_terminal_open` 时创建空 `Arc<Mutex<Option<LogSink>>>`，clone 一份进 `spawn_channel_task`。
- `ChannelMsg::Data` 分支：若 `Some(sink)`，`strip_ansi(&data)` 后 `write_all` + `flush`（终端输出块频率低，逐块 flush 保证异常退出不丢尾部）。
- 写盘失败：清空 sink + emit `ssh://terminal-log-error { terminalId, message }` → 前端 toast 并自动停止录制（**禁止静默**）。
- 命令：
  - `ssh_terminal_log_start(terminalId, dir)` → `{ path }`：目录不存在则创建；文件名 `<profile>-<host>-<yyyyMMdd-HHmmss>.log`，`<>:"/\|?*` 等非法字符替换为 `_`，同秒重名加 `-2` 序号。
  - `ssh_terminal_log_stop(terminalId)` → `{ path, bytes }`：flush + 关闭句柄。
- **ANSI 剥离**：自研纯函数 `strip_ansi(&str) -> String`（CSI / OSC / 单字符转义序列状态机，约 40 行）+ 单测，不引新依赖。规则：`\r` 丢弃（进度条覆盖类输出取最终态）、保留 `\n` 与 `\t`。单测覆盖：`\x1b[0m`、`\x1b[38;2;240;86;44m` 真彩色、OSC 标题 `\x1b]0;xxx\x07`、多序列混合、纯文本原样、折行与 `\r` 混合。
- 终端正常关闭 / 连接断开 / 应用退出时，若仍在录制则自动 flush 并结束。

### 4.3 前端侧

- 新建 `src/plugins/ssh/terminal/useTerminalLog.ts`：状态机 `idle → starting → recording → stopping`，持有 `path`，负责目录选择、命令调用、错误事件订阅、toast 文案。
- `TerminalTab.vue` 头部工具条（在「清空」左侧）加一个按钮：
  - 未录制：「日志」；点击 → 取目录（见下）→ `sshTerminalLogStart` → toast `日志已开始：<文件名>`。
  - 录制中：文案「停止日志」+ 前置红点（`danger` 色）标识录制中 → 点击 → 停止 → toast `日志已保存：<完整路径>`。
- 停止/断开后提供「打开所在文件夹」的入口（`@tauri-apps/plugin-opener` 已注册，`revealItemInDir`）——可选，若实现需在 toast 之外给一个显式按钮，不要做隐式行为。
- 终端按钮文案与状态放在状态栏右侧，避免终端可视区被压缩。

### 4.4 目录来源（依赖 §5）

日志根目录解析**只允许出现在一个函数里**，便于后续切换：

```rust
/// SSH 会话日志根目录：优先框架存储配置的 logs 分区，未配置时回落 app_data_dir/ssh-logs
pub(crate) fn ssh_log_dir(app: &AppHandle) -> Result<PathBuf, String>
```

- 框架存储配置就绪后：`<存储根>/logs/ssh`。
- 未就绪时：`app_data_dir()/ssh-logs`。
- 前端「记住上次目录」：仅在框架存储配置未就绪时需要；若配置已就绪则直接用配置目录，**不再单独记忆**（避免两套目录来源打架）。

### 4.5 边界与错误处理

| 场景 | 期望行为 |
| ---- | -------- |
| 目录不可写 / 被拒 | toast 明确原因（含路径），不开始录制 |
| 录制中连接断开 | 自动 flush + 停止 + toast 路径（断开横幅照旧写入终端） |
| 录制中关闭终端页签 | 自动 flush + 停止 |
| 磁盘写满 | 触发写失败路径 → toast + 停止录制 |
| 同一终端重复点开始 | 幂等：已在录制则忽略（或按停止处理），不产生第二个文件 |
| 多终端 | 各自独立文件，互不影响 |
| 文件轮转 | **本轮不做**（不做按大小/按天切分与压缩） |

### 4.6 验收

- 开启日志 → 执行 `ls -l`、`cat /proc/cpuinfo | head`、带颜色的 `ll` → 停止 → 打开文件：内容为可读纯文本，无 `\x1b[`、无 `\r` 残留。
- 断开连接后文件完整（含断开横幅文本），toast 给出完整路径。
- 写盘失败（可临时改权限或指向只读目录复现）时有明确 toast 且自动停止，无静默失败。
- 冷启动（`pnpm tauri dev`）无 panic；`cargo test` 覆盖 `strip_ansi` 各分支。

## 5. 依赖与顺序

**批 4 的日志目录**依赖框架级「存储目录配置」（独立任务书：`docs/tasks/2026-09-11-存储目录配置任务书.md`）。

两种接法，任选其一：

| 接法 | 做法 | 代价 |
| ---- | ---- | ---- |
| A（推荐） | 先做框架存储配置，批 4 的 `ssh_log_dir` 直接读配置 | 框架改动约 2 天，但日志文件从第一天起就落在用户指定位置，**免去日后迁移已有日志** |
| B | 批 4 先用 `app_data_dir/ssh-logs` 上线，配置就绪后改 `ssh_log_dir` 一行 | 上线快；日后要迁移旧日志（可接受，日志是易失数据） |

无论选哪种，`ssh_log_dir` 必须是唯一路径解析入口，任何地方不得手拼日志路径。

### 建议开工顺序

1. 批 1（终端搜索）→ 批 2（复制当前行）：纯前端，当天可验，先看到东西。
2. 批 3（系统信息 + 磁盘）：Rust 新命令，独立。
3. 框架存储配置（若走接法 A）→ 批 4（会话日志）。
