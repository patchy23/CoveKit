# dbx 项目参考：数据库树分派机制与图标资产

> 来源：G:\workspace\dbx（2026-08-15 阅读）。CoveKit database 插件的 9 类型树分层即按此机制实现，M3 接真实连接（MySQL/PG/Oracle/达梦/国产库）时继续参考。

## 关键结论：树结构随数据库类型分派

dbx 不为所有库用同一棵树，而是用「能力集合」决定层级，定义在
`apps/desktop/src/lib/database/databaseCapabilitySets.ts`：

- `SCHEMA_AWARE_TYPES`：有 schema 概念（postgres/oracle/dameng/kingbase/vastbase/sqlserver/gaussdb…）
- `TREE_SCHEMA_TYPES`：树上呈现 schema 层节点（postgres/redshift/kingbase/vastbase/highgo/uxdb/yashandb…）——连接 → 数据库 → **schema** → 对象分组
- `SINGLE_DATABASE_TYPES`：单库（oracle/dameng/firebird/oceanbase-oracle…）
- `CONNECTION_ROOT_SCHEMA_TYPES`（在 `jdbcDialect.ts`）：oracle / dameng / oceanbase-oracle——**连接根直接挂 schema（用户），无 database 层**
- MySQL 系：连接 → 数据库 → 对象分组（**无 schema 层**）
- Redis：`ConnectionTree.vue` 单独分派 `loadRedisDatabases`——连接 → db0~15 → keys

树节点类型 `TreeNodeType`（`types/database.ts`）约 40 种：connection / database / schema / table / view / procedure / function / sequence / synonym / package / type / extension… 加分组节点 `group-tables` / `group-views` / `group-functions` / `group-sequences` / `group-packages` / `group-synonyms` 等。对象分组也按类型过滤（只有 Oracle/达梦有 packages/synonyms/types）。

展开加载逻辑在 `components/sidebar/ConnectionTree.vue`（`ensureTreeLoadedForTarget`）：按 `config.db_type` 分派 redis/mongodb/es/vector/mq/nacos/默认，再用 `usesTreeSchemaMode(effectiveDatabaseTypeForConnection(config))` 决定走 schema 树还是直接 loadTables。

## CoveKit 落点（2026-08-15 实现）

`src/plugins/database/useDatabaseMock.ts`：

- `V2DbType` = 9 种；`DB_TYPE_META`（label + icon import）；`DB_TYPE_OPTIONS`（对话框九宫格）
- `SCHEMA_TREE_TYPES`（postgresql/polardb/kingbase/vastbase）→ `usesSchemaTree()`
- `CONNECTION_ROOT_SCHEMA_TYPES`（oracle/dameng）→ `usesConnectionRootSchema()`
- `objectGroupsFor()` 按类型返回分组定义（mysql 表/视图/函数/事件；PG 系加序列；oracle/dameng 加存储过程/包/同义词；sqlite 加索引/触发器；redis 键）
- `buildTreeForConnection()` 三种层级分派；schema 层连接的子节点 id 带 schema 前缀（`<conn>::<schema>::tables` / `<conn>::<schema>::table:<名>`）
