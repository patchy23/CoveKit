# 数据库工作台 · 界面模式与 mock 结构

> **何时读**：给数据库插件加界面、改对象树、写前端 mock 时。
> **本文讲什么**：数据库工作台当前布局、紧凑组件原则、补全与结果浏览契约，以及目录组织背景。
> **出处**：由 `docs/standards/11-插件UI开发约定.md` 的数据库专题迁入，随当前实现维护。

## 当前工作台布局与密度

- 数据库是高密度工作台：高频按钮、输入框、选择器、子页签优先使用 `xs`；数据网格保持 25px 行高，对象树保持 24px 行高。通过减少重复工具栏与留白提高密度，不继续缩小正文。
- 操作栏使用公共 `UiToolbar density="compact"`，右侧内容放 `#trailing`。普通调用不传 density 时保留公共工具栏原有尺寸。
- 新建连接放在左侧搜索框右侧；新建 SQL 查询放在页签栏末端，继承当前页签的连接及库/schema；已保存 SQL 的入口在其旁边。页签溢出仅预留实际容器内触发器的宽度。
- 连接表单使用紧凑字段：名称、类型、主机端口、用户名密码、默认库；环境、SSL、只读和超时放在默认收起的「更多配置」。凭证保存契约不随布局变化。
- SQL 编辑器的执行栏紧邻行号，保留折叠能力；窄查询工具栏将格式化和保存收进更多操作。摘要在窄窗口默认收起，用户选择通过工具设置保存；始终保留展开入口。
- SQL 补全在首次挂载即启用，并跟随补全源变化更新。当前库/schema 对象独立预取，不依赖手动展开树；列缓存按连接、库/schema、表名隔离，失败不缓存空结果，刷新目录或断开连接时失效。
- SQL 查询结果使用前端过滤和分页；复制、导出取全部筛选结果。表数据页使用后端分页，并区分加载中、空表与失败，显示返回耗时。DDL 使用公共只读代码编辑器。

## 数据库管理功能模式（2026-08-16 dbx 对齐批定稿）

- **管理类 SQL（建库/授权/DDL/索引/重命名/清空/删除）一律后端方言层构造**，前端只传选项参数：dialect trait 加管理方法（默认 `None` 不支持，mysql 主力实现、pg/sqlite 按需覆盖），标识符走 `quote_ident`、字符串字面量走 `quote_literal`（单引号转义）、权限入参白名单校验（readonly/readwrite/all → 固定 GRANT 文本），禁止前端拼 SQL 发 dbc_execute。
- **scope 入参约定**：`dbc_columns`/`dbc_table_data` 等的 `schema` 参数 mysql/polardb 传**库名**、PG 系传 schema、sqlite 忽略。页签 TabContext 的 database/schema 必须来自**树节点 id 的 scope 段**（`conn::scope::kind:name` 解析），不能取连接配置默认库——否则非默认库对象查看数据/结构全失效（本批修的 bug）。
- **DDL 预览用纯函数 + vitest 实测**（`createTableSql.ts` 模式：buildXxxSql 纯函数生成、单测覆盖标识符转义/非法输入丢弃）；默认值渲染自动判别（数字/NULL/TRUE/FALSE/CURRENT_* 原样，其余按字符串加引号），不给用户加「是否字面量」开关。
- **mysql_async 行转换会 panic 而非报错**（2026-08-16 实测拖垮 tokio worker）：预编译语句（exec/exec_first 带参）下 information_schema 的 BIGINT 列（如 TABLE_ROWS）到达时是 `Int`，`exec_first::<String>`/`query::<String>` 触发 FromRow panic（"Couldn't convert Row{...} to String"），NULL 同理。**标量/统计值一律 `exec_first::<Option<mysql_async::Value>, _>` 取值后用 `mysql_value_str` 转字符串再 parse**；行集用 `Vec<Row>` + `row.get::<Option<String>>` 逐列取。`.ok().flatten()` 兜不住 panic——类型选错在 from_row 阶段就崩。
- **危险操作三件套**：UiConfirmDialog 确认（文案写明不可恢复）→ 执行成功 `useUiStore().toast`（成功反馈不再借道 showError/errorHint，那是错误通道）→ 刷新该 scope 对象缓存 + 关闭受影响页签（drop/rename 后关掉旧表的 data/structure 页签）。
- **编辑器区域是多类型页签容器**（不只是 SQL 编辑器）：V2TabKind 已含 query/data/structure/redis/create-table，新页签类型 = 加 kind + DatabaseWorkbench 模板分支 + tabContexts 上下文。

## 数据库工作台 mock 结构（database 插件，2026-08-15 定稿）

- 目标数据库 9 种：mysql / postgresql / oracle / dameng / vastbase / kingbase / polardb / redis / sqlite（`V2DbType`）；`DB_TYPE_META`（中文显示名 + logo 图标）与 `DB_TYPE_OPTIONS`（新建对话框九宫格）集中定义在 useDatabaseMock
- **树层级按类型分派**（参考 dbx `databaseCapabilitySets.ts`，勿全类型一刀切）：PG 系（postgresql/polardb/kingbase/vastbase）连接→库→schema→分组；oracle/dameng 单库连接直挂 schema（用户）；mysql/sqlite/redis 连接→库→分组；redis 叶子是 key 不是表
- **对象分组按类型裁剪**：mysql 表/视图/函数/事件；PG 系加序列；oracle/dameng 加存储过程/包/同义词；sqlite 加索引/触发器；redis 键列表
- 连接节点图标 = 真实数据库 logo（`src/assets/db-icons/`，拷贝自 dbx `apps/desktop/public/icons/database/`；dm.svg→dameng、postgres.svg→postgresql、polardb 仅 .webp）——字母徽章配色方案已废弃删除
- 叶子节点 id 末段 `::table:<名>` / `::key:<名>`，schema 层连接的 id 带 schema 前缀；selectResource 用 `/::(table|key):(.+)$/` 末段匹配解析，勿用 split('::')
- 初始只保留查询页签；数据/结构页签全部由树点击动态创建（避免硬编码 tab 与动态 tab 并存重复）
- dbx 树结构分派机制细节（能力集合清单、图标资产目录）见 `docs/plugins/database/设计.md`
