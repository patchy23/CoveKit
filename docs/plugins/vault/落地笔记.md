# framework/vault 凭证库落地笔记（2026-08-16 会话）

设计书 `docs/plugins/vault/设计.md` §1–§5+§8 的落地实录与 Rust 踩坑。§6 SSH/DNS 迁移当时明确不做。

## 落地形态（as-implemented）

- Rust `src-tauri/src/framework/vault/`：`mod.rs`（6 命令薄层 + register + 校验）/ `models.rs`（serde）/ `store.rs`（主密钥 + 加解密 + 原子写）/ `export.rs`（Argon2id 备份）。
- 6 命令 `vault_list/save/delete/reveal/export/import` 挂 `framework/mod.rs` 的 generate_handler（`vault_` 前缀不与 plugins/mod.rs 的插件前缀冲突，自动走框架 handler）；register 在 lib.rs 装配一行。
- 数据模型：`CredentialFields` 用 serde 内部标签 `tag = "type"`，变体名 kebab-case（`#[serde(rename = "ssh-key", rename_all = "camelCase")]` 逐变体标），`Credential.kind` 冗余存储由后端以 `fields.kind()` 回填保一致。
- 主密钥 keyring 3.x：`Entry::new("com.patchy23.patchybox", "vault-master-key")` 返回 `Result`；**原始字节用 `set_secret`/`get_secret`**（`set_password` 要 UTF-8 字符串，32B 随机字节不保证合法）；缺记录 = `keyring::Error::NoEntry`（不是 Err 泛匹配）。
- 降级链：keyring → `vault-master.key` 文件 → 两处都无且 `vault.dat` 存在 = 报「无法解锁凭证库」**绝不重新生成密钥**（宁可锁死）；`vault_import` 路径先把读不出的 vault.dat 改名 `vault.dat.unreadable-<ts>.bak` 留档再按空库导入。
- 密文 `vault.dat`：`nonce(12B)‖ciphertext`，解密先校验 ≥28B；`replace_file`/`recover_backup` 从 `plugins/ssh/credential.rs` **复制**下沉（SSH 原文件未动，§6 迁移再切换）。
- 导出 `.pbvault` = JSON 信封：`version` + KDF 自描述参数（argon2 0.5，Argon2id，`Params::DEFAULT_*`，salt/nonce/ciphertext 均 hex）+ 密文；导入按文件内参数重新派生，调参不影响旧备份。
- `resolve()` 是 crate 内 API 非 Tauri 命令；`framework` 是 lib.rs 私有 mod，§6 迁移前无调用方，re-export 触发 `unused_imports` —— 用 `#[allow(unused_imports)]` 保留导出形状。
- 主密钥/存储函数全部拆 `_at(dir, store)` 目录参数版 + `MasterKeyStore` trait，单测注入内存桩（可注入读写失败模拟无桌面环境），不碰真实 keyring。

## Rust 踩坑（本会话实测编译错误）

- aes-gcm 的 `encrypt`/`decrypt` 错误类型是 `aes_gcm::Error`：`map_err` 必须给闭包 `map_err(|_| "…")`，直接给 `&str` 编译不过。
- `decrypt(nonce, &vec)` 不满足 `Payload` bound：`Vec<u8>` 要传 `ct.as_slice()`。
- 原始字节串字面量 `br#"…"#` **不能含非 ASCII**（中文）：用 `r#"…"#.as_bytes()`。
- **间接依赖不能 `use`**：uuid 虽被 tokio-postgres `with-uuid-1` 拉进 Cargo.lock，仍须在 `[dependencies]` 显式声明 `uuid = { version = "1", features = ["v4"] }` 才能引用（设计书「uuid SSH 已引入」说法不准确）。
- `cargo clippy --lib` 不带 `--tests` 时不编 cfg(test)：仅测试用到的 import 放 `mod tests` 里单独 `use`，否则 unused_imports 假警。

## keyring 静默丢写（2026-08-16 用户实测 bug，回归测试已入库）

Windows 凭据管理器存在 `set_secret` 返回 Ok 但条目没落库的**静默丢失**（实测：cmdkey /list 查无条目，vault.dat 却被没存住的密钥加密 → 下次启动永久无法解锁）。`create_master_key` 必须**写后立即回读比对**（`store.write` 成功后 `store.read` 不一致即视为未持久化），校验不过与写失败同路径降级 `vault-master.key`。回归测试 `silent_write_loss_falls_back_to_file`（内存桩注 `lose_writes`）。诊断手法：`cmdkey /list | iconv -f GBK -t UTF-8 | grep -i patchy` 查条目（cmdkey 输出是 GBK）；数据目录 `%APPDATA%/com.patchy23.patchybox/`。
