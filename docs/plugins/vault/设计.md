# Vault 凭证管理 · 设计（任务书）

> 定稿 2026-08-16，兼容策略更新 2026-08-24。本文档是 Vault 功能的唯一事实源，开发会话以此为准。
> 定位：**框架级能力，不是插件**（AGENTS.md「框架与插件分离」），落地 docs/02-architecture.md 预留的 secrets 抽象与 `secretRef` 引用模型。

## 1. 定位与边界

- Rust 侧：`src-tauri/src/framework/vault/`
- 前端入口：设置弹窗「凭证管理」区块 → 打开 workspace 页签管理界面
- **凭证只管"秘密"不管连接信息**：host/port/域名/库名留在各插件自己的 profile，vault 不变成第二个连接管理器
- 插件可在 profile/config 中保存 `credentialId` 引用；SSH/DNS 为兼容已有使用方式，同时保留原手工凭据路径。选择 Vault 时**明文不出 Rust 后端**

## 2. 存储与加密

### 2.1 主密钥（keyring 方案，2026-08-16 用户拍板）

- 首次启动 `OsRng` 生成 32B 主密钥，存**系统密钥库**（`keyring` crate）：
  - Windows → Credential Manager（DPAPI 绑定当前用户）
  - macOS → Keychain
  - Linux → Secret Service
  - service = `com.patchy23.patchybox`，account = `vault-master-key`
- **降级**：keyring 调用失败（无桌面环境等）→ 回退本地文件 `app_data_dir/vault-master.key`，启动日志告警
- keyring 只存这把 32B 主密钥，**凭证本体不进 keyring**（Credential Manager 单条 ~2.5KB 上限，放不下 SSH 私钥与全量凭证）

### 2.2 凭证密文

- AES-256-GCM（`aes-gcm` crate，SSH 已引入），每次加密新 nonce，落盘格式 `nonce(12B)‖ciphertext` → `app_data_dir/vault.dat`
- 解密先校验密文 ≥ 28B（12 nonce + 16 认证标签），损坏即报错不 panic
- **原子写 + 备份恢复**：复用 `plugins/ssh/credential.rs` 的 `replace_file`/`recover_backup`（临时文件刷盘 → 旧文件改 .bak → 替换 → 删 .bak；启动时恢复中断遗留），加密原语一并下沉到 framework
- 全量读改写用 Mutex 串行化

### 2.3 密钥丢失的处理（宁可锁死，不可误删）

- keyring 取不到密钥但 vault.dat 存在 → 明确报「无法解锁凭证库」（可能原因：换机/重装/密钥库被清），给「导入备份 / 重新初始化」两个选项，**绝不静默清空 vault.dat**
- 丢失影响 = 重填凭证（密码在用户脑子、API key 可重新签发、SSH 私钥有原件），非数据灾难

### 2.4 导出/导入备份（v1 必做，不等 v1.5）

- 导出：用户设一次性密码 → **Argon2id** 派生密钥 → AES-256-GCM 加密全量 vault → `.pbvault` 文件（换机迁移 + 灾难恢复）
- 导入：输入密码解开，合并/覆盖策略由 UI 让用户选

### 2.5 安全边界（如实写进文档与注释）

防「凭证明文落盘、文件被拷走即泄密」；不防「已登录当前系统账户的恶意进程」。stronghold（内存隔离）与主密码解锁是后续升级项，接入时只换存储/解锁层，数据模型与引用关系不变。

## 3. 数据模型

```rust
/// 凭证条目（vault.dat 解密后的数组元素）
struct Credential {
    id: String,                // uuid v4，引用方只存这个
    name: String,              // 显示名，如「生产 MySQL」「腾讯云 CAM」
    kind: CredentialKind,      // 类型枚举，决定 fields 结构
    fields: CredentialFields,  // serde tagged enum，按 kind 分派
    note: String,              // 备注（可空）
    created_at: i64,           // 创建时间（秒级时间戳）
    updated_at: i64,           // 更新时间
}
```

### 凭证类型（第一版 5 种，覆盖现有+规划工具）

| kind | 字段 | 使用方 |
|---|---|---|
| `password` | username + password | 数据库 9 类型、SSH 密码登录、HTTP Basic |
| `ssh-key` | username + private_key + passphrase(可选) | SSH 密钥登录 |
| `api-token` | token | HTTP 调试 Bearer、开放平台 token |
| `access-key-pair` | access_key_id + access_key_secret | 阿里云、腾讯云 CAM、CF API |
| `custom` | key-value 数组 | 兜底任意结构 |

数据库凭证**不单独设类型**（复用 `password`），避免类型爆炸。

## 4. 引用方式（核心机制）

- 插件 profile/config 可存 `credentialId`；选择 Vault 时不落插件私有明文
- **后端解析（默认路径）**：crate 内 API `framework::vault::resolve(app, credential_id) -> Result<Credential, String>`，插件命令（ssh_connect / db_open 等）在 Rust 侧解析后直接用于建连，**明文不过 IPC、不到前端**。此 API **不做成 Tauri 命令**
- **前端读取（例外路径）**：`vault_reveal` 命令仅在用户点「显示/复制」时调用；列表永远走脱敏数据

### 框架命令清单（全部入 ipc_registry）

| 命令 | 说明 |
|---|---|
| `vault_list` | 凭证列表（脱敏：id/name/kind/掩码摘要如 `AKI****xyz`/时间，无明文） |
| `vault_save` | 新增/更新（payload 结构体打包，id 可选 upsert） |
| `vault_delete` | 删除（返回被引用计数供前端提示） |
| `vault_reveal` | 读取单条明文（仅显示/复制场景） |
| `vault_export` | 密码加密导出 .pbvault（走 dialog 选路径） |
| `vault_import` | 解密导入 .pbvault |

## 5. 前端

- **SettingsModal** 加「凭证管理」区块：一行说明 + 凭证数量 + 「管理凭证」按钮
- **凭证管理页**（workspace 页签载体）：顶部类型筛选 chip + 搜索；列表列 = 名称/类型徽标/掩码摘要/更新时间；**右键菜单**（编辑/复制值/删除），删除走弹窗确认；编辑表单按 kind 动态渲染，秘密字段 password 输入框 + 眼睛切换
- **公共组件 `CredentialPicker`**（`src/core/ui/`）：按 kind 过滤的凭证下拉 + 末尾「+ 新建凭证」项（唤起表单保存后自动选中）；SSH/DB/DNS 表单统一接入
- 遵守字体/组件规范：font-mono 只用于掩码值等数据，UI 文字 sans；下拉用公共 Select；删除防误触

## 6. SSH / DNS 兼容接入（2026-08-24 用户决策）

1. **SSH**：`ServerProfile.secretRef` 可引用 `password` 或 `ssh-key` 凭证，`ssh_connect/ssh_reconnect` 在 Rust 内解析；未选择时继续使用 `ssh_credential_save/get/delete` 与插件私有 AES 文件，已有配置无迁移要求。
2. **DNS**：阿里云和腾讯云配置各增加可选 `credentialRef`，限定 `access-key-pair`；云 API 调用时 Vault 优先，未选择时继续读取 `dns.db` 中的手工 ID/Secret。
3. **切换语义**：选择 Vault 即优先使用引用；清空选择即回退手工路径。删除连接配置不删除可能被其他工具复用的 Vault 凭证。
