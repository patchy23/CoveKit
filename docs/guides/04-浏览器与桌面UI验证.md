# 04 · 浏览器与桌面UI验证

> 只在实际交互或视觉验证时读取。以当前可用工具及其说明为准，不假设特定助手 API、窗口标题、端口、坐标比例或缓存位置。

## 选择验证环境

- 纯前端页面可用浏览器预览；依赖 Tauri IPC、系统权限、窗口或原生拖动的行为，需要实际 WebView 或桌面环境。
- 先确认应用版本、开发服务工作目录和实例归属。Vite ready 或 HMR 无错误只证明服务更新，不能证明页面功能通过。
- 复用已确认属于本项目的合适服务。启动、重启和调试端口遵守用户授权与[验证矩阵](02-验证矩阵.md)执行边界；只清理由本任务启动的实例。

## 交互方法

- 优先使用工具提供的角色、可访问名称和实际点击；图像坐标仅在需要时使用，并按当前截图与窗口换算，不套旧会话比例。
- 每次状态变化后重新定位目标，等待明确可见条件；同名元素按所在面板或会话区分。
- Reka 浮层可能 Portal 到 body。查实际 DOM 和错误，不能一律归因于父元素 overflow，也不能因为能显示就认为可点击。
- 程序化 dispatchEvent、IPC 直接调用和真实鼠标是不同证据。模拟菜单逻辑可以验证数据；拖动、遮挡、滚动条、编辑器选区和焦点需要真实输入路径。
- 视觉改动检查亮/暗主题、窗口边缘、缩放、溢出和相关交互状态；截图与计算样式可辅助定位，不以 CSS 类名或像素颜色存在代替可用性结论。

## 数据与输出

优先用隔离测试档案和应用公开创建入口。直接改磁盘不保证应用刷新，也可能绕过业务校验。用户已有数据只在当前授权范围内操作。

HMR 或重新加载可能丢失会话状态，验证前核对连接和页面状态；工具注入失败与产品行为失败分开记录。工具不可用时明确未实测，不把替代单测算作视觉验收。

临时截图、trace、调试脚本和原始输出放 `.work/` 等本地忽略目录；只将可重复用例与必要结论入库。取证区分模拟行为与真实平台结果，不将截图或工具调用成功当作完整功能验收。
