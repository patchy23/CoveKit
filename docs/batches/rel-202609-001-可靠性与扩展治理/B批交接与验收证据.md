- 提交失败保留源目录、计划与错误详情，并写入 `attempts` / `lastError`（不推进版本、不改根）。

## T02 · 迁移预检、暂存与一致性校验

- 清单校验：复制前生成逐文件清单（相对路径、字节数、SHA-256），复制后重新扫描比对缺失 / 多余 / 同长度异内容（`storage/scan.rs`）。
- 暂存与原子提交：复制落到本次任务自己的暂存目录（带随机计划 id），逐个校验通过后按分区改名到位；任一成员失败整组回滚并清理暂存，旧位置保持唯一真相。
- 路径校验两级：词法规范化（大小写、分隔符、`.`/`..`）+ 最近存在祖先规范化，识破同一目录的别名；源与目标互相嵌套一律拒绝。
- 非空目标默认拒绝，不覆盖也不隐式合并；目标内容与源清单逐项一致时允许续跑提交（上次在提交路径中断的场景）。
- 同名冲突（新位置内容不一致）：先改名留档为 `*.incomplete-<时间戳>`，再以旧位置数据为准，绝不静默覆盖。
- 复制树遇到符号链接 / 目录联接立即报错并指出路径，不跟随链接；`read_dir` 失败照实报错，不用 `flatten` 静默漏项。
- SQLite 属于完整离线处理（维护阶段在所有 `.db` 打开之前），`.db` 与 `-wal` / `-shm` 一并复制，迁移后逐个跑 `PRAGMA quick_check`；Vault 只做解析校验，不生成新主密钥。
- 探针与清理：暂存目录内 `create_new` 写探针（带随机 id），不覆盖用户已有的 `.patchybox-write-probe`；只清理本次任务创建的目录。
- 进度按文件节流上报（250ms 或每 128 个文件），不再每分区只发一次。

## T03 · 旧布局按数据集合可恢复迁移

- 迁移实现迁至 `framework/storage/layout.rs`，按集合处理：密文与主密钥、数据库与恢复文件同组，整组要么到位要么全部保留原位。
- 补齐遗漏项：`db-secrets.enc`、`db-secrets.bak`、`db.stronghold`、`db-client.snapshot` 进入迁移矩阵；根下 `*.db` 及伴生文件动态成组。
- 「目标存在」不再等于「已完成」：内容一致才清理旧位置；不一致先留档再以旧位置数据为准；类型不符（文件/目录）直接报失败。
- 版本只在整组无失败时推进；版本已是最新但根下仍有旧文件时触发修复遍（`leftovers`），历史遗漏可被补上。
- 读取路径统一回落：数据分区文件、Vault 目录、凭据目录在旧位置仍有数据时按旧位置解析，避免「数据看不到」或「读到旧密文却生成新密钥」；SSH 插件旧凭据路径改走 `framework::paths`，不再直接用系统 app_data_dir。
- 旧凭据转换：数据库插件改为全量读入 → 一次原子写入 → 逐条解密回读确认 → 才清理旧文件；回读失败保留旧文件并可重试。

## T06 · PluginDb 迁移事务化与版本保护

- 每条迁移的 SQL 与 `user_version` 更新在同一事务内提交，SQL 失败或版本号写入失败都整条回滚。
- 删除「遇到 duplicate column 就整条迁移成功」的兜底，改为按该版本声明的列 / 表 / 索引做 schema 校验：全部已存在才判定已生效并推进版本，缺对象时原样报错。
- 不按分号切 SQL：修复判定只做静态提取与 schema 查询，语句执行仍交给 SQLite 的批处理。
- `user_version` 大于当前支持的迁移条数（降级打开）或为负数时拒绝写入并保留文件。
- 锁等待上限集中设置（10s）；明确不为「统一现代化」开启 WAL 与外键，避免改变迁移需要复制的文件集合与老库行为。
- `PluginDb` 新增按路径打开入口供测试与诊断使用。
