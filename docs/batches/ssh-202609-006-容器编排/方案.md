# SSH 容器编排方案

起始 HEAD：`a6f66c1a4436245499371df7fa1bf92bbb99ac70`。用户授权新增 Compose 管理，并明确不扫描目录。

## 目标与边界

- SSH 新增按需加载的“编排”页签，使用 `docker compose ls --all --format json` 查询项目，不遍历目录。
- 项目保留配置文件顺序和项目名，支持逐文件 YAML 编辑；复用 UiCodeEditor 与远程编辑冲突检查。
- 新建弹窗提供名称、远程项目目录、文件名与代表性模板，默认使用远程用户主目录下 `compose/<名称>/docker-compose.yml`，展示最终路径。记忆每台服务器最近使用的基础目录；可浏览用户指定目录，不扫描目录发现项目。
- 保存时创建缺失的项目目录，SFTP 独占创建文件、拒绝覆盖；新增与 YAML 编辑仅保存，不部署。尚未部署的项目仅保存路径元数据，不保存 YAML 内容。不代建挂载配置文件，失败时不递归清理用户目录。新增窗口未修改时直接关闭，有修改时在窗口内确认放弃；目录选择通过路径栏左侧上级图标或输入路径回车导航。
- 列表提供启动、停止、重启、更新镜像、重建和拆除。使用远端 Docker Compose 插件；命令不可用、无权限、非零退出均显式展示。编辑弹窗只负责改文件与保存，不提供校验或运行按钮。
- 多文件按查询结果顺序传递 `-f`，项目名通过 `-p` 指定。已有项目从 Docker 容器标签恢复原工作目录并记忆，标签冲突显式报错；旧记录缺省时才以首配置文件目录为准。自定义环境文件和 profiles 暂不引入专门配置入口，保留默认 `.env` 语义。
- 编排页使用全宽列表，提供搜索、刷新、新建，展示名称、状态与容器数量。列表始终保持挂载，保留搜索和滚动位置。每行右侧提供“查看容器”和“编辑”两个独立弹窗入口，以及运行操作按钮；运行结果仍在列表展示。
- 查看容器通过 Compose 查询成员 ID，再从 Docker 容器列表中匹配对应记录；复用 DockerTable 的 ID、名称、镜像、状态、运行时间与端口列，仅保留日志和终端操作。关闭弹窗卸载容器面板及其日志、终端。
- 编辑弹窗仅保留文件路径、文本编辑器、关闭与保存；多文件项目可切换文件，切换和关闭前保护草稿。新增与编辑区域都有明确高度；公共编辑器使用独立 DOM 宿主并在宿主就绪后初始化，避免滚动容器透传引用或延后渲染导致空白。
- 更新镜像会拉取并应用，重建可选择同时构建镜像；拆除不删除卷。执行时通过请求专属 Channel 输出进度，完成后刷新状态。草稿校验通过 SSH stdin 替代当前 `-f` 文件，不写盘、不把内容放进远端命令行。

## 实现与验收

- Rust 在 SSH owner 内增加 Compose 命令、DTO 和清单登记。参数逐项 shell quoting，操作白名单，命令设置时间与输出上限；超时不声称远端任务已停止。
- 查询与操作输出分离，stderr 不污染项目 JSON。新建用 SFTP 独占创建，已有文件保存复用 mtime 冲突机制。
- 切换功能页保留编辑状态；切换项目/文件提示未保存更改。应用关闭进入现有生命周期协商；连接关闭提示未保存内容与任务。
- 验证项目解析、多文件命令构造、异常退出、编辑冲突、迟到响应及未保存状态。相关前端轻量测试本地执行；Cargo、完整构建及真实 Docker 服务由用户或 CI 验证。
