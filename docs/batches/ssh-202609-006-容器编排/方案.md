# SSH 容器编排方案

起始 HEAD：`a6f66c1a4436245499371df7fa1bf92bbb99ac70`。用户授权新增 Compose 管理，并明确不扫描目录。

## 目标与边界

- SSH 新增按需加载的“编排”页签，使用 `docker compose ls --all --format json` 查询项目，不遍历目录。
- 项目保留配置文件顺序和项目名，支持逐文件 YAML 编辑；复用 UiCodeEditor 与远程编辑冲突检查。
- 新建配置写到用户指定的远程绝对路径，拒绝覆盖已有文件；保存与部署分开。尚未部署的项目仅保存路径元数据到 SSH 工具设置，不保存 YAML 内容。
- 支持校验、状态、日志、启动更新、启动、停止、重启、拉取镜像、构建和拆除。使用远端 Docker Compose 插件；命令不可用、无权限、非零退出均显式展示。
- 多文件按查询结果顺序传递 `-f`，项目名通过 `-p` 指定；工作目录以首配置文件目录为准。自定义环境文件和 profiles 暂不引入专门配置入口，保留默认 `.env` 语义。

## 实现与验收

- Rust 在 SSH owner 内增加 Compose 命令、DTO 和清单登记。参数逐项 shell quoting，操作白名单，命令设置时间与输出上限；超时不声称远端任务已停止。
- 查询与操作输出分离，stderr 不污染项目 JSON。新建用 SFTP 独占创建，已有文件保存复用 mtime 冲突机制。
- 切换功能页保留编辑状态；切换项目/文件提示未保存更改。应用关闭进入现有生命周期协商；连接关闭提示未保存内容与任务。
- 验证项目解析、多文件命令构造、异常退出、编辑冲突、迟到响应及未保存状态。相关前端轻量测试本地执行；Cargo、完整构建及真实 Docker 服务由用户或 CI 验证。
