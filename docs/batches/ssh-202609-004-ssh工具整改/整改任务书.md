## 一、必修 Bug（8 个高危，按依赖序）

### B1. ServerForm.vue「保存凭证」复选框不渲染（安全敏感）
- **现状**：模板用了 `<UiCheckbox>` 但 script 的 `@/core/ui` 导入里没有它（无自动注册），组件解析失败 → `saveCredential` 永远为默认 true，手工密码/私钥总是被静默写入凭证库，「仅本次连接使用」失效。
- **修法**：导入补上 `UiCheckbox`；顺带把 `saveCredential` 加进 profile watch 的重置列表（当前跨弹窗泄漏勾选状态）。
- **验证**：打开添加服务器表单，能看到并取消勾选；不勾选保存后凭证库无新增。

### B2. `ssh_reconnect` 前后端契约不一致
- **现状**：前端 `ipc.ts` 发 `{ sessionId, payload: { overrides } }`，Rust `conn.rs:951` 收扁平参数 `session_id, overrides`——payload 键被 Tauri 忽略，overrides 永远 None。一次性凭证（不入库）连接的会话重连必失败。
- **修法**：前端改 `cmd(commands.sshReconnect, { sessionId, overrides })` 并同步 `contracts.ts` 的 InvokePayloads 为扁平（与 ssh_disconnect 风格一致）。
- **验证**：不修 B1 本路径不可达；修完 B1 后，不勾选保存凭证连接 → 断开 → 手动/自动重连成功。

### B3. 重连成功清空终端缓冲
- **现状**：`ssh_reconnect` 总生成新 session_id；workspace 整体替换 `connection`；TerminalTab 的 sessionId watcher 无条件 `term.reset()`，随后 reconnectTick watcher 才把分隔线写进已清空的终端——scrollback 全丢。
- **修法**：watcher 中区分「重连换会话」与「换连接」：`reconnectTick` 递增伴随的 sessionId 变化跳过 `closeTerminal()/reset()`，走重连路径（保留缓冲 + 分隔线）。
- **验证**：连上后敲几行命令 → 断网/服务端重启 sshd → 自动重连成功 → 终端历史还在，分隔线可见。

### B4. 已连接状态点「重连」把终端打死
- **现状**：TerminalTab「重连」先本地 `closeTerminal()+reset()` 再 `emit('reconnect')`，但 `reconnectWorkspace` 守卫对 `connected` 状态直接 return——终端被关了、工作区不动作，页签报废只能重开。
- **修法**：TerminalTab 在 `connection.status === 'connected'` 时直接本地 `openTerminal()`（重建 PTY 通道），仅 `disconnected` 时才 emit 给工作区。
- **验证**：已连接状态点「重连」→ 终端通道重建且可用。

### B5. 旧凭证解密失败导致迁移永久失败循环（数据丢失级）
- **现状**：`store.rs:353` `ssh_profile_import` 开头 `credential::read_all(&app)?`——旧 AES 凭证文件解密失败（主密钥丢失）时整个导入中止；前端 `importLegacyOnce` 失败即重试 → localStorage 服务器配置永远迁不进 ssh.db，用户视角 = 服务器列表消失。
- **修法**：凭证读取失败降级为空表继续导入 profiles/groups（eprintln 记录），导入结果加 `legacyCredentialsSkipped` 字段，前端 toast 提示「N 个旧凭证未能迁移，请重新保存」。
- **验证**：构造一个无法解密的旧凭证文件 → 打开工具 → 服务器列表正常迁入。

### B6. 导入 upsert 抹掉已有 credentialRef
- **现状**：`store.rs:178` `upsert_profile` 的 `ON CONFLICT` 无条件 `credential_ref = excluded.credential_ref`——payload 无 ref 时把库里已有的引用抹成 NULL。
- **修法**：upsert 前先读现值：payload 与 legacy 都无 ref 时保留库中现有 `credential_ref`（merge 语义而非 overwrite）。
- **验证**：服务器已挂凭证 → 重复触发导入 → 凭证引用还在。

### B7. 凭证被删后对应服务器永远无法保存
- **现状**：`store.rs:284` 保存勾选凭证时用 `id: profile.credential_ref` 调 `vault_save` 做 upsert；凭证已被删除时 vault_save 直接 Err，且发生在 upsert_profile 之前 → 连名称修改都保存不了。
- **修法**：捕获「凭证不存在」错误后回退为 `id: None` 新建条目并回填新 credentialRef。
- **验证**：凭证库删掉某凭证 → 编辑对应服务器（改名 + 勾选保存凭证）→ 保存成功，凭证库出现新条目。

### B8. 连接途中关闭占位页签导致会话泄漏
- **现状**：`useSshWorkspace.ts` `openConnection` 在 `await sshConnect` 返回后只查 `disposed`，不查占位工作区是否还在 `connectionWorkspaces` 里；此时关闭页签因 placeholder sessionId 为空跳过后端断开，连接成功后后端会话无人持有。
- **修法**：await 返回后加 `if (!connectionWorkspaces.value.includes(workspace)) { 若成功则断开该会话；return }`（`attemptReconnect` 里已有同款写法可参照）。
- **验证**：慢网/主机密钥确认挂起期间关闭页签 → 后端无残留会话（`ssh_connections` 为空）。

## 二、中危（7 个，与必修同批做）

1. **主机密钥确认单槽覆盖**（useSshWorkspace.ts `hostKeyRequest`）：改为队列（push/shift），卸载时对积压请求统一 respond cancel；现在两个新主机并发首连时前一个请求永远挂起。
2. **moveToGroup 失败不回滚**：先 `await sshProfileSave` 成功再改本地 `profile.groupId`（或 catch 中恢复旧值）。
3. **切换连接时 mkdirTarget 不重置**（FileManagerTab watch）：加 `mkdirTarget.value = null`，否则会在 B 服务器按 A 的路径建目录。
4. **编辑冲突「重新检查并保存」永远失败**（useRemoteFileOps）：冲突分支回填 `r.currentMtime` 为新基线（`editing.value = { ...target, content, conflict: true, modifiedAt: r.currentMtime ?? target.modifiedAt }`）。
5. **connect-stage 事件按 profileId 匹配串台**：同 profile 两条并行连接时进度文案写错工作区；改为记录/匹配 requestId（契约已有该字段）。
6. **ssh_reconnect 会话不存在返回 Err(String)**（conn.rs:965）：统一返回 `Ok(SshConnectOutcome{ ok:false, error: SESSION_NOT_FOUND })`，与其他失败路径一致；另：重连成功后补旧会话的终端/隧道清理，避免旧 terminal-closed 诱发二次重连。
7. **共享凭证被改名+覆盖**（store.rs:288）：多台服务器引用同一凭证时，upsert 不改名不整体覆盖 fields；或共享引用时强制新建。

## 三、低危顺手修（5 个）

- idleTimer 创建前加 `if (disposed) return`（onMounted await 期间卸载的泄漏）
- `attemptReconnect` 的 IPC 抛错分支也走退避（与业务失败一致，reconnectAttempt 上限由 scheduleAutoReconnect 自终止）
- `upsert_profile` 的 ON CONFLICT 去掉 `last_connected_at`（只由 touch 维护，防保存回退「最近连接」）
- `register_session` 锁中毒别吞（conn.rs:808 `if let Ok` → map_err 传播 + 断开会话）
- `useFileTransfer` 成功分支补写 `done: true`（否则已完成传输以「进行中」样式挂 10 秒，可误点取消）
- 删 FileManagerTab.vue:292 模板里孤立的 `"` 残留
