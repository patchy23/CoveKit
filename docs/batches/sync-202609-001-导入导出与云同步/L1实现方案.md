## 3. 目标与不变式

**目标**：同一份二进制在同一个存储根下能承载多个互相隔离的数据空间；默认空间（旧安装）在升级后**行为与数据位置零变化**；空间之间的数据、密钥、偏好三项都不能串。

不变式（改动前先读，破坏任一条即视为缺陷）：

1. **默认空间零迁移**：`default` 空间保持 `LegacyFlat`，其 `data/`、`vault/`、`logs/`、`cache/` 位置与既有 keyring 条目（`com.patchy23.patchybox` + `vault-master-key`）**一个字节都不动**。本机 `data/credentials/database.enc` 是真实密文，方案不得让它的可解性依赖新逻辑。
2. **密钥只增不改**：generation 切换与空间切换**不轮换既有空间主密钥**；只在「跨空间新建」时生成新密钥；保留旧代际时其可用密钥一并保留。
3. **切换重启生效**：进程内只有一个活动空间；不引入热切换；激活以「原子写活动指针 + 已刷盘提交日志」完成，中断后只能打开完整旧版或完整新版。
4. **越界零容忍**：空间 id 只接受小写 UUIDv4 形态，作为目录名与 keyring account 片段前必须校验，禁路径穿越与账户名注入。
5. **不静默兜底**：索引损坏、目标不可读、密钥缺失一律**可见失败**（登记恢复状态或拒绝该动作），不得静默退回默认空间，也不得新建空环境冒充成功。
6. **维护互斥只有一处**：空间切换、根迁移、导入提交、更新安装共用 `context::maintenance_guard()`。

## 4. 关键决策

### 4.1 已定（本方案直接按此实施）

| # | 决策 | 理由与代价 |
| --- | --- | --- |
| D1 | 布局用**一个 descriptor 表达两种形态**：`StorageLocation { layout, device_root, data, vault, preferences, logs, cache }`，新增 `LayoutKind::LegacyFlat \| Partitioned` | §13.3 冻结要求「两种布局都能被同一个启动解析表达」「唯一 StorageLocation 含布局类型与根」。代价：`StorageLocation::new()` 的调用点要区分形态，`paths` 内几处 `root.join(..)` 改读字段 |
| D2 | 密钥作用域按**空间后缀 account**：默认空间沿用 `vault-master-key` / `credentials-master-key`（§13.5 明写沿用），新空间用 `vault-master-key.space-<spaceId>` / `credentials-master-key.space-<spaceId>`；`KEYRING_SERVICE` 不变 | 只改 account 就能让 keyring 层真正分开（只分目录会共用同一把钥匙，隔离只剩目录层，§13.5 明确点名）。字符集只含小写字母、数字、`.`、`-`，不触碰 keyring target 的拼接规则。代价：`KeySpec.account` 由 `&'static str` 变 `String`，`secure_store/key/{mod,resolve,status}.rs`、`credentials.rs`、`vault/store/*` 的调用点都要改成「按当前空间取 spec」 |
| D3 | 空间索引与激活状态放**固定自举配置**（`settings.json` 的 `app` 对象），键名 `spaces`（索引数组）、`activeSpaceId`、`pendingActivation`，并加入 `settings.rs` 的 `RESERVED_KEYS` 由空间模块独占写 | 索引必须与数据根解耦才能自举（配置类文件永不搬移，与 `storageRoot` 指向哪个盘无关）。代价：`RESERVED_KEYS` 从 4 项变 7 项，通用设置写入要拒这三个键 |
| D4 | 活动空间解析放在**根迁移维护之后、`context::init` 之前**；`paths` 在上下文未初始化时保留现有的即时解析回落 | 上下文一旦固定不能换根，因此必须先把空间解析出来再固定。代价：启动顺序成为契约，`lib.rs` 里要写明顺序原因并加启动期守卫用例 |
| D5 | 空间 id 形态固定为**小写 UUIDv4 字符串**，新增 `space::is_valid_space_id()` 校验后才允许拼目录名与 account | §13.2 冻结（禁邮箱/机器名/路径派生）。代价：新增一处校验点，非法 id 的索引项一律拒绝启动到该空间并可见报错 |
| D6 | 切换激活 = 「写 `pendingActivation` → 校验目标可读 → 写 `activeSpaceId` → 清 `pendingActivation`」四步，每步落盘成功才继续 | §13.4 冻结（原子更新活动指针 + 已刷盘提交日志；中断后只能完整旧版或完整新版）。代价：激活中途失败会在下次启动时按 `pendingActivation` 重试，需要一条「重试失败即回到旧活动空间并可见报错」的路径 |
| D7 | 根迁移（换盘）的枚举范围从四分区扩为**四分区 + `spaces/` 整棵**，扫描/校验/复制三处同步改 | §13.3 冻结（必须枚举空间索引引用的所有空间及必要代际，不得只复制四个目录）。代价：`scan_root` 的清单口径变化，`verify` 的比对集合同步扩大，迁移耗时随空间数增长 |
| D8 | 按 `TODO.md` §五要求，开工时同步清理 §13.1 字段分类表里**已随功能移除而失效的行**（`globalHotkey`、`downloadMirror`） | 表里留着已删除的键会让 L1 的路由实现照着不存在的字段写。代价：改一行动已冻结的表，需在提交说明里点明「随快捷键/镜像设置移除而失效」 |
| D9 | **L1 只做「新建空空间」**，不做「导入创建空间」 | §3.3 的「导入创建」依赖 L2 的包格式与解密链路，提前做等于把 L2 的一半塞进 L1。验收「两空间同名记录互不串读」用空空间 + 各空间独立写入即可覆盖 |
| D10 | `entityUid` / `revision` 在 L1 **只落框架入口**（生成、校验、schema 声明位置、迁移辅助函数），逐 owner 补列随 L4「其余现有持久化 owner」推进 | §13.2 写「按 §4.1 在 L1 起落地」，而 L1 的验收判据（同名不串读、旧库可升级）不依赖记录级 UID；在 L1 给全部插件表加列会把改动面放大数倍却验不到增量收益 |

### 4.2 待你拍板（4 条，各有推荐）

1. **logs/cache 是否按空间分层**：§3.2 冻结写法是「设备根下按 `spaceId`/owner 分隔」，即 `<deviceRoot>/logs/<spaceId>/<scope>`。这会改变默认空间现有 SSH 会话日志的位置（`<root>/logs/ssh` → `<root>/logs/default/ssh`）。**推荐：按冻结条款分层，并把 default 空间的旧日志做一次幂等搬迁**（失败保留原位并回落读取），避免升级后会话日志从界面里消失。若你更想零改动，替代方案是给默认空间保留旧路径、只对新空间分层——代价是同一条路径两种语义。
2. **L1 是否含「新建空空间」界面**（D9）：**推荐含**（设置页存储卡片里的空间分区：列表、当前、新建、重命名、切换）。没有它，「两空间互不串读」就只能靠单测证明，交付物缺一块用户可见能力。
3. **新空间 keyring account 命名**（D2）：**推荐 `vault-master-key.space-<spaceId>`**，并在本批记录定稿（§13.5 要求「命名随 L1 定稿并在该批记录」）。
4. **`entityUid` 范围**（D10）：**推荐只落框架入口，逐 owner 留 L4**。

## 6. 实施步骤（每步一次提交，只 add 本步文件）

### W1 · 布局 descriptor 与路径空间化（默认空间行为零变化）

- 内容：`StorageLocation` 按 D1 扩字段与 `LayoutKind`；`paths` 的分区路径改读字段；`init` 增入参；`data_path` 回落语义按布局收窄。
- 判据：默认空间下 `data/vault/logs/cache` 四个路径与改动前**逐字符相等**（加一条对拍用例：旧实现算出的路径作为期望值写进夹具）；`cargo test --lib` 全绿。
- 风险：路径语义漂移会让真实数据「找不到」。对拍用例是本步的硬门禁。

### W2 · 空间索引、启动解析与激活

- 内容：`space` 模块（索引/激活/校验）、`RESERVED_KEYS` 扩展、`lib.rs` 启动顺序按 D4 调整、四个命令（列表/新建/重命名/切换）。新建空间按 `Partitioned` 建目录，不做任何数据拷贝。
- 判据：索引往返与非法 id 拒绝有用例；「写 `pendingActivation` 后中断」在下次启动能回到旧活动空间并可见报错；新建两个空间后同一插件库在两空间下路径不重叠。
- 风险：启动顺序错会让上下文先锁死默认空间。加启动期守卫用例。

### W3 · 密钥作用域

- 内容：`KeySpec.account` 动态化 + `for_space()`；降级密钥文件随空间目录；`credentials.rs` / `vault/store/*` 按当前空间解析。
- 判据（§13.5 要求两层都验）：① 默认空间密文在升级后仍可解（用真实目录的**副本**夹具，不碰真实目录）；② 空间 A 的密文用空间 B 的密钥解不开；③ 跨空间 resolve 不命中同一 keyring account。
- 风险：**本步风险最高**（本机有真实 namespace 密文）。红线：默认空间零改动；不在真实用户数据目录上做故障注入。

### W4 · 设置路由与空间界面

- 内容：`settings.rs` 按 §13.1 归属表分流（设备级留自举配置，空间级落 `<space>/preferences.json`），对外命令语义不变；清理 D8 的失效行；前端空间分区界面 + 契约/封装。
- 判据：空间级设置（`theme`、`language`、`tools['ssh']`、`tools['frp'].maxLogLines`、收藏、`recentTools`）按空间隔离；设备级（`storageRoot`、`layoutVersion`、`launchAtStartup`、`defaultDownloadDirectory`、`tools['frp'].frpcPath/profileDir`）切换空间后不变；FRP 直读设置的那条路径不再跨空间串值；`pnpm test` 与新增用例全绿。
- 风险：插件自行合并两份配置。对 FRP 这条已知直读路径单独加用例。

### W5 · 根迁移枚举全部空间 + 日志/缓存分层

- 内容：`scan`/`verify`/`migrate` 按 D7 扩范围；`layout.rs` 只对 `LegacyFlat` 生效；日志/缓存按 4.2 第 1 条的裁决落位。
- 判据：换盘迁移后**活跃空间与非活跃空间都可用**（§11 矩阵行）；迁移中断不产生混合库；`storage_info` 展示的空间与布局与实际目录一致。
- 风险：迁移清单口径变化是本步最易出错的地方，复用 T01/T02 的「只复制不删除 + 校验通过才提交」约定。

### W6 · 夹具与故障注入体检

- 内容：按 §13.8 夹具清单补齐可执行夹具（旧布局根、索引样例、半迁移、密钥不匹配、未知 `schemaVersion`、跨空间同 UID 记录）；冷启动体检。
- 判据：本方案 §7 的验证表逐行有结论，未做的写「未验证」。

## 8. 明确不做

L2 包格式与选定导出/隔离导入；L3 冲突预览、UID/引用重映射、generation 提交与回滚；L4 其余 owner 的导入导出与 `entityUid` 逐列落地；L5 全量验证与格式文档；云账户与任何网络同步；空间删除、多空间并发运行、空间热切换、团队 ACL；`AccountId` / `RemoteSpaceId` 建模。以上均按任务书分批表留到对应批次。

## 9. 交付物与完成判据

| 交付物 | 判据 |
| --- | --- |
| 空间索引与启动解析 | 索引可读写、非法 id 被拒、活动空间决定本次运行的全部数据位置 |
| 两种布局的 descriptor | `default` 与新建空间都能解析出唯一 `StorageLocation`，`paths` 消费同一实例 |

| 密钥作用域 | 每空间独立密钥（含降级文件与 keyring account）；跨空间不可解有用例 |
| 设置路由 | 按 §13.1 归属表分流，插件不自行合并；字段分类表失效行已清理 |
| 空间界面 | 列表、当前、新建、重命名、切换可见可用；切换需重启有明确提示 |
| 稳定身份入口 | `entityUid` 生成/校验与 `revision` 递增入口可用（逐 owner 落地留 L4） |
| 根迁移 | 换盘迁移覆盖活跃与非活跃空间，中断不产生混合库 |

**L1 完成判据**：§11 矩阵中与 L1 相关的行（两空间同名不串读、整根迁移多空间、跨空间密钥不可解）有实测结论；旧安装升级后默认空间数据位置与可解性零变化。仅机制与接口不算完成。
