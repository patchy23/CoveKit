# sync-202609-001 · L1「数据空间（namespace）骨架」实现方案

> 档位：**S3**（碰持久化、密钥、迁移、启动路径）。按 [ADR-0007](../../adr/ADR-0007-验收按变更分档与证据等级.md) 与 [20-验证矩阵](../../standards/20-验证矩阵.md) 选行，不兜底跑全量。
> 本方案不改变 [L0 数据边界冻结条款](导入导出与云同步预留任务书.md)（§13）的任一条；只把其中「空间」这一层在本批落成骨架。

## 1. 范围口径（2026-09-15 用户裁决）

**空间 = namespace。** 一套空间的资料是完整独立的一份：数据、凭证、偏好、密钥都在里面。切到另一个空间，理论上就是一个全新的环境。

本批（L1）只做三件事：

1. 把「空间」从一句话落成代码里的**唯一解析来源**——凡是取数据位置、取凭证、取偏好、取密钥，都必须经过它；
2. 把**全量隔离**做实：路径、密钥、偏好都按空间分开，而不是只分开目录；
3. **只放置一个初始的默认空间**，其余一律不管。

因此本批**产品面零变化**：用户看到的还是现在这个应用。变的是数据位置不再硬编码，而是由空间解析决定——这是后面能加第二个空间的前提。

**明确不在本批**：新建 / 切换 / 重命名 / 删除空间，空间索引与待激活状态，空间界面与管理入口，记录级稳定标识（`entityUid` / `revision`）。多空间的管理要跟「用户管理」一起设计，不是加个界面就完事。

> 与任务书 §10 分批表的差异：L1 行原文含「稳定 UID 与修订入口」。按本次裁决，该部分**本批不做**，列名与迁移方式待 L2/L3 定义合并语义时再定；本批只在 §13.2 既有约束上保留「空间 id 不得进入记录身份」。该行留待 L2 开工时一并更新。

## 3. 不变式

1. **默认空间零迁移（红线）**：本机存在真实凭证密文与密钥。默认空间的数据位置、密钥条目、密文文件一律保持原样，任何新增计算都必须对默认空间回落到与今天逐字符相同的路径。
2. **唯一来源**：一次运行只解析一次位置，`paths` 与 `PluginDb` 消费同一实例；不得出现「某处还按根目录现拼」的第二套。
3. **全量隔离**：数据、凭证、偏好、两把密钥都按空间分开。密钥必须分开到 keyring 条目一级——只分目录等于没隔离。
4. **设备级配置是唯一共享项**：存储根、开机自启、默认下载目录、`frpc` 路径、主机级设置不随空间变化（它们是设备事实，按空间各配一份只会互相矛盾）。这是「切换即全新环境」的**明确例外**，写在文档里而不是靠记忆。
5. **越界零容忍**：空间 id 只接受小写 UUIDv4 形态，作为目录名与 keyring service 片段前必须校验，禁路径穿越与名称注入。
6. **不静默兜底**：索引或目标不可读一律可见失败，不得静默退回默认空间，也不得新建空环境冒充成功。维护互斥仍只有 `context::maintenance_guard()` 一处。

## 4. 关键决策

| # | 决策 | 理由与代价 |
| --- | --- | --- |
| D1 | 位置用**一个 descriptor 表达两种形态**：`StorageLocation` 增 `layout`（`LegacyFlat` / `Partitioned`），`data`/`vault`/`logs`/`cache` 改为由形态算出的字段 | §13.3 要求两种布局都能被同一个启动解析表达。代价：`make_location` 的调用点要区分形态，`paths` 内几处 `root.join(..)` 改读字段 |
| D2 | 密钥作用域按**service 换名**（用户裁决）：默认空间沿用 `com.patchy23.patchybox`，其他空间用 `com.patchy23.patchybox.<spaceId>`，`account` 保持 `vault-master-key` / `credentials-master-key` 不变 | §13.5 要求默认空间沿用现有条目（否则升级即解不开）。换 service 而不是换 account，是为了让「同一把钥匙在不同空间的同名条目」在系统凭据管理器里天然分组。代价：`KeySpec` 要能带作用域，`secure_store/key/{mod,resolve,status}.rs`、`credentials.rs`、`vault/store/*` 的取用点都要按当前空间取 spec |
| D3 | 当前空间由**自举配置的一个保留键**给出：`activeSpaceId`（首次启动写入 `default`），缺失或非法时回落 `default` 并登记，不静默新建 | 需要一个真实来源，否则又退回编译期常量、第二空间无从接。只加一个键，不引入空间索引与管理动作。代价：`RESERVED_KEYS` 增一项，通用设置写入要拒它 |
| D4 | 空间解析排在**根迁移维护之后、`context::init` 之前**；上下文未初始化时 `paths` 保留现有即时解析回落 | 上下文固定后不能换根。代价：启动顺序成为契约，`lib.rs` 要写明原因并加启动期守卫用例 |
| D5 | 空间 id 固定为**小写 UUIDv4 字符串**，新增 `space::is_valid_space_id()`，校验通过才允许拼目录名与 service | §13.2 冻结（禁邮箱/机器名/路径派生）。代价：新增一处校验点 |
| D6 | 本轮**不建空间目录**：默认空间继续用现有根（`LegacyFlat`）；`spaces/<id>/generations/<n>/` 形态由测试夹具构造，产品面不产出 | 只有一个空间时建目录结构纯属空转，且会动到真实数据位置。夹具构造既能证明隔离，又不留无功能占位 |
| D7 | 空间级偏好统一落 `<space>/preferences.json`，默认空间做**一次性迁移**（读旧键 → 写新文件 → 旧键删除；失败则回落读旧键，设置不丢） | §13.6 要求 settings 对外语义不变、由框架适配层完成归属分流。代价：本批唯一一处迁移，需要「旧键回落读」这条兼容路径。**实际收窄**：只做旧键回落读，不做迁移与删除——单空间下删旧键只剩风险 |
| D8 | 根迁移与日志/缓存的枚举范围改为「四分区 + `spaces/` 下已存在的空间与必要代际」；`layout.rs` 的布局迁移只在 `LegacyFlat` 下执行 | §13.3 要求迁移覆盖空间索引引用的全部空间。代价：`scan`/`verify`/`plan` 三处口径同步改。**实际未做**：保持旧扁平布局时枚举范围没有差异，见 §6 W5 |
| D9 | 日志与缓存按空间分层（`<deviceRoot>/{logs,cache}/<spaceId>/<scope>`），默认空间的旧日志做一次幂等搬迁，失败保留原位并回落读取 | §3.2 冻结写法就是「设备根下按 spaceId/owner 分隔」。代价：本批第二处迁移，须保证失败不导致界面里的日志消失。**实际收窄**：非默认空间已按空间分层，默认空间不搬移，见 §6 W5 |

## 6. 实施步骤与偏离登记

实际只落**两笔提交**（原方案 W1–W5 每步一提交）：

| 提交 | 内容 |
| --- | --- |
| `2db2dba` feat(core): 数据空间成为真实身份并按空间隔离位置与密钥 | W1–W4 全部内容 |

### 6.1 与冻结条款的差异登记

| 条款 | 原文要求 | 本批实际 | 处置 |
