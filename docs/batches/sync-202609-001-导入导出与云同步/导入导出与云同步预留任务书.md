## 1. 产品决策与范围

云账户是已明确的后期规划，用于同一用户多地登录后的个人数据同步，不再列为“无需求/不建议建设”。本地使用保持完整，不登录也能管理、导入导出自己的数据。

本地传输与后期云同步共用**逻辑数据模型、稳定身份、引用解析和变更入口**，不共用整库覆盖协议。不能把 SQLite 文件、机器路径或本机 keyring 密钥当未来云端数据契约。

本期支持三类操作：

1. **选择导出**：按数据类别、工具、具体记录选择，可只导出配置、只导出凭证、只导出习惯，或组合导出。
2. **隔离导入（默认）**：在本机建立独立数据空间，与当前空间的服务器、凭证、收藏和工具配置完全分开；导入完成后用户决定是否切换。
3. **合并到当前空间**：先展示新增/冲突/跳过/缺依赖，再按类型选择保留本地、采用导入或保留两份。缺少的源记录不代表删除本地记录。

“覆盖整个当前环境”不作为本期单击选项；完整替换效果通过导入新空间并切换实现。旧空间保留，可切回。合并中的“采用导入”仅覆盖明确选中的记录/字段，不清空整库。

本期不扩展 OpenSSH Config、Postman 等第三方格式解析；仅支持本应用通用数据包与已有 `.pbvault` 的兼容导入。第三方格式后续通过独立解析适配器转为同一导入模型，不改变计划与提交引擎。

## 2. 数据清单与各类规则

实现前核对最新存储现状；以下依据本次仓库代码读取。框架负责组织，各 owner 的适配器负责理解自己的 schema。

| 类别 | 当前来源/消费方 | 本期导出内容 | 默认选择与限制 |
| --- | --- | --- | --- |
| 可移植应用偏好 | `settings.json/app`，settings store | 主题、语言及经声明可移植的通用设置 | 可选；按字段导入，不带 storageRoot/layoutVersion |
| 使用习惯 | `patchybox.json` 的 favorites/recent，UI 设置 | 收藏工具、最近使用顺序、已持久化视图偏好 | 收藏可默认选；最近使用显式选；不是上传遥测 |
| 工具偏好 | `settings.tools[id]` | schema 白名单内可移植字段 | 按 owner 选择；本机路径/可执行程序字段不带 |
| SSH 配置 | `ssh.db` 的 groups/profiles/tunnels/bookmarks | 服务器、分组、隧道定义、书签与引用 | 隧道不自动启动，lastConnected 等历史默认不带 |
| 凭证 | Vault 与 namespace credentials | 用户选定凭证及被选配置引用的凭证 | 默认不带秘密，勾选包含凭证后依赖联动；仅经加密包 |
| 数据库工作台 | `database.db` 与 `credentials/database.enc` | 连接定义、收藏 SQL；查询历史可另选 | 不导出远端表数据/本机 SQLite 实体文件；SQL 文本按敏感数据处理 |
| 接口配置 | `api.db/api_list`，HTTP/WS 消费 | 已保存请求、参数、header、body | 任意字段可能含秘密，整个包加密；不导出运行中连接/响应缓冲 |
| DNS 配置 | `dns.db/dns_config` | 平台配置与 Vault 引用；手工 id/key 作为秘密单元 | 每个平台当前单槽，不能在同空间“保留两个活动配置” |
| FRP 配置 | frp.db + 用户真实 TOML 文件 | 默认只导出可移植元数据；显式选“配置内容”时复制内容进包 | TOML 可能含 token，按秘密处理；外部文件须逐项授权选择，不递归打包其目录 |
| Hosts/系统状态 | 系统 hosts 文件 | 本期通用包不抓取和应用实时系统 hosts | 未来已保存方案可作为 owner 数据；导入不能提权写系统文件 |
| 无持久数据工具 | 格式转换、TTS 等 | 仅其已声明可移植偏好 | 不导出编辑器临时输入、音频缓存或内存状态 |
| 设备专属数据 | 本机路径、自启、全局键、驱动、窗口坐标、known_hosts 等 | 默认不在通用包中 | 本期不迁移系统信任状态；跨机器首次 SSH 仍需校验主机 key |
| 历史/日志/缓存 | 查询历史、日志文件、cache | 本期只允许显式选定的结构化查询历史 | 日志/缓存/临时文件不纳入本期；后期云同步也不默认开启历史同步 |

### 2.1 “不包含凭证”必须真实成立

- adapter 声明哪些字段是 secret/reference/device-local，剔除秘密后写占位和缺失依赖。DNS 手工 key、DB namespace 密码、FRP token 都在此范围，不能只过滤 Vault。
- API body/header/URL、收藏 SQL 等任意文本无法保证自动脱敏完整。含此类内容的数据集标记 `sensitiveContent`，默认不选；若用户只要无秘密配置模板，导出模板结构并排除原始文本，不声称已自动清干净。
- “不含凭证”表示不导出结构化凭证单元，不等于“无敏感信息”。最终预览列出自由文本风险，整个包仍加密。
- 缺凭证的 profile 可作为“待补全”记录导入，但不能偷偷绑定同名本地凭证或使用其他空间的凭证。

## 3. 数据空间：实际隔离，而不是仅加来源标签

### 3.1 空间与设备的边界

`DataSpace` 表示一套独立的个人数据环境，不是账号、团队或权限角色。当前所有数据注册为默认空间；用户可通过隔离导入创建“家用备份”“公司配置”等空间。

- **空间内**：插件数据库、Vault/namespace 凭证、工具与个人偏好、收藏/最近使用、导入来源映射。
- **设备级**：安装标识、存储根、空间索引、当前/待切换空间、全局快捷键、自启、本机路径绑定、设备信任信息、诊断与更新状态。
- `DataSpaceId`、未来 `AccountId`、`RemoteSpaceId` 分别建模，不能拿账户邮箱当目录名，也不能把登录等同于合并本机全部数据。
- 本期同时仅一个活动空间，切换重启生效，接入 T10 退出协商；隐藏/关闭工具与切空间不是同一操作。无需每条业务 SQL 现在就加 space_id。

### 3.2 推荐存储布局与兼容

```text
固定自举配置（原 app_data_dir）
  空间索引 / activeSpaceId / pendingActivation / 设备设置
可配置 storageRoot
  data/、vault/                 现有默认空间旧布局，兼容读取
  spaces/<spaceId>/generations/<generationId>/
    data/<plugin>.db
    vault/                     每空间独立密文，禁止跨空间 resolve
    preferences.json           可移植偏好与习惯，含按 owner 分区的设置
  logs/、cache/                设备根下按 spaceId/owner 分隔会暴露用户内容的产物
```

- 统一 paths 根据启动时固定的 `activeSpaceId + generationId` 解析；默认旧布局通过 location descriptor 表达，首次安全迁移/导入提交后才切新 generation，不能升级时硬搬全部数据。
- T01/T02 的整根迁移必须枚举空间索引引用的所有空间及必要 generation，不再只固定复制四个目录；不得遗漏非活动空间。先定义目标布局再实施这两个任务。
- 每空间 Vault 有独立 vaultKeyId，映射本机 keyring account；默认旧空间兼容现有 service/account，不改应用 identifier。生成新空间使用独立密钥，导出不带本机密钥；namespace 同样隔离。
- generation 切换不得轮换既有空间主密钥；跨空间创建则用新密钥。保留旧 generation 时其可用密钥也保留，不能为清理磁盘删除仍被引用的 key。
- 所有插件 settings 直读、收藏/recent store、credentials resolver 都要接入空间上下文，特别检查 FRP 直接读取 settings.json 的路径，不能仅隔离 DB 而偏好/秘密仍串空间。
- 前端查询缓存和后端任务也必须绑定发起时的 spaceId/generationId；切空间前完成释放，晚到事件不得更新另一空间。原 settings API 由适配层按字段策略路由设备/空间存储，插件不得自行合并两份配置。
- 本机路径绑定键为 `(spaceId, owner, entityUid, bindingKind)`；包只带绑定需求，不带可直接生效的本机路径。FRP 导入内容写空间内管理目录，重新绑定外部文件需用户操作。

### 3.3 范围限制

本期提供空间列表、切换、命名和导入创建，不实现多个空间同时运行、团队 ACL 或空间自动删除。空间之间可通过选择导出再合并导入交换数据；不同空间的凭证不得共用同一个引用句柄。隔离空间只能防应用内串数据，不宣称隔离当前 OS 用户的恶意进程。

## 4. 逻辑记录、身份与依赖

### 4.1 传输模型

每个数据集定义 `owner + dataset + schemaVersion`，每条记录至少有：

| 字段 | 语义 |
| --- | --- |
| entityUid | 稳定 UUID，与自增主键、名称、主机地址无关 |
| entityType | 如 ssh.profile、vault.credential、core.preference |
| revision | 本地单调修订号；不能拿两台机器的数字直接判谁更新 |
| payload | owner 定义的版本化逻辑数据，无 SQL/物理表结构 |
| references | 类型化 `(owner, dataset, entityUid)` 引用，不是随意替换字符串 |
| portability | portable/device-local/secret/sensitive-content 策略 |
| sourceLineage | 来源空间的稳定标识与原 entityUid；用于再次导入对照，不是可信账号身份 |

有现成 UUID 的记录优先复用；整数 id 的 API/SQL 历史增加稳定 UID 并以追加 migration 填充一次，不得每次导出生成新 UID。插件内将 UID 映射本地主键，framework 不理解 `conn_id` 或 `group_id` SQL。

单值偏好可以用 `(owner,key)` 做稳定逻辑键；DNS 平台配置按实际单槽约束建模。revision 与逻辑修改在同一插件事务中更新；同库元数据由插件迁移创建，不能出现元数据已写而实体未写。

### 4.2 依赖闭包

- 导出 SSH profile 时展示分组、凭证、书签/隧道等依赖；用户可选择一起带出、去掉可选依赖或形成待补全项。
- 导入先分配全部目标 UID，再按映射写引用；“保留两份”必须复制整条选中依赖链，不能复制 profile 却仍引用被覆盖的旧 credential。
- 同一导入批的多 profile 共享一个来源 credential 时，默认仍共享同一份导入 credential，不能重复创建 N 把。
- 源凭证未带入时只允许手工选择当前目标空间兼容凭证、保留未绑定或跳过关联项；不按名称/密码相同自动匹配。
- 用户选择替换共享凭证时，预览当前空间所有受影响配置；避免更新一个导入 profile 的密码，悄悄改变多个本地 profile。
- 验证缺引用、类型错配、重复 UID、引用循环及不支持的版本；必需依赖被跳过时重算计划，不能先写一半再报错。

## 5. 合并与冲突策略

### 5.1 先识别实体，再比较内容

- 同目标空间已有来源映射时按映射匹配；同一来源 UID 的重复导入必须可幂等处理。
- 仅名称/主机相同不证明同一实体，默认列为疑似重复，由用户确认。来自不相干空间恰好同 UID 也作为冲突，不视为自动覆盖授权。
- 比较规范化 payload；不比较密文字节（随机 nonce 导致同内容不同密文）。秘密只能在 Rust 内比较，预览仅显示“秘密有变化”，不展示值、不导出秘密指纹。
- 不按 updatedAt 自动“最新覆盖”，两台设备时钟不可靠；无共同基线时双方不同即冲突。

### 5.2 类型策略表

| 数据类型 | 默认合并 | 可选处理 | 禁止行为 |
| --- | --- | --- | --- |
| SSH/DB/API 多记录配置 | 新增；已识别且相同跳过；不同则待决策 | 保留本地、采用导入、保留两份 | 用 host/name 自动覆盖 |
| 分组/书签/隧道 | 依赖解析后新增，名称冲突展示 | 绑定已有组、保留两组或跳过 | 只改主记录 id 不改子引用 |
| Vault/namespace 凭证 | 同源相同跳过，不同默认保留本地并提示 | 显式替换或新建凭证后重绑 | 以相同密码归并、自动替换共享 key |
| DNS 单槽平台配置 | 冲突默认保留本地 | 采用导入或改为隔离空间导入 | 假装同一槽能保留两份 |
| 应用/工具单值偏好 | 本地已有值优先；缺值补入 | 按字段采用导入 | 整个 tools 对象覆盖未选字段 |
| 收藏 | 有序去重并集，保留本地顺序，新项追加 | 仅对选定收藏集合采用导入顺序 | 导入清单缺项就删除实体 |
| 最近使用 | 保留本地顺序，导入新项追加并按上限截断 | 显式采用导入顺序 | 用跨设备时间戳当可信排序 |
| 查询历史 | 显式选择后按 UID 去重追加，有条数上限 | 跳过不支持记录 | 默认并入历史、执行 SQL 内容 |
| FRP 文件内容 | 存为空间管理副本，待路径绑定/人工启用 | 选定文件级替换且留回滚版本 | 写源路径、启动 frpc、按文件名覆盖外部文件 |

“采用导入”是记录级替换，不默认递归深合并任意 JSON/数组。对请求 header、SQL、TOML 等按 owner 的明确规则处理，未知字段不能悄悄丢弃：已支持版本原样保留允许字段；不支持的新 schema 阻止该数据集并提示。

### 5.3 重复导入与删除

- 记录 importRunId、sourceSpaceId、entityUid → targetUid 映射和所采用 revision；importRunId 不作为唯一去重依据（同数据可被重新导出为新包）。
- 同包重复导入默认不新增副本；用户明确“再次作为新副本导入”时生成新目标 UID 和独立映射分支。
- 普通包是**选中记录的快照**，缺记录不表示远端删除。即使包带未来 tombstone，v1 快照导入也不应用删除事件；未知 change-set 格式拒绝。
- 本地已删除过的已映射记录再次出现时标“可能恢复已删项”，默认不复活，需确认；为本期导入来源映射保留最小删除状态，无需现在建设完整云同步日志。

## 6. 包格式与秘密处理

### 6.1 v1 格式

建议扩展名 `.pbdata`（不改变应用 identifier；扩展名为本任务定义）。使用版本化加密容器，逻辑数据为 JSON，不暴露或要求导入原始 SQLite 文件。

- 明文头只含 magic/containerVersion、KDF/算法参数、salt、nonce 和必要长度；工具名、服务器名、目录、记录清单和来源标识均在加密 manifest 内。
- 整包使用现有 Argon2id + AES-256-GCM 经审查后的安全原语，密码由用户设置，本机主密钥绝不进包。AEAD 认证格式版本及关键头字段；不能自行拼接未经评审的分块加密协议。
- 逻辑 manifest 含 packageId、sourceSpaceId、createdAt（仅展示）、appVersion、dataset schemaVersion、记录数、依赖与摘要。密码验证/认证通过前不相信内层内容。
- 默认全部加密，包括不选 Vault 的包；已有 `.pbvault` 可经兼容解析器转换为 credentials 数据集，复用同一预览/冲突/提交流程，保留旧格式读取。
- v1 不压缩、不接受归档任意路径，FRP 选中文本作为逻辑记录，减少解压炸弹/路径穿越入口。

### 6.2 资源上限与文件操作

- v1 建议逻辑明文最大32MiB、单记录最大2MiB、总记录数50,000、JSON 深度64；超过提示缩小选择，不静默截断。采用 hex/base64 时文件上限按编码膨胀显式计算，解码前限制文件长度。
- KDF 算法、salt/nonce 长度、内存/迭代/并行度均校验白名单与上限，不能照包内参数无限分配。实施前用两平台确定导出参数及接受范围，记录性能；在范围未冻结前不得开放任意参数导入。
- 解密/解析/生成在 Rust 有界后台任务中完成，秘密与完整包不进入 JS；仅明确保存密码输入走必要 IPC，禁日志。避免同时持有多个全量明文副本，记录峰值内存。
- 不落未加密临时 payload。大包后续若需流式方案另行版本化，不能为首版引入无上限缓冲。
- 导出写唯一临时文件、刷盘、原子提交；覆盖已有导出文件须正常覆盖确认，失败保留旧文件。
- 导入不触发任何登录、联网、SSH 连接、SQL 执行、系统配置修改或外部程序运行；文件内 source/account/device 标签是非可信数据。

## 7. 导入预览、提交与回滚

### 7.1 UI 流程

设置 → 数据管理 → 导入/导出；布局复用 Ui*，不自绘第二套确认或进度组件。

导出：选当前空间 → 选类别/记录 → 显示依赖和敏感内容 → 设置密码/保存位置 → 进度与报告。

导入：选文件/输入密码 → 校验 → 默认“新空间隔离”或“合并当前空间” → 选数据/解决冲突 → 预览新增、替换、跳过、待补全、路径待绑定数量 → 确认应用 → 重启后结果报告。预览清楚显示目标空间名，不能只写“导入”。

未知工具/新版本数据集允许用户显式排除后重新预览；依赖它的记录一并重新检查。不能把部分跳过包装成“全部成功”。

### 7.2 写入一致性

多个 SQLite 库 + Vault + 偏好文件不能靠一次 SQL 事务保证全局原子。采用**暂存完整目标 generation + 持久提交日志 + 单一活动指针切换**，复用 T01/T02/T05/T06，不引入第二个磁盘迁移引擎。

1. inspect/plan 只读，返回 planId、目标 generation/revision、包摘要、决策摘要，不修改业务数据。前端不能提交任意来源 SQL/物理路径。
2. commit 前取得同一维护锁，阻止新增相关写入；重核目标 revision 与导入文件摘要。用户预览后本地有变化则计划失效，必须重算，不静默套用旧决策。
3. 获取一致性源快照。合并时完整克隆当前空间的**全部持久数据**作为 staging，仅修改选定数据；否则切换会丢失未选工具数据。隔离空间从空的合法 schema 开始。
4. 由各 owner adapter 应用逻辑记录与映射，凭证在目标空间使用本机 key 重新加密；验证引用、schema、可读性、计数与清单。偏好在 staging 中保存。
5. 日志状态建议 prepared/staged/validated/activation-pending/committed/rolled-back；密钥准备与文件状态都要可恢复，日志不存明文秘密。
6. v1 应用在维护状态完成 staging 后立即安排重启激活；若允许稍后重启，维持受影响空间写保护并可撤销计划，不能释放写入后仍把过时 generation 激活。新空间隔离导入可不切换并返回原空间继续使用。
7. 重启前全部业务连接释放；启动按已刷盘提交日志验证、原子更新活动指针。中断后只打开完整旧版或完整新版，禁止混合 generation。
8. 提交失败回旧状态并报告。回滚后继续操作会产生新的修改，不能用旧回滚快照无提示覆盖这些新修改；此时先保存当前 generation 或按新的导入计划处理。

空间切换、根迁移、导入提交、更新安装共用维护互斥。generation 的旧版保留到至少一次成功启动和人工确认，清理只删本应用清单记录且无人引用的目录，不提供自动清空空间。

## 8. 为未来云账户现在留下的接口

### 8.1 本期要实际落地的基础

1. **数据访问上下文**：`DataContext { spaceId, generationId }` 由框架注入；未来账户绑定是可选独立关系，不要求现在每张表加 account_id。
2. **owner 数据适配器**：`describeDatasets / exportRecords / validateRecords / planImport / applyToStaging / enumerateReferences`。本地文件解析与未来云端传输都转为相同逻辑记录，但云端不得绕过授权/冲突检查。
3. **稳定 UID 与 revision**：凡本期可传输实体实际保存 UID；修改入口统一更新 revision。为未来可枚举快照、记录变化/删除留接口，本期只实现本地需要的变更通知与导入删除映射。
4. **字段传输策略**：portable、device-local、secret、sensitive-content、history 分类成为 adapter/schema 契约；框架新设置字段必须声明策略，默认 device-local，不默认可上传。
5. **来源/冲突信息**：导入记录稳定来源和映射；schemaVersion 与业务 revision 分离，支持将来携带 baseRevision/远端游标但不把本地 revision 当全局时序。
6. **传输与密钥分层**：文件容器加密、设备 Vault 加密、未来账户同步内容密钥分开；提供加解密材料来源接口，本期仅本机 keyring/文件密码实现，不添加假登录入口或空云服务常驻进程。

这些接口必须由本地导入导出真实消费并带测试；不为“以后可能用”创建无人调用的 server/client/outbox 框架。

### 8.2 后期接云时再实施

- Account ↔ RemoteSpace ↔ LocalSpace 的显式绑定与同步范围选择；首次登录由用户选择下载到新空间或合并，不能自动上传所有本地空间。
- 登录/退出、会话 token、设备授权/撤销、传输重试、增量 outbox、游标、墓碑确认和冲突解决；未登录时不运行同步网络任务。
- 从本期 UID/revision 快照建立首次同步基线，绑定后再启用完整变更日志。旧设备无日志不能装作拥有完整因果关系；不承诺时间戳自动解决并发。
- 配置/习惯按白名单可同步，凭证单独开关并采用端到端加密方向；服务端不保存可直接解密凭证的原始 key。本期只保证接口能接独立账户内容密钥，账号恢复/密码重置/密钥轮换协议后期单独设计评审。
- 离线继续编辑、账号切换后本地空间隔离；退出账号是否保留离线副本由用户选择，不能把退出等同于清空本地库。

**不作过度承诺**：这些预留能避免改写插件业务数据模型和整库迁移，但接云仍需新增身份认证、服务端、增量协议和安全恢复机制，不能声称未来只填一个 URL 即可同步。

## 13. L0 数据边界冻结（2026-09-13 定稿）

> 依据：[剩余项决策书](../arch-202609-001-架构重构与规范调整/剩余项决策书.md) §5「L0 先冻结」。本节是 L0 的唯一落点，**不再另建 L0 任务书**。
> 本节只冻结边界与命名，不实现 L1–L5；本节定稿不改变当前 `paths` / `settings` / `vault` 的运行时行为。

### 13.1 空间与设备字段归属表（冻结）

归属规则：**换机器需要重新设置或本来就属于本机的 → 设备级；跟着用户数据走的 → 空间级。** 未在表中登记的设置字段一律按设备级处理（§8.1 第 4 条「默认 device-local」），新增字段必须在自己 owner 的 schema/manifest 里显式声明策略。

| 当前存储项 | 现值位置 | 归属 | 可移植性 | 迁移动作 |
| --- | --- | --- | --- | --- |
| `storageRoot` | `settings.json/app` | 设备级 | device-local | 留在固定自举配置；绝不进包、不随空间切换 |
| `layoutVersion` | `settings.json/app` | 设备级 | device-local | 同上；由迁移写入，不作为数据字段导入 |
| `launchAtStartup` | `settings.json/app` | 设备级 | device-local | 同上 |
| `defaultDownloadDirectory` | `settings.json/app` | 设备级 | device-local | 本机路径，导入后待重新绑定 |
| `theme`、`language` | `settings.json/app` | 空间级 | portable | 按字段导入（可选），缺值用默认 |
| `recentTools` | `settings.json/app` + `patchybox.json` | 空间级 | history | 默认不带，显式选择后按上限截断追加 |
| 收藏工具 / 已保存视图 | `patchybox.json`（favorites） | 空间级 | portable | 可默认选；有序去重并集 |
| `tools['format-tools'].indent` | `settings.json/app.tools` | 空间级 | portable | 按 owner 选择导入 |
| `tools['ssh'].idleDisconnectMinutes`、`tools['ssh'].autoReconnect` | `settings.json/app.tools` | 空间级 | portable | 同上 |
| `tools['frp'].maxLogLines` | `settings.json/app.tools` | 空间级 | portable | 同上 |
| `tools['frp'].frpcPath`、`tools['frp'].profileDir` | `settings.json/app.tools` | 设备级 | device-local | 本机路径与可执行程序位置，不导入，按 `(spaceId, owner, entityUid, bindingKind)` 重新绑定 |
| `tools['frp'].downloadMirror` | `settings.json/app.tools` | 设备级 | device-local | 取决于本机网络可达性，不导入 |
| 插件数据库 `data/<owner>.db` | storageRoot 四分区 | 空间级 | portable（按记录） | L1 起按 `spaces/<id>/generations/<n>/data/` 落位 |
| Vault 凭证（vault.dat） | `vault/` | 空间级 | secret | 默认不带，勾选后仅经加密包 |
| namespace credentials | `data/credentials/` | 空间级 | secret | 同 Vault，逐单元声明 |
| `data/credentials-master.key`（`framework::credentials` 命名空间密文的主密钥） | `<storageRoot>/data/` | 空间级 | secret | 与 vault 主密钥**相互独立**的第二套密钥；分区后必须落在本空间目录，L1 分别验证跨空间不可解 |
| 历史密钥 `data/ssh-master.key`、`data/db-master.key`、`data/db-secrets.enc` | `<storageRoot>/data/` | 空间级 | secret（已停写，仅迁移用） | 随空间搬运以便旧密文可读；确认无旧密文后按 §7.2 清理，未验证前不得删除 |
| `data/ssh-known-hosts` | storageRoot 四分区 | 设备级 | device-local | 系统信任状态不迁移；跨机首次连接仍校验主机 key |
| 空间索引 / `activeSpaceId` / `pendingActivation` | 固定自举配置 | 设备级 | device-local | 本机空间列表与当前选择 |
| `logs/`、`cache/` | storageRoot 四分区 | 设备级 | 不可导出 | 不纳入任何数据集 |

### 13.2 稳定身份（冻结）

| 标识 | 规则 | 当前状态 |
| --- | --- | --- |
| `DataSpaceId` | 小写 UUIDv4 字符串，仅用于目录名与逻辑引用；**禁止**用账户邮箱、机器名或路径派生 | 现有数据注册为 `default` |
| `default` / `1` | **仅兼容承载位**：表示「尚未建立空间索引的旧布局」，不扩散为新数据的永久标识，不出现在新空间的命名里 | `context::DEFAULT_SPACE_ID` / `DEFAULT_GENERATION_ID` |
| `generationId` | 每个空间内单调递增的无符号整数，仅表示该空间的一次完整提交结果 | 旧布局为 `1` |
| `entityUid` | 稳定 UUIDv4，与自增主键、名称、主机地址无关；已有 UUID 的记录优先复用 | 按 §4.1 在 L1 起落地 |
| `revision` | 每空间本地单调修订号，与逻辑修改在同一插件事务内更新 | 同上 |
| `AccountId`、`RemoteSpaceId` | 与 `DataSpaceId` 分别建模，本期不实现账号，不得用 `AccountId` 代替 `spaceId` | 未实现 |
| 来源标识 `sourceLineage` | 记录来源空间稳定标识与原 `entityUid`，仅供再次导入对照，不是可信身份 | 同上 |

### 13.3 兼容布局与 location descriptor（冻结）

两种布局都必须能被同一个启动解析表达，**不要求首次升级就搬全部数据**：

| 布局 | 形态 | 何时使用 |
| --- | --- | --- |
| `LegacyFlat` | 用户根下直接 `data/`、`vault/`、`logs/`、`cache/` 四分区（现行为，`layoutVersion = 2`） | 未建立空间索引的旧安装；`default` 空间的当前形态 |
| `Partitioned` | `<root>/spaces/<spaceId>/generations/<generationId>/{data,vault,preferences.json}` | 由 L1 起为新建空间与导入提交后的 generation 使用 |

- 启动时按固定自举配置解析出唯一 `StorageLocation`（含布局类型与根），进程内只解析一次，`paths` 与 `PluginDb` 消费同一实例。
- `default` 空间在迁移/导入提交前保持 `LegacyFlat`；首次提交后才建立 `Partitioned` 目标 generation。旧 generation 目录保留到 §7.2 末段（至少一次成功启动并人工确认）才清理。
- 迁移必须枚举空间索引引用的**所有空间及其必要 generation**（T01/T02），不得只复制四个目录而遗漏非活动空间。

### 13.4 generation 激活（冻结）

- 同一时刻只有一个活动空间；切换**重启生效**，不引入空间热切换。
- 空间切换、根迁移、导入提交、更新安装共用同一维护互斥；前端按钮禁用不算锁。
- 激活以「原子更新活动指针 + 已刷盘提交日志」完成：中断后只能打开完整旧版或完整新版，禁止混合 generation。
- **generation 切换不轮换既有空间主密钥**；跨空间创建才使用新密钥。保留旧 generation 时其可用密钥一并保留，清理磁盘不得删除仍被引用的 key。
- 旧 generation 至少保留到一次成功启动且经人工确认。

### 13.5 密钥作用域（冻结）

| 作用域 | 规则 | 现状 |
| --- | --- | --- |
| 默认空间主密钥 | 沿用现有 keyring 条目 `service = com.patchy23.patchybox`、`account = vault-master-key`；keyring 不可用时的降级文件为 `<storageRoot>/vault/vault-master.key`（随存储根迁移） | 已实现（`framework/vault/store.rs`、`paths::vault_dir`） |
| 新空间主密钥 | 每空间独立 `vaultKeyId`，映射到本机 keyring 的独立 account（命名随 L1 定稿并在该批记录）；**不得**与默认空间共用同一密钥 | 未实现 |
| 隔离的两个层次必须同时做 | 降级文件天然落在各空间 `vault/` 目录内，但 keyring 条目按 `service + account` 取名：**只分目录不分 keyring account，多个空间会共用同一把主密钥**，隔离就只剩目录层。L1 落地时必须同时验证「跨空间 resolve 失败」与「空间 A 的密文用空间 B 的密钥解不开」 | 未实现 |
| 第二套主机密钥（`framework::credentials`） | 命名空间密文（如 database 连接密码）的主密钥是 `<storageRoot>/data/credentials-master.key`，与 vault 主密钥**彼此独立**；分区后两把密钥都要落在本空间目录内，L1 分别验证跨空间不可解，不能只验 vault | 已实现（`framework/credentials.rs`；`framework/paths.rs` 迁移表已含该文件） |
| 历史插件密钥（`ssh-master.key`、`db-master.key`、`db-secrets.enc`） | 只作旧密文迁移输入，不产生新作用域；清理前必须确认无旧密文引用 | 已停写 |
| namespace credentials | 与所属空间同作用域，禁止跨空间 resolve 同一句柄 | 未实现 |
| 导出/导入 | 本机主密钥绝不进包；导入的凭证在**目标空间**用该空间密钥重新加密；源机器 keyring 不参与解密 | 未实现 |
| `.pbvault` 兼容导入 | 用包自身密码解密，不读取源机器 keyring | 未实现 |

### 13.6 接口冻结（L1 起消费，命名先定）

1. Rust 上下文：`DataContext { spaceId, generationId, epoch, location }`（字段语义见原 arch 批次任务书 §9.1，现状见 `framework/context.rs`）；前端只取非秘密标识，业务组件不拼物理路径。
2. 设置路由：设备字段与空间字段按 schema 分流，插件不得自行合并两份配置；`settings` 命令的对外语义保持，路由由框架适配层完成（T07）。
3. owner 适配器：`describeDatasets` / `exportRecords` / `validateRecords` / `planImport` / `applyToStaging` / `enumerateReferences`（§8.1 第 2 条），必须由本地导入导出真实消费并带测试。
4. IPC 命令：§9 作为设计基线。未发布且无实际消费方的命名可随方案调整；已有发布或消费方时按真实兼容需要处理，不为规划名称强制建立别名。
5. 传输策略枚举：`portable` / `device-local` / `secret` / `sensitive-content` / `history`，作为 adapter/schema 契约字段。

### 13.7 旧 API 库与未选数据的保留（冻结）

- `data/api.db` **不改名、不清空**：owner 归入 `http_ws`，通过 `storageKey: api` 显式声明历史存储键（AR07 已落地）。
- 合并导入时以**当前空间全部持久数据的完整克隆**作为 staging，仅修改选定数据；未选工具/未选数据集的数据必须随 generation 一起提交，不得因切换丢失（§7.2 第 3 条）。
- 未选择任何数据集、凭证不含秘密、`schemaVersion` 未知、依赖缺失等情形，都按 §7.1 的「明确排除 / 待补全 / 阻止该数据集」处理，不得静默丢弃。
