## 2. 现状核对（含凭证加密逻辑，只读核对）

### 2.1 空间与目录

| 事实 | 位置 | 后果 |
| --- | --- | --- |
| 默认空间 id 是字面量 `"default"` | `framework/context.rs:23` | 每台机器同名，无全局唯一性 |
| 默认空间是 `LegacyFlat`：数据直接在 `<设备根>/{data,vault}` | `framework/context.rs:30,37`、`space/mod.rs:160` | 与其他空间的 `spaces/<id>/generations/<n>/` 两种布局并存 |
| 默认空间密钥库走历史 service `com.patchy23.patchybox` | `framework/secure_store/key/mod.rs:19` | 搬迁时要连密钥库条目一起搬 |
| 切换空间 = 写 `activeSpaceId` + 要求重启 | `data_transfer/commands.rs:259-289`、`space/mod.rs:128-153` | 空间身份在设备自举配置里 |
| 导出包 manifest 的 `sourceSpaceId` 写 `"default"` | `data_transfer/commands.rs:307` 等 | 两台机器的默认空间包来源 id 相同 |
| 前端无 `"default"` 字面量假设 | `src/` 全局检索为空 | 只需动后端 |

### 2.2 当前凭证加密逻辑（按代码逐层）

1. **密钥域**：每空间一把 32B 随机主密钥。密钥库 service 按空间分：默认空间 `com.patchy23.patchybox`（历史名），其他空间 `com.patchy23.patchybox.<空间id>`（`secure_store/key/mod.rs:18-23`）；生产侧只允许经 `keyring_store()` 按当前空间构造。
2. **主密钥解析顺序**（`secure_store/key/resolve.rs`）：系统密钥库 → 本地降级密钥文件（收紧 ACL）→ 首次生成（OsRng 32B）写入；写库失败降级写文件并告警；旧密钥每进程自动登记回密钥库一次。
3. **落盘**：`<空间>/vault/vault.dat`（旧布局回落 `<空间根>/vault.dat`，`vault/store/paths.rs`），整库 AES-256-GCM：`nonce(12B)‖ciphertext(16B 标签)`，每次新 nonce（`secure_store/crypto.rs`）；**AAD 为空——密文不含空间身份**。
4. **隔离强度**：靠「主密钥 per 空间 + 密文文件 per 空间」。同时拿到 A 空间的 `vault.dat` 与其主密钥，在 B 空间能解开——**当前没有数学上的 uid 绑定**。
5. **数据包（.pbdata）**：用户口令经 Argon2id 派生密钥 + AES-256-GCM，包头绑进 AAD；与空间主密钥无关。所以现有「勾选携带凭证」只要有口令跨空间可解——这是本方案要限制的路径。

## 3. C0：uid 化与数据搬迁（硬迁移，不留尾巴）

### 3.1 目标布局与身份

- 布局：`<设备根>/spaces/<uid>/generations/1/{data,vault,preferences,…}`；自举 `activeSpaceId = uid`；空间索引以 uid 为键。
- `DEFAULT_SPACE_ID` 常量、`LayoutKind::LegacyFlat`、`resolve_vault_dir` 的旧布局回落、密钥库历史 service 分支——**全部删除**，正常路径只有新布局。
- 导出 manifest 的 `sourceSpaceId` 与 L3 映射键一律用 uid。

### 3.2 迁移步骤（启动维护窗口，一次跑完）

1. 检测旧布局：自举 `activeSpaceId == "default"`、或设备根存在 `{data,vault}` 而 `spaces/` 下没有对应空间；
2. 生成 uid（UUIDv4），建 `spaces/<uid>/generations/1/`；
3. 把设备根的空间级内容（`data/`、`vault/`、`preferences.json` 等）移入新代目录；
4. 主密钥搬家：读旧 service `com.patchy23.patchybox` → 写新 service `.<uid>` → 回读校验一致 → 删除旧 service 条目；降级密钥文件随目录搬迁；
5. 写自举与索引（uid 为键），清理旧痕迹；
6. **任一步失败：fail-fast 拒绝启动**，保留现场并给出明确错误与日志位置——不回落、不猜、不半途继续。

### 3.3 迁移代码与正常代码的边界

迁移是一次性升级路径，只存在于启动维护窗口；迁移完成后正常路径无旧布局分支（不留双读）。旧安装的凭证可读性由「密钥搬家 + 回读校验」保证，不靠兼容层。

### 3.4 测试

| 用例 | 断言 |
| --- | --- |
| 全新安装首启 | 直接生成 uid 布局，无旧分支参与 |
| 老安装迁移 | 数据/凭证/偏好在 `spaces/<uid>/generations/1/` 下完整可读；自举与索引一致 |
| 密钥搬家 | 新 service 写入后回读一致；旧 service 条目已删；迁移后凭证可解密 |
| 迁移失败注入（每步中断） | 现场保留、下次启动可重跑或明确报错，不出现半迁移态 |
| 导出 manifest | `sourceSpaceId` = uid，非字面量 |
| 回归 | 现有空间/凭证/导入导出测试全绿（布局常量变了，测试基线同步更新） |

## 4. 凭证与 uid 绑死（D 裁决落地）

### 4.1 加密绑定：AAD = uid

- `vault.dat` 改用 `encrypt_with_aad(key, plain, uid)`：密文认证绑到 uid；换 uid（即使拿到同一把主密钥）认证失败。
- 老文件（AAD 为空）就地升级：首读用旧式解密成功 → 立即按新格式重写落盘。与 §3.2 搬迁同一维护窗口完成，不留长期双读。

### 4.2 包的口径：凭证不随包

- **导出**：凭证数据集不进包（含勾选入口——是否彻底移除见 §5 D-D1）；导出界面明示「凭证不随包导出，导入方需重新配置凭证」。
- **导入**：包内出现凭证块（旧版本包）→ 忽略该块，报告「N 条凭证未导入」，引用凭证的档案标「凭证待补录」。
- **待补录的可用性补救**：档案内联徽标 + 凭证列表「待补录」筛选，就地补录一次即恢复；合并导入时对未随包的凭证引用做业务键匹配（名称 + 用户名/主机），预览里给「采用本地同名凭证」显式入口，默认不勾、不自动绑定。
- `known_hosts` 不进包（既有裁决）不变。

### 4.3 与任务书冻结的关系

任务书 §13.5「携带秘密可选（用户显式勾选）」被 2026-09-16 裁决**取代**：凭证不随包导出。任务书相应行已加更新标注；§13.1 包 header 的 `sourceSpaceId` 字段不变（仍是来源标识，只是值从字面量变成 uid）。
