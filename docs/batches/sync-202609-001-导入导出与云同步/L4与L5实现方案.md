## 当前实现与范围

现有 `DatasetAdapter` 已覆盖目录、逻辑导出、校验、引用、预览、隔离写入与合并写入；框架注册 Vault 元数据及收藏、最近使用，SSH 在自己的 owner 内注册适配器。其余 owner 尚未接入。沿用这条调用链，不另建导入引擎或 IPC 命令表。

| 对象 | 源码现状 | 本次交付 |
| --- | --- | --- |
| HTTP/WS | `http_ws/persistence/mod.rs` 管理 `api.db/api_list`，主键为自增整数 | 由 HTTP/WS owner 导出逻辑请求，追加稳定 UID，支持隔离、合并、显式冲突决策 |
| 数据库 | `database/store.rs` 管理连接、查询历史、收藏 SQL；历史及收藏使用整数主键 | 连接及收藏、显式选择的历史；稳定 UID 与连接引用重映射；SQLite 本机路径不搬移 |
| 数据库凭证 | `database/secrets.rs` 经框架 namespace 存储密码 | 不导出 namespace 秘密；导入连接提示补录，不按来源连接 ID 绑定目标密码 |
| DNS | `dns/mod.rs` 按平台保存单槽配置，含手工密钥与 Vault 引用 | 导出无秘密配置及补录信息；单槽只允许保留或替换，拒绝保留两份 |
| FRP | `frp/mod.rs` 保存元数据，`profile.rs` 操作真实 TOML；配置目录可位于外部路径 | 可移植元数据、经显式选择的配置内容；导入内容只落空间管理目录，不覆盖外部源文件、不启动 frpc |
| 偏好 | 现适配器仅处理收藏与最近使用 | 按设置 schema 白名单导出应用及工具可移植字段，逐字段合并，排除路径、自启等设备字段 |
| 合并安全网 | `merge.rs` 的 `TRACKED_STORES` 仅含 SSH、偏好和映射文件 | 适配器声明受影响存储，统一驱动快照、变更检测与恢复；覆盖所有新增 owner |

## 需要确认的安全边界

任务书 §2.1、§6 允许用户显式导出可能含秘密的 API 原文、SQL 和 FRP TOML，标为 `sensitiveContent` 并整包加密；后续 [UID 方案](uid模型与凭证绑定方案.md) §4.2、§5 又规定“包永远不含凭证”。对于任意文本中的 token、口令及 SQL 字面量，不能承诺自动脱敏完整。

建议采用以下明确口径：

- Vault、数据库 namespace 密码、DNS 手工 key 等结构化凭证始终不导出；认证引用在目标空间补录。
- API 原文、SQL、FRP TOML 作为敏感内容默认不选；用户显式选择并确认风险后可进加密包。界面明确原文可能含 token 或密码，不宣称包内绝无秘密。
- 不选择敏感内容时，不在普通元数据中夹带这些原文；FRP 不递归扫描或打包外部目录。

另一选择是严格禁止任何潜在秘密原文进包：API 请求内容、SQL 文本与 FRP TOML 均不导出。这会缩减任务书承诺的能力，不能由实现者自行替用户选定。上述口径未确认前，不实现敏感内容传输。

## 实施步骤

1. **统一契约和保护范围**：补齐 owner 数据集覆盖表；将快照及变更检测存储清单改为适配器声明，拒绝绝对路径、父目录穿越和重复归属。SQLite 快照通过一致性读取处理 WAL，不直接把复制主文件当成完整备份。核对写冻结顺序、提交前计划复核和恢复路径。
2. **HTTP/WS 与数据库适配**：每 owner 自管 SQL 和 DTO。对整数主键记录追加稳定 UID，并在新增记录时产生 UID；导出不得临时生成身份。隔离导入映射本地主键，合并先确定目标 UID 再改写关联；保存 SQL 与历史不触发 SQL 执行。数据库连接引用不携带 namespace 密码，避免目标同名或同 ID 凭证被自动使用。
3. **DNS 与 FRP 适配**：DNS 依平台单槽约束规划，秘密字段排除。FRP 元数据与内容分开选择，稳定身份独立于文件名；导入文件名由目标身份安全生成，外部路径仅作为待绑定需求。为导入的管理副本补齐列表和打开入口，不能只写出无人可见的文件。
4. **应用与工具偏好**：沿用现有 settings schema 的设备/空间边界，按字段白名单处理；未知字段和不支持版本可见拒绝。合并保留未选偏好，覆盖仅作用于明确选中数据集。
5. **界面与刷新**：复用现有向导和公共 UI，补齐类别、敏感内容确认、凭证补录、本机路径待绑定、DNS 限制及结果说明。提交事件覆盖所有新增 owner，并核对各工具实际消费刷新事件；运行中的远端连接或进程不因导入自动新建、重连或执行。
6. **验收与文档**：完成下表对应测试代码、允许的本地验证和用户格式说明；统一总任务书及 L3 中已被最新裁决取代的状态文字；更新 TODO 与人工验证清单。不得将未运行的编译、测试或平台验证写成通过。

每个 owner 以独立事务或文件原子替换提交；跨 owner 原子性仍按已批准的 L3 边界处理，失败必须报告真实写入结果与可恢复快照，不能返回整体成功。发现需要改变该边界时另行确认。

## 验证与风险

| 验证项 | 必须证明 |
| --- | --- |
| owner 往返与选择 | 仅所选记录落地；每种数据集均有隔离与合并覆盖；未选 owner 保持不变 |
| 身份与引用 | 重复导入幂等；同名不同 UID 冲突；保留两份改写引用；历史关联目标连接；删除后重导默认不复活 |
| 凭证边界 | 结构化秘密不进入包；导入不会误绑定目标已有密码；DNS 秘密和引用缺失可见 |
| 单槽与偏好 | DNS 拒绝保留两份；偏好按字段合并；未知字段不静默丢弃；设备设置不被覆盖 |
| 文件边界 | FRP 路径穿越拒绝；外部源文件不变；SQL、FRP 与 API 导入不执行任何外部操作 |
| 故障与并发 | 预览后各 owner 修改使计划过期；WAL 数据可恢复；失败释放冻结；写入中断、失败及快照还原覆盖新增存储 |
| 包与限额 | 错密码、篡改、未知 owner/schema、超限、重复 UID 拒绝；导出失败保留原目标文件 |
| 用户流程 | 导出、预览、冲突处理、报告、工具刷新和快照还原可观察；格式、资源上限与排除项在界面可查 |
| 跨平台 | Windows/macOS 路径、凭证补录和管理副本行为；离线流程；当前构建的规模、耗时与内存证据 |

执行命令只引用[验证矩阵](../../standards/20-验证矩阵.md)。保留本地不执行 Cargo、产品编译和行为测试由 CI 或用户执行的裁决；本地执行相应前端检查及 Rust 静态扫描。远端未执行时明确标为未执行，不以静态扫描替代编译测试。真机、macOS、跨机器与性能实测纳入[人工验证清单](../../待人工验证清单.md)，不阻塞代码阶段收口，但不宣称已有实测结论。
