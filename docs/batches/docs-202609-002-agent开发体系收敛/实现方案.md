# Agent开发体系收敛实现方案

## 决定

- AGENTS只保留必读入口、不可遗漏边界、提交与协作约定；工作流管定档；新增20验证矩阵统一命令。
- 必读集合：AGENTS、TODO、10工作流、README。台账只读当前批次；README不重复状态。
- 台账继续使用Markdown表格，按表头解析状态、证据和批次文件；不引入数据库或重复JSON状态源。
- 预算保留字符代理度量，明确不等于token；新超限即失败，存量例外有限额与原因。
- Markdown检查仅验证本地文档链接及锚点，跳过示例代码与模板占位符；显式报告边界，外链不联网。
- Python标准库unittest运行临时目录负例，不改真实仓库来注入错误；CI新任务使用完整Git历史。

## 改动面

AGENTS、TODO、docs/README、进度台账、standards/10/16/17及旧模板引用；新增standards/20验证矩阵。
scripts/check_progress.py、check_doc_budget.py、新增check_markdown.py与test_doc_checks.py；CI文档job。
UI手册改为按章节使用，现有专题内容保留；历史批次只加必要入口，不批量重写。

## 步骤

1. 两份文档先落盘并登记待实施；保留用户授权来源。
2. 先建立回归夹具；改检查器，验证错误输入不能假绿。
3. 修改常青规则和导航，修复实际链接、台账结构及证据缺口。
4. CI接入；运行负例与仓库检查，按四条任务路径查规则和字符量。
5. 实现提交后，用独立记录提交回填实现hash及验收证据，避免hash自引用。

## 风险与回退

收紧检查器可能暴露存量问题：修真实引用或如实降级无证据状态，不抬高基线隐藏错误。
历史只存在Git的内容引用应显式写提交证据；用户裁决保留原义。
改动仅文档与开发工具，可逆序回退本批提交；不碰branding或其他人的未提交文件。
