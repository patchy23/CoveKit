# SSH 插件 · 装配说明（集成者落库用）

## 1. Cargo.toml 依赖（已完成 ✅）

```toml
# SSH 插件：russh 客户端 + SFTP + 凭证 AES-GCM 加密（ssh-key 由 russh 依赖提供）
# ring 后端：避免 aws-lc-rs 在 Windows 依赖 NASM 汇编器
russh = { version = "0.62.5", default-features = false, features = ["flate2", "ring", "rsa"] }
russh-sftp = "2.4.0"
aes-gcm = "0.10"
rand = "0.8"
base64 = "0.22"
```

## 3. 凭证加密方案（v1 定稿：AES-GCM，非 stronghold）

- **背景**：设计阶段推荐 stronghold；实现时发现 iota_stronghold 2.x 为 procedures 架构（Rust 侧胶水成本高），且 tauri-plugin-stronghold 仅暴露前端命令层（内部 StrongholdCollection 私有）——Rust 侧直接集成成本过高
- **v1 方案**：AES-256-GCM 本地加密
  - 主密钥：随机 32B，存 `app_data_dir/ssh-master.key`（首次生成）
  - 凭证：JSON 全量加密存 `app_data_dir/ssh-credentials.json`（nonce||ciphertext）
  - 每次读写：解密全量 → 增删改 → 加密写回
- **P2 升级**：stronghold 引擎集成或系统钥匙串（keyring），需在凭证模型抽象后替换
