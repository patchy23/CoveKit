## 0. 一句话目标

把「手写 frpc.toml + 开终端跑 frpc」变成「列表选配置 → 表单或源码改 → 校验 → 一键启停 → 看实时日志与状态」，并与手写配置文件完全互通（工具不藏配置）。

## 1. v1 范围（做 / 不做）

**做**

1. 多配置档管理：扫描配置目录下 `*.toml`，新建 / 复制 / 重命名 / 删除（删除走备份到 `.trash/` 或 `.bak`，不直接抹除）。
2. 双模式编辑：**表单模式**（服务器 / 认证 / 传输 / 日志 + 代理列表）与**源码模式**（`UiCodeEditor`，TOML 高亮），切换时保留未保存内容并提示。
3. 配置校验：调 `frpc verify -c <path>`，错误行列回显到编辑器（源码模式给行号，表单模式给字段标签）。
4. 运行：启动 / 停止 / 重启单个配置档，支持多档同时运行；实时日志（stdout+stderr 合并）经事件推送到前端。
5. 状态判定：`stopped / starting / running / error`，来自日志行与进程退出码（无 `webServer` 时的唯一信息源），含启动兜底超时。
6. frpc 可执行文件：检测（设置路径 → PATH → 常见安装位置）+ 一键下载（列出可用版本、下载、解压、校验、落盘）+ 手动指定路径兜底。
7. 工具级设置：frpc 路径、配置目录、下载镜像前缀、日志缓冲行数。

**不做（v1 明确排除）**

- 关掉界面后 frpc 继续跑、开机自启、Windows 服务 / macOS launchd 常驻。
- 流量与连接数监控、运行时热改代理（`reload` / `store` API）、`webServer` 相关一切。
- 定时连接、代理健康检查可视化、frps 服务端管理、配置模板市场。
- 批量操作（批量启停 / 批量导入目录）、配置版本历史。

## 3. IPC 契约（冻结）

命令名一律 `frp_` 前缀，共 **16 条**。入参/返回在 `contracts.ts` 与 `models.rs` 各出现一次，字段名两侧完全一致（serde 用 `camelCase` 重命名）。

### 3.1 配置档

| 命令 | 入参 | 返回 | 说明 |
| ---- | ---- | ---- | ---- |
| `frp_profiles_list` | `{}` | `FrpProfileList` | 扫描配置目录，返回档列表（含元数据与运行状态） |
| `frp_profile_read` | `{ fileName }` | `FrpProfileContent` | 返回 `content`（原文）+ `parsed`（TOML→JSON Value） |
| `frp_profile_save_text` | `{ fileName, content }` | `FrpOpResult` | 源码模式保存：写原文（改前自动 `.bak`） |
| `frp_profile_save_form` | `{ fileName, parsed }` | `FrpOpResult` | 表单模式保存：由 Rust 用 `parsed` 重建 TOML（保留未知字段，**注释会丢**，见 §7） |
| `frp_profile_create` | `{ fileName, template }` | `FrpOpResult` | 新建（`template` 为内置模板 id：`tcp` / `http` / `stcp` / `empty`） |
| `frp_profile_duplicate` | `{ fileName, newName }` | `FrpOpResult` | 复制 |
| `frp_profile_rename` | `{ fileName, newName }` | `FrpOpResult` | 重命名 |
| `frp_profile_delete` | `{ fileName }` | `FrpOpResult` | 删除 → 移入配置目录 `.trash/`（带时间戳），不做物理删除 |
| `frp_profile_remark` | `{ fileName, remark }` | `FrpOpResult` | 备注写入 `frp.db`（不污染用户 TOML） |

### 3.2 校验

| 命令 | 入参 | 返回 | 说明 |
| ---- | ---- | ---- | ---- |
| `frp_verify` | `{ fileName }` | `FrpVerifyResult` | 调 `frpc verify -c <path>`；返回 `ok` / `raw`（原样输出）/ `errors[]`（解析出的 `{ line?, column?, message }`） |

### 3.3 运行

| 命令 | 入参 | 返回 | 说明 |
| ---- | ---- | ---- | ---- |
| `frp_start` | `{ fileName }` | `FrpRuntimeState` | 启动；重复启动同档返回当前状态不报错 |
| `frp_stop` | `{ fileName }` | `FrpRuntimeState` | 终止进程（先优雅，2s 未退则强杀） |
| `frp_restart` | `{ fileName }` | `FrpRuntimeState` | 停 + 启 |
| `frp_status` | `{}` | `FrpRuntimeState[]` | 全部档的当前状态（前端 5s 轮询兜底，事件为主） |

### 3.4 二进制

| 命令 | 入参 | 返回 | 说明 |
| ---- | ---- | ---- | ---- |
| `frp_binary_detect` | `{ path? }` | `FrpBinaryInfo` | 探测可执行文件（给定路径 / 设置项 / PATH / 常见位置），返回路径、版本、来源 |
| `frp_binary_versions` | `{ limit? }` | `FrpReleaseInfo[]` | 上游 Release 列表（默认取最近 10 个），供下载选择 |
| `frp_binary_download` | `{ version }` | `FrpBinaryInfo` | 下载 + 解压 + 校验 + 原子落盘到 `<app_data>/frp/bin/`；进度走事件 |

## 5. Rust 设计要点

### 5.1 路径安全（安全红线）

- 所有 `fileName` 视为**单段文件名**：拒绝含 `/`、`\`、`..`、绝对路径、Windows 保留名（`CON`/`NUL` 等）与空串；扩展名强制 `.toml`。
- 读写前用 `canonicalize` 校验结果仍位于配置目录内（防符号链接逃逸）。
- 违反即返回 `{ ok: false, error: "非法文件名" }`，**绝不 panic**。

### 5.2 状态机（`runtime.rs`，纯函数判定 + 单测）

输入：日志行（stdout/stderr 合并，剥 ANSI）、进程退出码、启动时刻。

| 触发 | 迁移 |
| ---- | ---- |
| `frp_start` 成功 spawn | `stopped/error` → `starting` |
| 行含 `login to server success` 或 `start proxy success` | `starting` → `running` |
| 行含 `login to server failed` / `token is incorrect` / `authentication failed` | 任意 → `error`（`lastError` = 该行） |
| 行含 `port already used` / `bind: address already in use` | 任意 → `error` |
| 行含 `start error` | 任意 → `error` |
| 进程退出码 0 | 任意 → `stopped` |
| 进程退出码非 0 | 任意 → `error`（`exitCode` + 最后一行） |
| `starting` 持续 30s 未出现成功/失败行 | `starting` → `error`（`lastError = "30 秒内未连接成功，请检查网络与服务端"`） |
| 兜底：`running` 后日志静默 60s | 不动（frpc 正常会静默，避免假红灯；仅由退出判定） |

> 反例防护：进程活着但早已掉线时，靠上述 `login to server failed` 等行转红；不出现"假绿灯"（MoonProxy 同思路）。

### 5.3 进程与清理

- `tokio::process::Command` spawn `frpc -c <abs path>`；`stdout`/`stderr` 均 `piped`，`tokio::spawn` 两个读取任务按行 emit。
- 进程句柄存 `State<FrpState>`（`Mutex<HashMap<String, RuntimeEntry>>`）。
- 停止：先发终止（Windows 用 `child.kill()`；进程自退优先），2s 未退强杀；`wait()` 回收僵尸。
- **应用退出兜底**：`lib.rs` 的窗口事件或 `RunEvent::Exit` 中 kill 全部 frpc，防残留进程（v1 无守护，界面关掉不该留后台进程）。
- 日志缓冲：Rust 侧仅做转发，不在内存长期累积；前端环形缓冲保留 `maxLogLines`（设置项，默认 2000）。

### 5.4 下载与校验（零新增依赖）

- 版本列表：`GET https://api.github.com/repos/fatedier/frp/releases`（`reqwest`，已有依赖），取 `limit` 条。
- 资产名按平台映射：Windows `frp_<v>_windows_amd64.zip`；macOS `frp_<v>_darwin_<arch>.tar.gz`。
- 下载：流式写入 `<app_data>/frp/bin/.download.<v>`（`reqwest` + `tokio::fs`）。
- 校验：若该 Release 含 `checksums` 资产 → 取期望 SHA256 比对（`sha2` + `hex`，已有依赖）；否则计算实际 SHA256，在 UI 明示「未强校验，SHA256 = ...」。
- 解压：Windows 用 `Expand-Archive`（PowerShell，已有调用先例）；macOS 用系统 `tar -xzf`。解压后取 `frpc[.exe]`。
- 落盘：原子 `rename` 到 `bin/frpc[.exe]`；macOS 补 `chmod +x`。
- 网络不可达（GitHub 被墙/超时）→ 返回明确错误 + UI 引导「手动指定 frpc 路径」；设置项 `downloadMirror` 为可选前缀（如镜像地址），默认空。
- **新增依赖评审**：仅需 `toml`（0.8.x，做 `parsed` ⇄ TOML 互转与未知字段保留）。四问结论：①必要性——表单模式的结构化编辑无替代；②体积/传递依赖——无重依赖；③活跃度——`toml` 为 serde 生态事实标准；④维护成本——仅用 Value 层 API。其余全部复用现有依赖（`reqwest`/`sha2`/`hex`/`tokio`/`rusqlite`）。

### 5.5 脱敏

- `auth.token`、`auth.tokenSource` 等敏感值在**日志转发**与**错误信息**中出现时按 `前4****后4` 打码；文件内容原样读写（用户自己的文件，不擅自改写）。
- `verify` 的 `raw` 原样返回（供用户判读），但写入 `lastError` 时脱敏。

## 6. 前端设计要点

### 6.1 布局（参考既有工作台与 postman 式三区）

```
┌ 左 260px ────────┬ 右（剩余）──────────────────────────────┐
│ 搜索框            │ [状态胶囊] [启动/停止/重启] [校验]  ⋯    │
│ ─────────────    │ ┌ 页签：配置 | 日志 ─────────────────┐   │
│ ● 档案A  running  │ │  配置：[表单 | 源码] 分段控件      │   │
│ ○ 档案B  stopped  │ │   表单：服务器/认证/传输/日志      │   │
│ ○ 档案C  error ⚠  │ │         + 代理列表（可增删行）      │   │
│ ─────────────    │ │   源码：UiCodeEditor(lang=toml)    │   │
│ [+ 新建] [⋯ 菜单] │ │  日志：RuntimeLogPanel             │   │
└──────────────────┴──────────────────────────────────────┘
```

- 左侧行用 `UiListRow`，状态点颜色：绿 running / 灰 stopped / 黄 starting（转圈）/ 红 error；右键菜单用 `ContextMenu`（重命名 / 复制 / 备注 / 删除），删除走 `ConfirmDialog`。
- 顶栏启停用 `UiIconButton`（高频操作用图标按钮，运行中显示转圈并禁用）。
- 未配置 frpc 时，详情区替换为 `BinarySetupCard` 引导卡（三条路径：一键下载 / 指定已有 frpc / 稍后再说）。
- 所有操作必须有可见反馈（`useUiStore` toast），禁止静默 catch。

### 6.2 表单 ⇄ parsed 映射（`frpForm.ts`，纯函数 + 单测）

覆盖字段（v1）：

- 顶层：`serverAddr`、`serverPort`、`user`、`auth.method`、`auth.token`、`log.level`、`transport.protocol`、`transport.tls.enable`、`transport.tls.serverName`、`transport.poolCount`。
- 代理数组 `[[proxies]]`：`name`、`type`（`tcp`/`udp`/`http`/`https`/`stcp`）、`localIP`、`localPort`、`remotePort`（按类型显隐）、`customDomains`（http/https）、`secretKey`（stcp）、`enabled`（开关）。
- **未覆盖字段与未知段落必须原样保留**（在 `parsed` 中透传，不得丢弃）；有字段被表单隐藏时，以「高级字段（源码模式编辑）」提示用户而非静默清空。
- 表单保存前若 `hasComments` 为真 → 二次确认「表单保存会丢失 TOML 注释，建议用源码模式或先备份」，确认后仍会生成 `.bak`。

### 6.3 状态与日志

- `useFrpRuntime.ts` 订阅 `frp://log` 与 `frp://state`，维护 `Map<fileName, { state, lines[] }>`；日志按 `maxLogLines` 环切。
- 日志行按等级着色（`[E]` 红 / `[W]` 黄 / `[I]` 默认），提供关键字过滤与「自动滚动」开关（用户手动上滚即暂停，符合终端直觉）。
- 状态展示映射与文案在 `frpStatus.ts` 纯函数集中（含 error 场景的一句话解释），便于单测与文案统一。

### 6.4 设置项（`settingsSchema`）

| key | 类型 | 默认 | 说明 |
| --- | ---- | ---- | ---- |
| `frpcPath` | text | `''` | frpc 可执行文件路径（空则自动探测） |
| `profileDir` | text | `''` | 配置目录（空则用默认 `<app_data>/frp/profiles`） |
| `downloadMirror` | text | `''` | 下载镜像前缀（GitHub 不可达时用） |
| `maxLogLines` | number | `2000` | 前端日志环形缓冲行数 |

## 9. 验收标准（DoD）

1. 16 条命令全部可用，`validate_routing()` 通过，冷启动无 panic。
2. 配置档的新建/编辑/重命名/删除/备注全链路可用，且**手工写的 TOML 能被工具打开编辑后无意外改写**（未知字段与顺序稳定，注释丢失有明确提示）。
3. 一键下载在 GitHub 可达时成功、不可达时给出可操作错误（引导手填路径），不静默失败。
4. 状态机与真实 frpc 行为一致：错 token / 端口占用 / 服务端不可达均能转 `error` 并给出可读原因，无假绿灯。
5. 无残留进程：停止后与应用退出后 `frpc` 均不在进程表内。
6. 门禁全绿；组件 ≤300 行；无新增依赖（除评审通过的 `toml`）；Rust 规范 v1.1 合规（无 unwrap/expect、注释完整）。
7. 所有操作有 toast 或错误行反馈。

## 10. 风险与对策

| 风险 | 对策 |
| ---- | ---- |
| `frpc verify` 输出格式在不同版本不一致 | 解析器降级策略 + 原样展示 `raw`；单测覆盖「无法解析」分支 |
| 用户手写 TOML 含工具未知段落 | `parsed` 全量透传，绝不重建丢弃；表单保存前提示注释风险 + `.bak` |
| frpc 版本过新/过旧导致日志行文案变化 | 成功/失败关键字表按前缀匹配（`start proxy success` / `login to server failed`），并允许 `error` 状态附带原始行，便于用户判断 |
| GitHub 不可达 | 手填路径为第一兜底，镜像前缀为第二；下载失败不清空已配置路径 |
| 多档并发写同一文件 | 写入前检查 mtime 是否变化（外部改动），提示「文件已被外部修改，是否覆盖」 |
