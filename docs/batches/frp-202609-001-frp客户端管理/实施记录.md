## 客户端多版本管理（用户第二诉求，提交 `3aecf53` / `fd8e6cc`）

**诉求原话**：实际使用时由于服务端的限制，本地可能会存在多个客户端版本，也会随时添加官方不同版本或者定制客户端；现在没有地方可以看当前支持的客户端版本，也没有随时添加的入口，配置时也不能自己选择客户端；另外左下角的打开目录点了没反应。

### 定稿形态（用户拍板）

1. 入口放左侧栏左下角；默认客户端版本在客户端管理弹窗里设置
2. 客户端版本与具体配置档案绑定；新建档案默认选中默认版本
3. 添加方式两种：引用外部已有路径（不复制文件）+ 一键下载官方版本

### 实现要点与踩坑

- 表：`clients`（id/label/path/version/source/is_default）+ `profile_client`（档案 → 客户端）；
  迁移 v2 追加。`id` = 路径 SHA256 前 8 字节十六进制，同路径重复登记天然幂等
- **只登记路径，不复制文件**：定制客户端多在固定目录里持续更新，复制进工具目录会立刻过期
- 档案绑定为空表示「跟随默认」；档案列表直接带 `clientId`，避免每个档案单独查一次
- 工具内下载改按版本号分文件 `frpc-<版本>.exe`，多版本可并存；下载完成自动登记进清单
- 既有用户靠 `seed_if_empty` 补登记（清单为空时依次探测设置项 / 下载目录 / PATH / 常见位置），
  需同时认旧版遗留的 `bin/frpc.exe` 与新的 `frpc-*.exe`
- 版本号比较必须按点分段数值：字符串序会把 `0.9.0` 判成比 `0.71.0` 新
- **校验与启动统一走档案绑定的客户端**：此前 `verify` 用全局探测结果，会出现「校验通过但启动失败」
- 弹窗与档案详情共用一份状态（`provide`/`inject`），否则弹窗改完默认项、详情页还显示旧绑定
- 「打开目录」根因：`ProfileSidebar` 的 `emit('openDir')` 没有任何监听者，`FrpWorkbench` 挂载时漏写
  `@open-dir`，事件抛给空气。全仓库扫过自定义事件的监听情况，仅此一处

### 真机验证（pid 95692）

- 左下角：`frpc 0.71.0` + `[FRP 客户端管理]`（自动登记了此前下载的 0.71.0）
- 弹窗：客户端清单 1 项（frpc 0.71.0 / 默认 / 工具内下载 / 完整路径）；含「引用已有 frpc」与下载区
- 档案详情：`客户端 [跟随默认 ▾] 当前：frpc 0.71.0`
- 「打开目录」→ 已按用户反馈改为档案级（提交 `26c4061`）：左下角那行「配置目录路径 + 打开目录」
  删除，改为档案右键菜单「在资源管理器中显示」，定位到具体那一个 `.toml`。理由：配置目录固定
  不变、没有信息量，而「这个档案在磁盘哪里」才是从列表点进去时想知道的；真机点该菜单项后
  资源管理器打开 `profiles` 目录并选中目标文件

### 2026-09-15 强校验文件名真 bug 修复（提交 `c2e2240`）

- 真 bug：代码请求 `frp_{version}_checksums.txt`，而上游固定提供 `frp_sha256_checksums.txt`，每次都 404
  后静默退化成「未强校验」——下载路径从未真正校验过压缩包。现按上游真实文件名请求，并按三态分别报：
  通过 / 不符（丢弃文件并报期望与实际哈希）/ 拿不到（再区分该版本确实没有、网络取不到、列出的资产里没有这一条）
- 未强校验时给出的哈希改为压缩包哈希：上游列的就是压缩包哈希，给解压后的可执行文件哈希无法对照
- 前端此前把「装好了但未强校验」的说明整条丢弃，现在在卡片上以警告提示展示
- 真机取证（release 版 + CDP 直调 IPC，产物已清理）：
  - 下载 v0.71.0 → `ok: true`、`error: null`；能走到「无警告」的只有强校验通过这一条路径
  - 独立复核：另下 `frp_0.71.0_windows_amd64.zip` 实测 `9e5062e3…819f`，与上游 checksums 对应行逐字相同
  - 下载 v0.40.0（该版本上游没有 checksums 资产）→ `ok: true` 且带警告
    「上游未提供 frp_sha256_checksums.txt（版本 0.40.0 可能较旧），未强校验；仅校验了解压完整性。压缩包 SHA256：`184669dc…16c4`」
  - 独立复核：另下该压缩包实测 `184669dc…16c4`，与应用报出的哈希逐字相同
- 未取证：校验不符分支在真机无法构造（需篡改上游文件），只有单测覆盖
- 顺带观察（未修，不在本次范围）：Windows Defender 会查杀老版本 frpc，实测 v0.40.0 的 `frpc.exe` 与
  `frps.exe` 均被清除；应用仍按「下载成功」登记该客户端行且版本号为空
- 测试环境提醒：`APPDATA` 环境变量对 Tauri 的 `app_data_dir` 无效（走系统已知文件夹，不是环境变量），
  本次取证因此直接落在真实数据目录；测试产物已删并核对回原状
