### D1 · AR04 的行为测试手法（P3a 前置）

**背景事实**：`src/plugins/ssh/useSshWorkspace.ts`（723 行）要保住的等价行为全是事件驱动的——迁移失败可见提示、主机密钥队列并发确认、取消/dispose 后结果不得重开页签、卸载先于订阅 resolve 不泄漏。仓库前端测试**目前只覆盖纯函数，全仓无 `vi.mock` 先例**（自验：`grep -rln "vi.mock" src --include=*.test.ts` 无命中；`src/plugins/ssh/connection/useSsh.test.ts` 是纯函数写法）。

| 选项 | 说明 |
| --- | --- |
| A（建议） | 允许为 composable 引入 `vi.mock('./ipc')` 组件级测试，约 8–10 个用例，先跑通再拆结构 |
| B | 只测纯函数，行为等价靠真机手测（不引入新范式，但拆分无自动证据） |
| C | 先只产出行为清单文档，测试等拆分后补 |

**建议理由**：拆分后要自证「零行为变化」，没有自动证据就只能靠真机手测覆盖全部事件路径，成本更高且易漏。该范式一旦建立，后续 composable 拆分（connections/lifecycle）可直接复用。

**默认动作**：无回复则按 A 执行，并在提交说明中标注「仓库首例 IPC mock 范式，如需回退可 revert 该提交」。

**判据**：新增测试在拆分前后均通过；拆分前后「同输入 → 同状态转移」，用例覆盖上表四类行为。

## 五、决策不得违反的约束

- 提交：Conventional Commits `类型(scope): 中文描述`，标题自包含；只 commit 不 push；并行会话只 `git add` 本会话改过的文件，禁 `git add -A`。
- 一次一项、一项一提交；按风险层跑门禁（Rust：`cargo fmt` + 相关测试 + `clippy -- -D warnings`；前端：`pnpm test/lint/build/format:check` + `check:deps`；持久化/凭证/注册：加旧数据夹具与故障恢复）。
- 改 `tauri.conf.json` / 插件注册 / `Cargo.toml` / 能力权限必须 `pnpm tauri dev` 冷启动冒烟。
- 规模红线是评审信号（Vue 约 300 行、Rust 生产实现约 400 行触发职责审查），不自动失败。
- 不新增功能（用户口径「功能不要做的太冗余」）；行为不确定先固化为特征测试再动结构。
- 历史任务书不重写，只补失效说明；门禁类改动（skill / 检查器 / CI 规则）与新增测试范式须先确认。
- 不记录任何凭据；凭证不写文档、不入库。
