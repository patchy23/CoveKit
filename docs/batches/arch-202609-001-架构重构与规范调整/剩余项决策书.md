## 2. D1：行为测试方案

### 2.1 测试边界

仓库已有所需测试依赖，`vitest.config.ts` 使用happy-dom并发现 `src/**/*.test.ts`，本批不新增测试框架。mock实际导入的IPC门面及事件订阅、时钟、存储边界；路径按测试文件与消费模块解析，不能机械复制 `vi.mock('./ipc')`。

使用最小宿主组件执行带生命周期的composable，真实挂载/卸载触发Vue钩子；纯响应式逻辑可在作用域内测试。Pinia使用独立测试实例，外部协议及平台效应由假实现控制。不要把待测状态所有者整体mock掉，也不要用源码字符串断言替代行为断言。

延迟Promise、可触发事件、可检查的取消/退订句柄、可控时钟用于稳定制造乱序和竞态；每例恢复计时器、卸载宿主、清理store/localStorage与mock，保证单独及整套运行都通过。断言用户可感知状态和资源责任，不固定无关内部调用顺序。

### 2.2 SSH 必需场景

1. 旧配置迁移失败可见且保留快照；成功与部分凭证失败提示分别验证。
2. 保存成功关闭表单；失败保留可编辑数据；profiles/groups只有一个有效状态源。
3. 删除服务器关闭其关联工作区，不误关其他服务器；删除失败不得伪装成功。
4. 两个连接并发完成且顺序颠倒，结果仍归原连接；取消/关闭后成功结果不重开页签。
5. 主机密钥两个请求依次应答；取消、卸载不会遗留等待者或错误应答下一项。
6. 卸载先于订阅Promise完成，晚到退订句柄仍被调用且只释放一次。
7. 旧会话断开事件不覆盖重连后的新会话；手动关闭后自动重连计时器不复活连接。
8. 空闲断开、终端会话/缓冲保持与清理责任按现有活跃实现核对，避免恢复孤儿模块的过期行为。

用例数量由上述分支决定，8–10不是上限。P3a先对当前活跃根建立证据；发现已有行为违反任务要求时保留失败复现，单独fix后作为新基线，不将缺陷冻结为正确行为。每个重构提交复用同组行为断言。

### 2.3 Database 必需场景

补测四域及兼容门面：两连接/两tab的结果归属、旧响应晚到、取消后重试、关闭一个tab不影响另一个、元数据缓存按连接与schema隔离及失效、历史与收藏成功/失败、保存期间切tab的归属。IPC假实现可以证明前端状态责任，不需要真实MySQL/PG/Redis才能开工。

现状核对中，`useQueryWorkspace.ts` 的执行与取消涉及 `await` 及活动连接/tab；须用切tab和乱序用例实证，不能因返回77个key相等就视为通过。后端取消粒度若实际为connection级而无法满足同连接多tab隔离，先写失败复现，按最小请求身份/取消契约修复并同步前后端；不得只改测试期望或把问题藏在UI禁用中。具体修复以复现为依据，本文件不宣称已经证实该缺陷。

### 2.4 AR03 补证据

依赖守卫和构建只能证明依赖/类型约束，不能证明挂载成功。补代表性Ui基础控件无Pinia/Vault时的挂载与交互，以及凭证选择/新建失败和复制反馈测试；复用本节宿主，不要求所有控件机械新增同类测试。

## 3. D2、D5：串行实施与P3边界

由接手的同一执行会话逐项实施；完成一项后继续下一项，不逐步重复请求执行者选择。跨会话恢复仍先核对HEAD和工作区。发现别人正在改同一文件时不覆盖，调整到独立项或协调归属；本决策不控制其他用户任务，也不授权覆盖其改动。

统一此前两个计划中不一致的P3编号：

| 步骤 | 唯一范围与完成要求 |
| --- | --- |
| P3a | 当前活跃SSH实现的行为测试、现有缺陷复现及基线记录 |
| P3b | profiles/groups唯一所有者实际接入；补齐活跃根的较新逻辑；同一步删除根中的重复实现 |
| P3c | connections、hostkey、lifecycle实际接入；根保留协调门面；同一步删除被替代的useSshIdleWatch等孤儿实现 |

不能把“删除旧实现”拖到全部拆分后的不确定阶段。保留根入口以减少消费方无关修改，必要接口调整允许同步改消费方，不以“index.vue绝不能动”牺牲正确性。

SSH目录已移动，不伪造“执行前迁移表”。通过 `69f7c90` 的重命名diff和当前文件清单补一份**事后迁移核对表**，逐文件标旧路径、新路径、消费方、测试、缺失/新增；核对无遗留孤儿。该证据补齐验收，但历史上未先制表的事实保留。

一项可包含多个小提交，测试、真实缺陷修复和纯重构分别写清；回退后续依赖提交时按逆序处理，不能承诺任何中间提交随意revert都与后续兼容。

## 4. D3：测试环境与合入边界

### 4.1 确定策略

- 先做可控IPC自动化；再使用本机/隔离测试环境中的临时SSH服务、临时文件及一次性数据进行真实协议集成。
- 执行者先盘点现有环境。可复用已有本地服务能力；没有可用环境时记录缺口，不要求用户提供生产凭证来解锁自动化开发。不擅自新增系统服务、开放公网端口或使用文档出现的远端IP连接。
- 用户服务器联合冒烟保留，凭证由用户在应用内输入，不要求写进聊天、文档、测试夹具或提交。系统Vault的产品凭证存储能力仍保留；“测试凭证不入库”特指不写入仓库/验收材料，不是废除Vault功能。
- 本地临时真实服务可以承担协议验收；它不能替代Windows/macOS桌面交互及用户环境专有问题验证。只给出主机地址不等于授权连接和修改该服务器。

### 4.2 状态和放行条件

P3a/P3b/P3c在自动化、lint、build、依赖守卫及适用冷启动通过后可提交；协议测试或平台交互未完成时标“实现完成，验收待补”，不能标AR04全部完成，不能据此宣称可以发布。本决策没有豁免真机验收。若已测场景出现数据损坏、错误连接归属或资源泄漏，应先修复，不按普通环境缺项放行。

协议冒烟至少覆盖连接、取消、重连、并发主机密钥确认/拒绝、关闭后后台资源释放。Database以临时SQLite先验证真实存储，再在可用的临时MySQL/PG/Redis服务验证对应驱动路径，逐驱动列已测/未测，SQLite结果不能代替其他驱动。

## 5. D4：公共数据能力的依赖顺序

L0是设计冻结，允许现在先完成；原文“两者无文件交集”未经核验，且密钥、settings、paths、context事实上存在契约交集，因此不采用并行假设。确定顺序如下：

1. **L0冻结**：在现有导入导出专项文档落下空间/设备字段归属表、稳定身份、兼容布局、generation激活、密钥作用域及接口。不要再生成一份重复的“L0任务书”。`default/1`仅兼容承载位，不扩散为新数据的永久标识。设计同时考虑旧API库和未选数据的保留。
2. **A批T04/T05**：真实密钥库、旧密钥兼容与安全文件崩溃恢复；实现按L0边界，先在临时数据和测试密钥适配器上验证，补系统密钥库平台实测。
3. **B批T01/T02/T03/T06**：生效根、离线迁移、旧布局恢复、事务迁移；修复失败时数据位置一致性，不能因有OnceLock就当已修完。禁止空间功能复制尚不安全的迁移实现。
4. **C批相关T07/T09**：设置权威和设备/空间字段路由、凭证引用语义；T08平台交付检查纳入平台验收。P4必须追踪T09，不能只完成A批就勾凭证上下文接入。
5. **L1/P6及P4收尾**：默认空间身份/索引、上下文、路径、PluginDb、设置和密钥引用使用同一有效空间。前置修复先交付，L1完成消费方接线，避免互等。此步不交付整个导入向导。
6. **D批T10/T11与P5**：关闭协商、资源释放与维护互斥真实接入；T12/T13复用AR02/AR07成果，仅核对剩余差距，不重建装配器。
7. **L2–L5**：分类导出、预览、隔离/合并、引用重映射、加密与故障恢复按专项任务书交付；需要的关闭/维护和数据底座必须已通过验收。

P3与Database补测可在完成L0后先串行交付；上述安全前置若已发现可复现的高风险问题，可提前处理独立修复，不能为了目录整理推迟。执行者从当前HEAD核对哪些T项已经实现，以缺口为单位接续，不重复建设。

### 5.1 生命周期收口必须检查的语义

当前 `lifecycle.rs` 是模块级同步钩子，`Tab`等原因尚无完整消费方；现有签名不能被当成固定不可改契约。T10接入应支持异步前端协商，携带关闭请求身份、目标工具实例与上下文，单tab关闭不能执行全局模块清理；所有退出入口采用同一协调状态机，拒绝后不dispose，确认后不重复dispose。

超时仅结束等待，不代表工作线程或外部资源已经停止。必须验证超时后的迟到清理不能污染仍运行的空间；空间激活/迁移要求资源实际静默，无法确认静默则中止激活，不能照搬进程最终退出时的超时策略。维持重启生效，不引入空间热切换。

## 6. D6：P7分段及遗漏验收收口

**P7a现在先做基线**：记录提交、OS/架构、命令、配置、启动日志和关键窗口交互，Windows/macOS分别登记。冷启动必须来自当前代码的新构建及 `pnpm tauri dev` 路径，不能把旧exe存活12秒作为完整证据。缺macOS环境时明确保留缺项；CI安装包构建不等于桌面冷启动已验证。

**P7b最终收口**：P4/P5/P6实际接入后，在同一候选HEAD执行跨层全量检查、旧数据夹具、故障恢复与双平台冷启动。早期基线只作比较，不能替代后续改动验证；只重跑被后续改动影响的阶段性检查，但最终跨层门禁不能省略。
