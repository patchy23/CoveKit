## 3. 旧库实测（缺口 1）

新增 `src-tauri/src/plugins/http_ws/persistence/mod.rs` 的 `#[cfg(test)] mod tests`，3 个用例。
夹具在系统临时目录合成（历史 schema + 合成数据），**不触碰** `%APPDATA%` 下的用户真实收藏与密码。

| 用例 | 覆盖的事实 |
| --- | --- |
| `legacy_api_db_survives_layout_and_schema_migration` | 老布局 `<root>/api.db` 经 `migrate_layout_at` 搬入 `data` 分区（断言搬迁计数 = 1）；旧 schema（`api_list` 无 `type` 列、`user_version = 1`）经 `migrate` 补列后，两条老数据的名称与 URL 原样保留、`type` 统一落为 `http`；随后新增 `type='ws'` 记录与更新老记录均成功；关闭连接后重开同一文件，新增与修改均未丢失，`user_version` 推进到迁移表长度 |
| `legacy_api_db_readable_at_original_path_when_layout_not_migrated` | 布局迁移未执行时库仍在根下原路径，直接打开原文件迁移后仍可读（`data_path` 旧布局回落要保护的场景） |
| `fresh_db_migration_is_idempotent_across_reopen` | 新库 v1 建表已含 `type` 列，v2 的 `ADD COLUMN` 必然报 `duplicate column`，迁移按幂等跳过；第二次打开数据条数与类型不变 |

实测：`cargo test --locked --no-default-features --lib` → **187 passed / 0 failed / 3 ignored**（含本项 5 例）。

## 4. 测试模块路由（缺口 2）

新增 `src-tauri/src/framework/manifest_contract_tests.rs` 两个用例。

**为什么要新增**：运行期登记表本身由 `plugins/mod.rs` 的 `patchybox_routes!` 清单生成，因此既有的
「模块描述数量 == `ROUTABLE_OWNERS` 长度」是恒真比对，**抓不住「模块写了自己、忘在清单加一行」**——
这种模块根本不会被 `register_all` 装配，前端调用只会得到 `command not found`。

| 用例 | 覆盖的事实 |
| --- | --- |
| `route_manifest_covers_every_declared_module` | 用 `syn` 扫源码树取每个 `patchybox_module!` 的 `owner` 字面量（含 framework），与 `plugins/mod.rs` 的 `patchybox_routes!` 清单逐一对上（framework 豁免）；并要求清单每行都能解析到 handler，不能是死行 |
| `module_missing_from_route_manifest_fails_startup_validation` | 负例：模块登记了自己却没进路由清单时，`validate_routing()` 必须 panic，不得静默不装配 |

**有效性实测（关键）**：临时抽掉清单里的 `"tts" => tts,` 后重跑，用例按预期失败，断言输出为
「模块声明与路由清单不一致」并给出 `left`（声明侧 7 项）/ `right`（清单侧 6 项），随后恢复清单并复跑通过。
该临时改动**未提交**，最终工作区不含它。
