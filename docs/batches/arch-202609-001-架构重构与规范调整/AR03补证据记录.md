## 3. 手法与可复跑命令

- 宿主：`mount(..., { attachTo: document.body })`。弹窗（`UiModal` / `CredentialForm`）经 reka 传送门渲染到
  `document.body`，**必须挂到 body 并按 `document.body` 查询**；用 `stubs: { teleport: true }` 会把 reka 自己的
  `Teleport` 组件整个替换掉，面板内容一并消失（一度让「表单没渲染」的假象出现，已证实是桩的副作用而非组件缺陷）。
- 只替身 IPC：`vi.mock('@/core/ipc/ipc', …)` 提供 `ipc.vaultList` / `ipc.vaultSave`，不替身待测组件。
  凭证复合组件自己会调 `useUiStore()`，因此用 Pinia 独立测试实例；**基础 UI 侧一个 Pinia 都不装**（这正是要证明的事）。
- 复跑：
  - `npx vitest run src/core/ui/components.test.ts src/core/vault/ui/credentialComposite.test.ts src/core/feedback/useCopy.test.ts`
  - 全量：`pnpm test`

## 4. 未覆盖（诚实清单）

- `UiSelect` / `UiCombobox` 的**下拉展开与选项点击**未纳入：内容在传送门里且依赖 pointer 事件，本环境稳定性不足；
  本次只断言挂载与选中回显（用户在真实界面点开选项的行为未自动化，属 UI 走查范围）。
- 未做「每个控件机械挂一遍」的全量扫描（决策书 §2.4 明确不要求），只挑结构复杂与凭证复合两类代表性控件。
- 其余基础控件（按钮、输入、页签、分页等）沿用 `components.test.ts` 既有用例，本次未增删。
